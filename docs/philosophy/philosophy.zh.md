# DevolaFlow 哲学导读

本文面向人阅读。它解释这套哲学在说什么、为什么这样定、在仓库里长成什么样。它不是约束文本——约束 agent 的是 `.devola/philosophy/PHILOSOPHY.md` 这一个视图（总纲 + 普适原理 + 本仓反思），英文，由两条链渲染并经人 ratify。若与本文有出入，以英文约束稿为准，并请修正本文。

编号 `Ch1–Ch9` 是总纲九条，`Ax1–Ax6` 是六条第一性原理，`Drv1–Drv6` 是由它们推出的派生原则，`Rf1–Rf6` 是本仓关于自身的反思；每条原理下的判据有自己的地址，如 `Ax3.v2`。仓库里每一条 artifact 或 method 域的决策都必须引用其中至少一个地址，所以这些编号会在 `DECISIONS.index`、rules.md 和错误码注册表里反复出现。约束稿的链是纯英文的；本文的中文是从作者稿采摘而来，不入链。

## 为什么是哲学，不是 Soul

近来流行给 agent 写一份 soul：它是什么性格、偏好什么风格。Soul 是一项被锚定的特质。哲学不是特质，而是一组能推出所有具体做法的理念——面对没见过的情境，特质只能类比，理念可以推导。DevolaFlow 选择后者：不规定 agent 怎么做，只规定什么叫做对了，剩下的让它自己推。

## 三层：形式、普适、反思

这套哲学分三层，区别很大，先说清楚：

- **形式（总纲 Ch1–Ch9）**——"哲学这一理念"的操作化：原理怎么编址、怎么证伪、怎么锁、怎么修、冲突怎么办。它**不在链上**：文本住在 devola 工具里，随工具版本化；你接受了哪个版本的形式，记在锁里。用 devola 就等于接受形式；工具升级带来新形式时，工具会停下来等你确认；不接受的出路是降级、不用或 fork 工具。
- **普适原理（Ax1–6 / Drv1–6）**——治理"agent 驱动的工作"。任何采用 DevolaFlow 的仓库里的 agent 都会遇到它们。它们自己是一条链，随工具作为**提议**到达下游；下游 enact 之后就是下游自己的了，可修可废。
- **本仓反思（Rf1–6）**——本仓对普适原理的**特化理解**，加上关于"如何构建 DevolaFlow 自身"的**信念**。也是一条独立的链：改反思永远不会动普适段的锚（下游钉住的是普适链的头，我们改一条 Rf 不该让下游看到"上游变了"）。只在本仓生效，永远不导出。每个采用 devola 的仓库都拥有自己的反思段；本仓的 Rf 只是这个形式的第一个实例。

区分的尺子只有一把：**下游仓库的 agent 违反它时，装在那个仓库里的 DevolaFlow 应当拒绝吗？** 应当 → 普适；不应当，或者那条压根不描述下游会发生的事 → 反思。归档由工具替 agent 做，agent 无从违反"采摘非保全"，所以它是反思；注入面是我们设计的，所以"注入面极薄"也是反思。

反思有两种来源。**特化**：把某条普适原理放到本仓语境里，读出来的具体立场——"路由统一"是 Ax6 在"我们造调度器"这个语境下的读法，必须引它所特化的原理。**信念**：不由普适推出、只关于本仓自身的主张——"递归构造"就是。两种都不得与普适矛盾（矛盾就停放，不许自己改普适），也不得成为普适条目的父；反思引用了哪条 Ax，那条 Ax 就不算死原理。

## 本仓的两顶帽子

本仓很特殊：它既是**研发目标**（我们在这里造 DevolaFlow），也是**模板**（每个下游仓库长得和它一样）。所以本仓持有两种哲学材料：

- 作为模板持有的——总纲文本（形式）、普适链（对外的统一边界）、三条域中立的**示例反思**。这些随工具下发：总纲随工具携带，普适链在构建时导出为默认提议，示例反思用来示范"反思长什么样"，采用方可以接受也可以无视。
- 作为研发目标持有的——反思链（本仓的特化理解）、这份导读、G01 里的审阅稿。这些留在本仓。

模板自己也得是模板的第一个实例：本仓的 Rf2 就是接受了自己下发的示例 Ex1 再本地扩展而来。

## 文件在哪、何时生成、注入什么

任何用 devola 的仓库（本仓也一样）只在 `.devola/philosophy/` 下有四件东西：`universal.jsonl`（普适链）、`reflection.jsonl`（反思链）、`ratified`（指纹锁文件：形式版本 + 两个链头 + 视图指纹——名字即内容，"人已批准的四项"；不叫 lock，因为 goal 里另有互斥用的 `.devola.lock`）、`PHILOSOPHY.md`（唯一视图，反思为空时第二部不渲染）。根目录零足迹。链和 `ratified` 在 agent 忽略清单里（由 `.devola/config.toml` 声明、`devola host render` 渲染到每个宿主的忽略面）——agent 读哲学只经视图和 `devola philosophy` 查询面（Ch6），链上的决策快照它看不到。

本仓多一个 `philosophy/` 源目录，与 `ops/` 平级：`charter.md`（总纲真相源，英文，严格结构，front matter 带 `charter_version`；文本变了版本没 bump，`ops verify` 会拒绝）和 `reflection.example.jsonl`（示例反思源）。构建时 `ops render` 把总纲、普适链的 active 版本、示例三样嵌进 devola 二进制——所以 CI 要求本仓的锁匹配，未 ratify 的哲学编不进工具。

生成时机：`devola init` 在终端里一次确认完成导入、enact、渲染、ratify（非终端只 enact，进入锁缺失态）；此后每次链写入都在同一事务里重渲染视图；ratify 写 `ratified`。工具升级后第一次运行，形式版本不同就进"形式待确认"态（只许 ratify / verify），普适 seed 的头不同就在 brief 里出一行"N 条上游提议待处理"，处理只经 `philosophy proposals`（逐条 accept / decline，名字不叫 upgrade——上游变更是提议不是义务，Ch9），永不自动应用。

注入——或者说不注入：哲学**不进任何常驻面**（Drv5）。宿主的 rules 对主 agent 和 subagent 一视同仁，往那里写哲学等于让每个只管干活的 subagent 都背一份用不上的索引。哲学只在**设计时刻被拉取**：编排者开工先跑 `devola brief`，brief 头部就是那约 80 tokens（Ch1 一句、"Charter Ch1–Ch9"、普适与反思标题、查询方法）；`park resolve` / `goal align` 要填 `ref` 时，CLI 就地提示用 `devola philosophy` 查地址。执行者拿到的是 `checklist start` 给的条目、验证方式和适用决策的陈述，或 `handoff` 生成的交接包（带地址作引注，不带原理正文）。skill 的 SKILL.md 只留静态两句：先 brief；原理经 philosophy。

## 总纲：这份哲学如何运作

1. **Ch1 效力**——链是所在仓库的第一性原理。任何决策、规约、工具里的约束，都要能说出自己来自哪一条（总纲条款、原理或判据地址皆可）。说不出的决策会被 CLI 拒绝。它对自己也一样。
2. **Ch2 适用**——它同时约束工具、agent 和人。每条原理自带"怎样算违反"的判据，否则它只是口号。每条判据有地址（`Ax3.v2`）并标明性质：`[M]` 本质上能让工具判，`[R]` 只能人评审。标的是性质，不是"现在有没有人守着"——后者由 `--check` 从错误码的 `guards` 反算；标了 `[M]` 却没有任何守卫的判据会被点名。普适与反思两段在此定义。
3. **Ch3 修订**——改原理是全仓最不可逆的事。只能经一条 method 域决策取代或撤销，而且裁决、修订、重新 ratify 三步在同一次终端确认里一口气完成——任一步失败全部不生效。修订事件会把它所依据的决策冻结一份快照进链。地址不变，血缘保留。总纲条款不在此列：它属于形式，不在链上，随工具版本化——形式变了同样要人在终端确认才生效。
4. **Ch4 守卫**——锁记着你接受的形式版本、两条链各自的头和视图的指纹，有三种状态：锁不存在，只许 enact 和 verify；锁不匹配（包括形式版本不符），只许 ratify 和只读校验；锁匹配，一切正常。
5. **Ch5 冲突**——原理之间没有优先级，编号只是叙述顺序。两条原理拉扯时，停放给人判，决策同时引用两条并记下权衡。已知张力预先登记（普适段 `Tn1–Tn5`，反思段 `Rt1`），命中的决策引用编号即可。
6. **Ch6 解释**——解释权归人。agent 拿不准就停放。agent 只读视图和查询面；链上的原始事件（含修订时冻结的决策快照）和锁不属于查询面，agent 不读——这两件在 agent 忽略清单里。修订理由不另写文件：它已经在链上的快照里，人要看历史用 git 看视图的版本即可。
7. **Ch7 过渡**——enact 之前的草稿没有效力；第一次 ratify 才生效。工具就位前直接写文件，是登记在册的例外。
8. **Ch8 层级**——原理不指名任何机制；机制声明自己体现哪条原理，"哪些错误码体现了 Ax3"由 `devola philosophy --check` 反算。约束稿正文只准用自然语言和所属段的受控词表写，命令名、选项名、文件名一个都不能出现——`philosophy verify` 拿 CLI 自省导出的标识符表逐词查。所以下文的"在本仓的样子"只存在于这份导读里。
9. **Ch9 传播与主权**——哲学没有优越感。每个仓库对自己链上的原理有完全主权。原理以带血缘的提议到达，enact 后归本仓所有，在本仓修订。上游后来的变更也是提议，不是义务，逐条接受或拒绝，拒绝也留痕。任何仓库都可以把自己的普适段导出给它的下游——血缘链于是可以有很多代：devolaflow → 团队仓 → 项目仓，每一代都可以变异。反思永不导出；但工具可以带几条域中立的**示例反思**作提议，示范反思长什么样，接受了才算你的。认同"要有哲学"是使用这套装置的唯一前提，认同哪一条具体原理不是。

## 第一部：六条普适原理

### Ax1 可度量

> 驱动力的源头是可度量；可度量的基石是可重复；可重复的基石是 Harness。

一切迭代的动力来自能量出来的差距。量不出来，就没有方向；量得出来但每次结果不一样，等于没量。所以可度量依赖可重复，而可重复依赖 Harness——那套让行为能被反复执行、反复观测、被门禁把住的内部脚手架：环境、夹具、探针、构建发布装置。它不交付，拆掉也不影响能力本体——这正是它与"能力"的分界。

在本仓的样子：清单条目没有 `--verify` 不能建；没有 `--evidence` 不能标 done；CLI 每条命令都往 telemetry 记账，包括记账本身；CI 有四个量化门禁（行覆盖 95、分支 90、功能 100、攻击性 100）。

怎样算违反：验收步骤写不成可重复的命令；有 done 却没有证据；某条命令路径不产生 telemetry；合并或发布路径上没有门禁。

### Ax2 表现优先

> 只定义并验收行为表现，不规定实现与操作；交界面是行为定义的载体。

对 agent 说"按这些步骤做"是脆弱的——步骤总有不适用的时候。说"做到这样算完成"才稳。而"这样"要能说清楚，靠的是交界面：输出信封、错误码、ID 语法这些契约。契约清楚，行为定义就清楚；实现可以整个换掉而外面感觉不到。

在本仓的样子：所有命令的 `--json` 信封和错误码是一等产物；ID 的两级引用语法固定；evals 只断言表现不看过程；引擎归一就是一次"表现不变、实现替换"。

怎样算违反：规约写成了步骤；某个交界面没有契约或契约悄悄漂移；验收标准里出现实现细节；不读实现就判断不了合规。

### Ax3 约束机械化

> 规约必然被打破；约束应由工具承载并端到端包住，而非依赖文本规约与自律。

写在文档里的规约，agent 会忘、会误读、会在压力下绕过——不是恶意，是不可靠。所以约束要住在工具里：违反就拒绝，不做容错，不"警告但放行"。写在文本里的规约只是暂时还没机械化的约束，要标明它处在 none → rule → hook 阶梯的哪一级；实在机械化不了的，显式停放为风险。

在本仓的样子：哈希链让手改文件必被 verify 发现；授信矩阵锁住未授信条目；类型校验 fail-quick；每个错误码都声明它守卫哪条判据，攻击性测试语料对每个错误码至少有一个案例证明它真的会开火、开火后状态无损。

怎样算违反：一条没机械化的约束既没标它处在阶梯哪一级、也没停放（本仓即 method 决策 enforce=none 又无 R 引用）；存在绕过 CLI 直写受管面的通道；对违约只警告不拒绝；某个错误码说不出它守卫什么。

### Ax4 显式优于隐式

> 一切决定、废弃、假设与例外都必须显式留痕；没有静默的缺省。

隐式的东西无法被审查、无法被度量、无法被撤销。废弃一项承袭能力要写明；拿不准的事要停放而不是搁在脑子里；决策必须走唯一入径并带上血缘；例外要入账。连"这条判据目前查不了"也要写出来——不可查而不说，就是隐式。

在本仓的样子：26 项历史能力逐条显式处置；停放区 `parking.jsonl` 承接一切待人裁决之事（Q 前缀——它们是待人回答的问题，不只是风险）；决策只能从 `goal align --decisions` 或 `park resolve` 产生并带 `cause`；`--override` 必须带 `--reason`；选不出 `kind` 时用 `other` 兜底并在堆积时告警。

怎样算违反：承袭下来的能力没有处置记录；放弃、撤回、越权（本仓即 drop / withdraw / override）不带理由；决策没有来源；裁决缺 context 或 quote。

### Ax5 可逆性分级

> 门槛与不可逆程度成正比——可逆之事放行，可撤销之事留痕，不可逆之事设门归人。

这条原理解释了整套体系里所有"为什么这里要人确认、那里不用"。可逆的操作不该设人工门槛，设了就是让人做机器能做的事；可撤销的操作要留痕，方便回退；不可逆的操作要有理由、要人确认。每个操作都要声明自己属于哪一级，引擎据此决定门有多高。级别按**后果**判，不按"记录能不能回滚"判——改哲学在链上随时能改回来，但下游据此做出的决策收不回，所以它是不可逆级。

在本仓的样子：profile 里每个 op 声明 `reversibility`；改哲学要 TTY 确认；draft 状态随便改，授信后加锁；决策的 supersede（可撤销）与 revoke 分开；drop / withdraw 必带理由；`revisit` 让约束到期进入复审（不自动失效）。

怎样算违反：不可逆操作没人确认；可逆操作被设了人工门槛；某个操作没声明可逆级别。

### Ax6 上下文稀缺

> 上下文是最稀缺的资源；一切冗余都是成本，一切过期都是污染。

Agent 的上下文窗口是硬约束，塞进去的每一段文本都在挤占别的东西。所以注入的每段文本都得有消费者；目录无需求不建；过期的东西要消解而不是留着；用约定的结构让数据天生紧凑，而不是事后摘要。

在本仓的样子：skill 薄壳只有 Ch1 一句加原理标题索引；Router 注册表按需路由；`revisit` 让约束到期复审；byproducts 随 goal 消解、读取经 rtk 瘦身；历史版本的 compression 管线被显式废弃。

怎样算违反：注入了却没被用到（性质上可机械查，等 Profiler 有消费统计后才有守卫）；不经路由全量注入；长期文本约束没有失效条件；中间产物没有消解路径。

## 六条派生原则

派生原则由原理推出，有独立编号，可以被决策直接引用。

- **Drv1 目标驱动**（← Ax1, Ax2）——一切工作从被定义、被拆解、可验收的目标开始。度量要有标的，表现要有标尺，两者都是目标。目标没定义清楚不进生产。
- **Drv2 三权归属**（← Ax2, Ax3, Ax5）——判别归人、执行归 agent、约束归工具。"判别归人"是排除法推出来的：Ax3 说被约束者不能自持约束，agent 出局；Ax3 推论说机械化不了的要停放，工具也判不了停放的事；剩下只有人。Ax5 的不可逆之门更直接归人。
- **Drv3 Harness 优先**（← Ax1）——先建度量能力，再做主力产出。无 Harness 则无度量，无度量则无驱动。所以分级授信时 harness 类条目先放行。
- **Drv4 规约的归宿**（← Ax6, Ax3）——每条规约问两个问题：能机械化吗？永久吗？能机械化的进工具；不能机械化但永久的留作常驻规则（应极少）；不能机械化又非永久的转为 experience，按需查询。
- **Drv5 分层传导**（← Ax3, Ax2, Ax6）——哲学驱动设计，设计驱动装置，装置约束行为，行为由此贴合哲学；执行者不必被要求理解一次哲学。谁读哲学？设计和裁决的人与编排 agent。执行任务的 subagent 遇到的是交界面上的约束——条目、验证方式、适用决策——不是原理。这条解释了为什么哲学不进常驻注入面：宿主 rules 不分角色，写进去就是给所有执行者背包。违反的样子：派给执行者的简报里贴原理正文；哲学被注入到执行者会读的面；某项对执行者的期望只靠"理解哲学"、没有任何装置或交界面兜着。
- **Drv6 命名即边界**（← Ax2, Ax4）——命名即描述，描述即行为，行为即边界。名字是最短的交界面（Ax2）；名字不描述行为，含义就是隐式的（Ax4）——一名多义、一物多名都是隐式含义的形态。一物一名，一名一物。这条是第三十四轮术语审计的产物：审计发现 `risk` 装的不是风险而是待人裁决的问题、`dispatch` 并不派发、`lock` 同时指指纹凭据和互斥量、`seed` / `reason` / `verify` / `context` 各有两义、`sunset` 与 `revisit` 是一个行为的两个名字——每一处名字失真背后都有一处设计含混。违反的样子：受管文本里出现没定义的专名或已弃用的旧名；名字的行为超出或不及描述；两名一物或一名两物。它的机械化形态见下文"词表"。

## 第二部：本仓的六条反思

这些是 DevolaFlow 对普适原理的特化理解，和关于自己怎么造自己的信念。它们约束本仓的决策，不约束任何下游。下游仓库会写自己的一组。带 "←" 的是特化（引它所特化的原理），不带的是信念。

### Rf1 递归构造

> 面对任务不止于造工具，而要造出能构造工具的方法论；每一层抽象都必须能被上一层构造出来。

需要一个清单管理就写一个清单管理，需要一个风险登记再写一个——这是造工具。DevolaFlow 要的是造出那个能生成"清单管理""风险登记"的引擎，让下一个受管面只需要一份声明。扩展走声明和注册表，不改代码；schema 先于功能。这是本仓的存在理由，但对一个用 DevolaFlow 写机器人驱动的 agent 来说，"先造驱动生成器"不是它的义务——所以它是反思，不是普适。

在本仓的样子：单引擎加多个 profile；ID 前缀走注册表；ledger 在运行期声明 schema；Router 用一套注册表承载所有路由类别。

怎样算违反：新增一个受管面要复制一遍实现；扩展需要特判代码；某个交互面没有 schema。

### Rf2 自用优先（← 示例 Ex1，接受并本地扩展）

> 本仓先把自己造出的东西用在自己身上，然后才交给任何人；本仓的原理必须能驱动本仓自身的设计、迭代与收敛，并对原理自身同样生效。

这条是本仓接受了自己下发的示例 Ex1（"自用优先"）再加上本地扩展得到的——模板必须是模板的第一个采用方。前面的原理不是用来约束别人的，先约束 DevolaFlow 自己。任何机制先在本仓自举；原理集合本身要可度量（哪些原理有引用、哪些没有）、可证伪（每条都有判据）；本仓自己的流程若用本仓机制表达不出来，说明机制有缺。下游需要的那一点点——"约束对自身生效"——已经在 Ch1 里了。

在本仓的样子：G01 这个目标就是用 devola 管理的；决策必须引用原理；brief 报告原理覆盖度和可机械化判据守卫率，零引用的原理是"死原理"（信号，不是门禁）；telemetry 记录自己；哲学文件本身由 philosophy profile 管理。

怎样算违反：对外提供的能力本仓自己一处都没用；存在死原理；存在本仓机制表达不了的本仓流程；仓库自己不遵守自己的规约。

### Rf3 路由统一（← Ax6, Rf1）

> 调度、环境、知识、清单皆是路由问题，共用一套注册表与查询面。

这是 DevolaFlow Router 的架构宣言。下游 agent 把它当功能用，不需要持有它。

怎样算违反：不经注册表的硬编码分发；同类路由多套实现。

### Rf4 采摘非保全（← Ax6, Ax4）

> 归档与压缩是显式提取沉淀、显式随葬其余，而非整体保全。

过期即污染，所以不整体保全；随葬也要显式，不是静默删除。采摘得先能分辨——决策按 domain 三分，就是为归档时分得清。归档由工具替 agent 做，所以这是我们设计归档机制时的信念，不是下游 agent 的义务。

怎样算违反：归档整体搬走没有提取；决策没标 domain；删除不留痕。

### Rf5 注入面极薄（← Ax6, Ax3, Drv5）

> 注入面只承载入口与查询方式，不承载约束；约束强度来自工具而非文本长度；哲学本身不进任何常驻注入面，只在设计时刻被拉取。

哲学自己第一个服从这条：常驻面（skill 薄壳、rules）里没有哲学，只有"先 brief、原理经 philosophy 查"两句；那约 80 tokens 的索引在 brief 头部，编排者开工时读到，subagent 永远不会碰到。rules.md 的行预算由工具执行，agent 无从违反——所以是反思。

怎样算违反：注入面出现入口与查询方式之外的约束条款；注入面长度随规约数量增长。

### Rf6 宿主无关（← Ax2, Rf1）

> 本仓造的装置不依赖任一宿主；宿主是适配器的实例，装置的任何行为经交界面定义而与宿主无涉。

devola 是普适能力，不是某个 IDE 的插件。Cursor、Claude Code、Codex、Copilot、dsh 各有自己的规则文件、技能目录、忽略文件、hooks 格式——这些差异全部收进适配器：goal 里的 `rules.md` 是宿主中立的源，由适配器渲染成 `.cursor/rules/*.mdc`、`CLAUDE.md` 托管块、`AGENTS.md`……；忽略清单同理。新增一个宿主是"一条注册 + 一个小模块"，不动引擎。这条是 Ax2 在"我们要交付到很多宿主里"这个语境下的读法。

在本仓的样子：宿主是 Router 注册表的一类条目；`.devola/config.toml [hosts]` 列启用宿主；core 的 adapters 模块做渲染（`devola host render`），driver 模块（AgentDriver）驱动各宿主的 agent 做实测；`ops verify` 扫引擎代码里有没有出现宿主名。

怎样算违反：引擎或受管面代码里出现宿主名；某能力只在一个宿主可用却没标注状态。

## 张力与词表

普适段有六组已知张力（`Tn1–Tn6`）——比如度量要花上下文（Tn1：Ax1 × Ax6）、机械化约束容易滑向规定步骤（Tn2：Ax3 × Ax2）、执行者看到约束却看不到理由（Tn6：Drv5 × Ax4，默认方向：停放而非解释，理由经地址可追溯）。反思段有一组（Rt1：Rf2 × Ax6，全量自举成本）。命中的决策引用编号，按默认方向处理，不必重新停放。

词表按段分：普适段词表约四十条，分结构 / 装置 / 边界 / 行为 / 记录五组，含血缘、提议、导出、普适段、反思段、示例反思、形式版本、accept / decline、设计与裁决者、执行者；"修订记录"一词已删（链上快照取代了它）。第三十四轮增了两条装置词：**Harness（基建）**——面向工程内部、不交付、拆掉也不影响能力本体的脚手架（环境、夹具、探针、构建发布装置）；**能力**——交付给使用者的可调用行为，由 Harness 搭起来但不靠 Harness 存在。这两条是同一把尺子的两面：拆了它能力还在吗？在 → 它是 Harness；不在 → 它是能力。`revoke` 取代了 `repeal`——撤销一条原理和撤销一条决策是同一个动作，不该有两个名字。反思段另有增补（反思、模式、注册表、采摘、自举、死原理、宿主、适配器）。

### 词表之外：工程名字怎么定义

哲学词表管的是原理正文里的词。代码里的名字——命令、文件、字段、枚举值、前缀、角色——另有一套，但**没有独立的词表文件**：名字在哪里声明，一行定义（`doc`）就写在哪里——clap 的命令说明、profile 的字段声明、注册表的条目、`roles/*.toml`、manifest 的路径条目。`devola glossary` 只是把这些聚合起来查；缺 `doc` 的名字 `verify` 直接报。哲学词与工程名之间可以标对照（telemetry ↔ 度量痕迹、approve ↔ 授信、park ↔ 停放）——跨层同义不算一名多义，因为 Ch8 本来就要求哲学层用自己的词。

禁用词也不手写：每次改名是一条 method 决策，写着"旧名 → 新名"；`glossary --forbidden` 从这些决策里收集旧名。第三十四轮一次产生了十五条（risk → park、dispatch → handoff、user-interface.md → BRIEF.md、upgrade → proposals、infra → fault、sunset → revisit、repeal → revoke、Injector → adapters、AgentWrapper → AgentDriver、E → Ex……）。Preflighter 拿这两样当判据：受管文本命中旧名就拒绝，出现没定义的反引号标识符就告警交人。这就是 Drv6 的机械化形态。

## 示例反思

随工具携带的三条域中立示例（第三十一轮从八条候选中选定；前缀 `Ex`，repo 层多字母）：**Ex1 自用优先**（信念）——先把自己造的东西用在自己身上；**Ex2 门槛只升不降**（← Ax1, Ax5）——达到过的质量阈值不得降低，除非经不可逆停放裁决；**Ex3 缺陷先复现**（← Ax1, Ax2）——不能按需复现失败的缺陷不得宣告修复。它们不是任何仓库的反思，接受了才是；本仓接受了 Ex1 作为 Rf2。正文里出现的每个专名都必须在所属段词表有定义；反过来，CLI 自省导出的任何标识符，只要不在词表里，就不许出现在正文——这就是 Ch8 的机械化形态。schema 层一律使用英文术语。
