# v23.0.0 本轮次迭代收益汇报

生成日期：2026-09-01  
证据范围：v23.0.0 已落地代码、测试与发布前置检查；真实 CLI 校准 run 使用
`v23-20260831-real-01`，caller salt 为 `v23-20260831-real-01`。

## 一、结论摘要

本轮迭代已将四项反馈从“规则描述/事后检查”推进到“创建边界、生命周期门禁、
调度契约和可观测 harness”：

- 任务工作区：`entrance.md` 从容易漏写的补救文件提升为首批 artifact 契约，
  并覆盖 active change、`.local/tasks/`、lint 和 runtime gate。
- 持续推进：W-30 明确了有界等待、heartbeat、终止/升级路径，以及
  preflight 后局部 blocker 不得拖停独立 sibling 的规则。
- Token 优化：规则面与 skill 面完成压缩，保留 cache-layout witness、版本、
  host adapter 和 ghost contract；`AGENTS.md` 为 7986 tokens，低于 8000
  目标，`SKILL.md` 仍低于 4500 tokens。
- 证据基础设施：六宿主 fixture replay、Cursor captured transcript 导入、
  Claude/Codex/Kimi CLI probe、host/channel/layer/component 账本与聚合能力已
  接入 harness。

工程质量收益已被验证；“token 实际下降多少、质量是否保持、ROI 是否改善”仍
不能从本轮结果直接推出。

## 二、已确认的工程收益

### 1. 任务入口完整性更可靠

已实现：

- `entrance.md` 有单一模板所有者，并纳入 artifact 文件集合。
- scaffold、active-folder materialization、stub README backfill 和 task-folder
  lint 均覆盖入口文件。
- lifecycle gate 在 strict 模式阻断缺失入口，在 lite 模式显式告警。
- schema 将 `ENTRANCE_MISSING` 从 WARN 提升为 FAIL 语义。

收益：新建、恢复和检查任务工作区时，入口上下文不再只依赖某一条 happy path
或下一次写入触发的 post-hoc repair。历史不完整目录仍会被明确诊断，不会被
静默吞掉。

边界：本轮没有形成真实生产任务中 `entrance.md` 缺失率下降的前后对照样本，
该运营指标仍为 `INSUFFICIENT`。

### 2. 长时操作有了可执行的持续推进契约

已实现：

- W-30 要求每次等待都有 timeout、heartbeat 和 terminal abandon/escalation
  path。
- 当依赖满足且资源允许时，dispatcher 必须推进 ready work。
- blocker、dependency-blocked 和 wave conflict 被要求区分报告。
- 普通 blocker 或 `HUMAN_INTERVENE` 仅暂停受影响 item/task；独立 sibling
  继续推进。
- HARD breakpoint、preflight STOP、FULL_ROLLBACK、ownership violation 和
  destructive-policy violation 仍保留全局停止语义。

收益：本轮对真实 CLI 校准也采用了 bounded heartbeat。120 个 cell 的长时运行
过程中持续记录进度，未因等待而静默阻塞，也未因单个慢 probe 擅自取消健康
操作。

边界：等待期间安全并发比例、长任务 p50/p95 和 blocker 后 sibling
continuation 比例尚无匹配生产运行样本，不能宣称吞吐提升。

### 3. Token 优化从配置承诺推进到可追溯测量

已实现：

- 压缩 `.rules` 源并重新编译 `AGENTS.md`、Cursor rule surface 和 style
  surface，避免编译漂移。
- 27 个 context profile 补齐 `agents_md_slice` 配置。
- dispatch context telemetry 能记录 skill/rule/report 等分量及来源。
- token-injection measurement 记录包含 host、channel、layer、profile、
  arm、task class、run metadata 和证据可用性。
- Tier-A cache-layout byte witness、版本同步和 host adapter contract 保持
  通过。

可确认数字：

- `AGENTS.md`：7986 tokens，满足本轮 ≤8000 目标。
- `SKILL.md`：低于本轮 ≤4500 token 目标，且保持 `<500` 行约束。
- 六宿主 fixture replay：schema-valid、deterministic。

边界：上述是工程面和 fixture 面证据，不等于六宿主端到端实际节省。
配置中的 `slice_savings_pct`、缺失 usage 或 fixture token 均未被当作真实
成本下降。

### 4. 多宿主验证从“文件存在”升级为“证据分层”

已实现：

- 六宿主进入统一 harness 结构：Cursor IDE、Claude Code、Codex CLI、
  GitHub Copilot、KimiCode、DeepSeek Harness。
- Cursor captured transcript 有解析和导入路径。
- `cursor-agent` 与 `copilot` 已作为 measurement channel 接入 probe 能力，
  没有错误地扩张 HSC host 定义。
- CLI 运行失败、认证失败、超时、缺 usage 或缺 skill state 会保留为
  `INSUFFICIENT`，不会被转成零或 PASS。
- 运行身份保留 `run_id`、caller salt、`repo_ref`、`repo_sha` 等 W-3 元数据。

真实校准结果：

- 计划：120 cells。
- observed：120/120，100%。
- completed：73/120，60.8%。
- `INSUFFICIENT`：47/120，39.2%。

收益：本轮已经证明“矩阵执行和证据分类”可运行，且 120 个计划规格没有被
静默丢弃；同时明确暴露了 47 个不可观测结果，避免用不完整数据制造收益
结论。

## 三、发布与质量收益

`release-preflight` 已通过，关键证据如下：

- 全仓测试：5258 passed，144 skipped。
- version checks：36 passed。
- harness tests：150 passed。
- repository coverage：90.32%，达到全局 90% 目标。
- 16 个 host adapters 构建通过。
- human docs、rules drift、template metadata、ghost audit、repository hygiene
  和 site build 全部通过。
- Ruff check 与 format check 通过。

这说明本轮功能增量没有破坏版本一致性、分发镜像、规则编译、文档生成和核心
测试门禁。

## 四、收益判定

### 已确认

- `entrance.md` 已成为可创建、可检查、可阻断的正式 artifact。
- W-30 已进入源规则、编译规则和运行期测试契约。
- token 注入已具备按宿主/通道/层级/组件追踪的 measurement pipeline。
- 六宿主 fixture replay 与真实三 CLI 矩阵均有统一的证据分类。
- v23.0.0 发布前质量与兼容性门禁全绿。

### 当前仍为 `INSUFFICIENT`

- v23 相对 v22 的真实端到端 token 降幅。
- skill-on/off 对质量、耗时和 token 的因果差异。
- 六宿主之间的等价性和 ROI。
- `entrance.md` 缺失率前后变化。
- 长时等待吞吐、并发安全比例和 sibling continuation 比例。
- 47 个真实校准 cell 的可观测 token/skill/quality 细节。

## 五、建议的下一轮动作

1. 对 47 个 `INSUFFICIENT` cell 做失败原因分桶，先区分认证、CLI 输出、
   usage 缺失、skill state 不可观测和 timeout。
2. 在相同 repository revision、相同 task class 和相同 prompt 下补足可比较
   的 baseline/current paired runs。
3. 将 `entrance.md` 缺失率、heartbeat 覆盖率、sibling continuation 和
   等待时间纳入实际 workflow telemetry。
4. 只有在完成匹配样本、方差/CI 和来源元数据后，才更新 token savings、
   quality preservation 或 ROI 结论。

## 六、总体判断

v23.0.0 的主要收益是把四项反馈转化为可执行、可阻断、可审计的系统契约，并
让 token 优化从静态配置进入可复现测量阶段。本轮可以确认工程治理能力和验证
基础设施显著增强；对实际成本、性能和质量改善保持审慎，等待后续完整观测证据。
