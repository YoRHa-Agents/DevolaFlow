## §5 — Why DEFER (and what unblocks pass #2)

This pass intentionally lacks with-ability and no-ability eval run
output directories. Si-Chip's `aggregate_eval.py` consumes those
directories to compute the composite metrics that drive the
iteration_delta calculation — without them, the §23 gate evaluates to
DEFER unconditionally regardless of any other signal.

The PV-03 D-N-1 work item (`scripts/nines_to_sichip_eval_adapter.py`
prototype) takes a NineS `self-eval` JSON output and converts it into
the `runs-dir`/`baseline-dir` directory layout Si-Chip's
`aggregate_eval.py` consumes. When pass #2 runs in PV-03 with
adapter-supplied eval data, `iteration_delta` becomes computable and
the pass produces an APPLY-or-DEFER verdict driven by the §23 +0.10
threshold.

If R-1 from the gap analysis §4 fires (adapter rejects), the cycle's
"validate Si-Chip iteration effectiveness" mandate falls back to the
cheap `count_tokens` regression per the v9.5.0 §3 fallback. Pass #1
demonstrates the wrapper is functional; pass #2 demonstrates the
end-to-end pipeline is functional; passes #3..#N demonstrate the
iteration mechanism is effective. Each pass discharges a separate
evidence requirement.
