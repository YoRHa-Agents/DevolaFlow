### D-2 — `evaluate_gate` cc=22 refactor (MAJOR, telegraphed from v12.3.0 retro §3 D-4 → PV-03)

**Symptom** (verbatim from `.local/research/v12.4.0_nines_deep_evaluate_gate.json` finding `CC-67079a-0000`):
> `Function 'evaluate_gate' has cyclomatic complexity 22` at `src/devolaflow/gate/scorer.py:1859`

**Function signature** (verbatim from `src/devolaflow/gate/scorer.py:1859`):
```python
def evaluate_gate(
    gate_input: GateInput,
    profile: GateProfile,
    round_num: int = 1,
    history: list[ConvergenceRound] | None = None,
    gate_type: str = "standard",
    breaker: TokenBudgetBreaker | None = None,
    cumulative_tokens: int | None = None,
    cycle_detector: CycleDetector | None = None,
    ratchet: MonotonicRatchet | None = None,
    ratchet_artifact: dict[str, object] | None = None,
    complexity_detector: ComplexityDetector | None = None,
    complexity_signals: ComplexitySignals | None = None,
    complexity_task_complexity: str = "standard",
    legibility_scorer: LegibilityScorer | None = None,
    legibility_files: Sequence[str] | None = None,
) -> GateVerdict:
```

**Root cause**: 15 parameters (4 required + 11 optional); the function body accumulates conditional branches inspecting each optional collaborator (breaker / cycle_detector / ratchet / complexity_detector / legibility_scorer). Each `if collaborator is not None:` adds a branch and another nested `if condition:` for the collaborator's verdict — cc compounds.

**Impact** (per `.local/research/v12.3.0_evaluation.md` §2.1 code-quality deduction): drags Code Quality score 9.5 → 9.0 (0.5 deduction). Maintainability impact: long function discourages collaborator addition (next PV that wants to add a hypothetical `dependency_scorer` would push cc to 24+).

**Proposed refactor** (PV-03) — extract 4 helper functions each cc ≤ 8:

| Helper | Purpose | Estimated cc |
|---|---|---|
| `_apply_breaker_check(gate_input, profile, breaker, cumulative_tokens) -> GateVerdict \| None` | Pre-flight breaker; returns early FAIL/ESCALATE or None to proceed | cc ≈ 6 |
| `_apply_cycle_detection(verdict, cycle_detector, round_num, history) -> GateVerdict` | Appends cycle_detected + cycle_details to verdict.details | cc ≈ 4 |
| `_apply_ratchet(verdict, ratchet, ratchet_artifact, gate_input) -> GateVerdict` | Records ratchet decision; upgrades verdict.decision only on ESCALATE | cc ≈ 5 |
| `_apply_complexity_and_legibility(verdict, complexity_detector, complexity_signals, complexity_task_complexity, legibility_scorer, legibility_files) -> GateVerdict` | Composite complexity + legibility evaluation (these collaborate per existing logic) | cc ≈ 8 |

The orchestrator `evaluate_gate` becomes a linear pipeline:
```python
def evaluate_gate(...) -> GateVerdict:
    if early := _apply_breaker_check(...): return early
    verdict = _compute_standard_verdict(gate_input, profile, round_num, history, gate_type)
    verdict = _apply_cycle_detection(verdict, cycle_detector, round_num, history)
    verdict = _apply_ratchet(verdict, ratchet, ratchet_artifact, gate_input)
    verdict = _apply_complexity_and_legibility(verdict, complexity_detector, complexity_signals, complexity_task_complexity, legibility_scorer, legibility_files)
    return verdict
```
Orchestrator cc ≈ 6 (one `if` + 4 sequential calls).
