### 2.1 Retirement rationale chain (per v11.1.0 retrospective §3 D-2 origin)

Per `CHANGELOG.md ## [11.1.0]` line 866 (verbatim):

> Three "skip cascade" mechanisms (`force_no_change` + `--no-change` + `SHORTCUT_SIMPLE`) currently coexist; SHORTCUT_SIMPLE retirement telegraphed for v12.0.0 SI-1 (3 → 2 mechanisms).

And `CHANGELOG.md ## [11.1.0]` line 987 (verbatim):

> **SHORTCUT_SIMPLE retirement** (`DEVOLAFLOW_SIMPLE_SHORTCUT` env flag + v9.7.0 default-ON forecast) — telegraphed for **v12.0.0** SI-1 (3 → 2 mechanisms; reduces operator R-2 confusion risk).

**Retirement was a coherence cleanup**, not a feature deletion. The 3 coexisting skip-cascade mechanisms (`force_no_change=True` parameter + `--no-change` CLI flag + `DEVOLAFLOW_SIMPLE_SHORTCUT=1` env flag) each provided the same L0→L3 collapse with subtly different opt-in surfaces (parameter / CLI / env). The 3-mechanism R-2 confusion risk was operator-facing — operators had to know which of the 3 to use for their context. v12.0.0 consolidated to 2 (parameter + CLI), eliminating the env flag layer.

### 2.2 What was retained (the migration path)

The retirement was NOT a capability deletion — every SHORTCUT_SIMPLE use case has a covered replacement:

| Use case | Pre-v12.0.0 mechanism | Post-v12.0.0 replacement |
|---|---|---|
| Operator wants L0→L3 collapse for SIMPLE/TRIVIAL workload | `DEVOLAFLOW_SIMPLE_SHORTCUT=1` env flag | `activation_verdict(complexity, env_flag, force_no_change=True)` parameter |
| CI script wants opt-in collapse | `DEVOLAFLOW_SIMPLE_SHORTCUT=1` in CI env | `--no-change` CLI flag on `/devola:propose` |
| Operator wants single-file edit < 20 lines | (would have triggered SHORTCUT_SIMPLE if SIMPLE classified) | A-7.2 trivial waiver fires automatically (no opt-in needed) |
| Dispatch-classifier needs to skip change-workspace scaffolding | (would have keyed off `shortcut_verdict()`) | A-6.3 opt-out → `force_no_change=True` |

The retirement deleted a redundant opt-in surface, not a capability.
