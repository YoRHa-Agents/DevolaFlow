# v21.0.0 — SI-1 Gap Analysis

## 1. Objective and evidence boundary

This is the PV-01 SI-1 research artifact for the v21.0.0 cycle. It
identifies evidence-backed gaps arising from the v18–v20 feedback; it is not
an implementation report and does not claim that the proposed v21 work is
complete. No code, rule, version, CHANGELOG, or plan file is changed by this
artifact.

## 2. Confirmed current state

### 2.1 Existing risk and ceremony declarations

`src/devolaflow/skills/change_activation.py` has a four-tier complexity
classifier. It maps `TRIVIAL` and `SIMPLE` to `NO_CHANGE` for workspace
scaffolding, and `STANDARD`/`COMPLEX` to the declared cascade behavior when
the existing workspace flag is enabled. `workflow-system/agent/SKILL.md`
declares the same Quick Action Decision table and says to match ceremony to
risk.

This confirms a classification and prompt contract. It does not confirm that
the actual execution path skips full preflight/harness ceremony for every
trivial or low-risk task, nor that the avoided ceremony cost and task outcome
are measured. End-to-end ceremony behavior is therefore an open gap, not a
completed v21 feature.

### 2.2 Existing telemetry and harness

`src/devolaflow/harness/telemetry.py` records measured dispatch input tokens,
layer token budgets, constraint summaries, host-rule token estimates,
configured slice savings, model hints, and capacity metadata. It also
validates structured metric observations with source revision, command,
environment, and measurement provenance.

`tests/functional/matrix.yaml` is an existing offline, fail-closed functional
matrix with deterministic typed outcomes. Its current rows validate runtime,
packaging, safety, plugin, hostbridge, and telemetry contracts. These are
correctness-infrastructure signals; the matrix is not evidence that a
multi-turn implementation task improved in quality.

## 3. Evidence-backed deficiencies

### P0 — Risk-gated ceremony lacks runtime outcome and ROI evidence

The existing classifier expresses complexity, but no current harness contract
joins a complexity tier to the actually executed ceremony path, avoided
preflight/harness work, task outcome, or fixed-context share. The feedback
specifically recommends a short path for one-file, under-20-line, no-interface
change work and full decomposition only for standard/complex work. The
current source establishes the decision vocabulary, not measurable
behavioral closure.

Scope for a future implementation:

- `src/devolaflow/skills/change_activation.py`
- `src/devolaflow/dispatch.py`
- `src/devolaflow/feedback.py`
- `src/devolaflow/task_adaptive_selector.py`
- `src/devolaflow/harness/telemetry.py`
- `src/devolaflow/harness/aggregator.py`
- `tests/test_change_activation_heuristic.py`
- `tests/test_harness_telemetry.py`
- `tests/harness/test_aggregator.py`
- `tests/functional/matrix.yaml`
- `tests/functional/runner.py`
- `workflow-system/agent/SKILL.md`

Required evidence is a deterministic per-tier contract showing the selected
path, measured input/output tokens and bounded wall time, observable task
outcome, and no full ceremony for the covered trivial/low-risk case. The
existing classifier tests alone are insufficient.

### P0 — Runtime cost and latency telemetry is incomplete for causal claims

Current dispatch telemetry contains `tokens_injected_measured`, but the
dispatch record does not provide a corresponding per-stage output-token
measure, model-call wall time, or stage p50/p99 outcome. The evaluator's
`suite_wall_seconds` is a bounded evaluator-suite probe, not per-stage runtime
telemetry. The feedback therefore correctly says that precise ceremony ROI
and real latency claims are blocked. Probe token accounting exists in
`src/devolaflow/harness/probe.py`, but it is not the same as a matched
task-execution series in `.local/telemetry/harness.jsonl`.

Scope:

- `src/devolaflow/harness/telemetry.py`
- `src/devolaflow/harness/aggregator.py`
- `src/devolaflow/harness/evaluator.py`
- `src/devolaflow/harness/probe.py`
- `src/devolaflow/harness/__main__.py`
- `tests/test_harness_telemetry.py`
- `tests/harness/test_aggregator.py`
- `tests/harness/test_evaluator.py`
- `tests/harness/test_probe.py`

Any new fields must preserve old JSONL compatibility and keep provenance
explicit. A current aggregate `READY` result must not be used as a substitute
for missing stage telemetry.

### P0 — Release-delta validity remains unresolved

The feedback's five-salt sweep has approximate 95% intervals crossing zero for
quality, pass rate, and cost on all v17.5→v18, v18→v19, and v19→v20
transitions. The current ledger contains 13 records from five v17-era changes,
not a matched v20.1.0/v21 workload series. There is no repository evidence
that a single-seed release delta is an implementation effect.

Scope:

- `src/devolaflow/harness/aggregator.py`
- `src/devolaflow/harness/evaluator.py`
- `src/devolaflow/harness/probe.py`
- `src/devolaflow/harness/fixtures.py`

- `tests/harness/test_probe.py`
- `tests/functional/matrix.yaml`
- `.local/telemetry/harness.jsonl`
- `.local/telemetry/baselines/`

Closure requires matched workload identity, recorded salt/run metadata,
replicated observations, and an explicit insufficient-evidence result when
the comparison cannot be made. It must not turn simulator variance into an
upstream quality claim.

### P1 — Functional evidence is not yet compactly reusable task evidence

The functional matrix has row IDs, expected statuses, and design-source
anchors, but the current evidence surface does not demonstrate that an agent
can cite one executed row plus one stable artifact instead of reproducing a
whole verification ceremony. The feedback recommends compact reusable
references while retaining typed `ac_results`, `self_check`, and `diff_stats`
style evidence.

Scope:

- `tests/functional/matrix.yaml`
- `tests/functional/runner.py`
- `tests/functional/test_matrix_contract.py`

The v21 contract should define stable row/artifact identity and bounded
references without duplicating historical prose or changing the dispatch
layout unless the A-2 nest-vs-append decision explicitly permits it.

### P1 — Skill availability is not a uniformly recorded cross-channel fact

The four-model feedback reports that the selected Claude Code and Kimi Code
channels could not serve the intended model IDs, and that their skill-on
comparison was unavailable. The two Cursor-dispatcher probes loaded the skill,
but the current result is a channel-boundary finding rather than a
cross-channel skill equivalence result. Current probe evidence does not
provide a single machine-readable fact that the expected skill artifact was
available and loaded for each channel.

Scope:

- `src/devolaflow/harness/probe.py`
- `src/devolaflow/harness/fixtures.py`
- `workflow-system/agent/hosts.yaml`
- `adapter_configs/`
- `tests/harness/test_probe.py`

The scope is evidence and channel parity, not an assumption that every host
can serve every model. Unsupported channels must remain explicitly
`undeclared`, `designed`, or `broken`, and unavailable skill-on comparisons
must remain `INSUFFICIENT`.

### P1 — Fixed ceremony versus useful task context has no warning contract

The repository has token budgets and rule-slicing/accounting surfaces, but the
current harness does not establish a warning threshold for when fixed skill,
rule, and report-envelope text dominates the expected task context. The
feedback recommends measuring those components separately and warning before
the ceremony consumes the task budget.

Scope:

- `src/devolaflow/task_adaptive_selector.py`
- `src/devolaflow/agents_md_slice.py`

- `src/devolaflow/harness/aggregator.py`
- `tests/test_task_adaptive_selector.py`
- `tests/test_harness_telemetry.py`

The warning must be observational or an explicit gate result; it must not
silently rewrite dispatch payloads or bypass governance constraints.

Read-only, tool-heavy, multi-file, and recovery cases are not represented as a
matched outcome series in the current harness ledger.

Scope:

offline/fail-closed policy. They should not be presented as release-quality
evidence until the workload is replicated and its provenance is complete.

## 4. Two-cycle boundary

### v21.0.0 boundary

v21.0.0 should close the minimum evidence contract needed to make the
feedback actionable without claiming causal quality gains:

1. Tie the existing complexity decision to an observable short/full ceremony
   path and a bounded acceptance outcome.
2. Add provenance-safe per-stage cost and runtime measurements, including
   explicit unavailable states.
3. Make functional evidence citeable by stable row/artifact references.
4. Record skill availability/loading as a channel fact and preserve
   unsupported-channel boundaries.
5. Add representative offline workload contracts for the risk tiers, without
   treating them as a release delta until replication evidence exists.
6. Record matched run/salt metadata and preserve old ledger compatibility.

The v21.0.0 scope does not authorize a new `DEVOLAFLOW_*` flag, a new CLI, an
automatic learning write, a dispatch-layout change, or a CHANGELOG claim by
itself. Any such change requires its own design and governance checks.

### v21.1.0 boundary

v21.1.0 is the follow-up evidence cycle, not part of PV-01. It should use the
v21.0.0 contract to collect replicated matched workloads across the supported
channels and task classes, settle a comparable baseline, and evaluate:

- salt/run replication and confidence intervals;
- ceremony cost versus observable task outcome;
- stage p50/p99 latency and input/output token distributions;
- skill-on/off comparisons only where channel availability is proven;
- checklist completion, reversion, blocker, and recovery trends.

If the matched data remains unavailable or intervals still cross zero, the
v21.1.0 report must retain `INSUFFICIENT` or `UNRESOLVED`; it must not promote
the intended factor ladder or a single-run jump to a quality claim.

## 6. Explicit `INSUFFICIENT` limits

- The feedback's EvoBench quality/cost output is modeled simulator evidence;
  the salt sweep measures simulator variance, not direct upstream
  implementation quality.
- The current ledger has 13 v17-era dispatch records and no matched
  v20.1.0/v21 workload series.
- The evaluator's historical aggregate measurements for
  `agents_md_tokens`, `suite_wall_seconds`, `cjk_violations`, and `ghost_loc`
  are `INSUFFICIENT`; current top-level probe values do not repair that gap.
- The W-2 report's `READY`/`9.84` verdict is current harness readiness only.
  It does not mean the P0/P1/P2 gaps in this artifact are implemented.
- The current W-17 value `18` is a single-base-ref observation and is not
  proof of a compliant per-PV or per-cycle test-function split.
- Four-model skill-on/off comparison is `INSUFFICIENT` for channels where the
  requested model or skill artifact was unavailable; those are channel
  boundaries, not quality comparisons.
- No current evidence proves that a trivial task avoids all full ceremony, that
  ceremony reduction improves task quality, or that stage p50/p99 latency and
  output-token cost meet a runtime budget.
