# v21.0.0 Retrospective

## Gaps identified

The v21.0.0 gap analysis identified six evidence-boundary gaps from the v18–v20
feedback:

- complexity classification did not prove which ceremony path actually ran;
- matched per-stage cost, latency, and task-outcome telemetry was absent;
- matched release-delta evidence with replicated salts was absent;
- functional evidence was not yet a compact reusable task reference;
- cross-channel skill availability was not uniformly recorded; and
- fixed skill/rule/report context had no component-level warning contract.

The final ledger still contains 13 records from five v17-era changes, rather
than a matched v20.1.0/v21.0.0 workload series. Historical, per-PV, matched
real-task quality, and salt-based release-delta evidence are therefore
**INSUFFICIENT**. The evaluator also reports zero observed records for
`skill_tokens`, `rule_tokens`, and `report_tokens`; those component histories
are **INSUFFICIENT**.

## Implemented

- T1 added post-hoc trivial-path validation against measured one-file diff
  statistics, with stable violation codes and an upgrade target.
- T2 added bounded, typed StatusReport evidence references and preserved the
  inline evidence byte budget at the handoff boundary.
- T3 added separate skill/rule/report token accounting and a ceremony-share
  warning when fixed context dominates the task budget.
- T6 added explicit run, repository, salt, and provenance status metadata to
  harness and StatusReport evidence surfaces.
- The current-cycle W-18 ghost audit covers T1, T2, T3, and T6 in
  `tests/ghost/test_features_v21_0.py`.

These are runtime and evidence contracts. They do not establish a causal
quality improvement for multi-turn implementation work.

## Deferred and insufficient evidence

- Matched real-task outcomes, per-stage output tokens, and per-stage latency
  remain **INSUFFICIENT** because no representative v21 workload series exists.
- Historical and per-PV comparisons remain **INSUFFICIENT**; the available
  ledger is not a v20.1.0-to-v21.0.0 matched comparison.
- Salt/replication evidence remains **INSUFFICIENT**: the final evaluator has
  `salt: null` and `salt_status: INSUFFICIENT`.
- Per-record component context measurements remain **INSUFFICIENT**.
- Cross-channel skill-on equivalence remains **INSUFFICIENT** where no
  channel-bound probe evidence exists.

## Final evidence and key learnings

The final evaluator artifact is
`.local/research/v21.0.0_harness_evaluation_final.json`. It reports
`verdict: READY`, `composite: 9.84`, and `threshold: 8.5`; its full-suite probe
is true, coverage is `91.0`, and W-17 observes 20 added test functions.
Available measurements are `suite_wall_seconds: 212.648735958006`,
`agents_md_tokens: 11169`, `cjk_violations: 0`, and `ghost_loc: 12719`.
The evaluator's READY verdict is a bounded repository-quality result, not a
claim that missing historical or real-task evidence is available.

The final settled baseline preserves the prior v20.1.0 baseline and records
the available composite delta. The main operational lesson is that generated
human documentation is part of release correctness: after the version bump,
the first full-suite probe found stale generated guides and demo metadata;
regenerating them and updating the version timeline restored parity before
the final evaluator run.

The W-9 release-preflight chain passed every gate through documentation and
rules drift, but the final module-size gate returned **BLOCKED**:
`src/devolaflow/harness/evaluator.py` grew from 1005 to 1046 lines and
`src/devolaflow/harness/telemetry.py` grew from 1229 to 1503 lines. This
finding is preserved as a release blocker; no threshold or baseline was
modified to conceal it.
