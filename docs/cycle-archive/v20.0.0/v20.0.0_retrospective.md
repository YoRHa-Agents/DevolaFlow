# v20.0.0 Retrospective — Functional Test System Loop v3

Cycle close: 2026-08-28. This retrospective records the W-7 close evidence
for the v20.0.0 MAJOR cycle. The source planning contract remains
`.local/tasks/functional_test_system/loop_plan_v3.md`; the SI-1 gate artifact
is `.local/research/loop3_functional_test_system_gap_analysis.md`.

## 1. Gaps identified

The Loop v3 SI-1 gap analysis identified a coverage-architecture gap rather
than a single runtime defect:

- No machine-readable traceability existed from design expectations
  (SKILL/references/schemas/CHANGELOG) to behavioral tests; existing coverage
  was measured in lines, not in design-expectation rows.
- The external calling surface (13 console scripts, `python -m` entrypoints,
  the installed-wheel public API import contract, and the npm channel) had no
  subprocess black-box coverage; several entrypoints were exercised only
  in-process.
- Five Phase 0 audits (B1 entrypoints, B2 design expectations, B3 existing
  tests, B4 behavior-design deviations, B5 plugin coupling) produced the
  candidate matrix rows and a deviation list adjudicated one-by-one at the
  final grilling.
- Adjudicated behavior-design deviations included: a skipped required check
  could score as a standard-profile PASS, explicit zero parallelism was
  silently coerced, handoff envelope writes lacked exclusive-create
  enforcement at the store level, proposal targets accepted traversal and
  absolute paths, third-party compression stages could omit `should_bypass`,
  and local-archive apply lacked an explicit approval artifact.
- Plugin coupling was concentrated in derived views and references, not the
  registry: all five plugins were already `tier: suggest` with
  `auto_install: false`.

## 3. Deferred and why

- The curl channel and host-adapter consumer side stay out of scope, as
  adjudicated in the SI-1 gap analysis; they need their own evidence base.
- The `remove+decouple` plugin path was not exercised; revisiting requires
  new coupling evidence, not a policy change.
- The evaluator's `w17` probe observes 64 against a single base ref and
  scores 0.0; the per-wave split (max 14 per PV) is documented in the W-17
  reconciliation, so no per-PV evaluator split is fabricated. Capturing
  per-PV function deltas at each PV boundary remains the standing
  recommendation from v19.
- Historical checklist, reversion/blocker, and matched baseline trends remain
  `INSUFFICIENT` in the fresh evaluator output; the v20 baseline is settled
  from the fresh report without inventing a before/after delta.

## 4. Key learnings

- Matrix-driven parametrization reconciles hard-fail full-surface coverage
  with the W-17 function budget: 46 rows executed as 91 collected cases cost
  only a handful of `def test_` declarations.
- Byte-determinism of captured artifacts must be designed in (pinned clocks,
  stable ordering) before an artifact becomes gate evidence; the reporter
  `--now` repair was found by diffing two full matrix runs.
- Behavioral closures adjudicated as code fixes (not doc fixes) each needed a
  matrix row plus a unit-level regression test; the pairing kept the closure
  observable at both the contract and implementation levels.
- Cycle-close order matters: CHANGELOG, demo window, version timeline, and
  regenerated human docs are all version-coupled surfaces; running the
  evaluator before propagating the bump produced a transient `NOT_READY`
  that disappeared once the surfaces were consistent.
- The module-size ratchet catches growth exactly where behavioral closures
  concentrate; splitting by responsibility (durability primitives, record
  types, payload codecs, rollback guards) reduced every offender below its
  baseline without breaking a single test, because consumers kept their
  patchable module-level aliases.
