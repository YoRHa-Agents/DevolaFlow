# v24-ADR-001 — Workspace Compact, Risk Parking, and Judgment Ledger

Status: ACCEPTED for implementation (PV-01 design gate).
Supersedes: nothing. Amends: S-9 (narrowest scope, separate track — see §8).
Gap analysis: `.local/research/v24.0.0_gap_analysis.md`.

## 1. Decision Summary

Three cooperating surfaces are introduced, each with exactly one owner module:

| Surface | Owner | Purpose |
|---|---|---|
| Risk parking | `src/devolaflow/parking/` | One file per risk, six-state lifecycle, generated index |
| Judgment ledger | `src/devolaflow/parking/` | Append-only user decisions; the single decision entry point |
| Event ledger | `src/devolaflow/parking/` | Append-only state-transition and provenance record |
| Workspace compact | `src/devolaflow/workspace_compact/` | Non-destructive shrink of one task/change folder |
| Shared ledger kernel | `src/devolaflow/workspace_ledger.py` | Path safety, atomic generated writes, marker drift, append-only YAML |

`devolaflow.local.archive_kernel` is deliberately **not** refactored. It owns the
cross-surface `tasks`/`feedbacks`/`research` archive and is pinned by a large test
surface; v24 reuses its *patterns* (append-only mapping rows, marker index, plan
fingerprint approval) through a new shared module rather than mutating it. This keeps
A-5 single-owner intact: `workspace_ledger` owns the primitives, the two domains own
their registries.

## 2. Why Move-and-Index Rather Than Rewrite

Claude Code's compaction replaces conversational history with a generated summary; the
original is gone because conversation memory is ephemeral. DevolaFlow's bloat lives in
persistent files that are cited by checklists, preflight sections, and judgments. A
lossy rewrite would break those citations irrecoverably.

Therefore compaction is defined as: **move the original into an archive directory inside
the same folder, append a before/after mapping row carrying a content hash, and leave a
generated digest plus pointer in place.** Nothing is deleted; every byte stays reachable
through the mapping ledger. Deletion remains operator-only (W-26).

## 3. Layout

Per task folder (`.local/tasks/<name>/`) and per change folder
(`.local/.agent/active/<id>/`), created with the first artifact batch alongside
`goal.md` / `checklist.md` / `entrance.md`:

```
parking/
  risks/RISK-NNN.md    one risk, frontmatter + in-place history
  INDEX.md             generated active-risk index (marker)
  judgments.yaml       append-only judgment ledger (never compacted)
  judge.md             generated view: pending queue + settled decisions
  events.yaml          append-only event ledger (rotatable segments)
compact/
  DIGEST.md            generated digest + pointers (marker)
  mappings.yaml        append-only before/after mapping (hash, bytes, tokens)
  archived/<seq>/      relocated originals
```

## 4. Schemas

### 4.1 Risk frontmatter

| Field | Type | Notes |
|---|---|---|
| `id` | `RISK-NNN` | Task-scoped sequence; cross-task citation uses `<task>/RISK-NNN` |
| `title` | str | One line |
| `state` | enum | `open`, `parked`, `active`, `mitigating`, `closed`, `archived` |
| `severity` | enum | `blocker`, `critical`, `major`, `minor` |
| `trigger` | str | The condition under which this risk bites |
| `disposition` | str | Current handling |
| `judgment_refs` | list | `J-NNN` ids; a pending decision is a reference, not a state |
| `legacy_id` | str? | Verbatim prior identifier, preserved by `adopt` |
| `opened_at` / `updated_at` | UTC | `%Y-%m-%dT%H:%M:%SZ` |

State transitions are a closed graph: `open→{parked,active,mitigating,closed}`,
`parked→{active,mitigating,closed}`, `active→{mitigating,parked,closed}`,
`mitigating→{active,closed}`, `closed→{archived,active}`, `archived→{}`. Reopening from
`closed` is legal (a risk can recur); `archived` is terminal because the file has been
relocated by compact.

### 4.2 Judgment ledger row (append-only, never rotated, never compacted)

`sequence`, `id` (`J-NNN`), `question`, `decision`, `subject`, `decided_at`,
`supersedes` (nullable `J-NNN`). A changed decision is a **new row** citing the prior
one; rows are never edited.

### 4.3 Event ledger row (append-only, segment-rotatable)

`sequence`, `event`, `subject`, `detail`, `timestamp`. Events:
`risk_opened`, `risk_state_changed`, `risk_updated`, `judgment_recorded`,
`risk_archived`, `compact_applied`.

### 4.4 Compact mapping row (append-only)

`sequence`, `source`, `destination`, `reason`, `timestamp`, `sha256`, `bytes`,
`tokens_estimated`. The hash is what makes "zero loss" checkable rather than asserted.

## 5. Write Convergence (three layers)

1. **Tool is the only writer.** Every mutation goes through `devola-parking` /
   `devola-compact`, which write the artifact, append the ledger row, and re-render the
   generated views in one operation. There is no partial-write path that leaves the
   index disagreeing with the ledger.
2. **Marker plus drift detection.** Generated files start with a surface marker; a
   missing marker means the file is human-maintained and the tool refuses to overwrite
   it (`HUMAN_INDEX`), and content disagreeing with the ledger is `INDEX_DRIFT`. Mirrors
   W-28 exactly.
3. **Lifecycle hook.** `check_parking_write` warns in lite mode and blocks in STRICT,
   mirroring the S-8 severity split.

The operator never hand-edits these files. Decisions are spoken in chat and the agent
records them through the tool.

## 6. Authorization

`plan` is always report-only and free. `apply` requires an approval artifact whose
fingerprint matches the current plan — the harness proposal pattern. There is **no
standing pre-authorization**: during unattended runs the agent produces plans and queues
them; it never applies. This is the deliberate cost of the guarantee that no content
moves without a human having seen exactly what moves.

## 7. Runtime Is a Hard Prerequisite

Without the Python runtime, parking and compact **writes are unavailable** and the tool
says so with the exact install command. Reads (index, risk files) are plain Markdown and
remain usable. There is no hand-written degraded mode: permitting one would recreate the
unstructured bloat this cycle exists to eliminate.

## 8. S-9 Amendment (separate track, human-gated)

Proposed narrowest scope: an envelope becomes eligible for relocation **only** when its
owning change has already been archived as a whole, the move is performed by the compact
tool, and an approval artifact matches the plan. The two core prohibitions are
unchanged: envelope content is never rewritten, and no envelope is ever deleted.

Until this is signed, handoff receives **index-only** treatment: a generated index
summarising envelopes without moving them. The main cycle does not depend on it.

## 9. Self-Determined Items (operator may override)

- Ids are task-scoped sequences; cross-task references are fully qualified.
- Amended decisions append with `supersedes` rather than editing.
- L0's suggestion threshold is configuration with a default, not a new env flag; the
  activation surface stays `DEVOLAFLOW_AGENT_WORKSPACE=1` (W-20 reuse-first).
- `devola-local-archive` and `devola-compact` stay separate tools: the former relocates
  whole folders across `.local` surfaces, the latter shrinks inside one folder.
- Risk files carry C-9-style soft/hard token budgets so splitting does not relocate bloat.
- `events.yaml` may rotate into segments; `judgments.yaml` never rotates and is never
  compacted.
- `DIGEST.md` is re-rendered whole on every compact; history lives in `mappings.yaml`.
- `adopt` is report-only preview then approved write; legacy ids are preserved verbatim.
- Checklist progress counts archived completed items, read from the ledger, so a compact
  never appears to regress progress.
- No `TaskDispatch` schema change in v24 — risk context rides existing `key_facts`, so
  the A-2 cache prefix is untouched.

## 10. Digest Authorship

Two layers. The script emits the deterministic structural extract (ids, states,
dispositions, judgment references, pointers) — this is the guarantee layer and is fully
reproducible. An agent may optionally add a narrative section, explicitly marked as
agent-authored, in which **every claim carries a verbatim anchor** into an archived
original; lint verifies each anchor resolves. Tool-owned files may be section-compacted
after the full prior version is archived; hand-written artifacts are only ever moved
whole.
