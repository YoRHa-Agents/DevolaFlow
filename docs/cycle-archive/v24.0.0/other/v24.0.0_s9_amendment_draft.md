# S-9 Amendment Draft — Tool-Mediated Relocation of Archived-Change Envelopes

Status: **DRAFT — awaiting operator signature.** Not applied to `.rules/soul.mdc`.
Track: independent of the v24.0.0 main line; the cycle ships whether or not this lands.
Pending decision: recorded in the v24 judgment ledger as the cycle's first pending item.

## 1. Why an Amendment Is Needed

F-03 of `.local/research/v24.0.0_gap_analysis.md`: handoff envelopes have creation but
no lifecycle. An N-round change accumulates envelopes indefinitely with no index and no
relief path. The current S-9 text prohibits modification and deletion, and the exclusive
`os.link` write path plus `lifecycle/check_envelope_append_only` plus
`tests/test_handoff_envelope_immutable.py` enforce it at three levels.

Relocation is not modification and not deletion, but the current wording does not say
so, and reading a prohibition permissively is exactly the failure mode this repository's
governance exists to prevent. Hence: amend explicitly, or do not relocate at all.

## 2. What This Amendment Does NOT Change

Both core prohibitions survive verbatim:

- Envelope **content is never rewritten**. Not a byte, not a reformat, not a re-serialization.
- No envelope is **ever deleted**, by any agent, in any mode. Deletion remains
  operator-only (W-26) and no automatic deletion API exists.

The append-only sequence discipline (`seq+1` for new information) is untouched.

## 3. Proposed Addition to S-9

> ### S-9.1 — Tool-Mediated Relocation of Archived-Change Envelopes
>
> An envelope MAY be relocated — moved without any content change — from
> `.local/.agent/handoff/` to `.local/.agent/archive/handoff/<change-id>/` when **all**
> of the following hold:
>
> 1. the change that owns the envelope has already been archived as a whole
>    (`.local/.agent/archive/<date>-<change-id>/` exists);
> 2. the move is performed by the workspace-compact tool, never by hand;
> 3. an approval artifact whose fingerprint matches the current plan authorizes the
>    exact set of envelopes being moved;
> 4. an append-only mapping row records source, destination, reason, timestamp, and the
>    content hash, and a generated index preserves navigability.
>
> Envelopes belonging to an active change MUST NOT be relocated. Envelope content MUST
> NOT be rewritten and no envelope may be deleted; relocation changes location only, and
> the mapping ledger's hash makes that verifiable.

## 4. Scope Discipline

This is deliberately the narrowest workable口径. Wider alternatives were considered and
rejected in grill:

| Alternative | Rejected because |
|---|---|
| Relocate active-change envelopes above a sequence threshold | The append-only ledger's value is highest precisely while parallel agents are still writing it |
| Per-envelope named approval | Approval fatigue; plan-fingerprint approval already pins the exact set |
| No amendment, index only | Retained as the interim state; solves readability but not accumulation |

## 5. Enforcement Changes If Signed

- `lifecycle/check_envelope_append_only.py`: add a relocation-aware branch that still
  blocks content mutation and deletion, and additionally verifies the four conditions.
- `tests/test_handoff_envelope_immutable.py`: extend with cases proving relocation of an
  archived-change envelope is permitted while active-change relocation, content
  mutation, and deletion all remain refused.
- `.rules/soul.mdc` S-9 section, then `make compile-rules` to regenerate `AGENTS.md` and
  `.cursor/rules/repo-governance.mdc` (hand-editing compiled outputs is blocked by
  `tests/test_no_ghost_features.py::test_rule_surfaces_compile_only`).

## 6. Interim State (in effect now)

Handoff receives **index-only** treatment: `devola-compact` renders a generated index of
envelopes for a change without moving anything. This restores navigability — the agent
reads one index line instead of opening every envelope — while the amendment is pending.

## 7. W-21 Note

W-21 freezes the Soul **set** at its current count and governs adding S-(N+1). This
draft adds no new Soul rule; it narrows an existing one's wording to distinguish
relocation from modification. Current freeze S-1..S-10 is unchanged, and the 60-rule cap
(`tests/ghost/test_rules.py::test_rule_count_under_cap`) is unaffected.
