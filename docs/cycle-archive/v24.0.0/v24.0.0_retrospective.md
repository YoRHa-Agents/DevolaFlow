# v24.0.0 Retrospective — Workspace Compaction and Risk Parking

Cycle: v24.0.0 (MAJOR) · Entry composite 9.17 · Exit composite 9.83 (READY)
Settled baseline: `.local/telemetry/baselines/harness_baseline_24.0.0.json`

## 1. What the cycle set out to close

Task folders grew until an agent could no longer read one in a single pass, and
the risks found along the way lived in prose nobody could query. Two surfaces
were added — risk parking and workspace compaction — plus the metering needed to
tell whether they actually help.

## 3. Measured outcome

On the v2.8.6 sample (217-line mixed document, 15 rows):

| Metric | Before | After | Change |
|---|---:|---:|---:|
| Agent working set | 8679 | 1284 | −85.2% |
| Resident stored tokens | 25190 | 15261 | −39.4% |
| Recovery cost per fact | 8679 | 77 | 0.9% |
| Mapping rows verified | — | 15/15 | zero loss |

The acceptance criterion was "≥70% reduction, measured to settle". It is met on
working set and missed on resident tokens, and both numbers are reported
because the gap between them is the actual finding — see §4.

## 4. What we learned

**The obvious metric was the wrong one.** The first reading showed resident
tokens *rising* after adoption, which looked like the feature had failed. It had
not: splitting one blob into per-risk files adds frontmatter and structure, so
the stored total grows while the amount an agent must read collapses. Two
genuine inefficiencies were also hiding behind that number — every field was
duplicated between frontmatter and body, and provenance carried an absolute
path (an S-2 violation). Fixing those cut resident tokens from 31787 to 25190.

The lasting change is that the reading now reports working set *and* resident
sum together. Either one alone misleads, in opposite directions.

**Compaction has a fixed cost.** On the dogfood workspace, relocating two closed
risks saved 432 tokens and the digest it wrote cost nearly as much: net 2.9%.
Compaction only pays above a size threshold, which is why it is suggested rather
than automatic. The design decision made in grilling turned out to be load
bearing for a reason nobody articulated at the time.

**A strict shared ledger is a single point of failure.** One
`iteration-delta-gate` row made the entire harness ledger unreadable, taking
every downstream evaluation with it (F-00). The initial workaround was a
filtered copy, which is honest but leaves the real ledger broken. The fix — a
retired-name vocabulary the reader accepts and the writer refuses — restored
end-to-end evaluation for the first time this cycle. It also directly shaped
the decision to give compaction telemetry its own ledger with a reader that
skips damaged rows instead of aborting.

**Permanently red tests train people to ignore red.** Three npm delivery tests
had been failing on a clean tree because `npm pack --json` changed shape. They
were outside the nominal scope but fixed anyway: a suite with known failures
cannot tell you about an unknown one.
