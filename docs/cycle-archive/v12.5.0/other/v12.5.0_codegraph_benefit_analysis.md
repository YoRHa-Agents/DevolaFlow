## §4 — Risks + mitigations (codegraph-specific; complements gap-analysis §5)

### R-A — Codegraph index becomes stale across long sessions

`codegraph` auto-syncs via OS file events but a long-running L0 session could outpace the 2s debounce on rapid edits. Mitigation: `verify` stage at mode=full asserts `.codegraph/codegraph.db` mtime > workflow start; if stale, emit WARN and suggest manual `codegraph sync`.

### R-B — `.codegraph/` directory bloat

Index for a 100K-LOC repo is typically 5-50MB; for monorepos (1M+ LOC) can hit 500MB. Mitigation: `references/codegraph.md` §6 documents the cache management discipline (gitignore, periodic prune via `codegraph index --prune-deleted`).

### R-C — npm install fails on offline / restricted networks

`@colbymchenry/codegraph` requires npm registry access for first install. Mitigation: degraded-mode contract (`references/degraded-mode.md` codegraph row) — when CLI unavailable, fall back to Read/Glob/Grep with a one-time WARN. Repo-init scaffold WARN-on-missing path is non-blocking (S-5 explicit warn + continue, NOT silent fail).

### R-D — Tree-sitter parser version drift across language ecosystems

Codegraph bundles tree-sitter parsers with each release; a language-spec update upstream could leave the bundled parser one version behind. Mitigation: `update_triggers` in reference-dependencies.yaml include "new language support added" → reference-review cycle catches drift.

### R-E — Privacy: codegraph indexes EVERY tracked file

The `.codegraph/codegraph.db` contains symbol names + signatures + snippet offsets for every file not in `.gitignore`. For repos with secrets-in-comments anti-patterns, this could surface PII. Mitigation: `references/codegraph.md` §6 documents the gitignore-driven filter; add `.local/secrets/` style patterns to `.gitignore` proactively.

## §5 — Degraded-mode contract

When `codegraph` CLI is unavailable (not on `$PATH`, returns non-zero on `--version`, or `.codegraph/codegraph.db` missing/corrupt):

1. `src/devolaflow/codegraph/_cli.py::_run_codegraph` raises `CodegraphUnavailableError` with structured cause (`"path_missing"` | `"version_check_failed"` | `"db_missing"` | `"db_corrupt"`)
2. `src/devolaflow/codegraph/researcher.py` public helpers catch the error and:
   * Log a one-time WARN per session (deduplicated via module-level sentinel)
   * Return an empty / sentinel result (`""` for `build_context`, `[]` for `search_symbols` / `get_callers` / `get_affected_tests`, `{}` for `get_impact`)
   * Caller (L0/L1/L2/L3 dispatcher) detects empty result and falls back to Read/Glob/Grep
3. Repo-init scaffold step `codegraph_init` catches the error and emits a non-blocking WARN suggesting `npm i -g @colbymchenry/codegraph`; workflow continues
4. Gate scoring drops the `codegraph_impact` dimension when codegraph unavailable; the dimension's weight redistributes to the other gate inputs

This contract is documented in `workflow-system/agent/references/degraded-mode.md` (PV-05) as a NEW row alongside the existing nines + plugin-fallback rows.
