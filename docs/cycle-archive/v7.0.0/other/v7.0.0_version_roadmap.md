## Summary

The v7.0.0 → v7.1.0 cycle ships the research report's top-5 ranked
recommendations across **five versions**, sized so each can ship and
revert independently. v7.0.0 is a true MAJOR bump: it introduces the
first publicly-documented cache-layout invariant, which is an additive
API at the Python level but a **backwards-incompatible governance
constraint** on any downstream tooling that previously assumed free
reordering of dispatch sections. v7.1.0 is the rollup / adoption
release: no net-new primitives, just profile opt-ins, doc adoption, and
the SI-8 retrospective.

## Version map (5 versions)

The cycle ships as **one MAJOR + three PATCH + one MINOR/rollup** — a
deliberately unusual mix. v7.0.0 is MAJOR because it introduces the
layout-invariant governance contract (breaking expectation for dispatch
producers that reorder sections). v7.0.1 → v7.0.3 are PATCH because
each adds an additive primitive with a feature flag defaulting to off.
v7.1.0 is MINOR because adoption flips those flags on by default and
the retrospective is user-visible.

## Sequencing rationale

The five versions sequence like this because:

- **v7.0.0 first** — the layout invariant is a governance contract. It
  must land before any further primitive; otherwise every subsequent
  feature risks silently violating the invariant (ADR-001's additive
  rule). Everything else is architected to be "appended after `gate`".
- **v7.0.1 before v7.0.2** — tool-output truncation (J.2) has smaller
  surface area (~280 LOC) than the hierarchical summariser (~360 LOC).
  Shipping the smaller item second would leave the big item's rollback
  risk unmitigated. We ship the bigger change with more accumulated
  regression evidence.
- **v7.0.2 before v7.0.3** — the persistence probe (ADR-004) consumes
  `extract_named_entities` from the summariser (ADR-003). We cannot
  ship the probe first. Similarly, learnings v2 is independent but
  pairs naturally with the probe because both belong to the "quality
  / measurement" theme; co-shipping them reduces overhead.
- **v7.1.0 last** — opt-in and retrospective. Flipping feature flags
  requires confidence from 4 prior versions' worth of benchmark data;
  shipping the retrospective earlier would be premature.

If any single version fails its gate, the cycle pauses at that version.
Subsequent versions remain queued but do not ship until the failing
gate converges or is escalated.

| v7.1.0 | v7.0.3 | Medium | Rollback flips default opt-ins back to off; no data loss but existing live sessions lose truncation / summarisation behaviour until re-opted-in. |

All rollbacks are contained within one patch version. Cross-cycle
rollback (e.g., revert from v7.1.0 to v6.2.1) requires sequential
revert of all intermediate versions — this is expected and aligned
with `semver.org` semantics for MAJOR releases.
