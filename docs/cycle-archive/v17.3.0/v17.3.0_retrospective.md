# v17.3.0 Retrospective — Pathfinder Look-Ahead Reconnaissance

## 1. Gaps identified

- Pathfinder's first implementation declared a report schema but enforced only
  its token budget; semantic report validation was missing.
- The design specified an artifact-based automatic activation track, but only
  natural-language activation had an executable surface.
- The Pathfinder profile contained dead model overrides and an overly broad
  `next wave` routing hint.
- Existing cycle bookkeeping was incomplete: v17.1.0 and v17.2.0 had not
  been archived at cycle close, and no v17.3.0 settlement artifact existed.

## 2. What was implemented

- Added `PFR_*` semantic lint findings for frontmatter, schema version,
  section order, gap-report references, absolute paths, and blocker closure
  signals. Missing `pathfinder_report.md` remains a valid no-op.
- Added `should_schedule_pathfind()` using the existing
  `harness_preflight.md` artifact-as-flag and exported it through the skills
  surface.
- Added executable initial/incremental `devolaflow.harness gap` commands to
  the Pathfinder reference and checklist seed.
- Added the 2700-second profile-timeout regression contract and removed dead
  profile overrides and the broad routing hint.
- Bumped the release to v17.3.0, refreshed generated docs and mirrors, and
  renamed the Pathfinder design artifact to its release-cycle path.
- Archived the available v17.1.0 and v17.2.0 research artifacts without
  fabricating missing evidence.

## 3. Deferred work and why

The following items are materialized for a later human-gated change:

- **F-1 — Mechanism-unification cycle:** role-ify preflight and introduce a
  dedicated harness-build task specialization. This is a separate architecture
  change and requires its own SI-1 analysis.
- **F-2 — Pattern 3 cleanup:** decide whether to remove the deferred
  `AGENT_POOL_FORWARD` and `gate.subagent_pattern` prewiring. This requires an
  ADR, rule recompilation, and A-2.4 witness protection.
- **F-3 — Pool-runtime archive confirmation:** retain the deferred pool-runtime
  design as historical evidence and confirm its archive placement.
- **HSC G-1/G-2:** implement the host-contract phases only through a human-gated
  follow-up; the v17.3.0 Host Support Contract document is design-only and is
  intentionally not included as a CHANGELOG feature.
- **HSC G-3/G-4:** keep the DSH plugin/web work independent and defer the Tier-C
  host-retention decision until real usage evidence exists.

W-2 evaluation completed with a 9.84/10 composite and `READY` verdict; the
passing test-suite, ruff, compatibility, and coverage signals are recorded in
`.local/research/v17.3.0_harness_evaluation.json`.
W-16 settlement remains `INSUFFICIENT`: the available 13-record ledger is not a
cycle-specific v17.3.0 telemetry settlement, so no
`.local/telemetry/baselines/harness_baseline_v17.3.0.json` was fabricated.
The v17.1.0 and v17.2.0 closeout gaps are recorded rather than backfilled.

## 4. Key learnings

1. An artifact schema without a corresponding linter is a declaration, not an
   enforced contract; every new report schema needs both surfaces together.
2. Artifact-as-flag activation is useful only when the flag has a small,
   directly testable scheduling predicate.
3. Profile task types and timeout classes are different namespaces; resolving
   `pathfind` through its `research` class avoids expanding the legacy map.
4. Generated catalogs and mirrors must be refreshed after seed or skill edits
   before release validation.
