5. **Anthropic docs (slash commands):** `https://docs.anthropic.com/en/docs/claude-code/slash-commands`

### B.2 — What `/init` does (synthesised, citations inline)

| # | Question | Answer | Citation |
|---|---|---|---|
| B.2.1 | What files does `/init` create? | The slash-command form (`/init` inside an interactive Claude Code session) creates **CLAUDE.md only** in the project root. The CLI form (`claude --init`) additionally lays down `.claude/settings.json` (empty `permissions.allow/deny`) and an empty `.claude/commands/` directory. | [1], [3] |
| B.2.2 | What does it analyze? | Project structure (directory tree), config files (`package.json`, `tsconfig.json`, `pyproject.toml`, `Cargo.toml`, etc.), tech stack & deps, ESLint/Prettier/lint-staged configs for code style, and existing docs. | [1], [2] |
| B.2.3 | Does it RUN any commands (tests / builds / installers)? | **NO.** "Claude examines your codebase—reading package files, existing documentation, configuration files, and code structure—then generates a CLAUDE.md tailored to your project." Pure read + write-one-file. No `npm install`, no `pytest`, no benchmark. | [1] (verbatim above), [2] |
| B.2.4 | How does it handle an existing CLAUDE.md? | NON-DESTRUCTIVE: "If a CLAUDE.md already exists, `/init` will update it based on the current codebase rather than overwriting it" — surface diff for review. | [2] |
| B.2.5 | What flags / options? | None substantive on the slash-command form; runs once per session in interactive mode. CLI form has `--init`. The 2026-03 NEW init (env `CLAUDE_CODE_NEW_INIT=1`) switches to an "interview model" that asks questions instead of auto-scanning. | [4], [5] |
| B.2.6 | Is there a depth/scope parameter? | **NO** — single fixed behavior. Depth is achieved via post-edit (`#` shortcut to append rules) and via `/memory` command, not via `/init` flags. | [1], [5] |

### B.3 — Implication for DevolaFlow

The DevolaFlow `repo-init` paper-spec (`analyze → scaffold → compile → verify`, gate threshold 85, Test team owning `verify`) is **architecturally over-scoped** vs. Claude Code's `/init` (read + write one or three files, no tests, no gate). Feedback bullet #2 is grounded: parity with Claude Code requires (a) a default DEPTH that does only read + scaffold + (optional) docs, (b) the heavier `verify` stage to be opt-in, not the default path.

### E.5 — D-5: Depth-mode parameter (RECOMMEND OPTION α)

**Comparison table:**

| Option | Mechanism | Pros | Cons |
|---|---|---|---|
| **α — `mode: minimal\|standard\|deep` enum on the workflow template** | Template-level `parameters:` block (see E.1 skeleton); template engine passes `mode` to each stage; stages self-skip via `environment_modes` style or via guard | Single source of truth in YAML; mirrors Claude Code's parity story; trivially testable; aligns with existing `parameters:` patterns in other templates; user can call `--mode=minimal` or set in `.workflow/config.yaml` | Requires template-engine support for parameter injection (small extension to `template_engine/parser.py`) |
| **β — Per-stage skip flags (`skip_verify: true`, `skip_compile: true`)** | Boolean flags on each opt-out stage, consumed by composition | Maximum granularity per stage | Combinatorial explosion (2^N flags); leaks template internals to user; no semantic name for "Claude Code parity" mode; harder to document |
| **γ — A single `--no-tests` / `--with-tests` flag** mirrored on `devola-init local` and `install.sh` | CLI-level boolean, not in template | Lowest impl cost for v7.4.2 (no template-engine work) | Hides the depth concept from the workflow template (violates A-1 P3 Structured Messages — workflow definition should self-describe); cannot express the 3-tier minimal/standard/deep nuance; ties depth control to CLI invocation only, not to in-session `/devola-flow init` calls |

**Recommendation: Option α.** It is the only option that (a) mirrors Claude Code `/init`'s "single fixed behavior + scope choice" UX from Part B §B.2.6 by giving DevolaFlow's `init repo` an analogous (but slightly richer) 3-mode default; (b) keeps depth decisions in the workflow template per **A-1 P5 Artifacts as Contracts** (the YAML is the contract, not the CLI invocation); (c) is the smallest delta for a user-facing claim of "depth-aware init" that survives both CLI and L0/L1 dispatch entry points.
