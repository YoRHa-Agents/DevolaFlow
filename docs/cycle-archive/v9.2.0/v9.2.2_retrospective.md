## 4. Key learnings (process improvements for next cycle)

### 4.1 What worked well (continue doing)

1. **Feedback-driven PATCH cycles are fast and have full traceability.** The 3-PV cycle (v9.2.2 → v9.2.3 → v9.2.4) closed 4 issues in a single session with explicit gap-to-close mapping at every step: every CHANGELOG entry cites the issue ID; every test name encodes the closure invariant; every retrospective row maps to a verbatim feedback excerpt. Total wall-clock budget was small because the user pre-classified severity + suggested fix priority. **Recommendation for v9.3.0+**: when feedback files arrive with severity-ranked issue IDs + suggested-fix priorities, structure subsequent cycles around them as PATCH series rather than folding into a MINOR bag.

2. **Deferred-check pattern is reusable.** `AGENT_DIR_REQUIRED_TARGETS: frozenset[str]` + a loop-local gate (`if t in AGENT_DIR_REQUIRED_TARGETS and not (agent_dir / "SKILL.md").exists():`) is the canonical shape for any future per-target CLI option that has different runtime requirements. The `frozenset` immutability + the AST-lint pinning the membership (in `tests/test_no_ghost_features.py::test_v9_2_2_new_symbols_have_coverage`) prevent silent widening / narrowing of the gate surface. **Recommendation for v9.3.0+**: when introducing per-target CLI behaviour divergence, codify the divergence as a frozenset constant + W-18 lint pin + AST-walk lint asserting the contract holds in the implementation body.

3. **Scaffold auditing prevents silent-drift.** The I-003 fix pattern (audit + emit WARN + recommend the exact whitelist line inline) generalises to any other scaffolding code where an existing repo-state could silently mask the new artifact. Operators see the diagnosis + the exact remediation in one log message — no extra round-trip to docs. **Recommendation for v9.3.0+**: when scaffolding writes through pre-existing config (e.g. `.rules/`, `.cursor/rules/`, future `.devola/`), mirror this pattern — read the config, classify each scaffold target, log per-match WARN with the precise fix.

4. **`--mode={core,standard,full}` shorthand reduces operator cognitive load.** The 3-mode dispatch maps 1:1 onto the SKILL.md mode table; `core` is the lean install (the shortest pip-wheel-install recipe), `standard` is the pre-v9.2.3 default, `full` adds example seeds. Individual flags override per explicit-beats-implicit. The shorthand reduces the per-call decision matrix from N flags to 1. **Recommendation for v9.3.0+**: consider adopting similar shorthand surfaces for other multi-flag CLI entrypoints (e.g. `devola-init <target> --tier={lean,balanced,maximal}` for adapter-config bundles).

5. **NineS byte-stable across 3 PATCHes (0.9073 → 0.9074 → 0.9074) signals architectural surface preservation.** A surgical fix (PV-01 I-001) + DX additions (PV-02 I-003 + `--mode`) + cycle-close validation (PV-03) all kept the NineS composite within ±0.000002 — exactly the canonical byte-stable PATCH signature. The composite drift threshold (≤ 0.001 = noise floor) was honoured at every PV. **Recommendation for v9.3.0+**: when planning a PV, predict the expected NineS shift before authoring code; a > 0.001 swing on a PATCH-scope PV signals the change is structural rather than additive and should escalate to a MINOR bump or be re-scoped.

6. **W-18 ghost-audit refresh BEFORE CHANGELOG held discipline at every PV.** Each PV authored its `test_v9_2_X_new_symbols_have_coverage` lint BEFORE adding the CHANGELOG `## [9.2.X]` entry. The W-18 PASS at every PV is a strong signal — when the lint passes green, the CHANGELOG can mention the feature with confidence. The PV-03 ghost-audit also pins the retrospective section headings + the E2E parametrize count, extending W-18 coverage to validation artefacts.

7. **W-19 idempotent archive at PATCH cycle close.** Per W-19 the cycle-archive cadence is by MAJOR/MINOR cycle; v9.2.2 / v9.2.3 / v9.2.4 are PATCH versions of the v9.2.0 MINOR cycle, so all v9.2.* research rolls into `docs/cycle-archive/v9.2.0/`. ### 4.2 What didn't work well (process improvements for v9.3.0+)

1. **The v9.2.3 `--mode` resolver duplicates argv parsing logic.** PV-02 added `_parse_mode` alongside the pre-existing `_parse_no_compile` + `_parse_with_examples` resolvers. Each walks argv independently with slightly different semantics (`startswith("--mode=")` vs `--no-compile` vs `--with-examples` / `--no-with-examples`). The triplet works correctly today (every test passes; explicit-beats-implicit precedence holds) but lints harder than necessary. **Recommendation for v9.3.0+**: migrate `init_project.py::main()` to `argparse.ArgumentParser` with `add_mutually_exclusive_group` for the `--with-examples` / `--no-with-examples` pair + `choices=["core", "standard", "full"]` for `--mode`. Mostly mechanical but touches the existing test fixtures, so warrants a dedicated PV.

2. **The I-001 surgical fix leaves the architectural-fix telegraph unactioned.** The PV-01 closure is correct (the `local` target succeeds; cursor/claude/codex/copilot fail informatively) but the wheel still doesn't ship `workflow-system/`. Operators who want the agent-dir-required targets must `git clone + pip install -e .` — a meaningful UX gap for the cursor/claude/codex/copilot install paths that are the **most common** deployment scenarios. **Recommendation for v9.3.0**: prioritise the wheel-package-data architectural fix as the v9.3.0 SI-1 #1 candidate; it would let `_find_agent_dir()` fall back to `importlib.resources.files("devolaflow_workflow_system")` and `AGENT_DIR_REQUIRED_TARGETS` could shrink (or disappear).

3. **`_path_matches_gitignore` is a partial gitignore semantics implementation.** The PV-02 helper documents the conservative subset (directory-prefix, root-anchor, fnmatch, basename-anywhere) and explicitly skips negation rules. The audit's purpose is detecting "written but hidden" cases, so the conservative semantics are correct — but a future PV that genuinely needs full gitignore semantics (e.g. for a `.devola/.gitignore` lint) would need to either upgrade the helper or vendor a battle-tested library (`pathspec`). **Recommendation for v9.3.0+**: if a second consumer of the gitignore-matching helper emerges, swap to `pathspec` rather than expanding the in-house parser.
