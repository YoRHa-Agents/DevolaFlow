## 4. Key learnings (process improvements for next cycle)

### 4.1 What worked well (continue doing)

1. **The 6-PV cycle structure honored the v9.0.0 retro §4.1 #1 pattern** — every PV shipped as a real semver patch (v9.1.1 → v9.1.2 → v9.1.3 → v9.1.4 → v9.1.5 → v9.2.0). The per-PV git history is more discoverable than v8.3.0's lightweight-tag approach. **Recommendation**: continue this pattern in v9.3.0+ when there are ≥ 3 PVs.

2. **W-17 per-PV test cap discipline (codified in PV-05) directly controlled cycle test growth.** Predicted ≤ +150 cycle cap; delivered **+93 NEW test functions = 0.62× the cap** (vs v9.0.0's 0.65× and v8.0.0's 4.7× over-delivery). The mid-cycle audit at PV-04 (cycle's halfway point) caught the trajectory and re-calibrated PV-05 / PV-06 budgets. **Recommendation**: make this the default discipline for v9.3.0+.

3. **R5 strict triple codification stayed disciplined for all 6 PVs.** Every new feature in this cycle has the R5 contract codified at THREE layers (unit test + lifecycle/integration + EvoBench scenario) and proves byte-identical behavior when env-flag is OFF. PV-03's `auto_write_handoff` env-flag OFF zero-IO test, PV-04's `consult_for_dispatch` env-flag OFF zero-IO test, PV-05's `agents_md_slice=0` byte-identical proof, and PV-06's e2e env-flag-OFF / env-flag-ON divergence test all hold the line. **Recommendation**: continue this for v9.3.0+ opt-in features.

4. **NEST-over-APPEND (A-2.3) preserved cache-prefix invariance across the entire cycle.** `change_context` (position 16) gained 3 sub-fields in PV-04; `canonical_order` length STAYED at 16 / version STAYED at 5. The 6 historical multi-baseline byte tests (v7.0.0 / v7.3.0 / v8.0.0 P-08 / v8.0.0 P-10 / v8.3.0 PV-05 / v8.4.0) ALL continue to PASS without modification, plus the v9.2.0 baseline witness (PV-04) is byte-identical to v8.4.0. **Recommendation**: any new dispatch behaviour in v9.3.0+ should default to NEST under an existing canonical key; APPEND only when the data shape is truly orthogonal (per A-2.3 decision matrix).

5. **W-20 reuse-first achieved ZERO new env flags in the entire 6-PV cycle.** The 5 env flags touched (`DEVOLAFLOW_AGENT_WORKSPACE` for PV-01 + PV-02 + PV-03; `DEVOLAFLOW_MEMORY_ROUTER` for PV-04; `DEVOLAFLOW_AGENTS_MD_SLICE` for PV-05) ALL existed before the cycle started. The v9.0.0 cycle plan §"Self-iteration constraint compliance matrix" prediction "0 new flags across the entire 7-PV cycle" was met for the 6-PV cycle (PV-07 deferred to v9.2.1). **Recommendation**: continue the reuse-first discipline; any new flag in v9.3.0+ MUST clear the W-20 §3 orthogonality test in the PR body.

6. **W-18 ghost-audit refresh BEFORE CHANGELOG entry held discipline at every PV.** Every PV authored its `test_v9_1_X_new_symbols_have_coverage` lint BEFORE adding the CHANGELOG `## [9.1.X]` entry. PV-06 follows the same pattern — `test_v9_2_0_new_symbols_have_coverage` lands BEFORE the CHANGELOG `## [9.2.0]` entry. **Recommendation**: codify this further by adding a CI lint that walks the latest CHANGELOG block and asserts every cited test name resolves to an actual `test_v9_2_0_*` symbol in `tests/`.

7. **The cycle plan + per-PV STATUS pattern from v9.0.0 carried over cleanly.** The single `.cursor/plans/workspace-capability-activation_ec560bc8.plan.md` file (~700 lines) drove all 6 PVs without rewriting; the cycle plan §PV-NN sub-sections functioned as per-PV runbooks. **Recommendation**: continue using a single cycle-plan file with §PV-NN sub-sections in v9.3.0+.

### 4.2 What didn't work well (process improvements for v9.3.0+)

1. **The static-template `_seed_example_artifacts` approach in PV-06 sidestepped the seed_initial_spec production-caller intent telegraphed in PV-05.** The PV-05 `scripts/detect_dead_apis.py::DEFAULT_ALLOWLIST` comment explicitly stated the in-repo Python production caller for `seed_initial_spec` would land in v9.2.0 PV-06. PV-06 instead opted for static templates (which is correct for the bootstrap-of-empty-repo use case — `seed_initial_spec` requires an existing archive folder, which a brand-new repo does not have). The seed_initial_spec function therefore remains test-only in v9.2.0 cycle close. **Recommendation for v9.3.0+**: either (a) wire seed_initial_spec into a different production caller (e.g. as a CLI subcommand `devola-init seed-spec --domain X --archive Y`), OR (b) remove `seed_initial_spec` from the allowlist in v9.3.0 PV-01 and re-classify it as test-only-for-now.

2. **The `_seed_example_artifacts` static templates duplicate the production schemas in inline string literals.** The `_EXAMPLE_HANDOFF_ENVELOPE_YAML` constant manually mirrors the `schemas/agent-workspace/handoff-envelope.yaml` shape; if the schema evolves (e.g. v9.4.0 adds a required field), the static template silently drifts out of sync. **Recommendation for v9.3.0+**: replace the static templates with calls to the schema-package authoring helpers (`devolaflow.agent_workspace.handoff.HandoffEnvelope.author_dispatch(...)`); this would couple the example seeds to schema evolution automatically.

3. **The cycle's tests/test_capability_e2e.py is not parametrized by repo-mode.** The 10 e2e tests assume a single fresh repo — they don't exercise the `change-driven` workflow against (a) `tier=startup`, (b) `tier=enterprise-saas`, etc. PV-07 (deferred to v9.2.1) is intended to close this gap by running the e2e suite against multi-fixture consumer repos. **Recommendation for v9.2.1 PV-07**: parametrize `test_capability_e2e.py::test_*` over the 5 Tier-2 adapter configs from v9.0.1 (jetbrains/amazon_q/gemini/augment/trae) plus the canonical Cursor/Codex/Claude/Copilot quartet — this gives 9 fixture variants per test = 90 parametrize cases, well within the W-17 cap because parametrize expansions of EXISTING tests do not count.

4. **NineS A1/A3 upstream blockers persisted across yet another cycle.** v9.0.0 cycle deferred them; v9.2.0 cycle deferred them again. The cycle target ≥ 0.91 was missed by 0.27 pp because of upstream `code_coverage: 0.0` + `index_recall: 0.8` + `source_freshness: 0.5`. **Recommendation for v9.3.0**: explicitly track NineS v3.4 release as the SI-1 input candidate; if NineS v3.4 still doesn't honor the cov_timeout key, the right move is forking / contributing to NineS rather than continuing to hold the cycle target at 0.91.
