from repository evidence, with optional L0 curation. It is not an
implementation report and does not claim that the feature exists.

## 2. Non-negotiable target contract

The implementation must preserve these decisions:

1. **Deterministic base extraction.** The base digest is derived from explicit
   repository artifacts using stable source ordering, stable identifiers, and
   no wall-clock or model-dependent content.
2. **Verbatim source preservation.** Deterministic extraction and optional L0
   curation MUST preserve verbatim source text. Curation may select, order, or
   attach explicit labels/metadata, but must not paraphrase, silently
   summarize, normalize, or replace source text. The artifact should retain
   source path and source span/record identity so every selected passage is
   traceable.
3. **Optional L0 curation.** L0 may curate the deterministic base for operator
   readability; curation is a separate layer and must not alter the canonical
   extracted source records. L1/L2 agents must not mutate the source substrate
   merely because they consume a digest.
4. **Report-only by default.** A normal Retro-Digest run emits a report/artifact
   and performs no automatic promotion, pruning, rewriting, archive move, or
   other state mutation. Any explicit persistence path needs a separate,
   auditable operator-consent contract.
5. **No new environment flag or CLI is planned.** The feature should use
   existing workflow/skill activation and artifact surfaces. Do not add a
   `DEVOLAFLOW_*` flag or a new console/module CLI. If an activation helper is
   needed, follow the existing pure natural-language intent pattern rather than
   adding process-wide configuration.
6. **No dispatch-layout change is implied.** The digest should remain an
   artifact/reference or L0-only context surface; do not add a top-level
   dispatch key. Any future dispatch behavior must pass the A-2.3
   nest-vs-append decision and all layout witnesses.

## 3. Evidence-backed deficiencies

### P0 — Source fidelity and deterministic output

1. `src/devolaflow/learnings.py` has no retrospective/base-extraction API. Its
   public write operations (`capture_learning`, `consolidate_session`,
   `promote_learning`, `prune_learnings`) are operational state mutations, and
   its `Learning` model stores a free-form `insight` but no immutable source
   text plus source span/record provenance.
2. Existing `dedup_learnings()` is timestamp last-write-wins and
   `format_learnings_section()` renders/truncates a human-facing section.
   Neither defines a deterministic retrospective source ordering or a
   byte-preserving digest envelope. The formatter must not be reused as the
   canonical base extractor because it adds Markdown and applies a token
   budget.
3. There is no output schema or byte-level contract for a Retro-Digest artifact.
   Without one, optional curation could accidentally replace source text or
   make repeated runs differ.

**Required direction:** add a pure extraction/serialization surface owned by
`src/devolaflow/learnings.py` or a narrowly scoped sibling owned by that
module's domain. Define stable record identity, repository-relative source
references, deterministic ordering, explicit empty/malformed-input behavior,
and a report-only result. Keep existing JSONL compatibility and mutation APIs
unchanged. Add tests that compare repeated output bytes and assert exact
source-text equality before and after optional curation.

### P1 — L0 activation and context contract

1. `src/devolaflow/skills/__init__.py` exports classifiers for grill,
   Pathfinder, subagent pattern, and change activation, but no Retro-Digest
   intent surface exists.
2. Existing intent modules deliberately use pure functions with no import-time
   I/O. `change_activation.py` owns the existing workspace environment flag;
   `grill_mode.py` and `pathfinder.py` demonstrate natural-language requested /
   suggested / disabled verdicts without new flags. Retro-Digest has no
   corresponding activation contract.
3. `workflow-system/agent/SKILL.md` only states that operational learnings
   decay, promote, and may be pinned. It does not define retrospective
   extraction, L0 curation, source-fidelity rules, or report-only behavior.
   `workflow-skill.yaml` has an `operational-learnings` body section but no
   Retro-Digest section or reference.
4. `context_profiles.yaml` treats `operational_learnings` as L0-only API prose
   (`skip` by default for subagents) and separately enables bounded learning
   injection. There is no profile-level distinction between deterministic base
   extraction and optional L0 presentation/curation.

**Required direction:** add a pure `src/devolaflow/skills/retro_digest.py`
classifier only if operator intent is part of the approved scope, re-export
it from `skills/__init__.py`, and document requested/suggested/no-op semantics
in the skill source. Add the smallest necessary L0-only context/profile
contract. Do not route the digest through L1/L2 operational mutation paths,
and do not introduce an environment flag or CLI.

### P1 — Template/seed discoverability and parity

The template system is registry-driven:

- `workflow-system/agent/templates/registry.yaml` owns identity, seed path,
  category, tags, and catalog description.
- Each `workflow-system/agent/templates/seeds/*.yaml` is a declarative
  `checklist-seed`; `src/devolaflow/template_engine/seeds.py` rejects
  executable DAG keys and validates repository-relative provenance.
- `workflow-skill.yaml` and seed metadata are retained derived/compatibility
  views. `scripts/check_template_metadata_parity.py` checks identity/path/
  category parity and currently expects 26 entries.
- The generated browser catalog is produced by
  `scripts/generate_demo_seed_catalog.py`; `tests/test_demo_seed_catalog.py`
  checks registry order, seed decomposition, and byte-idempotence.

No `retro-digest` seed or registry entry exists. If the approved feature is
exposed as a selectable workflow seed, the missing surfaces are:

- `workflow-system/agent/templates/registry.yaml`
- `workflow-system/agent/templates/seeds/retro-digest.yaml`
- derived `workflow-system/agent/workflow-skill.yaml`
- `scripts/check_template_metadata_parity.py` and its expected count
- `tests/test_demo_seed_catalog.py`
- generated `workflow-system/human/demo/shared/seed-catalog.js`, regenerated
  rather than hand-edited
- the current-cycle W-18 ghost audit, once the feature is claimed publicly

The seed must describe extraction, optional curation, traceability, and
report-only verification as assertions. It must not smuggle executable
`stages`, `loops`, `gates`, or automatic mutation into a checklist seed.

### P1 — Reference and install registration

There is no Retro-Digest Tier-2 reference. The repository's reference

- the Tier-2 navigation table in `workflow-system/agent/SKILL.md`

  `tests/test_reference_size_budgets.py`,

If a dedicated reference is approved, add
`workflow-system/agent/references/retro-digest.md` with frontmatter, then
register all required surfaces using the existing
`scripts/scaffold_reference.py` convention and add the SF-4 pin. The
reference must state verbatim preservation, report-only default, L0-only
curation, and no-new-flag/no-new-CLI decisions. It must not claim current
runtime behavior before implementation and tests land.

### P2 — Governance and generated-rule coupling

The current `.rules/` corpus contains no Retro-Digest rule. The compiler
contract is source-first:

- edit only the relevant `.rules/*.mdc` source;
- run `make compile-rules` (`sync-rules` wrapper);
- verify compiled outputs with `make check-rules-drift`;
- never hand-edit `AGENTS.md` or `.cursor/rules/repo-governance.mdc`.

If report-only, source-fidelity, or L0-only curation is made normative in the
governance corpus, append a Workflow-layer rule in
`.rules/workflow.mdc` (the Soul layer is frozen at S-1..S-10), update any
`.rules/index.md` count if required by the rule-count test, recompile, and add
the current-cycle ghost assertion. If the contract remains reference/skill
documentation rather than a new rule, no compiled output should be touched.
Either route must retain the rule-count ≤60 and compile-hash invariants.

## 6. Acceptance evidence required after implementation

Before treating the feature as implemented, evidence must show:

1. Repeated extraction from the same inputs produces byte-identical output
   without timestamps, model calls, or unordered traversal effects.
2. Every emitted passage retains exact source text and repository-relative
   provenance; optional L0 curation changes selection/presentation only.
3. Default execution is report-only and does not mutate learnings, source
   retrospectives, archive state, or dispatch payloads.
4. No `DEVOLAFLOW_*` flag and no new CLI/module entrypoint were added.
5. Existing learnings JSONL v1/v2/v3 compatibility tests remain green.
6. Seed registry, derived workflow rows, generated demo catalog, reference
   manifest, SF-4 set, and ghost-audit pins remain in parity.
7. Any governance addition was made in `.rules/` and compiled through
   `make compile-rules`; compiled drift checks pass.
8. The implementation and tests report unresolved or unavailable evidence as
   `INSUFFICIENT`, never as a fabricated PASS.
