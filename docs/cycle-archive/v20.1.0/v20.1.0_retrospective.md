# v20.1.0 Retrospective — Retro-Digest Evidence

Cycle close: 2026-08-29. This W-7 retrospective records the
v20.1.0 MINOR cycle and keeps operational lessons separate from
report-only evaluation benefits.

## 1. Gaps identified

The v20.1.0 SI-1 gap analysis identified an evidence-and-learning boundary
problem rather than a single runtime defect:

- Retrospective material had no deterministic extraction API with stable record
  identity, exact source text, source spans, and repository-relative
  provenance.
- Existing learning APIs were operational mutation surfaces. There was no
  report-only result that could be reviewed without writing to operational
  learning state.
- There was no natural-language Retro-Digest intent surface, and no explicit
  contract for requested, suggested, and no-op activation.
- Evaluation findings could be confused with lessons and promoted into
  operational learning, even though they are benefits/evidence that should
  remain report-only.
- The selectable seed, Tier-2 reference, install manifest, generated catalog,
  and current-cycle ghost audit had no Retro-Digest parity surface.
- The cycle-close evidence still needed to preserve the final evaluator’s
  `INSUFFICIENT` historical measurements and its single-base-ref W-17
  limitation without inventing deltas.

The detailed source analysis and file-level scope are recorded in
`.local/research/v20.1.0_gap_analysis.md`.

## 4. Key operational learnings

1. A report-only result and an explicit persistence helper make the consent
   boundary auditable: extraction can be deterministic and useful without
   mutating operational learning state.
2. Verbatim `text`, original `raw_text`, stable record IDs, and source spans
   are complementary. A source path alone is not enough to prove what was
   learned.
3. Current probes and historical measurements answer different questions.
   Current values can be recorded exactly; missing history must remain
   `INSUFFICIENT`, even when the current composite is ready.
4. Current research must win over an archived duplicate, while record ordering
   remains stable. This makes repeated reports reproducible and prevents an
   archived copy from silently replacing newer evidence.
5. Evaluation findings belong in a separate report-only benefits section.
   Excluding them from `to_learning_entries` prevents a quality observation
   from becoming an operational instruction.
6. A new selectable workflow capability requires parity across runtime,
   exports, tests, seed registry, reference manifest, generated catalog,
   governance compilation, and ghost audit. The W-18 pin is the final
   anti-ghost check before a release claim.
