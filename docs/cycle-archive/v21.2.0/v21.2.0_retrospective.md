# v21.2.0 Retrospective

## Gaps identified

The cycle entered with the v21 evidence boundary still unresolved: the
harness ledger was a 13-record v17-era series rather than matched v21 release
workloads, and replicated salt-based quality, cost, latency, checklist,
reversion, and blocker trends were unavailable. The v21.3.0 gap analysis
confirms that these evidence gaps, along with module-size grandfathering,
near-budget inventory, allowlist review, typing-marker packaging, stale
schema paths, host fixture provenance, and CI de-duplication proof, remain
open.

## Implemented

- Shipped feedback governance and safe local archival for tasks, feedbacks,
  and research, with repo-local entrance contracts, code-aware module
  budgets, operator approval, append-only mappings, and generated indexes.
- Shipped guarded GitHub-native release preparation, reusable release checks,
  exact-commit tagging, and npm publishing.
- Completed this W-7 close record: the canonical v21.2.0 evaluator output,
  W-16 settled baseline, cycle archive, Tier-B window, and duplicate
  `[Unreleased]` cleanup are preserved.

The release surfaces improve governance and release hygiene. They do not by
themselves establish a causal improvement in agent-task quality or ceremony
cost.

## Deferred and insufficient evidence

- The canonical evaluator reports `READY` with composite `8.67`, but its
  available `test_suite` and `compatibility_suite` signals are false.
- Salt evidence is absent (`salt_status: INSUFFICIENT`), and the ledger has no
  matched v21.2.0 workload series; historical comparison and release-delta
  uncertainty therefore remain `INSUFFICIENT`.
- Context-token components, per-PV test splits, checklist completion,
  reversion/blocker trends, and matched real-task outcomes remain
  `INSUFFICIENT`.
- The v21.3.0 analysis intentionally defers the remaining audit findings
  rather than marking T1 or other v21.3 themes resolved.

## Key learnings

1. A canonical evaluator can settle a repository snapshot while still
   preserving unavailable experiment and history evidence.
2. Release claims and quality claims need separate evidence boundaries;
   `READY` does not override failed available probes or missing replication.
3. The archive and Tier-B window must be maintained at cycle close so the next
   cycle can begin from a stable, auditable baseline.
