## 2 — Deficiency enumeration

### D-1 — Version banner is static + not actively announced on execution boundaries (BLOCKER, closes v12.1.1 feedback #1)

**Symptom**: operators starting / finishing a DevolaFlow session in Claude Code / Cursor don't see an explicit "**Now using DevolaFlow vX.Y.Z**" announcement from L0. SKILL.md DOES carry a static banner at line 32 (`> **Now Using DevolaFlow v12.2.0**`) and a §"Version & Update" block, but:

* **The banner is hardcoded text** in SKILL.md frontmatter context — operators don't see it as L0-emitted output in their chat UI; it just sits in the loaded SKILL bytes.
* **L0 has no contract** to ECHO the version when the skill activates (workflow-start) or when the workflow completes (workflow-end), so operators have no live visual confirmation that DevolaFlow is the active orchestrator and which version.
* **Stale version risk**: between bumps the banner / "Current version:" string can drift if `bump_version.py` misses a location.

**Root cause**: SKILL.md §"Version & Update" describes the version surface but contains NO normative obligation for L0 to print the version in the chat at session boundaries.

**Impact**: operators are unsure whether DevolaFlow is active, which version, or whether they're getting the latest skill behaviour.

**Proposed fix** (PV-02):

1. Replace the static `> **Now Using DevolaFlow v12.2.0**` blockquote with a tight 3-line "Session Banner Contract" subsection under §"Version & Update":
   * L0 SHALL announce `🌸 DevolaFlow vX.Y.Z (devola-flow skill) active. Workflow: <type>. Mode: <agent|plan|grill>.` at session start (or first dispatch).
   * L0 SHALL announce `🌸 DevolaFlow vX.Y.Z workflow complete. <stages> stages | <waves> waves | <tasks> tasks` at session end (or final report).
   * L0 SHALL include the version literal in the Task Quality Score footer line (see PV-03).
2. Add `bump_version.py` location for the new banner template strings so they stay in sync.

**File-level scope** (3 files):
* `workflow-system/agent/SKILL.md` (~12 added lines — new "Session Banner Contract" subsection)
* `tests/test_no_ghost_features.py` — W-18 stanza `test_v12_3_0_session_banner_contract` pinning the literal substrings
* `CHANGELOG.md` (new ## [12.3.0] entry)
* (auto via `bump_version.py`) version sync across canonical 8 files

### D-2 — Task Quality Score lives in main SKILL.md body — wastes context during execution (MAJOR, closes v12.1.1 feedback #2)

**Symptom**: SKILL.md §"Task Quality Score (L0 ONLY)" occupies **25 lines (~120 tokens)** at lines 467-491. The section is only consumed AT WORKFLOW END (L0 scores user's original request). During the execution loop (which dominates the session token budget), it is dead weight loaded with the rest of SKILL.md.

**Root cause** (verbatim from SKILL.md §"Task Quality Score (L0 ONLY)"):
* Lines 467-491 (25 lines / 4 dimensions × per-tier rubric / output template / rules paragraph)
* `task_adaptive_selector` profiles enumerate `task_quality_score` priority levels in `context_profiles.yaml` (per `select_context` extraction); when profiles set it to `supplementary` / `critical` / `important`, the section bytes flow into the L3 / L2 / L1 dispatch context even though only L0 consumes the section.

**Impact**:
* Wasted ~120 tokens × every dispatch that includes the section (most STANDARD+ workflows do)
* Increases probability that a `critical`-marked SKILL section gets dropped at the 8K L3 budget ceiling per `_select_sections_within_budget`
* Operator feedback explicitly cites the context-optimisation angle ("以优化上下文表现形式")

**Proposed fix** (PV-03):

1. **Extract** the §"Task Quality Score (L0 ONLY)" body to a NEW reference file `workflow-system/agent/references/task-quality-score.md` (Tier 3 on-demand reference per the existing references-navigation table).
2. **Collapse** the SKILL.md §"Task Quality Score (L0 ONLY)" section to a 5-line stub:
   * Section heading preserved (so SKILL.md TOC + ref-link integrity stays intact)
   * "**L0 ONLY** — Subagents MUST NOT score" prohibition preserved (the W-18 v12.1.0 stanza literal pin stays GREEN)
   * "When to load" trigger: AFTER workflow's final stage completes
   * Link to `references/task-quality-score.md` for full rubric + output format
3. **Update** `workflow-system/agent/context_profiles.yaml` to mark `task_quality_score` as `skip` for L1/L2/L3 task profiles (only L0 / project-level profiles keep it as `important`).
4. **Update** the Reference Navigation Guide table to list `references/task-quality-score.md` as a NEW Tier 3 on-demand reference.
5. **Update** task_adaptive_selector.py `_resolve_section_text` deprecated line-anchors to point at the new location.

**File-level scope** (~7 files):
* `workflow-system/agent/SKILL.md` (-20 net lines from the section collapse)
* `workflow-system/agent/references/task-quality-score.md` (NEW; ~80 lines with extended rubric)
