### 2.2 Architecture rationality (weight 0.20)

**Score: 9.7 / 10**

Evidence:
- **P1 (Dispatcher-Not-Implementer)** enforced via `.cursor/rules/devola-flow-rules.mdc` Rule 1 tool restrictions (L0-L2 may not `Write` / `StrReplace` / `Shell`); this SI-3 task itself was dispatched to an L3 agent with a single-file owned-set.
- **Layered separation.** Pure-function compressor primitives (`compressor.py`) ↔ schema contracts (`schemas/lean-dispatch.yaml#layout_invariant`, `schemas/lean-report.yaml#tool_results`) ↔ policy (`workflow-system/agent/context_profiles.yaml` opt-in blocks) ↔ doctrine (`workflow-system/agent/SKILL.md` + `references/context-isolation.md`). No bidirectional coupling.
- **Layout-invariant rule (ADR-001 §5) makes additive change safe.** Every v7.0.1 → v7.0.3 primitive landed without reordering the 12-key canonical layout: `tool_results` appended after `gate`; `summary_mode` / `summary_max_tokens` nested inside the existing `pred` entry; Learnings v2 never touched the dispatch surface. Workspace Rule P6 codifies this; `devolaflow.compressor.assert_dispatch_layout(payload)` enforces it.
- **Learnings v2 additive schema (ADR-005 §2.1, §2.4).** Four new optional fields + three new helpers; legacy entries parse unchanged via the lazy migration shim. No bulk rewrite pass, no migration script, no compatibility flag.
- **Persistence probe lives in `tests/` only (ADR-004).** 220 LOC of test code + 60 LOC of fixture + 50 LOC of promoted `extract_named_entities` — production code was untouched by the probe itself.

Deduction (−0.3): `references/context-isolation.md` doctrine is consumed as a single blob per the progressive-disclosure pattern; fracture it into a `references/staged-compression/` directory would sharpen the architectural shape for v7.2+.

### 2.5 Compatibility (weight 0.10)

**Score: 9.5 / 10**

Evidence:
- **Legacy Learnings v1 entries parse unchanged.** `tests/test_learnings.py::test_legacy_entry_parses` (line 506) seeds a v1 JSONL record (no `last_accessed` / `confidence_half_life_days` / `pinned_for_session` / `promotion_count` fields) and asserts `load_relevant_learnings()` returns it with defaulted v2 fields (ADR-005 §2.4 migration shim; `confidence_half_life_days = 30`, `last_accessed = ""`, `pinned_for_session = ""`, `promotion_count = 0`).
- **Cache-layout invariant is backward-compatible for canonical-order producers.** ADR-001 §2: the invariant codifies a *canonical* ordering (`hdr → task → goal → assumptions → pred → files → rules → shared → accept → reinforce → verify_cfg → gate`). Every existing dispatcher in the repo already emits keys in that order (verified by `test_layout_invariant_baseline`); the invariant formalises existing practice.
- **Additive schema policy.** Every schema change — `schemas/lean-dispatch.yaml#layout_invariant`, `schemas/lean-report.yaml#tool_results`, per-`pred` `summary_mode` / `summary_max_tokens`, Learnings v2 — lands at `layout_invariant.additive_positions` (ADR-001 §5). No key renamed, no key removed, no reorder above an earlier section.
- **Adapter builds remain stable.** The four core adapters (`cursor`, `codex`, `claude`, `copilot` — see `data/golden_test_set/adapter_registry_default.toml`) ship unchanged; the data-driven adapter engine (`DataDrivenAdapter`) has taken zero edits since v6.0.4; v7.x touched no adapter source files.

Deduction (−0.5): The MAJOR bump at v7.0.0 is an intentional **governance** break for downstream tooling that previously assumed free reordering of dispatch sections (see ADR-001 §1). This is the entire semantic reason v7.0.0 is MAJOR; no callers inside this repo exercise the freedom, but external consumers of the dispatch schema do need to audit their renderers.

### 2.6 Performance impact (weight 0.15)

**Score: 9.5 / 10**

Evidence:
- **Benchmark composite median unchanged or improved vs v7.0.0.** 33 pre-existing scenarios show 0 pp drift in `benchmarks/devolaflow_context/baselines/v7.1.0_baseline.json`; the new `compression_tool_output` scenario (added in v7.0.1) scores 98.33 composite at 0.9967 information density with 0.0769 noise ratio (noise is the intentional truncation-placeholder overhead, not omission).
- **LCP SLO (ADR-001 §2).** Round 1 → 2 = 0.8487 (threshold 0.80) and Round 1 → 3 = 0.8487 (threshold 0.70) — both above commitments, measured by `test_prefix_stability_rounds_1_2` / `test_prefix_stability_rounds_1_3` in `tests/test_compressor.py`.
- **Asymptotic analysis.** `extract_named_entities` runs deterministic regex over the artifact body — O(n) in artifact size. `summarise_predecessor` early-returns under the 25 % `summary_trigger_pct` (ADR-003 §2.1) — no wasted cycles on short artifacts. Learnings v2 `decay_confidence` is O(m) in entries, and pruning is bounded by `DECAY_FLOOR = 0.1` so degenerate entries are removed rather than re-processed on every reload.
- **Probe latency.** Probe telemetry records `elapsed_s = 0.0046 / 0.0228 / 0.0607` on easy / medium / hard tiers (5 / 20 / 50 entities). The full probe run completes in under 100 ms even at the current `hard` tier — fast enough to stay in CI hot paths.

Deduction (−0.5): Three hotfix/verify-profile scenarios (`hotfix_jwt`, `acceptance_verification_feature`, `interaction_accessibility_test`, `visual_regression_webapp`) sit at 84–88 composite because their budget allocations intentionally leave budget headroom (≤ 0.7 utilization). This is an architectural choice for verify-type profiles (preserve headroom for evidence accumulation), not a regression, but it is the single scoring gap between the cycle and the theoretical 100 ceiling.
