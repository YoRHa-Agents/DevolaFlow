## 4. Key learnings

### 4.1 NEST decision rule clarification (D-P-3)

The A-2.3 NEST-vs-APPEND decision rule is well-codified for the
`schemas/lean-dispatch.yaml#layout_invariant.canonical_order` surface
(the dispatch payload). v10.7.0 D-P-3 is the first time the rule has
been applied to a SECONDARY schema (`schemas/agent-workspace/change-status.yaml`).
The interpretation extends naturally: NEST means "group related
sub-fields into ONE dict-shaped optional key", APPEND means "spawn
multiple sibling top-level scalars". The rule applies wherever a
schema's flat surface is at risk of inflation.

The decision rationale lives inline in the schema YAML (in the
header comment block) so future operators can replay the choice.

### 4.2 Audit-only patterns are cheap insurance (D-P-1)

D-P-1 is a 430-LOC script + 5 tests that takes ~30 seconds to run
and produces zero schema mutation. The empirical data feeds future
NEST decisions without committing the cycle to any specific merge.
The cost is well under the M effort estimate per the PDS; the
informational value compounds across cycles (each run accumulates
sample data).

### 4.3 OPT-IN observability beats default-ON (D-O-2 + D-O-3)

D-O-2's auto-collector and D-O-3's research index are both OPT-IN
(operator-pull, not wired into release-preflight). This preserves
the SI-10 7-gate budget while unlocking the observability surface
for cycle-leads who want it. The pattern matches the W-20 reuse-
first / OPT-IN-first design philosophy: avoid forcing every cycle
to pay observability overhead; let cycle-leads opt in when the
signal-to-noise ratio justifies the wall-clock cost.

### 4.4 Reference cardinality discipline (D-O-1)

Adding the 16th SF-4 reference required updates in 7 distinct
locations (sync_cursor_skill.py + test_version.py + test_reference_size_budgets.py
+ test_adapter_golden.py + test_no_ghost_features.py + golden_test_set
TOML + SKILL.md). The W-18 ghost-audit lint catches the overall
absence; the per-test count assertions catch the specific cardinality
breaks. The 7-touchpoint cost is high but acceptable for the
operational benefit of the reference (SI-3 evaluation authoring
time reduction from ~90 min → ~50 min per the PDS §4 expected delta).

### 4.5 W-17 cycle-budget healthy

v10.7.0 adds 26 NEW test functions (5 D-P-1 + 3 D-P-3 + 5 D-O-1 +
7 D-O-2 + 6 D-O-3 + 1 W-18 stanza-level audit = 27 expected; close).
This is comfortably under the W-17 per-PV cap of +30 NEW tests, and
the cumulative cycle delta from v10.6.0 → v10.7.0 stays well under
the +150 cumulative cycle ceiling. The mid-cycle audit (W-17 line
"Mid-cycle audit at PV-05") confirms the projection is sustainable.

### 4.6 Cycle-rollup observability beats per-PV scaffolding

v10.7.0 ships 5 PDSs into a single MINOR cycle, mirroring the
v10.6.0 (3 PDSs) and v10.5.0 (6 PDSs) rollup patterns. The rollup
discipline keeps the version bump cadence reasonable while letting
related work co-mingle in the cycle plan + retrospective. The
trade-off: a single cycle now carries 5 risk surfaces, and a single
audit-only PDS (D-P-1) shipped alongside a schema-mutating PDS (D-P-3).
The W-18 ghost-audit lint gives us per-PV traceability without
forcing per-PV release boundaries.
