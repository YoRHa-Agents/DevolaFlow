## §3 — A-1 vs Soul-rule classification test

Apply the Soul-vs-Architecture decision rule from ADR-007 lines 183-188 ("Soul rules accrete
only when a new immutable constraint is discovered"). For the candidate "Parallel Wave
Dispatch Invariant — Every L2-wave with `parallel_mode: true` MUST go through
`dispatch_wave_tasks`":

### §3.1 — Is it an immutable invariant?

**Test**: would the constraint EVER be relaxed for any future cycle / task / agent layer?

| Answer | Evidence | Verdict |
|---|---|:---:|
| The constraint applies ONLY when `parallel_mode: true` — i.e., it is conditional on a parameter, not universal across all L2 dispatches | `parallel_mode: false` waves bypass the constraint entirely (single-task waves go L0 → L3 directly per A-6.1) | **conditional** — not a Soul-class universal invariant |
| The constraint enforces a CONCRETE FUNCTION CALL (`dispatch_wave_tasks`); future refactors that rename the function or add an alternative entry point would either break the rule or require a rule update | Soul rules are stated as ABSTRACT invariants (S-1 "Dispatcher-Not-Implementer" doesn't name a specific tool — it states a layer constraint) — the candidate names a specific function | **implementation-coupled** — not Soul-class abstract |
| The constraint already has a Workflow-rule-shaped equivalent: W-3 / W-9 / SI-10 ensure the gate chain runs; if `dispatch_wave_tasks` is the canonical path, the gate chain WOULD detect violations via existing tests | the v10.0.0 retrospective §3.5 explicitly notes "Pending full A-1 vs Soul-rule analysis" — flagging this very classification question | **deferred classification** |

**Verdict**: the candidate is NOT a true immutable invariant. It is **implementation-coupled
+ conditional** — both qualifiers indicate it belongs at Architecture (P1) or Workflow (P3)
layer, not Soul (P0).

### §3.2 — A-7 (Architecture) candidate?

**Test**: per ADR-007 line 183 "Architecture rules emerge naturally from refactor cycles":
does the constraint fit the A-1..A-6 pattern (architectural decisions about layering,
component boundaries, registry SSOT, append-only invariants)?

| A-* sibling | Pattern | Match score |
|---|---|:---:|
| A-1 | 4-layer agent hierarchy with sub-rules P1..P5 | the candidate IS a P1-class statement (about HOW L2 dispatches; refines the L2-wave layer's responsibility) | **strong match** |
| A-2 | cache-prefix governance | unrelated | n/a |
| A-3 | context budgets | unrelated | n/a |
| A-4 | spec source-of-truth | unrelated | n/a |
| A-5 | SSOT registry pattern | the candidate's "MUST go through `dispatch_wave_tasks`" IS a registry-routing statement | **moderate match** |
| A-6 | workspace activation | unrelated | n/a |

**Verdict**: A-1 is the natural home for this rule. The candidate could land as a NEW
sub-section A-1.5 "Parallel Wave Routing" or as part of an expanded A-1 P1 section. This
is structurally cheaper than Soul-rule landing because:

* Architecture rules don't require the W-21 ≥ 9.5/10 SI-3 §3.2 score (Architecture rules
  ship at the standard W-3 SI-3 ≥ 8.5 MINOR threshold).
* Architecture rules don't require the 2-cycle telegraph gap (the gap is a Soul-only
  governance item per W-21 D4 #1 verbatim).
* Architecture rules are NOT counted against the W-21 Soul cap (≤ 12); the current
  Architecture layer has 6 entries (A-1..A-6) with no published cap (per `.rules/architecture.mdc`
  there is no explicit numeric cap analogous to W-21 §4).

### §3.3 — W-22 (Workflow) candidate?

**Test**: per ADR-007 line 188 "Workflow rules accrete when a process step needs codification":
does the constraint fit the W-1..W-21 pattern (process gates, verification chains,
deliberation cadence)?

| Match | Evidence |
|---|---|
| The candidate is a runtime-dispatch invariant, not a process step | Process rules describe what HUMANS or DISPATCHERS do procedurally (e.g., W-7 retrospective authoring); the candidate describes what the RUNTIME does at the L2 layer dispatch surface |

**Verdict**: NOT a strong match for Workflow layer. Architecture (A-7) is the better home.

### §3.4 — Recommended classification

**A-7 (Architecture rule N+1)** is the appropriate landing layer. The candidate should be
re-titled to match A-1's P1..P5 sub-rule pattern, e.g., **A-7 Parallel Wave Dispatch
Routing — every L2-wave with `parallel_mode: true` routes via `dispatch_wave_tasks` to
preserve A-1 P1 (dispatcher-not-implementer) at the wave layer**.

This re-classification is NOT a proposal for v11.0.0; it is the recommended path for the
next cycle (v12.0.0+) that has L3 budget for the SI-1 entry + SI-3 evaluation work.

## §4 — Threshold calibration question (quantitative)

Compare the W-21 D4 #3 threshold (≥ 9.5/10 SI-3 §3.2 architecture-rationality score) to
actual SI-3 §3.2 architecture-rationality scores from cycles v9.0.0 → v10.8.x. Is 9.5
historically achievable?

| Cycle | SI-3 §3.2 architecture-rationality score | Source | Composite (for context) | Verdict re 9.5 floor |
|---|---:|---|---:|:---:|
| v9.0.0 (MAJOR close) | 9.0 | `.local/research/v9.0.0_evaluation.md` §3.2 (manual hand-grade era; pre-D-O-2 auto-collector) | 9.30 | below 9.5 |
| v9.7.0 (MINOR close) | 9.0 | per cycle plan §5 trajectory | 9.10 | below 9.5 |

| v10.2.0 (MINOR close) | 9.5 | per cycle history | ~9.3 | **at threshold** |

| v10.4.0 → v10.7.0 (per-MINOR retros) | (not granular per-MINOR §3.2; aggregate cycle composite ≥ 8.5) | per-MINOR retrospectives (`v10.4.0_retrospective.md` etc.) | per-MINOR ≥ 8.5 | tracked as cycle-cumulative |
| v10.8.x pre-v11 self-loop | 9.5 (subjective; objective 10.0 → final 9.80 weighted) | `.local/research/v10.8.x_pre_v11_evaluation.md` §3.2 line 16 (subjective 9.5; final weighted 9.80) | **9.30** | **at threshold** (subjective) / above (final weighted) |

**Empirical rate of meeting the 9.5 threshold**: 4 of 7 cycles cited above hit 9.5+ on the
§3.2 dimension (v10.0.0, v10.2.0, v10.3.0, v10.8.x). Pre-v10 cycles (v9.0.0, v9.7.0)
trended around 9.0 — the architecture maturation across the v10.x cycles (introduction of
A-2 cache-prefix governance + A-5 SSOT registry pattern + A-6 workspace activation)
elevated the §3.2 baseline.

**Threshold calibration verdict**: 9.5 is **achievable but not common**. ~60% of evaluated
cycles hit it on the §3.2 dimension; the threshold appropriately filters cycles where the
L0 evaluator subjectively scores architecture-rationality below "near-perfect". The
threshold is NOT mis-calibrated — it requires Soul-rule additions to land only in cycles
where architecture rationality is exceptional, which matches the multi-cycle deliberation
goal of W-21.

| Threshold characterization | Verdict |
|---|---|
| Too strict (no cycle ever meets it) | NO — 4/7 cycles meet it |
| Too loose (every cycle meets it) | NO — 3/7 cycles fall below |
| Appropriately calibrated (filters ~40% of cycles) | **YES** |

## §5 — Recommendation for v12.0.0+ deliberation

**Neutral recommendation** (does NOT bind any future cycle):

The next cycle that has ~0.5 PV of L3 budget for Soul-rule deliberation work should:

1. **Decide between two paths**:
   * **Path A — Land at A-7 (Architecture)**: re-classify the candidate as Architecture
     rule N+1 per §3.4 above. Author the SI-1 entry as an Architecture-rule rationale
     (no W-21 governance applies; standard MINOR cycle SI-3 ≥ 8.5 threshold suffices).
     Estimated effort: ~0.5 PV.
   * **Path B — Land at S-11 (Soul)**: author the dedicated W-21 D4 #2 SI-1 gap-analysis
     entry (~150 LOC) AND run the dedicated SI-3 §3.2 sub-evaluation explicitly scoring
     the candidate. If §3.2 ≥ 9.5/10, land as S-11. If < 9.5, defer with explicit
     deliberation-trail note. Estimated effort: ~1 PV (SI-1 entry + SI-3 sub-eval +
     STRICT MAJOR cycle close gating).

2. **Discriminating question for the choice**: is the constraint TRULY immutable (Path B)
   or is it a refinement of A-1 P1's L2-wave specialization (Path A)?
   * §3.1 verdict above is **conditional + implementation-coupled** — Path A is the
     simpler natural home.
   * Path B remains an option iff the cycle author argues the abstract invariant
     ("parallel waves preserve dispatcher-not-implementer at the L2 layer") is
     philosophically distinct from A-1's P1 and warrants Soul-class permanence.

3. **Defer iff** neither path's effort fits the cycle budget. Continued floating is
   acceptable per W-21 governance (the rule's 2-cycle gap is a FLOOR, not a CEILING; a
   candidate may telegraph for arbitrarily many cycles before landing or being formally
   rejected). The cost of floating is documented telegraph entries; the benefit of
   floating is ensuring no premature Soul-rule landing.

**This recommendation is the deliberation INPUT for v12.0.0+ cycles**. It does NOT
re-telegraph the candidate to v11.2.0 — the cycle plan §7 line 258 already does that. It
provides the SI-1-entry-style content the next cycle's L3 author can copy verbatim into
the per-cycle SI-1 gap-analysis file (per W-21 D4 #2 enumeration of (a)-(d)).
