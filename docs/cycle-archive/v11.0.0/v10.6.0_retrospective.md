## 1. Gaps identified (SI-1 planning gate)

The v10.6.0 cycle was scoped via the v11.0.0 admission rollout as the
third MINOR cycle after v10.4.0 + v10.5.0. Source-of-truth direction:
`.local/research/v10_internal_optimization_directions.md` §3.5 (D-Q
code quality). The per-PDS gap analyses live at
`.local/research/v11.0.0_patches/D-Q-1.md` / `D-Q-2.md` / `D-Q-4.md`.

The 3 gaps admitted for v10.6.0:

1. **D-Q-1** — v10.2.2 PV-03 NineS deep-analysis emitted 10 warning-class
   cyclomatic-complexity findings across `src/devolaflow/{lifecycle,plugins}/`.
   v10.2.3-PV-04 closed finding #2; v10.2.4-PV-05 closed findings #5 + #7;
   the remaining **7 warnings** were deferred to "v10.4.0+ candidate" per
   `v10.2.2_nines.md` §5. All 7 are mechanical helper-extraction refactors
   with full pre-existing test coverage. **Fix:** extract 14 single-purpose
   helpers across the 4 affected files; verify CC drops; behaviour
   byte-identical.
2. **D-Q-2** — `src/devolaflow/feedback.py::ProposalGenerator` had grown to
   carry **6 distinct responsibilities** in one cohesive but
   architecturally-mixed surface. The `_emit_dispatch` method (130 LOC)
   was the worst offender: 4 hook-event constants + 4 try/except scopes
   + lazy-import-lifecycle + per-event WARNING logging all in one
   place. **Fix:** extract responsibilities #1, #3, #4, #5 into a new
   `ProposalEmitter` class in NEW
   `src/devolaflow/feedback_emit.py`; reduce
   `ProposalGenerator.generate_round_dispatch` to a thin façade.
   **Critical S-10 invariant**:
   `tests/test_dispatch_emission_runs_hooks.py` 10 tests MUST stay
   byte-identical green.
3. **D-Q-4** — `src/devolaflow/compressor/` has had **NO NineS
   deep-analysis since v9.3.0** (547-day gap at v10.5.0 baseline).
   The v10.2.2 PV-03 NineS run explicitly EXCLUDED this package. The
   largest file (`transforms.py` at 2,198 LOC) is the largest single
   Python file in the entire `src/devolaflow/` tree — the single
   biggest unaudited risk surface for hidden complexity warnings.
   **Fix:** ship `scripts/snapshot_compressor_health.py` (radon-based
   audit script) + tests + Makefile target; commit the first audit
   output to `.local/research/v10.6.0_compressor_health.md`. Audit-only
   deliverable; any actionable refactors become v10.6.x or v11.0.x
   micro-PVs.

## 4. Key learnings

1. **Helper-extraction CC reduction has predictable leverage** — across
   all 7 D-Q-1 functions, the average CC dropped 69% with zero
   behaviour change. The pattern (extract 1-3 single-purpose
   helpers per function; orchestrator becomes thin) is reproducible
   and low-risk. Future cycles can confidently scope similar
   PV-shaped batches.
2. **Composition over inheritance is the right pattern for god-function
   refactors** — D-Q-2 chose composition (`ProposalGenerator` holds a
   `ProposalEmitter` instance via `self._emitter`) over inheritance,
   which keeps the public API surface byte-identical AND makes the
   new class testable in isolation. The 8 unit tests on
   `ProposalEmitter` complement the 10 integration tests on the
   façade — defence in depth.
3. **Byte-identical contracts are protected by tests, not by code
   review** — the S-10 invariant (10 tests in
   `test_dispatch_emission_runs_hooks.py`) caught zero regressions
   during PV-02 because the refactor was careful, but the test
   itself is the contract. Future refactors of `ProposalEmitter`
   can be done confidently because the test will catch ANY chain
   order / strict-mode / byte-output drift.
4. **Audit scripts have long-tail value** — D-Q-4's snapshot script
   will be re-run at every cycle close (now wired into the
   `snapshot-compressor` Makefile target). The 4 surfaced compressor
   warnings are a candidate pipeline for the next 4 micro-PVs;
   without the script, those would be invisible.
5. **The "actual CC ≠ PDS estimate" pattern recurs** — for several
   functions the PDS quoted a CC value 1-2 units lower than the
   actual radon measurement (e.g. `resolve_plugin` PDS=11 actual=13;
   `ensure_plugin` PDS=14 actual=16). The PDS authors were
   estimating from documentation rather than running radon. Future
   PDS authoring should baseline against the live radon output to
   set realistic targets.
6. **The v10.5.x "test count grows faster than coverage" pattern is
   under control this cycle** — only 13 NEW test functions added
   (8 D-Q-2 + 5 D-Q-4 + 0 D-Q-1 — the W-17 caveat for parametrize-
   over-data applies); well under the W-17 ≤+30/PV cap. Cumulative
   v10.5.0 → v10.6.0 delta = +13 NEW test functions; well under
   the +150/cycle cumulative cap.
