## 3. What was deferred and why

- **Real git-diff / pre-commit CI for INPUT immutability** (design §3c "git-diff lint") — current hook is
  API-level like its handoff-envelope analogue; a true pre-commit/CI surface is a larger, orthogonal
  change. Deferred to a future cycle unless requested.
- **Auto-`update_tracker()`** (ADR-7 optional enhancement) — not required by the review; deferred.
- **Wiring `check_human_input_append_only` into `DEFAULT_EVENTS`** — deliberately NOT done: it would change
  the cache-stable lifecycle event tuple (a cache-layout decision) and break the CI tests pinning the count.
  v14.0.0 chose opt-in by design; promoting to default-on is a separate, telegraphed decision.
- **S-11 Soul-rule candidates** — none proposed this cycle; W-21 freeze at 10/12 preserved (no telegraph
  needed).

## 4. Key learnings

- **`--report-log` is a plugin, not builtin** (pytest 9). `parse_pytest_report` was therefore designed to
  consume the JSONL format directly and is unit-tested with fixture JSONL — decoupled from whether
  `pytest-reportlog` is installed. The caller contract (run pytest with the plugin) is documented, not
  assumed at runtime.
- **Field growth with defaults is W-17-friendly** — appending `criterion`/`cycle` (defaulted) to
  `RequirementTraceResult` avoided churning every existing constructor and kept the v14.0.0 tests green.
- **The §6c join's real value is the OVERRIDE** — a failing test now demotes an optimistic `Satisfied`
  matrix cell to `unmet`; the regression test for this (`test_join_failed_node_overrides_optimistic_matrix_to_unmet`)
  is the load-bearing one.
- **Demo What's-New version is a release-gate** — `test_doc_consistency::test_demo_index_version_matches_package`
  requires the FIRST `New in vX.Y.Z` heading to match the package major.minor; remember to add the demo
  section on every MINOR/MAJOR bump (added to the cycle checklist).
- **W-16 regen can be a no-op** — when no benchmark-affecting file changes, the new baseline is byte-identical
  (per the v12.3.0 W-16 clarification, regen-at-close is valid). Still produced `v14.1.0_baseline.json` for
  the newest-baseline pin convention.
