# v21.1.0 — SI-1 Gap Analysis

## 1. Objective and evidence boundary

This is the SI-1 close artifact for the v21.1.0 evidence cycle. It starts
from `.local/feedbacks/feedback_for_v18-v20.md`, the v21.0.0 research and
retrospective artifacts, the current harness ledger, and the v21.0/v21.1
implementation surfaces. It distinguishes repository contract readiness from
agent-task quality, runtime cost, and release-delta evidence.

The feedback's EvoBench output is modeled simulator evidence. Its five-salt
sweep is useful for describing variance and claim validity, but it is not a
direct measurement of upstream implementation quality. The v21.1.0 CLI
calibration is a planned 240-artifact matrix, but all 240 artifacts are
`INSUFFICIENT`: no CLI outcome, token usage, or skill-loading observation was
available. Therefore this artifact does not claim a quality, latency, or ROI
improvement.

## 3. Current-cycle implementation state

The v21.0.0 contracts provide trivial-path validation, bounded status-report
evidence, component token accounting, and reproducibility metadata. The
v21.1.0 implementation adds a host-contract `skill_residency` axis, bounded
Claude/Codex/Kimi CLI probes, an ordered task-class × channel × arm ×
replicate calibration runner, and machine-readable ROI aggregation.

These are evidence and correctness contracts. Passing unit, ghost, harness,
or repository-hygiene checks proves that the contracts are wired and
fail-closed; it does not prove that the ceremony improves a real task outcome.

The calibration report records 240 planned and observed artifacts, with

skill-loading observations are missing across every cell. The report's ROI

and KimiCode are `designed`; other listed hosts remain `undeclared`. No host
has a captured or vendor-document fixture, so no host is eligible for an
`implemented` claim. A probe boolean is a runtime observation, not proof that
the channel's residency contract is validated.

File-level scope for closure:

the missing outcome and token evidence.

ghost tests validate contracts, not multi-turn implementation quality or

## 5. Close disposition

v21.1.0 closes the intended machine-readable contract work and settles a
baseline without converting unavailable calibration into a pass. The final
evaluator's repository readiness is a bounded engineering signal. It is not
evidence of improved task quality, reduced ceremony cost, cross-channel skill
equivalence, or validated release-factor movement.

No new environment flag or dispatch-layout mutation is required by this
analysis. Existing `DEVOLAFLOW_AGENT_WORKSPACE=1` semantics remain unchanged.
