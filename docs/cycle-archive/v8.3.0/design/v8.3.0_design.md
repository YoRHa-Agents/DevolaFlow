# v8.3.0 Design Document

> Date: 2026-04-22 | Author: L0 Project Agent | Predecessors: `.local/research/v8.3.0_gap_analysis.md`, `.local/research/v8.3.0_openspec_deep_analysis.md`
> Closes design surface for **A1–A4 + PATCH** from `feedback_for_v8.2.0.md`. Required before patch decomposition (per W-1 / SI-1).

## 0. Design Goals & Non-Goals

### 0.1 Goals (rank-ordered)

1. **G-A — Lightweight, agent-targeted change folders**: every in-flight change has its own `.local/.agent/active/<id>/` folder with **strict per-artifact token budgets**, machine-parseable, no verbose prose. (closes A1+A2)
2. **G-B — Cross-agent handoff protocol**: agents can hand off work via `.local/.agent/handoff/` with append-only envelopes, inbox/outbox semantics, no silent overwrites. (closes A1)
3. **G-C — Archive ledger**: completed changes preserved verbatim with date prefix; full audit trail; source-of-truth specs evolve via gated delta merges. (closes A1+A4)
4. **G-D — Rules + memory integration**: agents are constrained by new soul rule (no writes outside `owned_files`); memory layer is change-aware (per-change learnings + auto-extract on archive); rules-layer ships a per-change `applicable_rules` injection point. (closes A3)
5. **G-E — Human-readable REPORT.md surface**: per-change REPORT auto-generated at archive time; aggregate REPORTs at `.local/.agent/REPORT.md` + `.rules/REPORT.md` + `.local/memory/REPORT.md`. (closes A4)
6. **G-F — Runtime plugin auto-install**: `nines` and `ui-pro` install themselves on demand; failures are loud (S-5 no silent failures); supply-chain risk mitigated via pinned versions + sha256. (closes PATCH)
7. **G-G — Per-improvement patch validation**: every gap closes in its own PV with full SI-10 6/6 PASS before next patch starts. (closes A6)

### 0.2 Non-Goals

- **NG-1**: We do NOT build a 27-tool adapter surface (defer to v8.4.0+).
- **NG-2**: We do NOT introduce telemetry (none exists today; placeholder env var only).
- **NG-3**: We do NOT auto-merge deltas into source-of-truth without an explicit gate (preserves W-3 / SI-3 + W-4 / SI-4).
- **NG-4**: We do NOT migrate legacy `.local/research/<topic>.md` artifacts into `.local/.agent/archive/` (opt-in script only; deferred to v8.3.x).
- **NG-5**: We do NOT introduce a `/devola:onboard` slash command (defer to v8.4.0).
- **NG-6**: We do NOT add custom-schema-per-project parity with OpenSpec (DevolaFlow's existing template registry is more capable).

### 0.3 Hard invariants (carried from prior cycles)

- **I-1**: P6 cache layout — at most 1 transition (v15 → v16); positions 1–15 byte-identical (v7.0.0 + v7.3.0 byte-baselines must continue passing).
- **I-2**: SKILL.md ≤ 500 lines (currently 495/500; v8.2.9 must absorb +new section).
- **I-3**: Backward-compat byte-identical for `learnings.py` 14 public functions, `scaffold_local()`, and TaskDispatch v4 layout.
- **I-4**: 0 EvoBench regressions > 5pp across 43 baseline scenarios; v8.2.9 adds ≥ 2 new scenarios → 45 total.
- **I-5**: No absolute paths in any agent-facing file (S-2).
- **I-6**: External tool URLs only (S-7) — `nines` references `https://github.com/YoRHa-Agents/NineS`, `ui-pro` references its canonical GitHub URL (TBD: confirmed at v8.2.1 implementation time).

### 1.2 Path conventions (closes S-2 enforcement)

- **All paths relative to repo root** (S-2). Never absolute.
- **Change-id** = lowercase-kebab-case (e.g., `add-dark-mode`, `fix-auth-bug`, `v8.3.0-pv01`).
  - For DevolaFlow's own iteration cycles: `change-id == "v8.3.0-pvNN-<topic>"` to maintain cycle traceability.
- **Date prefix** for archives: `YYYY-MM-DD` (ISO-8601, sorts chronologically; same convention as OpenSpec).
- **Sequence numbers** for handoff envelopes: monotonic integers starting at 1, zero-padded to 4 digits (`0001`, `0002`, ...) for sort-correct directory listing.

### 1.3 Lifecycle FSM

```
[NEW IDEA / FEEDBACK]
        │
        │  /devola:propose <topic>
        ▼
[active/<id>/ created]
  ├─ goal.md         ← scaffolded
  ├─ acceptance.md   ← scaffolded
  ├─ spec.md         ← scaffolded
  ├─ tasks.md        ← scaffolded (empty checklist)
  ├─ STATUS.yaml     ← state: PROPOSED
  └─ owned_files.txt ← scaffolded
        │
        │  L0 dispatches L3 task agents per W-9 SI-10
        ▼
        │  /devola:apply         (loop until tasks.md all ticked)
        ▼
[active/<id>/ in progress]
  ├─ STATUS.yaml     ← state: IN_PROGRESS, percent_complete: ...
  ├─ tasks.md        ← checkboxes ticked as work completes
  └─ learnings.jsonl ← per-task reflections appended
        │
        │  /devola:verify        (optional gate)
        ▼
[STATUS.yaml state: VERIFYING]
  └─ verification report appended to STATUS.yaml
        │
        │  /devola:archive       (REQUIRES gate composite ≥ threshold per W-3 SI-3)
        ▼
[active/<id>/ → archive/<YYYY-MM-DD>-<id>/]
  ├─ All artifacts frozen
  ├─ REPORT.md auto-generated
  ├─ Delta merge to .local/memory/specs/<domain>/spec.md proposed (NOT auto-applied)
  └─ STATUS.yaml     ← state: ARCHIVED
        │
        ▼
[Aggregate REPORTs auto-regenerated]
  ├─ .local/.agent/REPORT.md          ← active-vs-archived dashboard
  ├─ .local/memory/REPORT.md          ← knowledge state report
  └─ .rules/REPORT.md                 ← rules-coverage report
```

**State transitions** (machine-enforced via `STATUS.yaml` `state` field):
- `PROPOSED` → `IN_PROGRESS` (first L3 dispatch starts)
- `IN_PROGRESS` → `VERIFYING` (`/devola:verify` invoked)
- `VERIFYING` → `IN_PROGRESS` (verify FAIL → bounded retry)
- `VERIFYING` → `ARCHIVED` (verify PASS + `/devola:archive` invoked + gate PASS)
- `IN_PROGRESS` → `ESCALATED` (P4 bounded retry exhausted; human intervention required)

### 2.7 Handoff envelope `<from>__<to>__<id>__<seq>.yaml` (≤ 600 tokens)

```yaml

  owned_files_ref: ".local/.agent/active/<id>/owned_files.txt"
  predecessor_artifact_refs:
    - path: <relpath>
      summary: <verbatim 3–5 sentence extract per CO-2>

# For envelope_kind == StatusReport:

  task_id: <id>
  state: completed|failed|escalated
  artifacts:
    - path: <relpath>
      type: source|test|doc
      summary: <verbatim>
  metrics:
    tests_passed: <int>
    coverage_pct: <float>
    findings_by_severity:

## 3. Rules Layer Integration (closes A3 part 1)

### 3.1 New soul rule **S-8** (added in v8.2.2 to `.rules/soul.mdc`)

```markdown
## S-8 — No Writes Outside Active Change Owned Files

When an L3 Task Agent is operating inside a `change-driven` workflow with an
active change folder (`.local/.agent/active/<change-id>/`), it MUST NOT modify
any file outside the union of:
1. paths listed in `.local/.agent/active/<change-id>/owned_files.txt`
2. the change folder itself
3. `.local/.agent/handoff/` (only its own outbox; append-only — see S-9)

Violations:
- Detected at file-write time via `lifecycle/check_file_ownership` hook
- In `mode: lite` — warn + log
- In `mode: full` (or STRICT) — block + escalate per P4

Exceptions:
- Trivial single-file edits < 20 lines (P1 trivial waiver also applies here)
- L0/L1/L2 dispatcher reads (Read/Glob/Grep/SemanticSearch) are unrestricted
```

### 3.2 New soul rule **S-9** (added in v8.2.2)

```markdown
## S-9 — Handoff Envelopes Are Append-Only

Once a `<from>__<to>__<change-id>__<seq>.yaml` envelope exists in
`.local/.agent/handoff/`, it MUST NOT be modified or deleted by any agent.

To convey new information, the agent MUST author a new envelope with `seq+1`.

Rationale: append-only ledger prevents silent overwrites between agents
operating in parallel. Mirrors P5 (Artifacts as Contracts).

Enforcement: `tests/test_handoff_envelope_immutable.py` lints CI runs;
`lifecycle/check_envelope_append_only` hook blocks at write time in STRICT.
```

### 3.3 New conventions rule **C-9** (added in v8.2.2 to `.rules/conventions.mdc`)

```markdown
## C-9 — Lightweight Agent Workspace Artifacts

Files inside `.local/.agent/active/<change-id>/` and
`.local/.agent/archive/<date>-<id>/` are subject to per-artifact token budgets:

| File | Soft budget | Hard ceiling |
|------|-------------|--------------|
| goal.md | 200 | 400 |
| acceptance.md | 400 | 800 |
| spec.md | 1500 | 3000 |
| tasks.md | 800 | 1500 |
| STATUS.yaml | 100 | 200 |
| owned_files.txt | 50 | 100 |
| Handoff envelope | 600 | 1200 |

Verify with:
```bash
python -m devolaflow.agent_workspace.lint <change-id>
```

Soft budget over → warn. Hard ceiling over → fail commit.
```

### 3.4 New architecture rule **A-4** (added in v8.2.2)

```markdown
## A-4 — Source-of-Truth Spec Location (M-004 ADR)

`.local/memory/specs/<domain>/spec.md` is the source-of-truth for current system
behavior. Per-change `.local/.agent/active/<id>/spec.md` files contain DELTAS
(ADDED/MODIFIED/REMOVED Requirements) relative to source-of-truth.

Source-of-truth is mutated ONLY at archive time, after the gate has PASSED
(W-3 / SI-3 composite ≥ 8.5 for minor changes, ≥ 9.0 for major). The gate
runs the explicit `mergeability_check` (v8.2.5 reporter module) before allowing
the merge.

Rationale: separates lifecycle of in-flight proposals from agreed contracts;
preserves W-3 / SI-3 + W-4 / SI-4 invariants by NOT auto-merging on archive.
```

## 4. Memory Layer Integration (closes A3 part 2)

### 4.1 Per-change learnings (`.local/.agent/active/<id>/learnings.jsonl`)

Same JSONL schema as `.local/memory/operational.jsonl` (the existing `Learning` dataclass; v8.2.2 PV-03 SessionState shape). Per-change scoping prevents cross-change pollution.

Captured by:
- `capture_session_reflection(session_id, task_type, files, insight, source, jsonl_path=...)` — extended in v8.2.8 to accept `change_id` parameter; default `jsonl_path` becomes `.local/.agent/active/<change_id>/learnings.jsonl` when `change_id` is present.

### 4.2 Auto-extract on archive (`/devola:archive`)

When archive runs:
1. Load `.local/.agent/active/<id>/learnings.jsonl`
2. Run `consolidate_session(change_id, learnings, .local/memory/operational.jsonl)` — promote durable learnings to global JSONL with confidence boost (existing v7.0.3 ADR-005 mechanism).
3. Move per-change `learnings.jsonl` to `.local/.agent/archive/<date>-<id>/learnings.jsonl` (preserved verbatim).

### 4.3 Change-aware load (`load_relevant_learnings`)

Extend signature (v8.2.8, R5 backward-compat — new param defaults to `None`):

```python
def load_relevant_learnings(
    task_type: str,
    jsonl_path: Path,
    min_confidence: float = 0.5,
    max_entries: int = 10,
    session_id: str | None = None,
    change_id: str | None = None,    # NEW v8.2.8 — additive
) -> list[Learning]:
    """When change_id is set, load BOTH per-change learnings (highest priority)
    and global operational learnings (ranked after). Returns merged top-N."""
```

When `change_id` is not None:
1. Load `.local/.agent/active/<change_id>/learnings.jsonl` (in-change scope)
2. Load `jsonl_path` (global scope, typically `.local/memory/operational.jsonl`)
3. Merge: in-change entries surface first, then global, dedup by `(stage, task_type, key)`, max_entries cap

### 6.3 `installer.py` API

```python
def ensure_plugin(
    plugin_id: str,
    *,
    registry_path: Path = Path("workflow-system/agent/knowledge/runtime-plugins.yaml"),
    auto_install: bool | None = None,    # None means honor registry default
    log_path: Path | None = None,
) -> str:
    """Ensure plugin is installed at >= min_version.

    Lookup chain:
    1. Run version_check_cmd; parse version
    2. If version >= min_version → return version (no-op)
    3. If auto_install is False → raise PluginVersionMismatch (loud, S-5)
    4. If local_fallback_path is set and points to an installed package → use it (`pip install -e <path>`)
    5. Otherwise run install_cmd
    6. Re-run version_check_cmd; verify version >= min_version; raise on failure
    7. Append install event to install_log_path

    Raises:
        PluginNotFoundError: plugin_id not in registry
        PluginInstallError: install attempt failed (subprocess error, network unreachable, etc.)
        PluginVersionMismatch: post-install version still < min_version (or auto_install disabled)
    """
```

### 6.5 Failure-mode catalog (S-5 no silent failures)

| Scenario | Behavior | Log |
|----------|----------|-----|
| Plugin already installed at >= min_version | Return version; no install | INFO `plugin_already_installed` |
| Plugin missing, auto_install=true, network OK | Install via install_cmd; verify; return version | INFO `plugin_installed` |
| Plugin missing, auto_install=false | Raise PluginVersionMismatch | WARN `plugin_install_blocked_by_config` |
| Plugin missing, network unreachable, local_fallback_path set | Install via `pip install -e <local_fallback_path>` | INFO `plugin_installed_from_local_fallback` |
| Plugin missing, network unreachable, no local fallback | Raise PluginInstallError | ERROR `plugin_install_network_unreachable` |
| Plugin install succeeds but version < min_version | Raise PluginVersionMismatch | ERROR `plugin_install_version_mismatch` |
| `expected_sha256` set and post-install hash mismatches | Uninstall; raise PluginInstallError | ERROR `plugin_install_sha_mismatch` |
| Subprocess timeout (> network_timeout_seconds) | Raise PluginInstallError | ERROR `plugin_install_timeout` |

All raises are LOUD (per S-5). Caller (workflow precondition stage) escalates to L0 per P4 bounded retry.
