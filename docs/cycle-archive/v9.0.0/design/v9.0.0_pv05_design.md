### 1.4 R5 strict pattern flags (control surface only)

The R5 strict pattern is enforced by the CONJUNCTION of:

* env-flag set to `"1"` exactly (rejects `"true"`, `"yes"`, `"on"`, `"01"`, `""`)
* runtime probe (e.g. `shutil.which("rtk")` for `DEVOLAFLOW_RTK_PROXY`,
  `Path.read_text` for `DEVOLAFLOW_MEMORY_ROUTER` with the cases index)

When EITHER side is missing the feature is a zero-IO no-op (no
`Path.read_text`, no `subprocess.run`, no `shutil.which` for the
strict-affected modules). Tests in `tests/test_shell_proxy_disabled_is_noop.py`,
`tests/test_memory_router.py::TestLookupCaseR5StrictOff`, and
`tests/test_shell_proxy_commands.py::TestLoadR5StrictOff` codify the
contract at the unit-test layer.

## 2. T02 — A1 closure path (chosen: path **(a)** with config bump in `nines.toml`)

**Background**: NineS self-eval reports `code_coverage: 0.0` because the
internal `pytest --cov` collection times out at the NineS-derived 54s
budget ceiling (the v8.1.0..v8.4.4 deferred carry-forward). The flagged
46179-token agent-context-overhead measurement (NineS issue
`AI-24c4f48d-0002` from v8.1.0-rc.1) is the second hygiene gap.

**Path (a) — extend cov budget via NineS config bump**: add an explicit
`[hygiene] cov_timeout = 180` (3 min) to `nines.toml` so the internal
cov collector has 3.3× the previous budget. This preserves the EXISTING
`devolaflow.nines.scorer` module (which is a thin CLI wrapper, not a cov
runner — the cov call is internal to the NineS binary) and keeps the
runtime path byte-identical. Also bump `[eval] timeout = 180` (was 60)
so the upstream knows the new ceiling.

**Path (b) — drop nested cov collection in `nines/scorer.py`**: would
require the NineS binary itself to honour a "skip-cov-if-host-runs-cov"
flag — not exposed by the v3.3.0 CLI. Rejected because we do NOT want
to ship a wrapper-side mutation of NineS internal scoring (S-7).

**Decision**: path (a). Implementation = single `nines.toml` edit
(~+10 LOC). If NineS still reports `code_coverage: 0.0` post-bump
(because the upstream binary ignores the new key), the result is a
graceful non-regression: PV-05 SHIPS with the budget bump documented in
ADR-005 and a STATUS-report transparent note that the upstream blocker
remains open (R-6 fallback to W-2 manual mode). The ADR documents this
as a **known external dependency** — the in-repo surface is correct,
the binary side awaits the upstream fix.

## 4. AGENTS.md ceiling pre-flight decision

Pre-flight reading: rule-compiler reports `agents_md: 5857/6000 tokens
(97.6%)` after PV-04. Adding W-16..W-20 (~+125 LOC of source rule body
≈ ~+750 tokens of compiled output) WOULD exceed the 6000-token cap.

**Decision**: raise the AGENTS.md `token_budget` to **8000** (matches
the `.cursor/rules/repo-governance.mdc` ceiling). One-time bump
documented in ADR-005 D5. Rationale:

1. AGENTS.md serves AGENTS.md-aware tools (Codex, KimiCode, Cline, Roo)
   — these tools have larger context windows than the original 6000-token
   target was set for (the 6000 was chosen in v8.0.0 when the rule corpus
   was 41 rules; now with W-16..W-20 we land at 55 rules).
2. The `.cursor/rules/repo-governance.mdc` target is already at 8000 —
   parity removes the surprise that one tool target accepts more rules
   than another.
3. Compression alternative would dilute the rule wording — every W-rule
   has a verbatim source-citation `## W-X — <title> (SI-X)` lineage
   that operators rely on for traceability.

The ceiling bump is a `compile-config.yaml` one-line edit. The
RuleCompiler then re-emits AGENTS.md with all 5 layers (soul +
architecture + conventions + workflow + style — currently AGENTS.md
includes 4 layers, missing style). PV-05 keeps the 4-layer
`include_layers` list to avoid expanding scope; the bump is purely
headroom for W-16..W-20 within the 4-layer set.
