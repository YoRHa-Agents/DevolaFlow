## v9.0.0-relevant patterns

Five patterns from the v7 era still active or load-bearing in v9.0.0:

2. **Anti-ghost meta-test infrastructure cadence (v7.4.4 P-01 → v9.x)** — `tests/test_no_ghost_features.py` `pytest.mark.xfail(strict=True)` discipline + per-cycle ghost-audit artifact (`.local/research/v*.0_ghost_audit.md` style) became the default S-4 / CP-1 enforcement mechanism for every minor/major release; the strict-XPASS-fails-suite trick is now the canonical "definition of done" anchor.
3. **EvoBench-feedback-driven mini-cycle pattern (v7.3.0 → v8.x)** — research → patch plan → per-patch feature branch → single `feat()` commit → lightweight tag → `--no-ff` merge → SI-10 6-step gate → ACCEPT/REJECT, then aggregate Stage C rollup into the minor/major bump with annotated tag + SI-8 retrospective. Established as the canonical multi-patch cycle template.
4. **Permissive-default + opt-in-strict lifecycle hook design (v7.4.8 P-05)** — `run_hooks(event, payload, *, strict=False)` two-mode pattern (collect violations + log WARNING by default; raise `HookViolation` only when caller opts in to `strict=True`) is the architectural template for any new runtime-enforcement primitive in v8.x+; central strict-raise decision in the dispatcher avoids handler-level double-logging.
5. **Prompt-side governance contract embedding (v7.8.0)** — the v7.4.1 → v7.5.0 → v7.7.0 three-time `repo-init` recurrence proved that runtime-only enforcement (Python `run_hooks`) is invisible to prompt-only L0 orchestrators (Claude Code / Cursor / Codex); SKILL.md must carry the contract directly (e.g. `SKILL.md §"Repo-Init Pre-Dispatch Contract"` listing all 5 canonical paths verbatim with `VOF001` blocker reference). This pattern now informs every v8.x+ governance addition: if a contract matters for prompt-only orchestrators, embed it in `SKILL.md` or a Tier-1 reference, NOT in a Python helper that only `run_hooks` consumers see.
