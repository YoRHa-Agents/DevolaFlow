# v9.0.0 SI-1 — Conflict Register (v2.x → v8.4.0)

> Source: .local/research/v9.0.0_version_history.md + schemas/
> Date: 2026-04-23 | Author: L3 Task Agent (Review team)

## Summary

Scope: a backwards scan of all 50+ DevolaFlow releases documented in the
v9.0.0 SI-1 era manifests (v2.x → v8.4.0), the live `schemas/lean-dispatch.yaml`
+ `schemas/lean-report.yaml` cache-layout invariants, and the live SKILL.md
budget state, looking for design decisions that pull in opposing directions
across the surface, the rule taxonomy, the operator opt-in surface, the
gate-vs-research boundary, and the ghost-feature / audit cadence.

**14 conflicts surfaced.** Severity distribution: **3 BLOCKER**, **5 CRITICAL**,
**4 MAJOR**, **2 MINOR**. The three BLOCKERs (C-01, C-02, C-08) form a tight
cluster around the cached-prefix + SKILL.md-budget + rule-count growth path —
all are direct consequences of "additive surface forever" running into a
hard ceiling that v8.x has now touched (canonical_order length 16 / SKILL.md
499/500 / 50 rules); v9.0.0 must address the ceilings directly, not via
another micro-compression. The CRITICALs include the env-flag opt-in cluster
(C-03), the source-of-truth registry split (C-07), the ghost-audit cadence
(C-05/C-06), and the plan-mode prompt-vs-runtime drift recurrence (C-12).

## Conflict Catalog

### C-01 — Cache-layout invariant vs dispatch-surface extension pressure [severity: BLOCKER]

- **Axis A**: P6 / Rule 6 mandates `schemas/lean-dispatch.yaml#layout_invariant.canonical_order` is append-only and never reorders existing keys; reordering is a release blocker.
- **Axis B**: Every minor/major since v7.0.0 has wanted at least one new top-level dispatch field (12 → 13 → 14 → 15 → 16 across v7.0.0/v7.2.6/v8.0.0-P-08/v8.0.0-P-10/v8.3.0-PV-05).
- **Tension**: The append-only rule is structurally satisfiable (each new field appends after `gate`), but the *surface budget* is not unbounded — every appended key re-enters the L0/L1/L2/L3 dispatch payload and competes for the same per-layer token budget (P2: L0 ~3K / L1 ~5K / L2 ~4K / L3 ~8K). Five successive schema generations have shipped under the additive rule, yet v8.4.0 explicitly held additions at 0 to leave breathing room.
- **Evidence** (verbatim):
  - Source 1: `.cursor/rules/devola-flow-rules.mdc` Rule 6 — "Dispatch payloads MUST honour the canonical layout declared in `schemas/lean-dispatch.yaml#layout_invariant`. Use `devolaflow.compressor.assert_dispatch_layout(payload)` before send. New top-level keys MUST be appended after `gate` (position 12). Reordering existing keys is a release blocker per `.local/research/adr/v7-ADR-001-cache-layout-invariant.md`."
  - Source 2: `schemas/lean-dispatch.yaml:427-445` — `layout_invariant: version: 5 / canonical_order: [hdr, task, goal, assumptions, pred, files, rules, shared, accept, reinforce, verify_cfg, gate, repos, behavioral_guidelines, acceptance_criteria_v2, change_context]`
  - Source 3: `.local/research/v9.0.0_history_v8.md:415` — "additivity proven across **FOUR successive schema generations** (13 → 14 → 15 → 16) plus 1 stable cycle"
  - Source 4: `CHANGELOG.md:12` — "The cycle achieves **0 P6 cache-layout invariant transitions** as planned. `schemas/lean-dispatch.yaml#layout_invariant.canonical_order` byte-identical pre/post v8.4.0 (length 16 / version 5)."
- **Historical attempts at reconciliation**: ADR-001 §2 "additive rule for new keys" (v7.0.0); P-08 nesting under existing keys when possible (v8.0.0 P-02 nested `compact_directive` under `pred[*]`, P-03 nested `token_budget` under `gate`); v8.4.0 deliberate-zero-transition cycle.
- **Current status**: lurking — append-only is honored, but the surface keeps growing.
- **Proposed v9.0.0 resolution**: split — codify a top-level vs nested-under-existing-key decision rule (any field that does NOT need a new cached-prefix segment MUST nest under an existing canonical_order entry); add explicit byte-identicality regression test on positions 1..N for ALL prior baselines (v7.0.0 + v7.3.0 + v8.0.0 + v8.3.0) per v8.3.0 retro §4.2 recommendation.
- **Depends on**: C-02 (SKILL.md budget pressure shares the same root); C-08 (rule-count growth has an analogous additive-forever shape).
