## v2.2.0 — 2026-04-10
**Theme**: Acceptance Readiness Gate + Task-Adaptive Context Selection + Lean Message Templates + EvoBench Integration (verbatim composite from `### Added` block — CHANGELOG carries no single bold intro line for this release).
**Type**: MINOR

### Key changes
**Added** (verbatim from `CHANGELOG.md` lines 2565–2569):

- **Acceptance Readiness Gate**: New `acceptance_readiness` gate type validates acceptance criteria quality (Testability, Completeness, Measurability, Clarity, Independence) before workflow starts. Reduces rework from vague criteria.
- **Task-Adaptive Context Selection**: Context profiles per task type (hotfix, research, design, refactor, review, feature). Agents receive only task-relevant SKILL.md sections.
- **Lean Message Templates**: Structured compact format for TaskDispatch and StatusReport inter-layer messages. Uses verbatim compaction instead of summarization.
- **EvoBench Integration**: Context density benchmark suite at `/benchmarks/devolaflow_context/` with Python evaluation harness.

**Changed** (verbatim from `CHANGELOG.md` lines 2571–2573):

- **SKILL.md optimized for information density**: Removed redundant sections (duplicate tables, triplicated constraints, verbose rare-action instructions). 449 → 293 lines, all behavioral specifications preserved.
- **Gate module extended**: `GateInput` now supports `acceptance_readiness_criteria`, `GateProfile` includes `acceptance_readiness_threshold`.

## Notes on v2.0.0 (no CHANGELOG entry)

There is no `## [2.0.0]` header in `CHANGELOG.md`. The string `2.0.0` appears in the file once, but only inside the v4.0.0 entry (CHANGELOG line 2214, verbatim):

```
- context_profiles.yaml: meta.version bumped to "2.0.0"; all 16 profiles now include `decomposition` configuration block
```

That mention refers to the `context_profiles.yaml` schema's internal `meta.version`, not a DevolaFlow release. The v2.1.0 changelog line `Version bump: 0.2.0 → 2.1.0 across all 9 version locations` (line 2598) implies the project skipped a v2.0.0 release entirely, going from a `0.2.0` working version directly to the published `2.1.0`.

A feedback file for v2.0.0 nonetheless exists. Its full verbatim content (`.local/feedbacks/feedback_for_v2.0.0.md`, 3 non-empty lines):

```
1. deep view for the design to make it more effecient and helpful(suitable for claude code and cursor at the same time)
2. add score ability after the job finished, and tell the user how the task info given scored(是否清醒明确，搜索并调研如何评价)，这个评分能力应该是轻量化的，只关注几个核心点即可，目的是给于用户一个反馈得分引导用户提升

更新 v2.1.0 版本并更新各种文档和 help，推送 release 到 github 并 pr
```

These asks were absorbed into v2.1.0 (Quick Action Decision + Task Quality Score). v2.0.0 is therefore an "expected but never cut" release in the version ledger.

## Anomalies for S02 attention

- **Version-numbering jump (0.1.0 → 2.1.0)**: skips both v1.x and v2.0.0 in a single release. The `.local/feedbacks/feedback_for_v2.0.0.md` file asks for a release labelled v2.1.0 explicitly. Worth noting in the multi-version retrospective as the project's first non-monotonic version step.
- **EvoBench is born inside v2.x**: v2.2.0 introduces `/benchmarks/devolaflow_context/` and the W-4 / SI-4 benchmark regression guard's substrate. This is the cradle of every later regression baseline; downstream eras' "no regression vs. baseline" claims trace back to this release.
- **Acceptance Readiness Gate cradle**: v2.2.0 introduces `acceptance_readiness` gate type plus `acceptance_readiness_criteria` and `acceptance_readiness_threshold` on `GateInput` / `GateProfile`. Any later gate-module changes (W-11 / CP-4) build on this v2.2.0 surface.
- **SKILL.md compression milestone**: v2.2.0 records a 449 → 293 line reduction with "Zero degradation verified across 7 output types" and "254/254 tests pass, all 4 adapters verified". This is the earliest documented enforcement of the < 500-line tier ceiling that later becomes Rule C-4 / SF-1.
- **Lean message format origin**: v2.2.0's "Lean Message Templates" is the seed for what becomes Rule C-2 (`schemas/lean-dispatch.yaml`, `schemas/lean-report.yaml`) and the P6 cached-prefix invariant (Rule A-2). Worth tagging at S02 as the genesis of the inter-layer-protocol lineage.
- **Feedback-driven release loop**: v2.1.0 is documentary evidence that the feedback-file → release pipeline existed before any formal SI-1 planning gate. The feedback file is dated against v2.0.0 but explicitly names v2.1.0 as the implementation target — a one-cycle lead between user ask and release.
