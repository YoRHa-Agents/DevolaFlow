## (a) Specific deficiencies

1. **No harness-construction trigger surface.** The registry-v3 seed set (23
   seeds) has no seed for "build harness infrastructure" work; intent routing
   (SKILL.md table) cannot classify it. Cross-cutting "build the harness
   first, then do the task" reordering (dependency-inversion per the source
   talk) has no mechanized signal.
2. **No inventory/gap mode in the harness domain.** `evaluate` scores six W-3
   dimensions and reports `INSUFFICIENT`/`auto_fill_rate`, but nothing turns
   those signals into a structured coverage/gap report an operator can act on
   at preflight time. "Where are the observation gaps" is answered by vibes.
3. **No coverage taxonomy.** No fixed set of axes describing what a complete
   harness covers (observation points per layer, evaluation dimensions, probe
   coverage, baseline window, local signals, propose→apply loop closure).
4. **No change-level capability review loop.** W-16 settlement is manual and
   cycle-level; `cross-validate` only diffs six-dimension scores. There is no
   before/after capability delta for a change that claims to build harness
   infrastructure — the staircase-ascent loop is open.
5. **No artifact contract for harness preflight analysis.** `preflight.md` is
   a signed 600-token artifact with a frozen section layout; harness gap
   analysis has nowhere to live under C-9.
