## §4 — Key learnings

### §4.1 NineS deep-analyze for reference refresh is fast and high-signal

The PV-01 harness completed deep-analysis of 5 cloned references in 1.6 seconds total (a single per-ref deep run is ~250-450ms with NineS v3.3.0). The output is high-signal — every concrete delta cited in PV-02 (intensity-levels expansion in caveman, +4 skills in superpowers, stall-detection clause in gates.md, subdomain-merging script in understand-anything, 11-spec catalog in openspec) was surfaced within the 5 deep analyses without manual repo browsing. The ROI for the harness itself (~400 LOC + 7 tests) is high enough that future MINOR cycles touching reference-dependencies.yaml should re-invoke the harness automatically rather than ad-hoc grep.

### §4.2 W-2 manual-review fallback was essential for 76% of refs (16 / 21)

Only 5 of 21 refs (24%) were locally cloned in the v9.6.0 dispatch environment. The W-2 fallback contract ("manual analysis... must be explicitly noted as manual") is what allowed the cycle to close — a strict NineS-or-bust policy would have BLOCKED 76% of the inventory. The harness's explicit `skipped_no_clone` / `skipped_non_repo` markers + the synthesis "Manual-review refs" section discharged the W-2 documentation requirement at zero per-ref author cost. This pattern (harness + explicit-skip markers + per-ref note in yaml) is the canonical way to handle reference inventories that span clonable + non-clonable + un-cloned sources.

### §4.3 Avoiding SKILL.md edits preserved A-2 byte-stability

The cycle deliberately routed all integration deltas through reference-doc edits + yaml updates, leaving SKILL.md untouched. This preserved:
* A-2 frozen prefix invariance (no `tests/test_layout_invariant_multi_baseline.py` re-baseline needed)
* W-5 SKILL coupling avoided (no adapter rebuild + benchmark recheck cascade for content-only changes)
* The 460-line SKILL.md headroom (still 40 lines under the C-4 default-tier 500-line ceiling)

The cost was minor: 4 ref-doc edits totaling ~110 NEW lines (well within their large-tier ≤1000 budget; max post-edit: execution-protocol.md = 757 lines). The benefit was a strictly content-only MINOR with zero invariant churn — exactly the structural shape the user requirement asked for ("refresh integration ... summarise into a minor").

### §4.4 W-17 test cap overshoot was driven by integration-pinning density (acknowledge + budget-balance forward)

The cycle landed at +24 NEW test functions in v9.6.0, bringing the v10.0.0 cycle running total to +163 (vs +150 cap). The overshoot of +13 was driven by 16 contract tests in `test_v9_6_0_reference_integrations.py` — necessary because every PV-02 ref-doc edit needed an anchor lint to prevent silent regression in future cycles. This is a structural mismatch with W-17 (designed for the +30 NEW unit tests per PV pattern, not for +30 contract-pin tests per PV); the v9.6.0 retrospective acknowledges the overshoot per W-17's mid-cycle audit clause and forecasts the v9.7.0/v9.8.0/v10.0.0-close reservoir at ~0 NEW tests to balance the cycle ledger by the v10.0.0 close. Future content-heavy MINORs should batch contract-pin tests across PVs (e.g., one anchor-lint test parametrized over all 4 anchors instead of 4 separate tests) to absorb the density into the parametrize-doesn't-count W-17 exception.
