## §3 Findings

| ID | Severity | Location | Finding | Recommendation |
|---|---|---|---|---|
| F-1 | major | §3b/§3c/§8a | Per-REQ immutability trigger is undefined/self-contradictory: §3c equates "editable/DRAFT" with "status not yet `Satisfied`", but §8a shows a **Ratified** requirement at **Status: Pending**, and the requirements.md Status enum (`Pending\|Satisfied\|Blocked`) has no Ratified/DRAFT dimension — so the proposed `check_human_input_append_only` hook cannot tell which REQ blocks are immutable. | Add an explicit per-REQ lifecycle field (e.g. `Ratified: <date> \| DRAFT`) **distinct from** Status, and define ratified-ness as the sole append-only trigger. |
| F-2 | major | §6c | The human convergence render is specified to populate per-REQ evidence rows "from the gate's per-REQ evidence", but the existing SI-3 gate emits a 6-dimension composite + `findings_by_severity`, **not** REQ-ID-keyed evidence. The source of `Result`/`Evidence` per REQ is unspecified. | Specify the REQ-ID→evidence producer (a traceability checker separate from the composite gate), or scope the render to consume `requirements.md` traceability + test-run artifacts directly. |
| F-3 | major | §3b/§4b/§4c | Budget vs unbounded accumulation: `requirements.md` (durable cross-version anchor, D-1) is hard-capped 2500 tok and `DIGEST.md` is capped 100/120 lines with a "≤1 line per REQ" coverage table — both grow monotonically as durable REQs accumulate, with no rotation/rollup policy. D-1 (durable accumulation) and D-2 (anti-flooding cap) collide at scale. | Define a rollover: DIGEST shows this-cycle REQ deltas + a rollup count; document a ceiling-overflow policy for `requirements.md` (archive superseded-only is insufficient since active durable REQs stay). |
| F-4 | minor | §4c/§9 | New DIGEST/convergence budgets are dual-unit (lines AND tokens; words AND tokens) but the existing `agent_workspace.lint` (`estimate_tokens`, `BudgetReport.actual_tokens`) is token-only. "Extending lint" understates a new measurement axis. | Scope the lint line/word-count extension explicitly, or normalize every human-artifact budget to tokens. |
| F-5 | minor | §5b | Relocating `FEEDBACK_DIR_DEFAULT` → `.local/.agent/sichip-deferred/` omits a migration step for existing `sichip_deferred_*.md` docs **and** the `.sichip_deferred_fingerprints.txt` sidecar; the dedup set resets, so one duplicate DEFER doc can re-emit post-relocation and old docs orphan in `feedbacks/`. | Specify a one-time move (docs + sidecar) or a dual-read fallback during the transition window. |
| F-6 | minor | §3a/§8a | Version-stamp ownership ambiguous: §8a requires a *requirements* amendment to "bump the **constitution** version stamp", coupling `requirements.md` changes to `constitution.md`'s version lifecycle. | Clarify whether the stamp is a single shared human-input version or one per file. |
| F-7 | minor | §9 | The `references/human-surface.md` roadmap row cites SF-4/C-7 + the SKILL.md nav row but omits the other two C-7 obligations: `_SF4_REFERENCE_SET` in `tests/test_no_ghost_features.py` and `scripts/sync_cursor_skill.py::MIRRORED_FILES`. | Enumerate all four C-7 obligations to avoid a CI trip in the implementation cycle. |
| F-8 | info | §5b/§7 | The sichip relocation (checklist decision-8) changes a backward-compat-relevant default path but is not elevated to an ADR (only §5b), unlike the other 7 forks. | Consider an ADR-8 for traceability of the irreversible default change. |
| F-9 | info | §2/§5d | Scaffold-spec gap: §2 shows a top-level `.local/human/README.md` and an `output/` parent dir, but §5d's `REQUIRED_DIRS`/`_DIR_README_CONTENT` list only `human/input`, `human/input/amendments`, `human/output/convergence`, `human/archive` (no `human/` root README, no `human/output` README). | List the root + `output/` READMEs in the scaffold spec. |
| F-10 | info | §1/§9 + §4c | (a) "closes D-N" slightly overstates for a design-only artifact (it *designs* the closure). (b) The two C-9 surfaces already diverge — `repo-governance.mdc` C-9 lacks the `REPORT.md`/`learnings.jsonl` rows that `agent-workspace.md` §9 carries — so "add to both" makes `repo-governance.mdc` carry its first report-like rows; note the asymmetry. | Cosmetic; align phrasing + note the C-9 surface asymmetry. |
