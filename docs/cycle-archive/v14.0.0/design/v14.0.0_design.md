## 1. Overview & Goals

The DevolaFlow `.local/` tree today has a rich AGENT surface (`.agent/`, `memory/`,
`research/`) but no first-class HUMAN surface. The v13.0.0 driver feedback
(`.local/feedbacks/feedback_for_v13.0.0.md`) asks for two human directions, cleanly
separated from the agent tree:

- **Direction 1 — immutable long-term human INPUT.** Durable requirements + constraints
  with regression/guidance value (引导回测). "重点在于人类输入要不能修改并有引导回测意义" —
  the headline is *immutability for regression value*.
- **Direction 2 — concise human OUTPUT.** Feedback / reports / convergence summaries.
  "面向人类的输出也要简洁明确，避免输出淹没" — the headline is *anti-flooding*.

**Goals (the four deficiencies this design closes — see §-by-§ mapping below):**

| Goal | Deficiency | Addressed in |
|---|---|---|
| Durable immutable cross-version requirements/constraints anchor | **D-1** (BLOCKER) | §3 |
| Concise, bounded, conclusion-first convergence output | **D-2** (BLOCKER) | §4 |
| Clean human↔agent separation + de-pollution (relocate `sichip_deferred_*`, resolve TRACKER) | **D-3** (MAJOR) | §5 |
| Git-tracked authoritative human zone | **D-4** (MINOR, coupled to D-1) | §5 |

> **"closes D-N" = "designs the closure of D-N" (F-10a).** This is a design-only artifact (S-4);
> the section headings' "closes D-N" is shorthand — the implementation cycle effects the actual
> closure once the deferred `src/`/`tests/`/`.gitignore`/schema/version work lands (§9).

**Design principles (drawn from `v14.0.0_reference_analysis.md` §4; external prior art by URL per S-7):**

1. **Immutable ≠ write-locked.** Durable INPUT = an *amendable constitution* + stable-ID
   requirements; revisions append a dated amendment (S-9), never edit-in-place. Regression
   value comes from the append ledger, not `chmod -w` (spec-kit `https://github.com/github/spec-kit`).
2. **Truth + delta + dated archive.** Each requirement has traceable lineage so the archive
   answers "what changed and **why**" (OpenSpec `https://github.com/Fission-AI/OpenSpec`; internal A-4).
3. **Budget-capped, conclusion-first OUTPUT.** Verdict on line 1; ≤500-word report + ≤100-line
   digest, enforced by explicit C-9 budget rows (agency-agents `https://github.com/msitarzewski/agency-agents`;
   gsd `https://github.com/gsd-build/get-shit-done`; Anthropic `https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents`).
4. **First-class sibling + explicit write-owner.** `.local/human/` sits beside `.agent/`/`memory/`/`research/`;
   each artifact is tagged write-owner = human (INPUT) or agent-draft→human-approve (OUTPUT) (Kiro
   dual-output `https://github.com/aws-samples/sample-kiro-cli-prompts-for-product-teams`).
5. **Evidence before claims.** Every "requirement met" row ties to fresh evidence (REQ-ID →
   test/commit/file:line); findings split blocking-vs-advisory so a report cannot over-claim
   (superpowers `https://github.com/obra/superpowers`).

## 2. Directory Layout

`.local/human/` is a new first-class sibling of the existing `.local/` shards. It holds
exactly two zones (INPUT, OUTPUT) plus a dated archive — a small fixed file set (gsd
"named-file set" takeaway), not a sprawling tree.

```
.local/human/
├── README.md                          # role + write-owner conventions (human-INPUT vs agent-draft-OUTPUT)
├── input/                             # WRITE-OWNER: human. Immutable post-approval (§3).
│   ├── constitution.md                # amendable principles/constraints; Version|Ratified|Last-Amended + Governance
│   ├── requirements.md                # REQ-<DOMAIN>-NN entries + Traceability matrix + Out-of-Scope (gsd); shards to requirements/<domain>.md on overflow (§3b)
│   └── amendments/                    # append-only amendment ledger (S-9 discipline) — the 引导回测 lineage
│       └── <YYYY-MM-DD>-<slug>.md      # one amendment per file; NEVER edited/deleted
├── output/                            # WRITE-OWNER: agent drafts → human approves (§4). Anti-flooding.
│   ├── DIGEST.md                      # ≤100-line read-first STATE digest (gsd STATE pattern)
│   └── convergence/                   # per-cycle convergence reports
│       └── <version>-convergence.md    # conclusion-first, ≤500 words, status enum, per-REQ evidence rows
└── archive/                           # dated frozen snapshots of superseded INPUT + closed OUTPUT (A-4/OpenSpec WHY)
    └── <YYYY-MM-DD>-<slug>/            # frozen prior version of a requirement / closed cycle report
```

**Separation boundary (who owns what; how `.local/human/` differs from its siblings):**

| Tree | Write-owner | Lifecycle | Tracked? | Role |
|---|---|---|---|---|
| `.local/human/input/` | **human** | durable, forward, immutable post-approval | **tracked (D-4)** | authoritative requirements/constraints |
| `.local/human/output/` | agent-draft → human-approve | per-cycle, bounded | **private (ignored)** | convergence digest + reports |
| `.local/human/archive/` | frozen snapshot | dated, on supersede | **private (ignored)** | superseded INPUT + closed OUTPUT (A-4 WHY) |
| `.local/.agent/` | agent | in-flight change folders + handoff | private (ignored) | machine substrate (S-8/S-9) |
| `.local/memory/` | agent (auto-memory) + A-4 specs | accumulated; specs at archive-time | only `specs/` tracked | learnings + source-of-truth behaviour |
| `.local/research/` | human/agent (cycle authors) | per-cycle research | tracked | gap analyses, designs, retros |
| `.local/feedbacks/` | human (reactive) | per-version, post-hoc | private (legacy) | reactive feedback + TRACKER (see §5) |

Distinctions: vs `.local/feedbacks/` (reactive/post-hoc), `.local/human/input/` is
**forward/durable** ("what every future version MUST honour"); vs `.local/memory/specs/`
(agent BEHAVIOUR, per W-23.4) it is **human INTENT**. They never overlap.

## 3. INPUT Design — Immutable + Regression Value (closes D-1)

The INPUT zone realizes "immutable for regression value WITHOUT literal write-locking" via two
schemas + an append-only amendment ledger.

### 3a. `constitution.md` — amendable principles (spec-kit pattern)

Durable principles/constraints that supersede ad-hoc practice; carries a version-stamp footer
+ a Governance amendment protocol. **Version stamps are PER-FILE (F-6):** `constitution.md` and
`requirements.md` each carry their OWN `Version` stamp and version independently — an amendment
bumps the stamp of the file whose ratified block changed (a principle → `constitution.md`'s
stamp; a REQ → `requirements.md`'s stamp). There is no single shared human-input version.

```markdown
---
artifact: human-constitution
version: <CONSTITUTION_VERSION>      # bumped on every ratified amendment (semver)
---
# DevolaFlow Constitution

## Principle <N>: <Title>
<RFC-2119 statement: the project MUST / MUST NOT / SHOULD ...>
Rationale: <1-2 lines>

## Governance
- This constitution supersedes ad-hoc practice when they conflict.
- Amendments require: (1) documented rationale, (2) human approval, (3) a migration note.
- Amendments are recorded by APPENDING a dated file under `input/amendments/`; the prior
  text is preserved verbatim (S-9 discipline) — never edited in place.

**Version**: <X.Y.Z> | **Ratified**: <YYYY-MM-DD> | **Last Amended**: <YYYY-MM-DD>
```

### 3b. `requirements.md` — stable REQ-IDs + traceability (gsd pattern)

```markdown
# Requirements (`artifact: human-requirements`)

## Requirements
### REQ-<DOMAIN>-NN: <title>            # DOMAIN = uppercase tag; NN = zero-padded
- **Constraint:** <RFC-2119 statement>
- **Acceptance:** <checkable criterion — a test/metric/observable, not prose>
- **Lifecycle:** DRAFT | RATIFIED <YYYY-MM-DD>   # append-only trigger — DISTINCT from Status
- **Status:** Pending | Satisfied | Blocked       # satisfaction progress — orthogonal to Lifecycle
- **Amendments:** <none> | `input/amendments/<YYYY-MM-DD>-<slug>.md`

## Traceability
| REQ-ID | Acceptance criterion | Cycle | Status |
|---|---|---|---|
| REQ-<DOMAIN>-NN | <criterion> | <version> | <status> |
| **Unmapped** | — | — | **0** ✓ |        # gsd scope-reduction detection: never silently drop scope

## Out of Scope
| Item | Reason |
|---|---|
| <explicitly excluded item> | <why> |

**Version**: <X.Y.Z> | **Last Amended**: <YYYY-MM-DD>   # requirements.md's OWN per-file stamp (F-6)
```

**Rotation & overflow (F-3 — durable accumulation vs the C-9 cap).** `requirements.md` holds
only the ACTIVE durable REQ set; two policies stop D-1's monotonic growth from colliding with
the §4c hard ceiling (D-2):

1. **Supersede → archive.** When an amendment replaces a REQ, the prior REQ block moves to
   `archive/<YYYY-MM-DD>-<slug>/` (frozen, with its amendment trail). Only LIVE REQs count
   against the budget — archiving superseded-only is necessary but, as F-3 notes, not
   sufficient alone (active durable REQs still accumulate).
2. **Shard on overflow.** When the live set would still exceed the 2500-tok hard ceiling, split
   by domain into `input/requirements/<DOMAIN>.md` (one file per `REQ-<DOMAIN>-*` family). The
   C-9 budget then applies **PER FILE** (§4c), and `requirements.md` degrades to a thin index
   (Governance pointer + the global Traceability matrix + per-domain links). The aggregate cap
   therefore never silently truncates scope — gsd scope-reduction detection (`Unmapped: 0 ✓`)
   is preserved across shards.

### 3c. Immutability mechanism (pre-approval mutable → post-approval immutable)

| Phase | Rule | Enforcement (WOULD work as) — keyed on the `Lifecycle` field, NOT `Status` |
|---|---|---|
| **Pre-approval** | A requirement/principle is freely editable while its lifecycle is `DRAFT` | per-REQ `Lifecycle: DRAFT` (constitution: no `Ratified:` stamp yet) — the `Status` enum plays no part |
| **Approval gate** | Human ratifies → text becomes a binding contract (superpowers HARD-GATE) | per-REQ `Lifecycle: DRAFT → RATIFIED <date>` (constitution: `Ratified` stamp set); THIS transition — independent of `Status` — is the sole append-only trigger |
| **Post-approval** | A `RATIFIED` block is IMMUTABLE; changes APPEND a new dated `input/amendments/<date>-<slug>.md` and bump that file's version stamp — the prior text stays verbatim | S-9 append discipline (reused, not a new rule) |

**Proposed (NOT built) enforcement — described only:** (1) a `pre_commit`/lint hook
`check_human_input_append_only` — its immutability predicate reads the per-REQ `Lifecycle`
field (a `### REQ-*` block is frozen **iff** `Lifecycle: RATIFIED *`) and the constitution's
`Ratified:` stamp; an in-place edit to such a block (vs adding an amendment + version bump)
warns in `lite`, blocks in `full`/STRICT, mirroring `lifecycle/check_envelope_append_only`
(S-9) + `check_file_ownership` (S-8). A `Lifecycle: DRAFT` block is exempt, so the hook never
inspects `Status` — this is what resolves the F-1 trigger ambiguity. (2) a CI test
`tests/test_human_input_immutability.py` (git-diff lint, analogous to
`tests/test_handoff_envelope_immutable.py`). Both land in the implementation cycle.

### 3d. Regression / 引导回测 lineage (A-4 truth + delta + dated archive)

Each requirement carries a checkable lineage so coverage is provable and drift is auditable:

```
REQ-<DOMAIN>-NN  →  acceptance criterion (checkable)  →  Traceability row (cycle, status)
                 →  input/amendments/<date>-<slug>.md  (every post-approval change, append-only, WHY)
                 →  archive/<date>-<slug>/             (frozen prior version when superseded)
```

This mirrors OpenSpec's "archive preserves not just *what* changed but *why* + the original
acceptance criteria" and DevolaFlow's A-4 ("the archive log answers 'what did we add to spec
X across all of vN'"). The amendment ledger is the regression anchor: a future cycle can
diff "what REQ-INPUT-01 required at ratification vs now" to verify no requirement silently
regressed.

## 4. OUTPUT Design — Concise, Anti-Flooding (closes D-2)

Two artifacts: a per-cycle convergence report and a read-first digest. Both are
conclusion-first and budget-capped.

### 4a. `output/convergence/<version>-convergence.md` — convergence report

```markdown
# Convergence Report — <version>
> **Status:** passed | gaps_found | human_needed      <- line-1 conclusion (status enum)
> Date: <YYYY-MM-DD> | Cycle: <version> | Author-layer: L0

## Verdict
<1-3 sentences, conclusion-first: did we converge, against which requirements?>

## Requirement evidence            # superpowers evidence-before-claims
| REQ-ID | Acceptance criterion | Result | Evidence (verbatim per C-3) |
|---|---|---|---|
| REQ-<DOMAIN>-NN | <criterion> | met / partial / unmet | `tests/test_x.py::test_y` PASS @ <commit> |

## Blocking findings               # MUST resolve before human approval
- <finding> → <required action>

## Advisory findings               # do NOT block approval
- <finding> (advisory)

## Next step
<owner + single action>           # agency-agents: owner + next-step, decide in <3 min
```

**Status enum:** `passed` (all REQ met, no blockers) · `gaps_found` (≥1 REQ unmet/partial,
advisory-resolvable) · `human_needed` (≥1 blocking finding or stagnation → human decision,
maps to P4 escalation + superpowers BLOCKED).

### 4b. `output/DIGEST.md` — read-first STATE digest (gsd ≤100-line pattern)

```markdown
# DevolaFlow Human Digest
> Updated: <YYYY-MM-DD> | Latest cycle: <version> | Status: passed|gaps_found|human_needed

## Where we are            (≤5 lines)
## Open asks for the human (≤5 items; BLOCKING only — advisory lives in the report)
## Requirement coverage    (THIS-cycle REQ deltas only, ≤1 line each) + rollup: <N total · M satisfied · K blocked>
## Latest convergence → output/convergence/<version>-convergence.md
```

The digest is the "read-once, know where we are" surface — a DIGEST, not an archive
(gsd STATE rule). Refreshed (overwritten) each cycle; superseded reports rotate to
`archive/`. **Coverage rollup (F-3):** the coverage section lists only REQs added/changed THIS
cycle (≤1 line each) plus ONE rollup line (`N total · M satisfied · K blocked`); it never
re-lists every durable REQ verbatim, so the DIGEST budget stays flat as the REQ set grows. The
full REQ→status matrix lives in `input/requirements.md` (or its per-domain shards, §3b).

### 4c. Explicit budgets — NEW C-9 rows (anti-flooding)

Proposed additions to the Rule C-9 table (`workflow-system/agent/references/agent-workspace.md`
§9 + `.cursor/rules/repo-governance.mdc` C-9), authored by the implementation cycle:

| File | Soft budget | Hard ceiling | Rationale |
|---|---|---|---|
| `.local/human/input/constitution.md` | 800 tokens | 1500 | Durable principles; opinionated, terse |
| `.local/human/input/requirements.md` | 1200 tokens | 2500 | REQ list + matrix + out-of-scope; degrades to a thin index once sharded (§3b) |
| `.local/human/input/requirements/<domain>.md` (shard, F-3) | 1200 tokens | 2500 | **PER-FILE** cap, applied when the aggregate would exceed 2500; one `REQ-<DOMAIN>-*` family per file |
| `input/amendments/<date>-<slug>.md` | 400 tokens | 800 | One delta + WHY per file (mirrors `acceptance.md`) |
| `.local/human/output/DIGEST.md` | 600 tokens (~100 lines) | 1000 tokens (~120 lines) | Read-first skim surface |
| `.local/human/output/convergence/<version>-convergence.md` | 700 tokens (~500 words) | 1000 tokens | Decide-in-3-min conclusion-first |

**TOKENS are the sole enforced unit (F-4):** every budget above is linted in TOKENS, matching
the existing token-only `agent_workspace.lint` (`estimate_tokens`, `BudgetReport.actual_tokens`)
— the parenthetical line/word figures are authoring guidance only, NOT a second linted axis, so
no new measurement machinery is added. **C-9 surface asymmetry (F-10b):** the two C-9 surfaces
already diverge — `.cursor/rules/repo-governance.mdc` C-9 lists only the agent-workspace
artifacts, whereas `workflow-system/agent/references/agent-workspace.md` §9 additionally carries
`REPORT.md`/`learnings` rows; adding the human rows to BOTH makes `repo-governance.mdc` carry its
first OUTPUT/report-like rows, so the implementation cycle must reconcile the asymmetry, not
merely append. Verified (in the future cycle) by extending `python -m devolaflow.agent_workspace.lint`.
Soft over → warn; hard over → fail commit (full/STRICT) — identical semantics to existing C-9 rows.

### 4d. Relationship to `reporter.py` and CHANGELOG/retrospective

- Rendered by a NEW, FIFTH `reporter.py` flavour `render_human_report`, reusing the Jinja2 +
  pinned-clock idempotency (AC-5) + opt-in semantics (no auto-trigger); `regenerate_all` gains
  a `"human"` key. The existing four flavours (per-change/workspace/memory/rules) stay
  byte-identical (R5).
- **No duplication of CHANGELOG / retrospective:** the report *cites* them by path (`CHANGELOG.md`
  `## [<version>]`, `.local/research/<version>_retrospective.md`), never restates — it answers
  "did we satisfy the human's REQ-IDs", which neither records.

## 5. Separation & De-Pollution (closes D-3 + D-4)

### 5a. Clean human↔agent boundary

`.local/human/` is the durable, versioned, human-authored tier (harness layering — Schmid
`https://www.philschmid.de/agent-harness-2026`); the agent tiers (`.agent/`, `memory/`) keep
ephemeral/accumulated state. The boundary is enforced by write-owner tags (§2) and extends
W-23.4: human INTENT in `.local/human/input/` vs agent BEHAVIOUR in `.local/memory/specs/`.

### 5b. Relocate agent-authored `sichip_deferred_*.md` OUT of `.local/feedbacks/` (D-3)

Today `src/devolaflow/lifecycle/post_skill_edit.py` writes `sichip_deferred_<timestamp>.md`
(+ the `.sichip_deferred_fingerprints.txt` sidecar) into `.local/feedbacks/`
(`FEEDBACK_DIR_DEFAULT = Path(".local") / "feedbacks"`) — AGENT authorship inside a HUMAN dir,
the exact pollution D-3 names. **Proposed (spec only; ADR-8):** relocate the default to the
(private) agent tree, `FEEDBACK_DIR_DEFAULT → Path(".local") / ".agent" / "sichip-deferred"`
(these are agent OUTPUT, NOT human-authored — so NOT `.local/human/`).

**One-time migration (F-5) — the dedup set MUST survive the move.** A bare path swap resets the
`.sichip_deferred_fingerprints.txt` dedup set (so a previously-deferred finding could re-emit a
duplicate DEFER doc) and orphans existing docs in `feedbacks/`. The implementation cycle therefore
performs a one-time move of BOTH (a) every existing `sichip_deferred_*.md` and (b) the
`.sichip_deferred_fingerprints.txt` sidecar from `.local/feedbacks/` → `.local/.agent/sichip-deferred/`,
preserving the fingerprint set verbatim; as a transition safety-net the hook dual-reads the legacy
path for dedup until the next cycle confirms the move. `tests/test_sichip_dedup_feedback_doc.py` +
`tests/test_post_skill_edit_hook.py` assert the new location AND that a pre-existing fingerprint
still suppresses a duplicate post-relocation.

### 5c. Resolve the `TRACKER.md` aspirational-vs-real gap (D-3)

`.local/feedbacks/TRACKER.md` claims "Auto-maintained" but `local/workspace.py::generate_tracker`
is only create-if-missing — nothing updates Open/Resolved/Deferred rows (stale since 2026-04-23).
**Decision (ADR-7):** the durable coverage SSOT becomes `requirements.md`'s Traceability matrix
(`Unmapped: 0 ✓`); `feedbacks/TRACKER.md` is retained only as the reactive feedback-resolution
ledger with its banner corrected "Auto-" → "Human-maintained" (removing the false claim). A real
`update_tracker()` is an OPTIONAL later enhancement, not a precondition.

### 5d. Git-tracking the human zone — `.gitignore` whitelist delta (closes D-4)

`.local/` is private-by-default under the v12.2.0 selective whitelist (`local/workspace.py::
_LOCAL_WHITELIST_BLOCK_LINES`, pinned by `tests/test_gitignore_policy.py`), which tracks only
`.local/memory/specs/**` + `.local/research/**`. The human INPUT zone must be authoritative ⇒
tracked, durable, PR-reviewable (D-4).

**Proposed delta (specified, NOT applied) — add to `_LOCAL_WHITELIST_BLOCK_LINES`:**

```gitignore
!.local/human/
!.local/human/input/
!.local/human/input/**
```

so ONLY the `.local/human/input/` zone (the authoritative zone) is git-tracked alongside
`memory/specs/` and `research/`. Per the operator decision (D2 override, 2026-06-03), `output/`
+ `archive/` stay PRIVATE (ignored) — the bounded (C-9-capped) convergence reports + digest are
local-only, not PR-visible. D-4 is closed via the tracked `input/` zone (the authoritative,
reviewable, durable requirements/constraints).

**Implementation-cycle obligations (noted, not done here):** `tests/test_gitignore_policy.py`
adds the human INPUT paths to `LOCAL_WHITELISTED_PATHS` and asserts an OUTPUT path stays IGNORED
(the private control); the detection key `_LOCAL_WHITELIST_REQUIRED_RULES` / `V12_2_0_WHITELIST_REQUIRED_RULES`
gains `!.local/human/` (so the repair path graduates older whitelists); `local/workspace.py::REQUIRED_DIRS`
gains `human`, `human/input`, `human/input/amendments`, `human/output`, `human/output/convergence`,
`human/archive`, each with a write-owner-tagged `_DIR_README_CONTENT` entry — explicitly including
the `human/` ROOT README (role + write-owner conventions per §2) and the `human/output/` README,
which the §2 layout shows but the earlier dir list omitted (F-9).

## 6. Integration Contract (SPEC ONLY — no code)

All three sub-contracts are described as signatures/behaviour; NO Python is written here.

### 6a. `scan_workspace` gains a `.local/human/` surface

`devolaflow.workspace_context.scan_workspace(repo_root)` (the pure, S-5-safe discovery
function L0 calls at session start) WOULD gain new `WorkspaceContext` fields, APPENDED after
the current fields (additive; existing `to_summary_dict` keys unchanged; new keys appended):

| New field | Type | Semantics | S-5 default |
|---|---|---|---|
| `has_human_dir` | bool | `.local/human/` exists as a directory | `False` |
| `human_constitution` | `Path \| None` | path to `input/constitution.md` when present | `None` |
| `human_requirements` | `Path \| None` | path to `input/requirements.md` when present | `None` |
| `human_digest` | `Path \| None` | path to `output/DIGEST.md` when present | `None` |

New private `_scan_human_input`/`_scan_human_output` helpers mirror the existing `_scan_*` (S-5:
PermissionError/OSError → WARNING + absent, never raise). A new `references/agent-workspace.md`
§1 "When to Engage" row: `has_human_dir=True` → READ `human_requirements` + `human_constitution`
as authoritative ground truth.

### 6b. Plan-mode ingestion consumes human INPUT as AUTHORITATIVE context

Per `references/plan-mode-enforcement.md` §5.5 (Feedback Ingestion), L0 already reads
`recent_feedbacks` as *advisory themes*. The human INPUT is STRONGER — it is *binding*:

- At plan-mode entry L0 reads `human_constitution` + `human_requirements` with the standard
  `Read` tool (no new permission — exactly like the §5.5 feedback read).
- Constitution principles are binding constraints; the REQ-ID set is the scope contract the
  plan MUST cover (gsd scope-reduction detection — dropping a REQ is a flagged gap).
- **Primary path needs NO dispatch field** (file reads only). OPTIONAL dispatch surfacing rides
  an existing `change_context` NEST sub-field (`human_input_refs`) per A-2.3 — no top-level key,
  canonical-order length unchanged, `tests/test_layout_invariant_multi_baseline.py` stays GREEN (A-2 untouched).

### 6c. L0 workflow-close emits the convergence digest

At workflow/cycle close, L0 (opt-in, no auto-trigger — same contract as the existing reporter)
invokes the new `render_human_report` flavour to (1) write `output/convergence/<version>-
convergence.md` and (2) refresh `output/DIGEST.md`. Idempotent under a pinned clock (AC-5). It
does NOT mutate INPUT (write-owner = human).

**Two DISTINCT producers feed the render (F-2).** The SI-3 composite gate emits a 6-dimension
score + `findings_by_severity` — it does NOT key evidence by REQ-ID, so the per-REQ rows cannot
come from it. The render therefore consumes two separate inputs:

1. **Per-REQ `Result`/`Evidence` rows ← a dedicated traceability checker, NOT the gate.** A new
   pure helper `requirements_trace.py` (proposed: `src/devolaflow/agent_workspace/requirements_trace.py`)
   maps each `REQ-<DOMAIN>-NN` to its acceptance evidence by joining `requirements.md`'s
   Traceability matrix (REQ-ID → acceptance criterion, ADR-4) with test-run artifacts (the pytest
   node-id + PASS/FAIL + commit hash, or a `file:line`), yielding
   `{REQ-ID → (result ∈ met|partial|unmet, evidence: str)}`. Evidence strings are verbatim per
   C-3. S-5-safe: a REQ with no matching artifact → `unmet` + an explicit "no evidence" note,
   never a silent drop.
2. **`Blocking`/`Advisory` finding sections ← the composite gate's `findings_by_severity`**
   (blockers/criticals → Blocking; minor/info → Advisory).

The line-1 `Status` enum is then DERIVED: `passed` (all REQ `met` ∧ no blockers) · `gaps_found`
(≥1 REQ `partial`/`unmet`, no blockers) · `human_needed` (≥1 blocker). This is the OUTPUT-side
counterpart to the INPUT-side plan-mode ingestion in §6b.

## 7. ADRs (irreversible choices)

**ADR-1 — `.local/human/` as a first-class sibling.**
*Context:* feedback wants "放在 .local/ 下，和 agent 分开". *Decision:* new top-level `.local/human/`
beside `.agent/`/`memory/`/`research/`. *Alternatives:* nest under `feedbacks/` (rejected —
reactive, not forward); reuse `memory/` (rejected — agent behaviour per W-23.4). *Consequences:*
new tree to scaffold + scan; clean boundary; no conflict with existing trees.

**ADR-2 — Track the `.local/human/input/` zone ONLY under git (operator-ratified 2026-06-03; override of the original design recommendation).**
*Context:* D-4 needs an authoritative, reviewable, durable zone. *Decision:* whitelist
`!.local/human/input/**` (INPUT only); OUTPUT + archive remain private (ignored). *Alternatives:*
track the whole tree `!.local/human/**` (INPUT + OUTPUT + archive) (rejected by operator — keeps
bounded reports local-only instead of PR-visible); all-private (rejected — defeats D-4).
*Consequences:* bounded (C-9-capped) OUTPUT reports are local-only (NOT PR-visible); D-4 is still
closed because the AUTHORITATIVE zone (`input/`) is tracked; `.gitignore` + `test_gitignore_policy.py`
delta stays small.

**ADR-3 — Immutability = amendment protocol + append, NOT a write-lock.**
*Context:* "人类输入要不能修改" with 引导回测 value. *Decision:* pre-approval mutable; post-approval
immutable via S-9 append (dated `input/amendments/`) + version stamp; never `chmod -w`.
*Alternatives:* read-only files (rejected — brittle, no WHY trail); freeze whole spec (rejected
— BCMS warns specs evolve). *Consequences:* reuses S-9 (no new Soul rule); amendments ARE the ledger.

**ADR-4 — Regression model = stable REQ-IDs + dated archive (A-4/OpenSpec).**
*Context:* coverage must be provable + drift auditable. *Decision:* `REQ-<DOMAIN>-NN` +
Traceability matrix (`Unmapped: 0 ✓`) + amendment ledger + dated archive. *Alternatives:*
prose requirements (rejected — not traceable); TRACKER status (rejected — status ≠ matrix).
*Consequences:* every requirement checkable; scope-reduction detectable; supersedes TRACKER coverage (ADR-7).

**ADR-5 — OUTPUT = conclusion-first + status enum + explicit C-9 budgets.**
*Context:* "避免输出淹没". *Decision:* ≤500-word report (enum `passed|gaps_found|human_needed`,
per-REQ evidence rows, blocking/advisory split) + ≤100-line DIGEST; NEW C-9 rows. *Alternatives:*
reuse agent `REPORT.md` flavours (rejected — none human-first/skim-capped); no budget (rejected —
that IS the flooding bug). *Consequences:* a 5th `reporter.py` flavour; `lint` extension; cites (not restates) CHANGELOG/retro.

**ADR-6 — `scan_workspace` surface extension (additive fields).**
*Context:* L0 must discover the human surface at session start. *Decision:* append
`has_human_dir`/`human_constitution`/`human_requirements`/`human_digest`. *Alternatives:* a
separate scanner (rejected — duplicates the contract); overload `recent_feedbacks` (rejected —
conflates advisory vs binding). *Consequences:* additive only (existing keys byte-stable); new "When to Engage" row.

**ADR-7 — TRACKER fate: supersede coverage; correct the reactive-role banner.**
*Context:* TRACKER claims "Auto-maintained" but nothing updates it. *Decision:* `requirements.md`
Traceability matrix is the coverage SSOT; `feedbacks/TRACKER.md` stays the reactive resolution
ledger with banner corrected to "Human-maintained". *Alternatives:* delete (rejected — loses
history); full auto-updater now (rejected — out of scope; optional later). *Consequences:* no parallel coverage trackers; false "auto" claim removed.

**ADR-8 — Relocate agent-authored `sichip_deferred_*` out of `.local/feedbacks/` (default-path fork).**
*Context:* `post_skill_edit.py` writes agent-authored DEFER docs into the human-facing
`.local/feedbacks/` dir (the D-3 pollution); `FEEDBACK_DIR_DEFAULT` is a backward-compat default
path, so changing it is an irreversible-default fork like the other seven. *Decision:* move the
default → `.local/.agent/sichip-deferred/` (private agent tree) WITH a one-time migration of
existing docs + the dedup sidecar and a transition-window dual-read (§5b). *Alternatives:* leave
in `feedbacks/` (rejected — that IS the D-3 pollution); move under `.local/human/` (rejected —
agent authorship, not human INPUT). *Consequences:* a backward-compat default-path change earns
its own ADR for traceability — this elevates checklist **decision-8** (previously tracked only in
§5b) to first-class ADR status, mirroring ADR-1..7; dedup continuity preserved; `test_post_skill_edit_hook.py`
+ `test_sichip_dedup_feedback_doc.py` re-pin the path. (The checklist file itself is unchanged;
only the design-side reference is made coherent.)
