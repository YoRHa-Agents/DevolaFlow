## §1. Executive Summary

This audit enumerates every S-4 / CP-1 No-Ghost-Features violation discovered in the
v7.4.2 working tree. The v7.4.0 `repo-init` workflow ghost is **explicitly out of scope**
(closed by v7.4.2 PR #45) and is not re-flagged.

- **Total ghosts found across A-K: 41** (excluding the closed v7.4.0 `repo-init` workflow ghost).
- **Severity distribution:** 1 blocker / 4 critical / 10 major / 26 minor.
- **Root-cause clusters:** (i) Lifecycle Hooks documented but unimplemented (Cat C, blocker);
  (ii) `validate-gate` CLI command is a stub (Cat B, critical);
  (iii) `parameters.mode` runtime wiring missing — declared on `repo-init.yaml` but never
  honored by the composer (Cat G, critical, the v7.4.2 internal follow-up);
  (iv) 4 schemas referenced in `workflow-skill.yaml` but never authored (Cat E, critical);
  (v) 3 Tier-3 template artifacts referenced in `SKILL.md` but absent on disk (Cat H, major);
  (vi) `workflow-skill.yaml.manifest` lists only 17/20 templates (Cat I, major);
  (vii) ~10 stale numeric / version references in `README.md` and `CLAUDE.md` (Cat K, minor).
- **Recommended patch count for v7.5.0 cycle:** **8 patches (P-01 .. P-08)** — see §5.
- **SI-10 risk profile:** medium overall — only P-01 (anti-ghost test infra), P-04
  (composer mode wiring) and P-05 (lifecycle hooks) carry meaningful regression risk;
  the rest are documentation/manifest fixes well below the SI-4 5pp drift threshold.

### §3.G Composer / runtime wiring (the v7.4.2 internal flag)

   `workflow-system/agent/templates/builtin/repo-init.yaml:87-95`.
2. `parser.py:73` (`parameters=raw.get("parameters", {}) or {},`) reads it into
   `WorkflowTemplate.parameters` (`models.py:229`).
3. **NO consumer reads it.** `composer.py` (159 lines) is purely a composition-tree
   walker (sequence/parallel/choice/loop/gate operators) and never references
   `parameters` or `template.parameters`. `Grep "parameters" src/devolaflow/template_engine/composer.py` → 0 matches.
4. The composition block at `repo-init.yaml:67-73` unconditionally lists all four stages
   (`analyze, scaffold, compile, verify`), with NO guard expression to elide `verify`
   when `mode != deep`.
5. `StageDefinition.skip_condition` field exists at `models.py:88` but is never set by
   any builtin template AND never consumed by composer / validator / runtime code:
   `Grep "skip_condition" src/devolaflow/` → only the model definition + 2 references
   in `validator.py` (`check_reachability` and `check_no_orphan_stages` use it to
   exempt skip-conditional stages from the "unreachable" / "orphan" warnings, NOT to
   actually skip them at runtime).

## §6. Anti-Ghost Test Infrastructure (P-01 design)

The meta-test that would have caught v7.4.2's `repo-init` ghost AND will catch all
ghosts found in §3 lives at the proposed path
`tests/test_no_ghost_features.py`.

### Design principles
1. **Build declared-set from agent-facing sources.** Each test parses one or more
   sources (SKILL.md tables, workflow-skill.yaml manifest, CHANGELOG.md "Added" sections,
   README.md tables) and reduces them to a Python set of identifiers (template names,
   schema paths, hook names, etc.).
2. **Build implemented-set from code/files.** Each test enumerates what actually exists
   on disk (`pathlib.Path.glob`) or in code (`importlib + dir()`).
3. **Assert symmetric difference is empty.** Both directions: declared-but-missing AND
   implemented-but-undeclared (the "inverse ghost" of §3.E G-E5/G-E6, §3.H G-H4/G-H5).
4. **Mark currently-failing assertions with `pytest.xfail(strict=True, reason=...)`** so
   the test file lands GREEN with P-01 and flips to XPASS as each subsequent patch
   closes its referenced ghost. Maintainers remove the xfail marker as part of the
   patch that closes the ghost.
