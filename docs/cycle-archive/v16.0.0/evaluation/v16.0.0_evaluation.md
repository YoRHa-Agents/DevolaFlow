## 2. S-1 不变量射程证明

正向修订本身的射程不变，证明如下：

1. **角色集不变性**：现行 dispatcher 集为 `{Project, Stage, Wave}`，implementer 集为 `{Task}`；目标 dispatcher 集为 `{Project, Wave}`，implementer 仍为 `{Task}`。`layers.py` 将当前角色固定为 `L0=Project, L1=Wave, L2=Task`，且可发射的 `hdr.layer` 仅为 `project|wave`。Stage 是删除，不是转为实施层。
2. **权限不变性**：§3.1 与 §3.2 的允许操作均为 `Read, Glob, Grep, SemanticSearch`；禁止实施操作均为 `Write, StrReplace, Shell (for code/test/build), EditNotebook`。变化仅是 dispatcher 数字范围由 L0–L2 改为 L0–L1。
3. **职责不变性**：设计 v4 §8.2 明确 L0“不得实施”、Wave“不得做任何任务的工作/修改产出”、L2 Task 为“唯一实施层”；§8.5 仅把分解、gate、reinforcement、升级路由重新分配给 Project/Wave。
4. **例外不变性**：`Trivial exception: single file, < 20 lines.` 逐字不变，权限或例外均未扩大。
5. **级联一致性**：`cascade.py` 的新默认值为 3，对应 `L0 Project → L1 Wave → L2 Task`；legacy 声明 4 只作兼容输入并按有效最小值 3 校验，不增加实施者。
6. **Soul 数量不变**：`.rules/soul.mdc` 仍为 S-1…S-10 共 **10** 条；提案只改 S-1/S-8 既有正文，不新增 S-11。

因此，**正向 S-1 文案不是放宽禁令**。拒绝原因不在正向射程，而在回滚契约。

## 3. 阻断项：§3.4 回滚不成立

§3.4 提议在拒绝 S-1 新措辞时保留 v15 原文，并仅在 A-1 说明 Stage 是“保守历史超集”。该回滚与目标编号不能同时成立：

1. 目标运行时明确 `L2=Task`（`layers.py::CURRENT_LAYER_ROLES`）。
2. 被保留的 v15 S-1 明确规定 `L0-L2 MUST NOT use Write, StrReplace, Shell ... or EditNotebook to implement`。
3. 两者合并后，唯一实施者 L2 Task 被 P0 Soul 禁止使用实施工具，与同一条中的 `Only Task Agents execute actual work` 直接冲突。
4. A-1 属 P1，不能用说明覆盖 P0 Soul；故这不是“更强但安全”的历史超集，而是令实施角色不可实施。

可接受的回滚必须二选一：

* 原子回退整个层级迁移，使 Task 恢复为 L3、cascade 恢复四层语义；或
* 在迁移前预先批准一份不依赖数字范围、仍精确约束 dispatcher 的替代 S-1 回滚文本。

仅保留 v15 S-1、同时继续采用新 L0/L1/L2 编号，不可接受。

## 4. 风险与裁决

* **P0/P1 分裂风险**：当前 `soul.mdc`/`architecture.mdc` 仍为四层文字，而 `layers.py`/`cascade.py` 已体现三层目标；在规则编译前，L2 Task 的实施权限存在字面冲突。
* **回滚失效风险**：按现有 §3.4 执行会使系统没有合法实施层，属于 release blocker。
* **兼容窗口风险**：双轨解析本身合理，但必须保持有界并在下一 major 明确退出，避免 token 语义永久双义。
* **证据风险**：测试结构已存在，但本评审没有动态执行结果；M4/M5 门禁仍须提供实际通过证据。

**S-1 verdict：REJECTED。**

**M4：不得按当前 §3.4 继续规则编辑。** 先修订回滚为与新编号一致的原子方案，再重新进行 S-1 专项 SI-3；只有架构合理性达到 **≥9.5/10** 且回滚复核通过后，方可编辑 `.rules/soul.mdc` 并编译派生规则面。
