# v24.3.0 Retrospective — Durability Queue Clearance

## 1. Gaps identified

The v24 line had accumulated a queue rather than a backlog. Five live risks
sat in `.local/tasks/v24.1-self-digest/parking/`, one in the older dogfood
workspace, and the v24.2.0 retrospective had telegraphed three more items
without a home. Eight open questions, none of them owned by a cycle.

`RISK-001` set the version. `apply_plan` moved a file and then appended its
mapping row, so a failure between the two left the file at its destination
with nothing recording it. `locate`, `restore`, and `verify` would all lose
it. It had survived three releases as the highest-severity item in the
repository.

## 2. Implemented

Two PVs, both inside the W-17 per-PV cap.

**PV-01 — the five live risks.** The ledger became a journal: the mapping row
is written before the move, which makes an interrupted apply a *pending move*
rather than a loss, and the next apply completes it. `verify_integrity`
reports `PENDING_MOVE` instead of a missing archive. Telemetry gained
`digest_tokens`, a derived `net_tokens`, and a pessimistic working-set pair,
so `summarize()` can say whether a run paid for itself. Both CLIs now answer a
malformed invocation with the single JSON object they always advertised,
carrying `error_kind`, with every exit code unchanged. The digest table traded
twelve characters of sha256 for a Category column. `references/risk-parking.md`
now states what was already true: the event ledger is authoritative for an
archived risk, and the relocated original is never rewritten because the
approval chain is bound to its content hash.

**PV-02 — the three telegraphed items.** A repo-wide AST scan reports enum
members and `Final[str]` constants with no production writer, generalising
v24.1.0's `bypassed`. `references/cycle-audit.md` institutionalises the
read-only sweep, cited from the existing W-7 body rather than as a new rule.
Retro-digest extraction learned to read prose, and its persistence became
incremental.

## 3. What we learned

**A guard against a class of defect will find another instance of it
immediately.** The enum-writer scan was built because `bypassed` had been
declared, validated, documented, tested, and written by nothing. Its first run
found `EVENT_COMPACT_APPLIED` — declared in v24.0.0, in the validating
frozenset, exported, written by nothing. The same defect, in the same cycle's
code, shipped past the audit that named the pattern. Building the check was
worth more than the fix that motivated it, and the gap between "we understand
this defect" and "we can detect this defect" is where the second instance
lives.

**A tool's first real use is its best test.** The cycle audit is a reference
this cycle wrote, and running it was the first thing the new W-7 line
required. It found `RISK-007` — the column swap PV-01 had just shipped left
four DIGEST.md files rendering a header the generator no longer emits, with
`verify` passing on all four. The finding came from the reference's own table,
question 4: for a generated artifact, if generation is skipped, does a reader
see the absence or a stale file that looks current. A sweep that found nothing
on its first run would have been the more worrying outcome.

**A strict contract written before there was a corpus will be wrong about the
corpus.** The retro-digest extracted lessons from bullets, and a v20-era test
pinned that a paragraph is not a lesson. Four cycles — v18, v21, v22, v23.1 —
write their learnings as unadorned prose. The extractor located each heading,
read it as empty, and reported OK. The contract was not defending anything; it
was describing the two retrospectives that existed when it was written. Two
tests had to be changed to fix it, which is the correct cost when the pinned
behaviour is the defect.

**Silence needs a taxonomy before it can be an error.** v24.1.0 added
`silent_sources` and reported all of it with one message. But a file with no
learnings heading may genuinely have none, and saying otherwise is its own
dishonesty; a file whose heading was found and yielded nothing promised
evidence and did not deliver. Only the second is worth a verdict, and
separating them is what let `INSUFFICIENT` mean something narrow enough to act
on.

## 4. Deferred, with reasons

`RISK-006` (major, parked) — the Rust binary runtime. Unchanged from the
v24.0.0 dogfood and owned by v25 SI-1, whose first action is install-outcome
telemetry rather than a rewrite. Deciding it needs data this repository does
not have.

`RISK-007` (minor, parked) — the digest staleness signal above. The fix is a
choice between a generation marker with drift detection, as W-28 already
requires of local-archive indexes, and regenerating the digest during verify.
That is a design decision, not a patch, and it arrived during release close.

## 6. Telegraphed for the next cycle

- **The composite has now read 9.83 four times running.** v24.1.0 called it a
  measurement gap, v24.2.0 called it the confirming instance, and this cycle
  cleared a blocker that had survived three releases without moving the
  number. The six W-3 dimensions cannot tell a durability fix from a struct
  refactor. This is the third cycle of evidence for a dimension scoring
  whether shipped surfaces are reachable and whether results are honest about
  what happened, and the argument for it no longer needs restating.
- **The w17 signal measures a cycle delta against a per-PV cap.** Its default
  `base_ref` is `HEAD~1`, which spans every PV committed since the last
  release, and it scores the result against 30. The first exit run of this
  cycle scored `test_adequacy` 6.67 for a compliant cycle. It is also blind to
  new untracked test files, which is how PV-02's 18 additions read as 11. A
  signal that needs the caller to know the right boundary before it means
  anything should either derive that boundary or report which one it used.
- **The audit sweep should be told what the cycle shipped.** This one covered
  the standing surfaces plus, by hand, what v24.3.0 touched. The reference asks
  for both, but only the standing half is mechanical. A sweep whose coverage
  depends on the auditor remembering the changelog will eventually miss the
  surface that mattered.
