## G1 — Durability and net-benefit accounting

### D-1 — `apply_plan` can move a file before its ledger row exists (BLOCKER)

`engine.apply_plan` calls `shutil.move` and only then `append_ledger_row`,
inside one `try`. If the append raises, the file sits at its destination with
no mapping row: `locate`, `restore`, and `verify` all lose it, and the result
reports `APPLY_ERROR` without rolling back. The move is fsynced, so this
survives a crash as silent divergence rather than a torn write. Every run so
far has been single-digit entries on a quiet filesystem, which is why it has
not fired.

Fix (decided): **ledger as journal**. Append the mapping row first, then move.
A row whose destination is missing while its source is still in place and still
hashes to the recorded value is a *pending move*, and a later `apply`
completes it idempotently instead of refusing with `MAPPING_DUPLICATE`.
`verify_integrity` gains a `PENDING_MOVE` finding so the state is visible
rather than inferred. Failure stops being invisible and becomes re-runnable.

Files: `src/devolaflow/workspace_compact/engine.py`,
`src/devolaflow/workspace_compact/models.py`.

### D-2 — Telemetry cannot say whether compaction paid for itself (MINOR)

`telemetry.summarize` reports `tokens_saved` as a gross sum over applied rows.
`CompactPlan` has computed `digest_tokens` and `net_tokens` since v24.1.0, but
`build_event` records neither, so no historical row can reconstruct net
benefit. The ledger also does not distinguish the agent's working set from the
resident sum, which the v24.0.0 retrospective named as the pair that must be
read together.

Fix (decided): `build_event` gains `digest_tokens`, `net_tokens`, and
`working_set_before`/`working_set_after`. The working set is a **pessimistic
estimate** — digest plus the largest single retained file — so the number
never flatters the tool. `summarize()` reports net benefit alongside gross.

Files: `src/devolaflow/workspace_compact/telemetry.py`.

## G2 — Honest reporting from the CLIs and the digest

### D-3 — Archived risk files contradict the ledger (MAJOR)

`record_archival` appends `risk_archived` to `events.yaml` and deliberately
does not rewrite the risk file, because by then the file has moved. A reader
who opens the archived file sees `state: closed` and has no reason to doubt it.

Fix (decided): **the ledger is authoritative, and this is a documentation
gap, not a code one.** Rewriting the archived original would break the content
hash the approval chain is bound to, which is a worse failure than a stale
`state:` line in a file the reader reached through a mapping row. The fix is to
say so in `references/risk-parking.md`. The archived v24.0.0 ADR is left alone
per W-7 historical retention.

Files: `workflow-system/agent/references/risk-parking.md`.

### D-4 — Argparse failures break the one-JSON-object contract (MINOR)

Both CLI module docstrings promise a single JSON object on stdout. Argparse
writes usage prose to stderr and exits 2, so a caller parsing stdout gets
nothing. Exit 2 is also what `ParkingError` uses, so a usage mistake and a
domain refusal are indistinguishable by code.

Fix (decided): both CLIs intercept argparse's error and exit paths and emit a
JSON error envelope on **stdout** carrying `error_kind` and the usage text.
**Exit codes do not change** — callers that already branch on them keep
working; the envelope is what makes the two kinds of exit-2 distinguishable.

Files: `src/devolaflow/workspace_compact/console.py`,
`src/devolaflow/parking/console.py`.

### D-5 — The digest spends a column on an unverifiable hash (MINOR)

`DIGEST.md` prints sha256 truncated to 12 characters, which verifies nothing;
the full hash is in `mappings.yaml`, where `verify` already reads it. Meanwhile
the category that explains *why* a file moved appears only in the ledger. On a
two-row digest the fixed boilerplate already costs 212 tokens against 432
relocated, so a column that does no work is not free.

Fix (decided): replace the sha256 column with Category. `digest_tokens`
reprices automatically because it is derived from the rendered rows.

Files: `src/devolaflow/workspace_compact/digest.py`.

## G3 — Turning telegraphed notes into mechanisms

### D-6 — Declared vocabulary with no production writer

v24.1.0 found `bypassed` declared in the compaction telemetry enum and written
by nothing, and fixed that one instance. The class of defect is unguarded: any
enum member can be declared, documented, and never written.

Fix (decided): a repo-wide **AST scan** for enum members with no production
writer, plus an allowlist for members that are legitimately read-only (external
inputs, reserved values). Owned by a single module per A-5, with the allowlist
kept honest per A-5.2.

### D-7 — Cycle auditing is a habit, not a step

The `GHOST_FULL=1` parity gap that v24.0.0 shipped and this cycle's landing
caught is the second time an audit found something only because someone thought
to run it. Nothing in the release sequence requires the audit.

Fix (decided): a new reference `cycle-audit.md` registered through the C-7
four-step contract, plus one line in the W-7 rule text pointing at it.
**No new numbered rule** — the Soul/Architecture/Convention/Workflow set stays
at its current count, and the obligation lands in the release checklist where
it will actually be read.

### D-8 — Retro-digest silence and unbounded backfill

v24.1.0 widened lesson extraction and added `silent_sources`, but sources the
extractor still cannot parse remain, and there is no policy for how much
history to adopt.

Fix (decided): close the remaining extraction gaps so `silent_sources` reaches
zero on this repo's own corpus — a source the extractor cannot read must be
*reported*, never absorbed into an aggregate OK — and adopt an **incremental**
persistence policy: `operational.jsonl` takes the current and previous cycle's
lessons only. Older cycles stay report-only; no historical backfill.
