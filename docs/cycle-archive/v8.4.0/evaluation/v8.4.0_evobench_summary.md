## §3. Root Cause Analysis (View A drift)

The 14 scenarios with > 5 pp negative drift all share a common signature:
they belong to feature/profile combinations whose `section_priorities` include
sections still resolved via the **deprecated line-based lookup**
(`context_profiles.yaml::sections` — superseded but not yet fully retired
per the v8.2.0 PV-05 R7 partial-coverage carry).

When SKILL.md grows by 1 line (the rollup added 1 net line via micro-
compression + 2 row additions), the line-based section anchors
(`lines: "X-Y"` ranges) become off-by-one for every section whose start-
line is at or below the insertion point. The `_resolve_section_text` helper
detects the drift via heuristic boundary matching and emits a
`DeprecationWarning` per anchor — this is the documented R7 deprecation path.

The emitted warnings (verbatim sample from `pytest tests/test_benchmarks.py -v`):

```
DeprecationWarning: section 'frontmatter' resolved via deprecated line-based
lookup (lines='1-30'); migrate to section_anchors registry per PV-05
(.local/research/v8.2.0_patch_plan.md §3 PV-05 AC #1).
```

This is the **R7 sustainability gap** carried forward from v8.0.0 retrospective
§3.3. The full migration (replacing every `lines: "X-Y"` anchor with a
symbolic `section_anchors:` entry) is **deferred** — no new gap added by
v8.4.0; this just exposes the latent gap when SKILL.md drifts.

Mitigation: the v8.3.0 PV-09 precedent regenerated baselines wholesale to
absorb the drift. v8.4.0 follows the same precedent (View B above).
