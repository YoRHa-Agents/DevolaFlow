## §4. Key Learnings (process improvements for next cycle)

### §4.1 What worked well (continue doing)

1. **D-001 split decision validated** — pre-committing to "decide split in SI-1" (gap_analysis §3) instead of forcing the answer during cycle plan worked well. Both PV-03 (cases) + PV-04 (commands) shipped with their own EvoBench scenarios proving distinct value; no PV-04 carve-out needed.

2. **Real published patches > lightweight pvNN tags** — The v8.4.0 cycle's "every PV is a real semver patch" cadence (per user A3) gave each PV a clean atomic surface (own CHANGELOG + own SI-3 + own NineS + own tag) that's easier to bisect than v8.3.0's lightweight-tag approach. Bonus: the per-PV git history (v8.3.1 → v8.3.2 → v8.3.3 → v8.3.4) is more discoverable in `git tag --list "v8.3.*"`. **Recommendation:** for v8.5.0+, default to real published patches when there are ≥ 3 PVs; lightweight tags are OK for ≤ 2 PVs in a cycle.

3. **Test cap discipline improved 4.7× → 1.06×** — v8.3.0 forecast +159 / actual +743 = 4.7× over-delivery. v8.4.0 forecast +100 / actual +106 = 1.06× over-delivery. **Drivers:** explicit per-PV test caps in gap_analysis §4 + mid-cycle test-count audits at PV-02 / PV-03 / PV-04 STATUS reports. **Recommendation:** continue the per-PV cap pattern in v8.5.0; gap_analysis §4 forecast remains honest.

4. **R5 strict triple-codification** — every feature in this cycle has the R5 contract codified at THREE layers (unit test + lifecycle integration + EvoBench scenario). When env-flag is off, all 3 layers prove byte-identical behavior to the predecessor version. **Drivers:** the v8.3.0 PV-08 71-test byte-identical precedent + the explicit "shell_proxy_disabled.yaml" + "memory_router_fastpath.yaml" pattern. **Recommendation:** make this the default for all opt-in features in v8.5.0+.

5. **Single-source-of-truth registry pattern** — the v8.3.2 `shell_proxy/registry.py::WHITELIST` + v8.3.3 `memory_router/cache.py::MemoryCase` + v8.3.4 `commands.py::CommandMapping` all follow the same pattern: one module owns the data structure, all consumers (proxy + hook + tests) delegate to it. Mirrored from RTK's own `src/discover/registry.rs` per SI-2 NineS analysis §4.1. **Recommendation:** continue this pattern; consider documenting it as a 5th canonical Architecture Rule in v8.5.0 (provisionally A-5 — "single-source-of-truth for whitelist + recipe registries").

6. **Baseline rebase precedent firmly established** — v8.3.0 PV-09 commit `12f4ea8` regenerated v7.8.0 + v8.2.0 baselines wholesale to absorb a SKILL.md edit. v8.4.0 rollup followed the same precedent (regenerated v7.8.0 + v8.3.0 wholesale). **Recommendation:** codify in CP-6 (or new W-16) — "any SKILL.md edit triggers wholesale baseline regen, not just additive entries".

### §4.2 What didn't work well (process improvements for v8.5.0+)

1. **SKILL.md headroom now at 1 line (499/500)** — the v8.4.0 rollup +1 Workflow Selection row + +1 Tier 2 references row (offset by 1-line micro-compression) used the entire 2-line buffer. v8.5.0+ MUST either:
   - (a) Promote SKILL.md to a higher tier (SF-1 Large tier 1000), OR
   - (b) Run a dedicated SKILL.md compression PV (likely the A2 carry-forward + R7 section-anchor migration)
   - (c) Defer all SKILL.md surface changes to a single "SKILL.md cycle" PV
   **Recommendation:** schedule a v8.5.0 SKILL.md compression cycle as PV-01 to restore 5-10 line headroom before any other surface changes.

2. **EvoBench rebase not anticipated in PV-02 commit** — v8.3.2 added `shell_proxy_disabled.yaml` but didn't initially account for the SKILL.md edit's cascade into `v7.8.0_baseline.json` (V6 path). Required PR #94 cleanup. **Recommendation:** v8.5.0+ PV checklists should explicitly include "regenerate v7.8.0 + previous-minor baselines" as step in version-bump cascade.

3. **CHANGELOG cleanup PRs (PR #91 + PR #94)** — 2 of the 4 PVs (PV-01 + PV-02) needed follow-up cleanup PRs to fix CHANGELOG duplicate entries / stale gate numbers. Indicates the L3 implementation agents are inserting CHANGELOG entries before they have final gate numbers. **Recommendation:** v8.5.0+ — author CHANGELOG entry as the FINAL step before commit, AFTER the SI-3 + NineS scores are computed. Document the order explicitly in the PV cycle template.

4. **`.local/research/` artifact name collisions** — v8.3.1 baseline file was created then deleted twice during PV-01 (once at v8.3.0 time, once at v8.3.1 mid-cycle). Indicates baseline regen timing is fragile. **Recommendation:** v8.5.0+ — generate baseline ONLY after `bump_version.py` succeeds; never generate at the predecessor version.

5. **Test pollution intermittently caused `test_exercise_modules` failures during full-suite runs** (3 tests failed full-suite, passed in isolation during PV-02). Root cause: `check_drift()` reading CHANGELOG before the new `[8.3.2]` entry was written. **Recommendation:** v8.5.0+ — author CHANGELOG entry BEFORE running the full SI-10 6-step gate, even if the gate numbers are placeholder. Then update placeholders post-gate run.

### §4.3 Process invariants strengthened in v8.4.0

1. **Per-PV gate template (gap analysis §5 I-1..I-10)** is now a tested, repeatable cycle pattern. Each PV consumed roughly the same wall-clock budget per closure with predictable test growth (+14, +59, +40, +36, +1 = +106 cumulative).

The 5 long-standing measurement artifacts (index_recall 0.8, source_freshness 0.5, scoring_accuracy 0.8667, scorer_agreement 0.8667, code_coverage 0.0) carry forward unchanged — bundling them into a single v8.4.x sustaining PV is the next opportunity to materially move the NineS composite.

3. **External reference handling** (S-7) — RTK reference clone at `/home/agent/reference/rtk/` was used ONLY in research artifacts (`.local/research/v8.4.0_rtk_nines_analysis.md` §4.1, §4.3, §6.2). Zero hardcoded paths in agent-facing files. Validated by `tests/test_no_ghost_features.py` family (3215+ tests, all pass).
