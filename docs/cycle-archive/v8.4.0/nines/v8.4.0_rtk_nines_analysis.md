## 4. Agent-Impact Assessment — Patterns DevolaFlow Should Adopt

NineS detected **47 agent-facing artifacts** across **9 mechanism categories**. The following 4 RTK design patterns are directly applicable to DevolaFlow's v8.4.0 cycle:

### 4.1 Hook-rewrite model (`hooks/claude/rtk-rewrite.sh` — 102 lines)

The Claude Code hook is a **thin delegator** — it does not contain rewrite rules itself; it parses `tool_input.command` from stdin (via `jq`), pipes to `rtk rewrite "$CMD"`, and emits a `hookSpecificOutput.permissionDecision` JSON block. Exit code protocol:
- 0 + stdout → rewrite found, auto-allow
- 1 → no RTK equivalent, pass through unchanged
- 2 → deny rule matched, let Claude Code's native deny handle
- 3 + stdout → ask rule matched, rewrite + prompt user

**Direct adoption for DevolaFlow PV-02 `shell_proxy/`:**
- Mirror the thin-delegator pattern: `lifecycle/pre_shell_call.py` parses dispatch, calls `devolaflow.shell_proxy.rewrite(cmd)`, returns rewrite-or-passthrough.
- Single source of truth: `src/devolaflow/shell_proxy/registry.py` (analog to RTK's `src/discover/registry.rs`) — the only file that knows the whitelist + rewrite rules.
- Version guard: RTK caches `rtk --version` once per `XDG_CACHE_HOME` to avoid spawning processes per hook call. DevolaFlow's `shell_proxy/` should do the same in `.local/memory/shell_proxy_cache.json`.

### 4.2 RTK.md @reference + CLAUDE.md fallback

`rtk init -g` installs:
1. The hook (`~/.claude/hooks/rtk-rewrite.sh`)
2. A 10-line `~/.claude/RTK.md` (just meta-commands like `rtk gain`)
3. An `@RTK.md` reference inserted into `~/.claude/CLAUDE.md`

The `@RTK.md` reference is the **opt-in surface**: 10 tokens of context vs the original 137-line CLAUDE.md inline injection. RTK explicitly documents this savings: "~99.5% reduction (2000 tokens → 10 tokens in context)".

**Adoption for DevolaFlow:** the v8.4.0 cycle is forecast to add ≤ 30 lines net to SKILL.md (currently 498/500). The RTK.md @reference pattern is exactly the right shape — if `references/memory-router.md` lands as the 11th canonical reference (per cycle plan §3 v8.4.0 contingency), it is loaded only when the dispatcher determines memory-router relevance, NOT injected into every L0 dispatch. This preserves the SKILL.md ceiling.

### 4.3 `filters.toml` schema — declarative compression rules

RTK's 60 filters under `src/filters/*.toml` follow a uniform schema:
```toml
[filters.<name>]
description = "..."
match_command = "^<regex>"
strip_ansi = true
strip_lines_matching = ["^pattern1", "^pattern2"]
truncate_lines_at = N
max_lines = N

[[tests.<name>]]
name = "..."
input  = "..."
expected = "..."
```

**Adoption for DevolaFlow PV-03 `.local/memory/cases/index.yaml` + per-case files:** the same declarative-with-inline-tests shape is a strong precedent. Each `<case-id>.md` recipe should carry inline test cases (`expected_dispatch`, `expected_savings_pp`) that the EvoBench scenario runner can verify. This couples PV-03 (memory router) to PV-04 (command mapping, conditional) cleanly: if D-001 splits the router, PV-04's `commands/<repo>/<cmd>.yaml` files can use the literal RTK filter schema (DSL re-use, not just pattern parallelism).

### 4.4 `multi_platform_sync` (38 cited files) — adapter parity discipline

RTK's `hooks/{antigravity, cline, codex, copilot, cursor, kilocode, opencode, windsurf}/` directory mirrors the same hook-script logic across 8 IDEs (plus claude in the parallel `.claude/` tree = 9 total agents). NineS rates this as RTK's #1 mechanism by impact_magnitude (0.843).

**DevolaFlow current state:** `scripts/install.sh` supports 4 adapters (cursor / codex / claude / copilot). v8.3.0 retrospective §3.1 notes L-001 (per-tool command files for 25+ AI assistants) is DEFERRED. **v8.4.0 should NOT expand the adapter set** — the priority is shipping RTK + memory router; expanding adapters is L-001 territory and remains deferred. Track for v8.5.0+.

## 5. Plugin Integration Recommendation (closes R-001 in PV-01)

### 5.1 Backend choice — `cargo` vs `curl_install_script` vs `brew`

| Backend | Pros | Cons | Verdict |
|---------|------|------|---------|
| **`brew install rtk`** | RTK is in `homebrew-core`; reproducible | macOS-only; agent hosts are mostly Linux | **REJECT** for primary, OK as secondary OS-detect fallback |
| **`cargo install --git https://github.com/rtk-ai/rtk`** | Always-fresh build; works on Linux/macOS/Windows; Rust toolchain + C deps via `bundled` features | Requires `cargo` (not always installed); compile time ~2-5 min on first install; **uses a lot of disk** during build | **REJECT** as primary — too slow for runtime ensure_plugin call; may be needed as fallback when binary download fails. |
| **`curl_install_script`** (download prebuilt binary from `releases`) | **Single command, ~3 sec on warm network**; matches RTK's documented "Quick Install" path; uses `~/.local/bin` (already on agent's PATH); zero compile dep; matches `install.sh` provenance via `RTK_INSTALL_DIR` env override | Requires network access at install time (no local fallback); TLS to GitHub releases | **ADOPT as primary backend for PV-01** |

**Concretely**, the new backend in `runtime-plugins.yaml` (schema bump 1 → 2):

    description: "..."
  - id: npm_then_init
    description: "..."

      curl-piped POSIX install script. Downloads a prebuilt binary via the
      script's GitHub-releases logic. Tracks RTK's install.sh contract:
      target-triple detection, RTK_INSTALL_DIR env var (defaults to
      $HOME/.local/bin), verifies via `<binary> --version` and a
      version-distinguishing `verify_distinguish_cmd`.

## 7. Risks

### R-1 — Name collision with `rtk-type-kit` (`reachingforthejack/rtk`)

**Source:** RTK's own `INSTALL.md` warns explicitly. `cargo install rtk` from crates.io may pull rtk-type-kit instead of Rust Token Killer.

**Likelihood:** MEDIUM — `cargo` is the documented fallback backend; if `curl_install_script` fails and we fall back to `cargo install --git https://github.com/rtk-ai/rtk`, we are protected (the `--git` flag pins source repo). But if a future agent rewrites the cmd to plain `cargo install rtk`, they get the wrong project.

**Mitigation:**
- PV-01 `installer.py::install_rtk()` MUST always pin `--git https://github.com/rtk-ai/rtk` for the cargo fallback (NEVER bare `cargo install rtk`).
- PV-01 verify step uses `rtk gain` (the Token Killer-only command) as the discriminator — **mandatory**, NOT optional, NOT just `rtk --version`.
- Document the pitfall in `references/runtime-plugins.md` (if/when that reference is added; otherwise inline-document in `runtime-plugins.yaml` comments).

### R-2 — Rust toolchain availability on agent hosts

**Source:** Agent hosts vary; `cargo` may or may not be present.

**Likelihood:** LOW for the **primary** backend (`curl_install_script` only needs `curl` + `tar` — universally available); MEDIUM for the **fallback** (cargo).

**Mitigation:**
- Primary backend (`curl_install_script`) does NOT require Rust — it downloads a prebuilt binary, so this risk only affects the cargo fallback path.
