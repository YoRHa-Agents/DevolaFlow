## Safe vs Unsafe Stages

Full analysis in `.local/sandbox/v7.2.0/V05/safe_unsafe_stages.md`.

**SAFE for inline_review** (defect detection comparable to verifier subagent):

1. **`research`** — defects are structural (missing source, weak claim, paraphrase-vs-verbatim); checklist deterministically catches them; the verifier subagent would run the same checklist with extra dispatch overhead.
2. **`design`** — defects are structural (missing interface contract, ADR section gaps, terminology drift); checklist enforces structural completeness; gen_verify provides marginal value.
3. **`documentation`** — defects are link/version/example issues; checklist catches them via deterministic checks (link resolution, code-runnable-as-shown); gen_verify provides marginal value.

**UNSAFE — must keep `gen_verify_mode`** (comparable defect detection NOT maintained):

1. **`implement`** (used in `feature`, `refactor`, `migration`, `full-pipeline`, `perf-optimization`, `security-audit`, `skill-optimization`) — logic bugs, race conditions, edge-case omissions are exactly what a fresh-eyed verifier catches; same agent has the same blind spot that produced the bug.
2. **`test`** — gate validity depends on independent test-suite execution; flaky tests, coverage misconfigurations, and assertion-skip patterns require a separate runner. SI-10 step 1 is itself a gen-verify pattern (`pytest tests/ -q` is the verifier).
3. **`refactor`** — "preserve behaviour while changing structure" needs a diff-aware second pair of eyes; refactor regressions surface in production with high blast radius.

**Borderline (excluded from v7.2 enablement):**
- `security-audit` — even structural sub-tasks should keep gen_verify due to cost-of-miss
- `RDRR` and `onboarding` — mixed safe/unsafe phases; defer to v7.3 once per-phase flag is supported

## Speedup Plausibility

| Component | gen_verify_mode (current) | inline_review_checklist (proposed) | Δ |
|-----------|---------------------------|-------------------------------------|---|
| Verifier dispatch round-trip | ~25 min (context load + tools + score + serialise) | 0 (no dispatch) | -25 min |
| In-process checklist execution | n/a | ~30 sec (5-10 yes/no items, no tool calls) | +30 sec |
| **Net wallclock per gate-round** | ~25 min | ~30 sec | **~50× faster** |

**Plausibility verdict:**
- **YES** for SAFE stages — superpowers v5.0.6 release notes report this empirically on `brainstorming` and `writing-plans` skills, which are direct analogues of DevolaFlow's `research` and `design` stages.
- **PARTIALLY** for `documentation` — the 50× ratio holds, but defect-detection equivalence depends on checklist completeness; recommend a brief `tests/test_inline_review_checklists.py` golden test in v7.2 (out of V05 scope).
- **NO** for UNSAFE stages — wallclock saving may even regress if the missed defect triggers a downstream stage rerun (SI-9 reinforcement loop). A single missed `implement`-stage bug costs more wallclock to remediate than the 25 min the verifier would have taken.

**Caveat on the "50×" headline:** the saving applies only to gate rounds where the verifier's would-have-been-finding rate is also low. On SAFE stages this matches; on UNSAFE stages the verifier was actively catching defects and skipping it costs you defects, not minutes.

## Risk Analysis

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Defect slips past inline checklist that verifier would have caught | Low (on SAFE stages); High (on UNSAFE stages if user enables) | Medium (doc bug) → High (logic bug) | Flag is opt-in default off; UNSAFE profiles do not have the flag added; `decomposition-gate.md §8` UNSAFE table makes the boundary explicit |
| User enables flag on UNSAFE profile | Medium (the flag is in schema, ergo discoverable) | High (P4 Bounded Retry compromised) | v7.3 follow-up: add runtime guard in `decomposition_gate.evaluate()` rejecting flag + `team: implement\|test` combo (out of v7.2 scope; tracked) |
| SKILL.md hits 499/499 with 0 headroom | High (already happens with this patch) | High (any future SKILL.md addition breaks SF-1) | See "PR-E Coordination Risk" below — REQUIRED to coordinate with C-004 |
| Mutex with `gen_verify_mode` not enforced | Low (selector reads both keys) | Medium (silent precedence wrong way) | `decomposition-gate.md §8 Activation` declares "if both set, gen_verify wins" — selector consumer code update is a v7.3 follow-up (out of v7.2 scope; SKILL doc is normative for v7.2) |

**Worst case:** A team enables `inline_review_checklist: true` on a `feature` profile (UNSAFE), a logic bug slips through inline review, the bug merges, surfaces in production. Mitigation: opt-in default off + decomposition-gate.md §8 hard "UNSAFE" table.
