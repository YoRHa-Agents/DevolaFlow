### Helper addition (after `load_relevant_learnings`, before `prune_learnings`)

```python
def dedup_learnings(entries: list[Learning]) -> list[Learning]:
    """Return latest-timestamp entry per ``(task_type, key)`` pair.

    Mirrors the gstack ``/learn`` JSONL ``{type, key}`` last-write-wins
    contract. Empty timestamps lose to populated timestamps. Insertion
    order preserved across distinct ``(task_type, key)`` tuples.
    """
    seen: dict[tuple[str, str], Learning] = {}
    for entry in entries:
        key = (entry.task_type, entry.key)
        prev = seen.get(key)
        if prev is None:
            seen[key] = entry
            continue
        if entry.timestamp > prev.timestamp:
            seen[key] = entry
    return list(seen.values())
```

Plus `__all__` extension to export `dedup_learnings`.

## Risks / Caveats

1. **Helper name conflict potential.** No existing function `dedup_learnings` in `src/devolaflow/learnings.py` (Grep verified). The name is descriptive and matches the gstack idiom — accept.
2. **Stage-aware vs stage-agnostic dedup.** C-007's helper dedups by `(task_type, key)` (2-tuple), but `capture_learning` skip-dup uses `(key, stage, task_type)` (3-tuple). This is **intentional** per gstack's `{type, key}` spec but the asymmetry should be documented in v7.2's CHANGELOG and SKILL.md "Operational Learnings" section so future agents do not assume `dedup_learnings` is the inverse of `capture_learning`'s skip-dup. Captured in V07's docstring; flag for the v7.2 implementation PR-C author.
3. **Empty timestamp comparison.** `entry.timestamp > prev.timestamp` uses string comparison. ISO 8601 sorts correctly because timestamps are left-padded; empty string `""` sorts before any non-empty string, so populated entries always win over empty-timestamp ones — desired behaviour, verified by `test_empty_timestamp_loses_to_populated`. If timestamps ever ship without timezone (`2026-04-18T00:00:00` vs `2026-04-18T00:00:00+00:00`), lexicographic comparison still works because both are length-29 and identical up to the offset suffix. Edge case: timestamps with different precisions (`2026-04-18T00:00:00.123456+00:00` vs `2026-04-18T00:00:00+00:00`) — fractional version sorts later, still correct (it IS later). No code change recommended.
4. **`operational.jsonl` does exist** at `workflow-system/agent/knowledge/learnings/operational.jsonl` (empty 0-byte file) — the candidate's "currently empty file per T02 §CC-3 + T04 evidence" claim is accurate. **No file-creation work needed in v7.2 PR-C** — it's already on disk waiting to be populated. The companion C-009 (reflective reflex, TIER-2) is the writer that makes the JSONL non-empty; without C-009, this PR ships dormant infrastructure (not a defect — that's the explicit two-phase plan in CCT-3).
5. **No P6 cache-layout-invariant touch.** Confirmed: changes are confined to `src/devolaflow/learnings.py`. No edit to `schemas/lean-dispatch.yaml` or `schemas/lean-report.yaml` (those would couple with C-009, not C-007). P6 invariant is **not** at risk here.
6. **`asdict()` round-trip safety.** `capture_learning` uses `json.dumps(asdict(learning))` for serialisation. For a dataclass with `field(default_factory=list)`, `asdict` returns `{"files": []}` — JSON-safe. Round-trip verified by `test_capture_then_load_preserves_files_and_source`.
