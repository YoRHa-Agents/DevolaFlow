# DevolaFlow v23.1.0 Phase A：Harness 与 Token Gap Analysis

审计对象：v23.1.0 计划的 Phase A 报告。审计依据是本仓库在报告生成前可读取的代码、schema、测试、历史归档和遥测目录；本报告不把旧摘要升级为新事实，也不补造 v23.1.0 数据。

## 1. 判定口径

本文统一使用以下证据标签：

- **measured / provider-reported（实测/提供方报告）**：由真实 CLI、捕获转录或遥测原件直接提供，并带来源、运行标识或 artifact provenance。provider-reported 只表示外部提供方声称的结果，不等于本仓库复测。
- **computed（计算值）**：由仓库代码对已存在原始记录计算出的均值、分位数、比率或 composite；计算值不能超越输入记录的证据等级。
- **configured（配置值）**：代码、schema 或 `context_profiles.yaml` 中声明的预算、阈值、矩阵维度；不是运行结果。
- **estimated（估算值）**：`estimate_tokens` 或压缩器对文本推导的 token 数；没有 provider 原始 usage 时不能称为 provider token。
- **INSUFFICIENT（证据不足）**：原始文件、观测、salt、运行元数据或不确定性证据缺失；禁止用零、默认值或历史值替代。

本阶段目标是 token metering，不是账单系统：**不做 billing，只计量 token**。任何价格、费用、节省金额或财务 ROI 均不在本阶段结论内。

## 3. v23 Token Chain 与压缩数字

### 3.1 计量链

```
dispatch payload
  -> stable YAML
  -> estimated dispatch tokens (tokens_injected_measured)
  -> layer budget check: L0 5000 / L1 5000 / L2 8000
  -> host full AGENTS estimate + configured slice_savings_pct
  -> optional skill/rule/report component accounting
  -> token-injection schema + source/provenance/uncertainty
  -> append-only JSONL
  -> strict aggregation (mean/p50/p95)
  -> W-3 evaluation / gap report / human proposal
```

可确认的边界：

- `src/devolaflow/harness/telemetry.py:115-127` 配置 L0/L1/L2 为 `5000/5000/8000`；这是 **configured**。
- `src/devolaflow/harness/telemetry.py:230-248` 明确记录 host 目前注入 full AGENTS corpus，`slice_savings_pct` 是配置可提供的 saving，不是 provider 实际少收的 token；这是 **estimated/configured accounting**。
- `src/devolaflow/harness/telemetry.py:330-360` 用 `estimate_tokens(stable_yaml(payload))` 生成 dispatch token 数；这是 **estimated**，除非另有真实 provider usage artifact，不能命名为 measured provider token。
- `src/devolaflow/harness/context_tokens.py:64-79` 对显式输入分别计数，缺失保持 `None`、空输入为 `0`；`src/devolaflow/harness/context_tokens.py:190-210` 明确不做隐式文件读取。因此缺失上下文不会被安全地反推。
- `schemas/token-injection-measurement.yaml:1-38` 要求 source、provenance、run metadata、四类 token、各自状态和 uncertainty；`schemas/token-injection-measurement.yaml:108-130` 要求 sample count、variance、interval 和 status。
- `src/devolaflow/harness/aggregator.py:170-182` 只允许 `[0,1]` 的有限 ratio；它能防止坏值进入计算，但不能创造缺失样本。

### 3.2 当前压缩契约中的数字

以下数字是 **configured / algorithmic bounds**，不是 v23.1.0 运行收益：

- `src/devolaflow/_compressor_transforms/common.py:31-37`：summary 默认模式 `extractive`、默认最大 summary `500` tokens、trigger `25%`、截断标记 `[TRUNCATED]`。
- `src/devolaflow/_compressor_transforms/common.py:108-132`：abstractive 低密度阈值 `0.30`、低密度最多 `2` 行、高密度最多 `5` 行、directed compaction 默认最多丢弃 `20%` 字符、dedup digest 上限 `320` 字符。
- `src/devolaflow/_compressor_transforms/validation.py:188-266`：`compression_ratio = 1 - compressed_tokens / original_tokens`，并在 bypass 时强制 ratio `0.0`、原文逐字返回。该 ratio 是基于本地 estimator 的 **computed from estimated counts**。
- `src/devolaflow/_compressor_transforms/compact.py:78-108`：focus 段不丢弃，理论 focus retention 为 `100%`，总字符丢弃受 `max_drop_pct` 约束；这是算法保证，不是任务质量或 provider token savings。
- `src/devolaflow/_compressor_transforms/summary.py:270-340`：按信息密度路由并在 `max_tokens` 内 greedy pack；`0.30/2/5` 是配置/算法边界。
- `src/devolaflow/_compressor_transforms/dedup.py:15-52`：短 digest 不超过 `320` 字符，长 digest 优先保留八类实体；`src/devolaflow/compressor/layout.py:77-110` 规定 dedup ledger 位于第 17 个 canonical position，digest 在 entry 内嵌套。
- `src/devolaflow/compressor/layout.py:127-168`：前 12 个 key 是 frozen prefix，后续 key append-only；当前 `DEFAULT_DISPATCH_LAYOUT` 长度为 17。这是 cache-layout governance，不是压缩比例。
- `tests/test_compression_pipeline.py:40-132`：测试确认空 pipeline、全 bypass、identity stage byte-identical，且 stage 按声明顺序执行；测试通过只能证明契约，不提供 v23.1.0 120-run 收益数字。

## 4. Findings

严重度含义：**blocker** 阻断 Phase A 的量化发布结论；**critical** 使核心可信度或可复现性不足；**major** 造成重要归因/覆盖缺口；**minor** 为局部可维护性或解释风险。

### F-01 — blocker：v23.1.0 120-run 原始证据缺失

- 证据：预写入扫描未找到 `.local/telemetry/` ledger/baseline 或 120-run artifact；现有 `v23.1.0_token_cross_validation.md` 和 `v23.1.0_kimi_diagnosis.md` 只有局部探针；代码侧 `src/devolaflow/harness/calibration.py:44-48` 仍定义 v21.1.0 默认输出命名。
- 影响：无法报告 120 个 run 的实际文件、通过率、token 分布、方差、跨 arm 差异或 ROI；任何填零、套用历史值或推定 120 都会制造 ghost evidence。

### F-02 — blocker：当前代码/项目元数据不是 v23.1.0

- 证据：`src/devolaflow/__init__.py:6` 为 `23.0.0`；`pyproject.toml:7-10` 为 `23.0.0`。
- 影响：v23.1.0 报告不能声称已审计 v23.1.0 发布代码；Phase B 必须先确认版本基线、commit 和 artifact 对齐。

### F-03 — critical：主 telemetry ledger 与 baseline 缺失，六轴 gap 无法闭环

- 证据：`src/devolaflow/harness/gap.py:47-60` 指向 observation/evaluation/probe/baseline/signal/loop-closure 六轴；`src/devolaflow/harness/gap.py:241-252` 在 baseline 目录或 settled artifact 缺失时返回 GAP；`src/devolaflow/harness/aggregator.py:110-150` 要求 ledger 与连续 segment。
- 影响：不能把代码存在当作 observation coverage；无法执行 W-16 baseline comparison，也无法确认迭代改善。

### F-04 — critical：上下文三分量没有可用于 v23 的观察记录

- 证据：`src/devolaflow/harness/context_tokens.py:64-79` 将 skill/rule/report 分开并保留 None；历史 artifact 的 context 子项 observed records 为 0、状态为 INSUFFICIENT；`src/devolaflow/harness/context_tokens.py:190-210` 禁止隐式文件读取。
- 影响：不能从 dispatch token 总量反推出 skill/rule/report 分摊；token chain 的组件归因仍 INSUFFICIENT。

### F-05 — critical：dispatch token 与 provider usage 的边界仍不完整

- 证据：`src/devolaflow/harness/telemetry.py:330-350` 对 stable YAML 调用 `estimate_tokens`；`src/devolaflow/task_adaptive_selector.py:1-12` 描述 selector 的估算机制；`src/devolaflow/harness/context_tokens.py:40-47` 明确 `estimate_text_tokens` 是本地计数。已有 `v23.1.0_token_cross_validation.md` 只在三个样本上得到 offline/tiktoken 差 `0`，CLI difference 仍为 `44/3205/181`，且官方 Anthropic count_tokens 为 INSUFFICIENT。
- 影响：三样本支持局部 estimator parity，不足以证明 provider-wide parity；不能据此推导 API 账单、provider input/output token 或财务 ROI。

### F-06 — critical：slice saving 与真实 host injection 尚未形成闭环

- 证据：`src/devolaflow/harness/telemetry.py:230-248` 明确 host 当前注入 full AGENTS corpus，而 `slice_savings_pct` 记录配置可用 saving；`src/devolaflow/harness/telemetry.py:249-260` 失败时将两个值降为 `0/0.0` 并 warning。
- 影响：`49.61538461538461%` 的历史 slice saving 只能算配置/估算 accounting，不能宣称真实线上减少了同等比例 token；异常降零还会降低可观测性，需结合 warning 和 provenance 解读。

### F-07 — major：calibration 默认矩阵与 v23 120-run 目标不一致

- 证据：`src/devolaflow/harness/calibration.py:44-48` 默认 replicates 为 10，默认 cycle/raw path 为 v21.1.0；`src/devolaflow/harness/calibration.py:90-138` 按所选维度生成 specs；`src/devolaflow/harness/calibration.py:200-228` 将不可用、认证失败、外层超时记录为 INSUFFICIENT。
- 影响：即使执行一次默认 calibration，也不能证明完成 120 个有效、可比较的 observations；必须披露 planned、executed、PASS、FAIL、INSUFFICIENT 四个计数。

### F-08 — major：外部 benchmark 与内部运行缺少同口径可比样本

- 证据：`src/devolaflow/harness/calibration.py:220-260` 输出 matrix、preflight、summary 和 artifact 目录；`src/devolaflow/harness/calibration_report.py` 负责报告呈现，但当前无 v23 artifact；`schemas/token-injection-measurement.yaml:108-130` 要求 uncertainty 元数据。
- 影响：外部 tokenizer、observability 或 agent-eval 的公开结果不能直接充当内部 control/treated 差值；没有相同任务、模型、版本、环境和样本数时，结论只能是方法对标。

### F-09 — major：历史 evaluation 的 READY 不能覆盖低维度和缺失组件

- 证据：`docs/cycle-archive/v21.3.0/evaluation/v21.3.0_evaluation.json` 的 computed composite 为 `8.67`，但 test adequacy `6.67`、compatibility `5.00`；同一 artifact 的 skill/rule/report context observations 均为 0 且 INSUFFICIENT；评价权重和 threshold 的实现见 `src/devolaflow/harness/evaluator.py:42-60`。
- 影响：不能把历史 overall verdict 解释为 token chain 已可信；Phase B 应按维度 gate，而非只看 composite。

### F-10 — major：压缩 ratio 没有 v23.1.0 120-run 原始输入与 provider 对照

- 证据：`src/devolaflow/_compressor_transforms/validation.py:188-266` 只根据本地 `estimate_tokens` 计算 ratio；`tests/test_compressor.py:138-188` 只验证 ratio 大于/等于零、token count 单调和 bypass 行为。
- 影响：当前可以验证算法契约，不能报告 v23.1.0 真实压缩均值、p50/p95、任务质量保持率或 token-in/token-out savings。

### F-11 — major：bypass 是正确性保护，不是压缩收益

- 证据：`src/devolaflow/_compressor_transforms/validation.py:214-238` 在 security/destructive 等条件命中时原文返回、ratio `0.0`；`tests/test_compressor.py:990-1060` 验证 DROP TABLE、多步有序操作等场景保持 byte-identical。
- 影响：混合样本若不分层，会把安全 bypass 误读为压缩失败或把未压缩安全文本计入 savings；v23 报告需分列 bypass rate 与 compression ratio。

### F-12 — major：cache layout 数字不是 token savings 数字

- 证据：`src/devolaflow/compressor/layout.py:127-168` 保护 12-key frozen prefix、17-key live layout；`src/devolaflow/compressor/layout.py:180-218` 只检查前 12 位不漂移。
- 影响：layout witness 通过只能说明 cache-prefix 兼容性；不能推出 token reduction、latency reduction 或 ROI。两类证据必须分开。

### F-13 — minor：summary 的 0.30/2/5 与 500 上限属于 configured bounds

- 证据：`src/devolaflow/_compressor_transforms/common.py:31-37` 和 `:108-132` 定义 500 token、0.30、2 行、5 行、20%、320 字符；`src/devolaflow/_compressor_transforms/summary.py:270-340` 执行该路由和预算。
- 影响：这些数字可用于验收算法边界，但若缺少任务级 before/after artifact，不能写成平均压缩效果或质量保持率。

### F-14 — minor：proposal、capacity、fixture 与 loop-closure 仍需要本轮产物证明

- 证据：`src/devolaflow/harness/gap.py:270-300` 在没有 `proposal_applied` 事件时将 loop-closure 判 GAP；`src/devolaflow/harness/calibration.py:180-228` 要求 preflight/auth evidence；`src/devolaflow/harness/fixtures.py` 校验 fixture set；`src/devolaflow/harness/capacity.py` 解析 capacity 配置。
- 影响：代码路径完整不等于本轮闭环；需要 proposal approval、capacity provenance、fixture hash 和真实执行结果，否则只能标 designed/configured。

## 5. Phase A 结论

1. **内部 harness 设计覆盖面较完整**：具备 telemetry、token-injection schema、metadata、聚合、W-3 evaluator、gap inventory、CLI calibration、压缩契约和 layout governance。
2. **v23.1.0 运行证据不足以支持量化发布结论**：已有三样本 tokenizer cross-validation 和两次 Kimi CLI availability probe，但 120-run 文件和数字缺失；完整 token-component chain、compression outcome、uncertainty、baseline 和 ROI 均不能从当前产物复原。
3. **历史 v21.3 数字可作为对照基线，不是 v23.1.0 事实**：18,585 total tokens、49.61538461538461% historical configured slice saving、8.67 composite 等均须带历史版本和 provenance。
4. 本阶段明确 **不做账单、只计量 token**；没有 provider usage 或费用输入，不构造金额。
5. **ROI 仍为 INSUFFICIENT**：没有 matched skill-on/off real-task outcomes、可验证的 token delta、质量 delta、运行成本和不确定性区间。
