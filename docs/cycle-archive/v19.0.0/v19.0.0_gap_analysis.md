## 4. Rule-corpus refactor contract

The operator accepted W-26, W-27, and W-28, plus a larger rule review. The
sequence is mandatory:

1. Inventory all current rules and classify obsolete, duplicate, mergeable,
   and frozen normative content.
2. Design a repository-relative restructuring map, preserving S-1..S-10,
   A-2 layout invariants, rule references, and enforcement mappings.
3. Re-audit the map for coverage, contradictions, count, generated-surface
   drift, and missing enforcement before editing rule sources.
4. Apply only the individually approved consolidations/simplifications and
   accepted W-26/W-27/W-28 text; compile all generated surfaces.
5. Run rule, ghost, compiler-drift, skill, and release checks. The rule cap is
   hard; the implementation must not silently exceed it.

The three accepted rules consume the currently reported 57→60 rule slots
before any consolidation. Therefore the refactor must account for rule-count
headroom explicitly; no additional rule may be added without removing or
merging an approved obsolete/duplicate entry.
