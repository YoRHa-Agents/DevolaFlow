## 4. Compilation and generated-surface contract

`.rules/compile-config.yaml` is the compilation configuration:

- sources: `.rules/`;
- layers: `soul`, `architecture`, `conventions`, `workflow`, `style`;
- `cursor` target: `.cursor/rules/repo-governance.mdc`, MDC, 14,000-token
  budget, all five layers;
- `agents_md` target: `AGENTS.md`, Markdown, 14,000-token budget, the first
  four layers plus the exact style pointer postscript;
- `style_md` target: `docs/STYLE-RULES.md`, Markdown, 4,000-token budget,
  Style only;
- drift store: `.rules/.compile-hashes.json`.

The compiler strips source frontmatter, orders layers by configured priority,
renders each target, rejects token overflow with
`TokenBudgetExceededError`, writes all targets only after compilation succeeds,
and saves one hash per target. `tests/test_local_compiler.py` covers parsing,
target formatting, overflow, no-partial-output behavior, postscripts, and
determinism. `tests/test_local_drift.py` covers in-sync, drifted, and missing
target/hash behavior. `tests/ghost/test_rules.py::test_rule_surfaces_compile_only`
is the repository-level reverse lint.

Required preservation during the later apply:

1. never edit `AGENTS.md`, `.cursor/rules/repo-governance.mdc`, or
   `docs/STYLE-RULES.md` by hand;
2. edit only `.rules/*.mdc`, then run the configured compiler;
3. retain all configured targets and their independent budgets;
4. retain the `AGENTS.md` Style pointer and the absence of inline Style body
   in that target;
5. run drift checks after compilation;
6. keep the six retired `.cursor/rules/` stubs absent.

## 6. Accepted W-26/W-27/W-28 treatment

The local-archive design and v19 gap analysis accept three independent
Workflow-layer additions. They are accepted as design/implementation items,
but their rule headings are not present in the current `.rules/workflow.mdc`.
They must not be inferred from the existing reference alone until the later
apply task writes and tests them.

### W-26 — Deletion safety (`C-G4.3`)

Proposed normative content:

- deletion is permanently operator-only;
- local-archive exposes no automatic deletion API or deletion mode;
- report-only planning and approved non-deletion moves remain allowed;
- clean checks and plan approval never authorize deletion;
- automatic `git clean -fdx` or equivalent destructive commands are forbidden;
- dirty, ambiguous, missing, unreadable, nested-repository, symlink, protected,
  or worktree-conflicted paths produce explicit refusal findings.

Primary evidence: `workflow-system/agent/references/local-archive.md` §§6–7,
`docs/cycle-archive/v17.4.0/design/v17.4.0_local_archive_design.md` §§3.4–3.5,
`src/devolaflow/local/archive.py`, `tests/test_local_archive.py`, and
`tests/ghost/test_features_v17_5.py`.

### W-27 — Mapping append-only behavior (`C-G4.4`)

Proposed normative content:

- physical moves append a dedicated task-archive record at
  `.local/tasks/archive-mappings.yaml`;
- each row records `sequence`, `source`, `destination`, `reason`, and
  `timestamp`;
- sequence values increase from the existing maximum;
- existing rows are immutable;
- duplicate source or destination paths are refused;
- this record is not an existing `.local/.agent/` handoff envelope, so S-9
  remains independently enforced.

Primary evidence: `references/local-archive.md` §8,
`src/devolaflow/local/archive.py::append_mapping_record`,
`tests/test_local_archive.py::test_mapping_append_only_and_no_clobber`, and
the local-archive ghost audit.

### W-28 — Index-generation honesty (`C-G4.5`)

Proposed normative content:

- `.local/tasks/INDEX.md` is a generated navigation view, not the mapping
  source of truth;
- generated output carries
  `<!-- devolaflow: generated task archive index -->`;
- a missing index may be created only by an approved apply operation;
- a human-maintained, symlinked, or unreadable index is never silently
  overwritten;
- stale or non-generated index bytes produce an explicit refusal or drift
  finding.

Primary evidence: `references/local-archive.md` §8,
`src/devolaflow/local/archive.py::render_index` and
`_validate_index_target`, `tests/test_local_archive.py`, and
`tests/ghost/test_features_v17_5.py`.

### Count and sequencing consequence

The accepted additions take the reported corpus from **57 to 60**, exactly at
the hard cap. No fourth rule may be added before a consolidation is applied.
The safe sequence is:

1. add W-26, W-27, and W-28 as separately testable headings;
2. update the index to 60 and add each rule's enforcement mapping;
3. run the second audit below;
4. only then apply approved low-risk merges, updating all lineage references;
5. recompile generated surfaces and re-run cap/drift tests.

Their independent acceptance should be preserved in the audit ledger even if a
later source-layout decision nests their text under one archive-governance
heading. No W-26/W-27/W-28 text is applied by this artifact.
