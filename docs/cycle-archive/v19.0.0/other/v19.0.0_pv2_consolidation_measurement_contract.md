# v19.0.0 PV-2 Consolidation Measurement Contract

## Purpose

This contract makes the v19 consolidation measurements reproducible before
per-item optimization is attempted. It defines what is measured, where the
value comes from, and how missing historical evidence is represented.

## Measurement set

The append-only `consolidation_metrics` telemetry event carries all four
metrics. Every event key is present; `null` means that the source was not
available at measurement time.

| Metric | Source and unit | Counting rule |
| --- | --- | --- |
| `agents_md_tokens` | `AGENTS.md`, estimated tokens | The repository token estimator is applied to the exact UTF-8 file bytes decoded as text. Dispatch telemetry may also supply this value from the existing AGENTS.md slice accounting. |
| `suite_wall_seconds` | bounded evaluator suite probe, seconds | Monotonic elapsed wall time from immediately before invoking the suite probe until it returns. A timeout has no elapsed measurement. |
| `cjk_violations` | agent-facing Markdown, code points | Count Unicode code points in the CJK ranges in `AGENTS.md`, `workflow-system/agent/SKILL.md`, and `workflow-system/agent/references/*.md`. Compiled duplicate surfaces are not counted. |
| `ghost_loc` | `tests/ghost/**/*.py`, source lines | Count non-empty, non-comment physical Python lines. Files are traversed in sorted path order. |

## Aggregation and evaluator behavior

`devolaflow.harness.aggregator` validates metric types and computes a mean
over observed values. Dedicated `consolidation_metrics` events take precedence
over dispatch-record fields, avoiding double counting when both are present.
The aggregate contains `mean`, `observed_records`, and `status`.

An absent metric is represented as:

```json
{"mean": null, "observed_records": 0, "status": "INSUFFICIENT"}
```

The evaluator exposes the same four names under `measurements`, with explicit
`value: null`, `status: "INSUFFICIENT"`, and an explanatory `error`. It never
derives a missing historical value from the current checkout. Current
evaluator probes may report newly collected values with `source: "evaluator"`;
ledger-backed values are marked `source: "telemetry"`.

## Relative optimization baseline

For a metric `M`, freeze one baseline observation before changing the item:

`relative_change_pct = ((M_after - M_before) / M_before) * 100`

Use an absolute delta when the baseline is zero (for example,
`cjk_violations` reaching zero). Do not compute a percentage from an
`INSUFFICIENT` or `null` baseline. Record the exact ledger/event reference,
metric name, unit, baseline value, after value, and formula inputs alongside
each later item-level comparison.
