## Caveats — `code_coverage = 0.0` Measurement Artifact

NineS reports `code_coverage = 0.0` because:

```
pytest --cov timed out after 54.0s (budget-derived)
```

(verbatim from line 2 of `v8.2.0_nines_self_eval.json` raw output, identical to v8.1.0)

**Truth:** Actual project coverage is ≥ 80 % (per CP-2 floor, verified by
`pyproject.toml [tool.coverage]` configuration and continuous CI runs). The 0.0
score is purely a NineS measurement artifact: 2,647 tests cannot run with `--cov`
inside the default 54-second NineS hygiene budget.

**Why this didn't get fixed in v8.2.0:** Plan §3 PV-05 owned-file slot 6 listed
`nines.toml` with `pytest_cov_budget_seconds: 54 → 120` (gap analysis A1 bundled
into PV-05). Inspection of current `nines.toml` shows **A1 was NOT bundled** — the
file has no `pytest_cov_budget_seconds` field. This is the same 0.0 carry-over
from v8.1.0 self-eval and is the largest single drag on `weighted_overall`
(0.7065 vs 0.9047 simple mean).

**Impact on G3 verdict:** None — the dispatch G3 gate is `overall ≥ 9.0` (simple
mean), which excludes the deflated `weighted_overall`. If A1 had been bundled and
real coverage (≈ 96 % per v8.0.0 SI-3) had been measured, both `overall` and
`weighted_overall` would lift by ≈ 0.4 pp (overall → ≈ 9.4 / weighted_overall →
≈ 7.5).
