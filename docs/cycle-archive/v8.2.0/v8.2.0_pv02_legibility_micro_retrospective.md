### 2.2 Three-dimensional scoring contract (the core deliverable)

| Dimension | Scoring rule | Score range |
|-----------|--------------|------------:|
| **Naming consistency** | snake_case for Python funcs, PascalCase for classes, camelCase / PascalCase for JS/TS; mixed-style modules score below 100; **dunder methods exempt** (per Python convention) | 0-100 |
| **Comment-to-code ratio** | U-curve scoring with sweet-spot **0.10-0.30**; under-commented (< 0.05) AND over-commented (> 0.50) both penalised | 0-100 |
| **Cyclomatic flow** | radon (per-function cc) when available; **indentation heuristic fallback** (S-5: failure path always logged via `legibility.radon_unavailable` warning, never silently swallowed) | 0-100 |

The composite legibility score is the simple mean of the three dimensions; the gate weight is applied per-profile (`legibility_weight=0.05` on STRICT/AUDIT means up to ±2.5pp impact on the gate composite).

## 3. What Was Deferred and Why

- **STANDARD / RELAXED profile flips for `legibility_weight`** — DEFERRED. Per the gap analysis B3 partial-flip discipline, only STRICT and AUDIT default to `0.05`; STANDARD / RELAXED stay at `0.0`. Justification: STANDARD is the most-used profile and any composite drift (even ±2.5pp) on STANDARD would risk EvoBench regression on long-running scenarios. Bench to v8.2.x once dogfooding data confirms net-positive impact on STRICT/AUDIT.
- **EvoBench `legibility_critical.yaml` scenario** — DEFERRED. The plan flagged a dedicated scenario validating the 0.05 weight impact; PV-02 ships without it because (a) all 36 existing scenarios pass at 0pp drift (so the regression-firewall holds), (b) PV-05's `r7_section_anchor_registry_no_drift.yaml` covers the cycle's emergent EvoBench debt, (c) authoring a meaningful legibility scenario requires synthetic well-legible vs illegible code samples that benchmark consistently across radon-installed and radon-missing environments — non-trivial, queued for v8.2.x.
- **Per-file `legibility_findings` integration into reinforcement loop** — DEFERRED. Currently legibility findings populate `GateResult.legibility_findings` but are NOT yet routed through `gate/reinforcement.py` to feed the next dispatch round. Wire-up to W-8 / SI-9 reinforcement is queued for v8.2.x — pairs naturally with the `cycle_detector_enabled` flip (PV-05 STRICT-only).
- **JS/TS file-extension support beyond `.js` / `.ts` / `.jsx` / `.tsx`** — DEFERRED. Mixed-language repos with `.mjs`, `.cjs`, `.mts`, `.cts` are scored as "unknown language → fall back to indentation heuristic only". Bench to v8.2.x.
- **Radon-equivalent for non-Python languages** — DEFERRED. The cyclomatic-flow dimension uses radon for Python and indentation-heuristic for everything else. Lizard / scc / cccc are alternatives that could provide native cc for JS/TS/Go/etc; PV-02 ships with the indentation-heuristic fallback as a pragmatic baseline.

## 4. Key Learnings

1. **The U-curve comment-to-code scoring is the right shape** — the design considered both a linear "more comments → higher score" and a step function "≥X% comments → 100, else 0", but the U-curve (sweet-spot 0.10-0.30, penalize both extremes) matches code-review intuition: under-commented modules are opaque, over-commented modules drown the reader. The 7 dedicated comment-ratio tests in `TestCommentRatio` exercise both tails of the U; the sweet-spot is the only zone where score → 100. Adopt for any future "Goldilocks zone" scoring (e.g., AC count: too few → vague, too many → noise).

2. **Dunder method exemption is essential for Python naming consistency** — without exempting `__init__`, `__repr__`, `__eq__`, etc., the snake_case rule fails on standard Python protocol implementations (which use `__double_underscore__`). The exemption list is a frozen tuple in `legibility/scorer.py`; future Python protocol additions (e.g., `__class_getitem__`) are added to the list. Lesson: any naming-convention scorer must explicitly enumerate language-protocol exemptions.

3. **The `pytest.importorskip` post-PR fix is a v8.x dependency-isolation reinforcement** — PV-02's `b0e4598` fix is the second confirmation (after P-09 MOCK fallback) that the cycle's optional-dependency discipline matters. The fix landed 5 minutes after the feature commit; the gap was caught by CI not local pre-commit. Adopt: any new test that imports a non-stdlib non-`pyproject.toml`-required module MUST use `pytest.importorskip` AND must be reviewed in PR for this discipline. Consider adding a pre-commit hook that flags `from radon` / `from openai` / etc. without an `importorskip` peer.

4. **Pure-function scorer composes cleanly with EvoBench** — because the scorer is deterministic and stateless, EvoBench scenarios can construct synthetic file samples and assert exact score values. The PV-02 ships without a dedicated EvoBench scenario but the architectural property is captured: future legibility-related EvoBench scenarios will be deterministic. This contrasts with the LLM-assisted Stage B path (PV-01) where determinism is preserved via the mock provider but real-provider scenarios are inherently non-deterministic. Lesson: when designing a scoring primitive, the determinism property determines whether it's EvoBench-safe; gate primitives should default to deterministic.

5. **Three-dimensional simple-mean scoring is the right granularity for v1** — the design considered weighted dimensions (e.g., naming 0.5 / comments 0.2 / flow 0.3), but the simple mean is (a) easier to explain, (b) doesn't bake in subjective weight choices, (c) leaves the gate-side `legibility_weight=0.05` as the single tuning knob. If future data shows the dimensions warrant unequal weight, that's a v8.2.x emergent enhancement. Adopt: v1 of any scoring primitive should use simple mean; weighted variants deserve their own iteration with empirical justification.

6. **+1766 LOC insert-only across 8 files merged in 10 minutes** — PV-02's pure-additive nature (no existing files modified beyond appending fields, no existing tests changed) made review fast. PR #75 merged 10 minutes after `c2680a1` was pushed (vs PV-01's 6-min for a +2008 LOC integration patch — both fast for v8.x discipline). Lesson: insert-only additive patches are the fastest-merging shape when the additivity discipline is honoured.
