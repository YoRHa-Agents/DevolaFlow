The deltas cluster in equivalence classes by `profile_name` (scoring is deterministic
per profile, so scenarios sharing a profile move together — same observation as
v8.0.0 cycle):

- `self_update` profile (2 scenarios) all moved **−0.990 pp** vs v7.8.0 (info-density
  0.9932 → 0.9684, budget_utilization 0.9932 → 0.9684, selected_count 13 → 12,
  total_tokens 3097 → 3002) — the only profile-level move > 0.8 pp; root cause is
  PV-04 / PV-05 dropping one section from the self-update context selection. Well
  within the 5 pp regression tolerance, but worth investigating in v8.2.x.
- `feature` profile (6 scenarios) all moved **−0.090 pp** uniformly — same as v8.0.0 cycle;
  attributable to net-new fields appended after the cached prefix (P-08
  `behavioral_guidelines` at position 14, P-10 `acceptance_criteria` at position 15)
  marginally diluting relevance ratio for the generic `feature` profile.
- `migration` profile (2 scenarios) all moved **+0.290 pp**.
- `research` profile (3 scenarios — including `long_context_repo_qa`) all moved **+0.590 pp**.
- `verify_visual` / `verify_interaction` (3 scenarios at 83-84 composite) drifted
  uniformly **−0.280 / +0.170 pp** — small drift from `verify_*` context profile updates.
- `feedback` profile (3 scenarios) drifted **−0.090 pp** uniformly.
