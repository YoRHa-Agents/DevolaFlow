## 3. What Was Deferred and Why

- **Statement-tier scope (`surgical_scope='statement'`)** - DEFERRED. The PV-04 patch ships line-tier as the finest granularity; statement-tier (single AST node) is queued for a future cycle once line-tier dogfooding signals demand finer granularity. Justification: line-tier already represents the practical floor for diff-based verification (most edits operate on line ranges, not single AST nodes); statement-tier requires AST integration (Python `ast` module + JS/TS parser) that significantly expands scope.
- **Per-language line-tier validation** - DEFERRED. Currently the LL-001..LL-005 criteria are language-agnostic (rely on git diff and ruff-format). Per-language enhancements (e.g., LL-004 mid-token splits validated by language parser) are queued for v8.2.x once a multi-parser strategy is designed (likely paired with PV-02's lizard/scc multi-language cc work).
- **Auto-detection of optimal scope tier** - DEFERRED. Today the L1 dispatcher must explicitly set `surgical_scope` (`function` / `module` / `line`); a future enhancement could auto-detect the appropriate tier from the task description (e.g., "fix typo on line X" -> line; "refactor module Y" -> module). Bench to v8.3.0 - pairs with the v8.0.0 retro §3.4 opt-in primitive auto-wiring debt.
- **EvoBench `surgical_line_strict.yaml` scenario** - DEFERRED. The plan flagged a dedicated scenario validating the LL-001..LL-005 enforcement; PV-04 ships without it because all 36 existing scenarios pass at 0pp drift. PV-05 covers the cycle's emergent EvoBench debt; a dedicated line-tier scenario is queued for v8.2.x.
- **Cross-PV integration with PV-03 SessionState `LifecycleEvent`** - DEFERRED. Line-tier scope changes could be recorded as `LifecycleEvent` records via PV-03's session model; the integration is opt-in only (PV-04 ships without the wire-up). Bench to v8.2.x.

## 4. Key Learnings

1. **The "value-set expansion" backward-compat pattern is distinct from the kwarg / opt-in / module-alias patterns** - PV-04 expands a string field's allowed value set from `{'function', 'module'}` to `{'function', 'module', 'line'}`. This is a different R5 surface than PV-01 (kwarg addition), PV-02 (opt-in via None default), or PV-03 (module-API alias preservation). The discipline: existing values must produce byte-identical behaviour; new values activate new code paths. Pinned by `test_function_scope_byte_identical_to_p08` + `test_module_scope_byte_identical_to_p08`. Adopt: when expanding a value set on an existing field, the existing values' code paths must be tested for byte-identicality, not just "still works".

2. **Comment-only YAML edits are a legitimate documentation primitive** - PV-04's `context_profiles.yaml +19 / -0` edit is **entirely comments** documenting the surgical_scope='line' augmentation. The file's runtime semantic is unchanged (no profile field changed). This is a legitimate self-documenting pattern - future readers of `context_profiles.yaml` see the line-tier reference without needing to read the patch history. Adopt: when a feature relies on a YAML config for context, add comment documentation to the YAML even if no semantic change is needed.

3. **The 240 line per-patch reference-doc ceiling is the right granularity** - PV-04 added 43 lines to `behavioral-guidelines.md` (final count 229 / 240 per-patch ceiling); this leaves 11 lines headroom for the next per-patch edit and 771 lines headroom against the 1000 Large-tier ceiling. The per-patch ceiling forces incremental growth (no one patch can dump 200 lines into a reference doc) which keeps reviews manageable. Adopt: every patch that touches a reference doc has a per-patch line ceiling enforced by test (`test_reference_size_budgets.py`).

4. **+519 LOC across 4 files merged in 23 minutes was the smallest PV in v8.2.0** - PV-04's tight scope (4 owned files, half the size of PV-01/PV-02/PV-03) made it the simplest review. The 23-min commit-to-merge window includes PR review + CI + `--no-ff` merge. Lesson: small surgical patches stay fast - when the patch can be sized to fit the smallest reasonable scope, do so.

5. **The existing `_select_behavioral_sections` / `_compose_behavioral_block` helper structure absorbed the new tier cleanly** - P-08 introduced these helpers with the 5-helper triad pattern; PV-04 added a single `_load_line_level_criteria` helper alongside, then branched the existing helpers to handle the new value. No restructuring of the existing helpers. This validates the v8.0.0 retro §4.9 pattern #1 ("the resolve / filter / apply 3-helper triad scales - refactor patterns established for cc-cleanup also support feature additions"). Adopt: helper triads designed for cc-cleanup are also extension points for tier-set expansions.

6. **19 new tests for a 4-file 519-LOC patch is within the v8.x test-overshoot pattern** - PV-04 tests are 7.5% of the LOC delta (344/519 = 66% if you include the test file). The 19/8 ratio (planned: >=8 tests; actual: 19) is the v8.x test-overshoot pattern in action (~140% over plan). Lesson: test-overshoot continues to be the v8.x norm, not the exception.
