# v22.1.0 Retrospective — Self-Contained npm Runtime Channel

## 1. Gaps identified

The feedback exposed a real npm-channel gap: skill files were installed
without the Python runtime required by operational commands, and npm doctor
only checked document parity. Python installation guidance also omitted the
3.11 floor and a managed-interpreter path. The reported tag gap was disproven:
remote release tags were current through v22.0.0; the evidence used
asciibetical `tail` output.

## 2. Implemented

- npm install/update now provisions the matching release-tagged Python package
  with uv and Python 3.13.
- Missing uv is bootstrapped through the official POSIX or Windows installer.
- Runtime failures preserve the installed skill files, record `docs-only`, and
  print a copyable repair command; `--no-runtime` is explicit.
- npm doctor probes `devola-version` and reports full-runtime, docs-only, or
  runtime-mismatch state.
- SKILL.md, the npm README, troubleshooting reference, demo release window,
  and version timeline document the channel contract.
- Version, test, ghost-audit, harness, and release-preflight evidence was
  refreshed for v22.1.0.

## 3. Deferred

- Broad migration of `python -m devolaflow.*` examples to dedicated console
  scripts remains deferred; this release documents the `uv run --with`
  escape hatch.
- Runtime provisioning remains an explicit `devola-flow install|update` step
  after npm package installation, rather than an npm lifecycle postinstall,
  so package installation itself has no network side effect.

## 4. Key learnings

The npm channel must describe both its document delivery and runtime
provisioning contracts. A pinned source tag is necessary but insufficient
without a Python-version strategy, and doctor needs a runtime probe rather
than inferring health from skill-file stamps. Release evidence should verify
tag listings with version-aware ordering instead of relying on `tail`.
