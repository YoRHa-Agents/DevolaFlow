## 1. TL;DR

The submitted P1 is valid: the npm channel installs skill documents but does
not install or detect the Python runtime required by operational workflows.
The submitted P2 is a measurement error: remote tags and release automation
are current through `v22.0.0`; the remaining gap is that the unpinned Python
install command does not tell operators how to match a skill copy to its tag.
P3 is valid: the package requires Python 3.11 or newer, but the channel does
not guide operators whose system Python is older.

This cycle will make npm installation self-contained while preserving the
thin package's zero npm dependency model:

1. Install skill files and provision the matching Python package with uv.
2. Bootstrap uv with the official platform-specific installer when absent.
3. Preserve successful skill installation if runtime provisioning fails, but
   report an explicit `docs-only` state and a copyable repair command.
4. Make `doctor` distinguish docs-only and full-runtime installations and
   report version mismatch.
5. Document runtime-dependent commands, tag-pinned installation, and the
   `python -m` escape hatch without rewriting all existing references.
