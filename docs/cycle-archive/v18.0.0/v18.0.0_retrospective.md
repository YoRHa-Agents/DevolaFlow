# v18.0.0 Retrospective — Consolidation Major

## 1. Gaps identified

The SI-1 analysis found cycle-closure debt, a coverage floor below measured
reality, oversized governance and implementation modules, an unbounded legacy
ghost suite, stale host-contract declarations, missing agent-facing language
enforcement, and two sidecar mechanisms that were not represented as L2 roles.
The harness ledger also lacked the consolidation metrics needed for a durable
W-16 comparison.

## 2. Implemented

- Settled the v15.1.0 and v17.4.0 archive debt and refreshed current-cycle
  research retention policy.
- Raised the global coverage floor to 90% and added a 70% per-module gate.
- Slimmed the compiled governance corpus and removed the unused Pattern 3
  advisory runtime path.
- Tiered legacy ghost tests, added per-gate timing, module-size ratcheting, and
  an import-cycle gate.
- Split the largest implementation modules into focused submodules.
- Aligned the DSH Host Support Contract with vendor-backed behavior and added a
  hard agent-facing CJK lint.
- Added the `preflight` and `harness_build` L2 task roles and wired their
  profiles, seeds, templates, and documentation.
- Added explicit `agents_md_tokens` accounting and settled the v18 harness
  evidence.

## 3. Deferred

- DSH web/progress UI and Tier-C host retention remain deferred because they
  would add new runtime or policy surfaces outside this consolidation major.
- The Pattern 3 persistent-state pool runtime remains deferred; only its dead
  advisory prewiring was removed.
- The unrelated `harness-construction.md` suggest-channel change remains
  deferred.

## 4. Key learnings

Consolidation work benefits from treating historical tests and generated
surfaces as contracts rather than deleting them opportunistically. Splitting
modules is safe when facades preserve public imports and import-graph checks
run before release. A coverage percentage alone is insufficient: per-module
floors exposed a newly split pipeline module that needed direct wrapper tests.
Finally, telemetry must distinguish measured current behavior from unavailable
historical evidence; the v18 baseline records both the harness summary and the
repository-level consolidation measurements.
