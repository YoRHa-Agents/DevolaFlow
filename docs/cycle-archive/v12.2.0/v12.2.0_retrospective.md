## 4 — Key learnings (process improvements for the next cycle)

### 4.1 Tooling-aware NineS coverage

NineS v3.3.0 is Python-AST-only at the analyser layer — it returns `0 findings` for markdown / blog post / X article inputs (PV-01 confirmed this on the cached Mnimiy article). The W-2 fallback "manual analysis following the same dimensions" works but is labour-intensive. **Recommendation for v12.3.0+**: standardise the W-2 fallback template (gap analysis cross-walk table + per-rule mapping) so future article-integration cycles can swap the article body without re-authoring the analysis structure.

### 4.2 W-16 wholesale regen timing

PV-01 attempted to regen the benchmark baseline at cycle start per the W-16 letter ("cycle start = the first PV after a tag bumps the MINOR digit"), but the v12.1.0 baseline stayed GREEN throughout PV-02 → PV-04. The wholesale regen was therefore DEFERRED to cycle close — only triggered when an actual regression surfaced. **Recommendation**: the W-16 §"per-PV regression is the delta from the wholesale baseline" semantic is correct, but the wholesale regen at cycle start is unnecessary overhead when subsequent PVs don't drift the baseline. Update W-16 wording to "wholesale regen MAY land at cycle start OR cycle close, whichever PV first observes drift"; the v12.2.0 cycle is the canonical example of the "regen-at-close" path.

### 4.3 Pre-existing working-tree corruption discovery

PV-01 surfaced a pre-existing corruption of `CHANGELOG.md` (7415 → 2628 lines deleted) and `tests/test_no_ghost_features.py` (9875 → 8089 lines deleted) BEFORE this cycle started. The corruption was restored from HEAD before PV-02 could proceed. **Recommendation**: future cycle-entry PV-01 SHOULD include an explicit `git status` + `git diff --stat HEAD` sanity check as the FIRST step before authoring the gap analysis. Add this to the SKILL.md §"Repo-Init Pre-Dispatch Contract" subsection in v12.3.0.

### 4.4 The "lifecycle hook extras are cleared by clear_hooks()" gotcha

PV-04's wiring tests initially failed when run after `tests/test_lifecycle_hooks.py` (which calls `clear_hooks()` to reset state between tests). The fix was to add a fixture (`hook_registered`) that re-registers the hook before each wiring test. **Recommendation**: document this pattern in `references/behavioral-guidelines.md` / lifecycle-hooks documentation — any future cycle adding a `pre_dispatch` extra will need the same fixture.

### 4.5 Article integration: "6 rules tuned to your failure modes beats 12 rules"

The Mnimiy article's own thesis (the empirical 41% → 11% → 3% mistake-rate data) is robust evidence that adding rules has diminishing returns past ~14 — but DevolaFlow's tiered taxonomy (S/A/C/W/BG) avoids the cognitive overload because each load surface (Soul + Architecture + Conventions + Workflow + BehavioralGuidelines) is independently ≤ 14 entries. PV-03 added 3 BGs (now 7 total) which stays well under the per-layer 14-cap. **Recommendation**: document the "per-layer 14-cap" interpretation in `.rules/architecture.mdc` for the v13.0.0 cycle (would be an A-* rule extension, but stays out of scope for v12.2.0).
