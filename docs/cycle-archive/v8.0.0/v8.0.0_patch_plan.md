## 10. 每 patch 后 self-update workflow 标准化模板

每个 v8.0.0 patch 落地后, 必须运行 `self-update` workflow (workflow type: `self-update`)。该 workflow 沿用 `workflow-system/agent/templates/builtin/self-update.yaml` 的 7-stage 设计 (假设该模板已存在, 见 v7.5.0 P-08 删除 `team_overrides: {}` 时确认)。

### 7 stages 标准化定义

| Stage | 名称 | 输入 | 输出 artifact | 关键 gate |
|-------|------|------|---------------|-----------|
| 1 | **check-refs** | `workflow-system/agent/knowledge/reference-dependencies.yaml` 全部 `active_tracking` 条目 | `.local/research/v8.0.0_p<NN>_check_refs.json` (含 NineS / Karpathy / EvoBench 仓库的 last-checked timestamp + diff) | C5 (biweekly Karpathy check 在 v8.0.0 周期内 ≥ 28 天必触发 ≥ 2 次) |
| 2 | **research-updates** | check-refs 输出 | `.local/research/v8.0.0_p<NN>_research_updates.md` (含外部 ref 的关键 diff 摘要) | 若 reference-dependencies 中任一 active_tracking 条目有 breaking change → 注入 v8.1.0 gap analysis |
| 3 | **decompose** | research-updates + 当前 patch 的 file diff | `.local/research/v8.0.0_p<NN>_decompose.md` (含本 patch 的 cc delta + LOC delta + NineS finding delta + EvoBench delta 估算) | S-4 / CP-1 ghost-feature 检查 (本 patch 引入的新声明必须有对应实现) |
| 4 | **integrate** | decompose 输出 | `CHANGELOG.md` 新增 `[8.0.0-p<NN>]` entry (per-patch entry, 含 §"Added" / §"Changed" / §"Removed" / §"Tests" 标准 sections) | C-3 / CO-2 verbatim extraction (entry 中所有 path/metric/commit hash 逐字提取, 严禁 paraphrase) |
| 5 | **test** | integrate 输出 + 本 patch 的源代码 | `pytest tests/ -q` + `ruff check src/ tests/` + `ruff format --check` + `pytest tests/test_version.py -v` + `pytest tests/test_benchmarks.py -v` + `make check-cursor-skill` 全 PASS | W-9 / SI-10 6/6 必 PASS; 任一失败立即 ROLLBACK + 重新 dispatch |
| 6 | **evaluate** | test 输出 + 本 patch 的最终状态 | `.local/research/v8.0.0_p<NN>_micro_retrospective.md` (含 4 sub-sections: gaps closed / what was implemented / what was deferred / key learnings) | NineS deep analyze 二次跑 (W-2 / SI-2), 取 finding count delta (相对 §2.2 12 项基线); EvoBench delta 必须 ≥ patch 在 §3 中声明的 delta (容差 ±2pp) |
| 7 | **release** | evaluate 输出 | git commit `chore(release): DevolaFlow v8.0.0-p<NN> — <patch_short_name>` + lightweight tag `v8.0.0-p<NN>` (区别于最终 ANNOTATED `v8.0.0` tag, 沿用 v7.5.0 cycle 的命名约定) | 不打 ANNOTATED tag (那是 v8.0.0 / v8.1.0 / v8.2.0 三个里程碑的专属); 必走 PR 流程 (`feat/v8.0.0-p<NN>-<short>` 分支 → PR to main → merge) |
