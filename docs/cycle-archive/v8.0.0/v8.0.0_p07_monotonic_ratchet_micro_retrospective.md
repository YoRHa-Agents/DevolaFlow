## 1. Gaps Identified

`.local/research/v8.0.0_patch_plan.md` §1 capability table line 67 + §3 P-07 (lines 295-324) jointly flagged this as the **single largest architectural gap in the v7.8.0 baseline** — verbatim from the capability table:

> *"4.11 | 单调递进保障 (Ratchet) | 完全缺失 (G13, 最大架构缺口) | `[NineS:CC-448821-0001]` cc=11 (`apply_round_escalation`) | P0 | **P-07** (与 `apply_round_escalation` 重构耦合, Task A §7.2 决议 3)"*

The four ground-truth gaps closed by this patch:

- **Gap 4.11 (G13) — Monotonic Ratchet completely missing.** At the v7.8.0 baseline, multi-round convergence loops could regress silently from a previously-attained best score, wasting tokens and masking real degradations. Verbatim from commit body line 5: *"multi-round convergence loops could regress silently from a previously-attained best score, wasting tokens and masking real degradations"*. There was no recorded `best_score`, no `RatchetAction` decision surface, no rollback path, no escalation trigger when post-rollback rounds still under-perform. Round N+1 < Round N was treated as just another data point rather than a regression signal.
- **Gap C4 sub-item — NineS finding `[NineS:CC-448821-0001]`** — verbatim from §2 NineS finding table (line 88): *"warn | 11 | `src/devolaflow/task_adaptive_selector.py:543` | `apply_round_escalation` | **P-07** | 拆 `escalate_round()` + `apply_severity_filter()` + `select_round_result()`, cc 目标 ≤6/each"*. The `apply_round_escalation` function had cyclomatic complexity 11 (target ≤ 6 per AC #6), inlining round selection + severity filtering + escalation decision in a single waterfall.
- **Karpathy non-gameable success criteria gap.** Pre-P-07, no oracle scoring function existed that excluded review_findings. Any S/O/R-attack agent (Sycophancy / Optimisation-mismatch / Reward-gaming) could lift its perceived score by silencing or fabricating review findings — the ratchet would have been gameable. Per AC #5: *"`compute_deterministic_oracle_score()` 输出仅基于 test+lint+build, `review_findings` 改动不影响该子集分数 (S/O/R 不可博弈原则)"*.
- **Convergence orchestrator integration gap.** `gate/convergence.py` had no bridge helper to thread a `MonotonicRatchet` into a `list[ConvergenceRound]`. Orchestrators that wanted ratcheted convergence had to reimplement the round-recording protocol — a guaranteed source of drift between callers.

Critical-path role: P-07 sits at the **mid-point of the v8.0.0 critical path** per patch_plan §5 line 549: *"整体关键路径: `P-03 → P-05 → P-07 → P-10` (4 patches, Wave 2 → Wave 5)"*. P-07 is also explicitly the **G13-closure patch** — the highest-value architectural deliverable in the entire v8.0.0 cycle (G13 = "largest architectural gap" per §1 capability table line 67).

## 3. What Was Deferred and Why

### 3.1 Wiring into `evaluate_gate` / `evaluate_ladder` — **DEFERRED** (orchestrator opt-in only at v8.0.0 cut)

**Verbatim from `scripts/detect_dead_apis.py` allowlist comment** (lines 97-104 of the diff):

> *"`record_round_with_ratchet` is the canonical way to append to `list[ConvergenceRound]` AND record on `MonotonicRatchet` in one call; `detect_ratchet_escalation` short-circuits the stagnation path when the ratchet's most recent verdict is `ESCALATE`. **Not yet wired into `evaluate_gate` / `evaluate_ladder` at v8.0.0 cut — orchestrator opt-in only** (matches the `evaluate_ladder` allowlisting precedent above)."*

The 5 new public APIs (`record_round_with_ratchet`, `detect_ratchet_escalation`, `select_round_result`, `apply_severity_filter`, `escalate_round`) are **allowlisted in `detect_dead_apis.py`** — they are intentionally exposed to L0/L1/L2 orchestrators but not yet auto-invoked by the gate. **Rationale**: keeping the wiring opt-in preserves the `ratchet=None` byte-identical default contract and lets the v8.0.0 release ship the ratchet primitive without forcing every existing convergence consumer to re-test. Auto-wiring is queued for v8.1.0 once at least one orchestrator (likely the v8.0.x SI-1 dogfooding loop) has battle-tested the ratchet on production traffic.

### 3.2 EvoBench scenarios `ratchet_rollback.yaml` + `ratchet_advance_chain.yaml` — **DEFERRED to v8.0.x**

Per patch_plan §3 P-07 line 311: *"EvoBench delta: 新 2 scenarios `ratchet_rollback.yaml` + `ratchet_advance_chain.yaml` composite ≥ 88; 既存 `convergence_noise_filter` 与 `feedback_regression` 预期 +1-2pp (ratchet 防退步)"*. P-07 shipped with **0 new EvoBench scenarios** — only the existing 36 scenarios were verified at 0pp drift. **Rationale**: EvoBench scenario authorship is a separate workstream (W-13 / CP-6 trigger); the new ratchet scenarios are queued for the v8.0.x rollup. The 36/36 0pp drift result is the strict minimum for AC #8; the +1-2pp uplift on `convergence_noise_filter` / `feedback_regression` is a stretch goal not yet measured.

### 3.3 Schema layout extension for ratchet artifact snapshot — **CORRECTLY DEFERRED (architectural decision)**

P-07 explicitly does **NOT** add a top-level `ratchet` field to `schemas/lean-dispatch.yaml`. Per commit body §"Schema invariant": *"The ratchet is a pure runtime concern with no top-level dispatch payload field"*. **Rationale** — pinned by P6 / ADR-001 §2: the ratchet's state is per-orchestrator and per-convergence-loop, not per-dispatch. Adding a top-level field would (a) inflate the cached prefix for every dispatch (P-02 compaction loss), (b) force every L3 task agent to deserialise ratchet state it doesn't need (S-2 minimal context violation), (c) leak the convergence layer's internal bookkeeping into the L3 contract (P5 artifact-as-contract pollution). The runtime-only design is the correct one.

### 3.4 CHANGELOG entry — DEFERRED to aggregate `[8.0.0]` rollup at S05 G1

Same pattern as P-01 / P-02 / P-03 / P-04 / P-05 / P-08 / P-11 / P-13. The aggregate entry will reference P-07 by tag + G13 closure + 4-verdict ratchet primitive + S/O/R-resistance proof + `apply_round_escalation` cc 11→2 refactor + 85-test suite + closure of NineS `[CC-448821-0001]`.

### 3.5 Other deferrals

- **Per-profile `regression_tolerance` / `max_regressions` overrides** — DEFERRED to v8.0.x. Currently both are class-level constants (`DEFAULT_REGRESSION_TOLERANCE = 0.02`, `DEFAULT_MAX_REGRESSIONS = 2`). A future iteration may want STRICT profile to enforce 0.01 tolerance + 1 max regression, while RELAXED stays at the lenient defaults.
- **Ratchet artifact compression / archival policy** — DEFERRED. The append-only `RatchetLogEntry` log grows unboundedly across long-running convergence loops; v8.0.0 ships with no rotation policy. v8.0.x candidate: add `max_log_entries` with FIFO eviction once the archive crosses N entries.

## 4. Key Learnings

- **Opt-in-by-default with `ratchet=None` is the v8.x backward-compat pattern for additive runtime primitives.** P-07's contract is `evaluate_gate(..., ratchet=None, ratchet_artifact=None)` — the default `None` value preserves byte-identical pre-P-07 behaviour for all existing callers, while opt-in callers can thread a `MonotonicRatchet` instance. This is the same pattern P-04 used for `evaluate_ladder` (allowlisted in `detect_dead_apis.py` for orchestrator opt-in). **Codify** for v8.x: every additive runtime primitive (ratchet, complexity_detector, cycle_detector, ...) MUST default to `None` in the scorer signature, MUST be allowlisted in `detect_dead_apis.py` with a comment explaining the orchestrator-opt-in rationale, MUST have a regression test proving byte-identical behaviour when omitted. The 391 existing tests passing unchanged is the regression pin.
- **S/O/R-resistance is a non-negotiable property of any oracle in the convergence loop.** `compute_deterministic_oracle_score()` consults EXACTLY 3 fields — test_results, lint_status, build_status — and zero subjective signals. The `TestOracleSORResistance` test class (4 tests) pins the contract: adding 50 blocker findings, mutating finding severity, zeroing acceptance / visual / interaction / accessibility checks all leave the oracle unchanged. **Adopt** as v8.x architectural rule: any function whose output drives a ratchet, rollback, or escalation decision MUST have a "S/O/R-resistance" test class proving its inputs are confined to non-gameable signals (compiler output, test runner output, lint/format tool output — never LLM judgements, never review findings, never self-reported metrics). This is the single most important defense against reward-hacking in long-horizon convergence.
- **Cyclomatic-complexity refactor recipe: extract 3 named helpers, target parent cc ≤ 4.** P-07 took `apply_round_escalation` from cc 11 to cc **2** (target was ≤6 per AC #6, exceeded by 4×) by extracting `select_round_result` (cc 4) + `apply_severity_filter` (cc 3) + `escalate_round` (cc 4). Each helper is single-responsibility, named after its semantic role (not implementation detail), and individually under cc ≤ 4. Result: `task_adaptive_selector.py` has **zero non-A-rank functions** — the entire file passes radon's strictest filter. **Adopt** as v8.x canonical refactor recipe (refines the v8.0.0-p08 5-helper recipe for `select_context`): when a cc-11 function spans 3 conceptual phases (select / filter / escalate), prefer 3-helper extraction over 5; the lower helper count keeps the call graph shallower and the parent function trivially scannable. The pattern: parent function becomes a **3-line orchestrator** that calls the 3 helpers in sequence, dropping cc to 2 (1 if-statement + 1 implicit return).
- **Type-checking-only imports keep the convergence/scorer dependency graph one-directional.** `gate/convergence.py` imports `MonotonicRatchet` ONLY under `TYPE_CHECKING:` to avoid creating a `convergence → ratchet` runtime cycle (since `ratchet` could one day need convergence types for context). Verbatim from commit body line 18: *"TYPE_CHECKING-only import keeps the dependency graph one-directional"*. **Adopt** as v8.x discipline: when a new gate primitive needs to be referenced from a sibling module purely for type hints, use `if TYPE_CHECKING:` imports + string annotations. The runtime dep graph stays a DAG; type-checkers still validate. This is critical for future plugin-style additions (e.g., a custom scorer that wants to type-check against `MonotonicRatchet` without forcing a runtime import).
- **Append-only `RatchetLogEntry` log is the audit trail for convergence forensics.** Every `record_round` call appends an entry; entries are never mutated or deleted. **Rationale**: when a convergence loop hits ESCALATE, the human reviewer needs to see the full sequence of (round_num, score, verdict, artifact_hash) tuples to diagnose whether the agent was over-iterating, oscillating, or honestly stuck. Mutable logs would let an S/O/R-attacker rewrite history after the fact. **Adopt** as v8.x rule: any state machine whose decisions feed into ESCALATE / ROLLBACK / human-handoff paths MUST keep an append-only log of its inputs and verdicts. The forensic value at debug time (and the audit value at trust-but-verify time) outweighs the small memory cost.
- **G13 closure is a v8.0.0 watershed for the convergence layer.** Before P-07, the convergence loop had no architectural guarantee against silent regressions. After P-07, the loop has a 4-verdict state machine + S/O/R-resistant oracle + append-only log + 100% test coverage on the new module. The "completely missing" status (verbatim from §1 capability table) becomes "shipping with 100% module coverage and 85 test scaffolding". **Document** in the v8.0.0 retrospective (S05 G1): G13 closure is the single most architecturally significant deliverable in the v8.0.0 cycle — outranking even the first P6 schema touch (P-08), because it closes the **largest** gap (per §1 capability table line 67: *"完全缺失 (G13, 最大架构缺口)"*). Future cycles inherit a convergence loop that physically cannot regress silently.
- **9-min commit-to-merge is the v8.x cadence target for opt-in primitives.** P-07 achieved 9-min commit-to-merge — fastest of the S03 patches. Compare: P-08 took 22 min (forced 2-commit feat+coupling split for SF-4 cascade). The differentiator: **opt-in primitives have zero coupling cost** — no SKILL.md row, no mirror cascade, no human-doc regen, no SF-4 reference set extension. **Adopt** as v8.x design heuristic: when designing a new primitive, ask "does this require a SKILL.md row or a new canonical reference?" — if no, the patch can ship in a single commit and merge fast (~10 min); if yes, budget ≥20 min for the coupling commit per the P-08 / P-11 precedent. The 9-min cadence is the upper bound on velocity for opt-in primitives; protect it.
- **Critical-path mid-point is the highest-leverage failure mode.** P-07 sits at position 3 of the 4-patch critical path (`P-03 → P-05 → P-07 → P-10`). If P-07 had REJECTED, P-10 (Wave 5, end of critical path) would have been blocked. Per patch_plan §5 line 679 R6 mitigation: *"若 P-07 必须 REJECT, 启用降级路径: P-09/P-10 用简化 ratchet stub (best_score 单调比较, 无 rollback)"*. The mitigation **was never invoked** because P-07 passed all 8 ACs cleanly, but the contingency design itself is a key learning: **always design a downgrade path for critical-path patches** so that a single-patch REJECT doesn't cascade into a full-cycle blockage. The downgrade path for P-07 (single-best comparison, no 4-verdict state machine, no rollback, no escalate) was a 1-day implementable fallback — small enough to be credible, large enough to not be free.
