## 2. What Was Implemented

Single-commit patch (`5076b42`) modifying **8 files**: `+1219 / -0` (insert-only). 6 owned files per plan §3 P-03 lines 179-185 + 2 strictly-necessary coupling files (`gate/__init__.py` re-export + `scripts/detect_dead_apis.py` allowlist) — same coupling pattern as P-02 used for `directed_compact`.

**New module — `src/devolaflow/gate/budget.py` (~296 lines, verified `wc -l = 296`)** — `class TokenBudgetBreaker` with three-path circuit breaker semantics (verbatim from commit body):

```
check(cumulative_tokens)  -> BudgetDecision      (pure)
record(delta)             -> int (running total) (stateful)
check_recorded()          -> BudgetDecision      (stateful helper)
reset()                                          (round boundary)
```

**Decision semantics** (verbatim from commit body):

```
utilization < 0.75            -> CONTINUE (recommendation NONE)
0.75 <= utilization < 1.00    -> WARN     (recommendation THROTTLE)
utilization >= 1.00 + STRICT  -> BREAK    (recommendation ESCALATE)
utilization >= 1.00 + AUDIT   -> BREAK    (recommendation ESCALATE)
utilization >= 1.00 + others  -> BREAK    (recommendation ITERATE)
```

Pure semantics on `check()`; honors **S-5 (No Silent Failures)** on every invalid input (negative tokens / negative budget / non-`GateProfile`) — raises `ValueError` / `TypeError` rather than silently degrading.

**Factory `from_profile_name(name, max_tokens=None)`** resolves profile name → breaker; unknown names log WARNING and fall back to STANDARD (the warning is logged, not silently swallowed — S-5 honored).

**Profile defaults (verbatim from commit body, per patch_plan §3 P-03 lines 183-184)**:

| Profile | `max_tokens` | BREAK recommendation |
|---|---:|---|
| STRICT | 80_000 | ESCALATE |
| STANDARD | 50_000 | ITERATE |
| RELAXED | 0 | unlimited (disabled) |
| AUDIT | 100_000 | ESCALATE |

**`max_tokens=0` is the byte-identical pre-P-03 path** — the breaker is a no-op for any cumulative count; this is the AC #2 contract that lets `evaluate_gate(breaker=None)` remain byte-identical to v7.8.0 for all existing callers.

**Schema — `schemas/lean-dispatch.yaml`** — NESTED `gate.token_budget` field added under `lean_format_spec.gate`. **TOP-LEVEL `layout_invariant.canonical_order` length stays 13, `version` stays 2** (P6 / A-2 cache-layout invariant preserved per ADR-001 §2 additive rule). Field shape (verbatim from commit body):

```
token_budget:
  max_tokens: int    # 0 = unlimited
  warn_at:  float    # default 0.75 (utilization)
  break_at: float    # default 1.00
```

**`gate/scorer.py::evaluate_gate(..., breaker=None, cumulative_tokens=None)`** integration (verbatim from commit body):

```
details = { budget_break: True, budget_action, budget_recommendation,

```

## 3. What Was Deferred and Why

- **Out-of-scope file expansion: 8 files vs 6 owned (single-commit, 2 OOB files explicit-not-silent in commit body).** The 2 coupling files are: (a) `src/devolaflow/gate/__init__.py` (re-exports the 5 new public symbols + 2 threshold constants — *"the package `__init__` already re-exports every other public gate symbol; adding the new ones is required for API consistency"*); (b) `scripts/detect_dead_apis.py` (allowlists `devolaflow.gate.budget:from_profile_name` — same convention as P-02 used for `directed_compact` and P-11 for `entropy_manager.cleanup`). Both are documented in the commit body's *"Coupling-required updates (out of the 6 owned files)"* section. **Acceptable to collapse into a single commit at 2 OOB files** (compare P-11 which split at 7 OOB files); future patches with ≥3 OOB should follow P-11's `feat(...) + coupling(<patch-id>)` pattern per the v8.0.0 retrospective recommendation.
- **`from_profile_name` factory has no in-repo production call site at v8.0.0 cut.** Verbatim from commit body: *"The factory IS exercised by tests/test_gate_budget.py but has no in-repo production call site at the v8.0.0 cut — direct construction via `TokenBudgetBreaker(profile=PROFILES[name])` is the in-repo pattern."* The `detect_dead_apis` allowlist entry is the explicit acknowledgment. The factory is intentionally exposed for **external dispatcher** consumption (the LLM dispatcher will call `TokenBudgetBreaker.from_profile_name(profile_name)` in round-by-round wiring, expected to land in P-07 or P-09). **Not a deferred bug** — deliberate forward provisioning.
- **`per_round` token budget — DEFERRED to P-09 (overcomplexity detector) or future grooming.** Plan §3 P-03 line 184 originally listed `max_tokens_per_round: int = 0` as an additional GateProfile field, but the as-shipped P-03 only ships `max_tokens` (per-task / cumulative). The per-round variant is naturally consumed by P-09's complexity-detector convergence work (per plan §3 P-09 owned-files). Splitting it out also keeps P-03's owned-files scope tighter. **Action item for P-09 dispatcher**: if the per-round budget is still needed, P-09 should add it as a `gate/profiles.py` field rather than re-touching `gate/budget.py`.
- **`STANDARD` profile BREAK → ITERATE rather than ESCALATE.** Per profile defaults table: STANDARD = 50_000 / ITERATE; STRICT and AUDIT both go to ESCALATE; RELAXED is disabled (unlimited). The choice means a STANDARD-profile budget breach triggers another convergence iteration rather than human escalation. Rationale: STANDARD is the "iterate-and-recover" profile (the convergence loop has its own max_iterations cap from P4 bounded retry); ESCALATE is reserved for STRICT (high-stakes paths) and AUDIT (compliance paths). **Documented in commit body and patch_plan §3 P-03 line 199**; not a deferral, but worth flagging for retro readers as a deliberate semantics choice that was discussed and intentionally split per profile.
- **CHANGELOG entry for P-03** — DEFERRED to **aggregate `[8.0.0]` rollup at S05 G1**, same pattern as P-01 / P-02 / P-11 / P-13. The aggregate entry will reference P-03 by tag + new module + new schema field (NESTED) + 84-test addition + critical-path-clearance role.

## 4. Key Learnings

- **`breaker=None` byte-identicality is the defining ergonomic for opt-in gate features.** P-03's AC #2 (`evaluate_gate(breaker=None)` byte-identical to v7.8.0) is exhaustively tested across all 4 profiles + multiple gate types (passthrough / acceptance_readiness / abort) by `TestEvaluateGateByteIdentityWithoutBreaker` + `TestV780ByteIdentityRegression`. This is the same `directive=None` pattern P-02 codified for compressor — applied here to a gate-side opt-in. The result: zero existing callers needed to change, and any future gate test that picks up `breaker=None` is guaranteed to behave like v7.8.0. **Codify** in v8.x: any new gate parameter MUST default to a value that produces byte-identical pre-existing behavior, AND must ship a regression test class named `TestEvaluateGateByteIdentityWithoutX` to lock that contract in.
- **Three-path semantics (CONTINUE / WARN / BREAK) generalize beyond token budgets.** P-03's three-path circuit breaker shape is a template for upcoming P-09 (overcomplexity detector) and the future overspend / fan-out detectors. The 0.75 / 1.00 thresholds + 4 recommendations (NONE / THROTTLE / ITERATE / ESCALATE) generalize cleanly — any "monitor a metric, warn at 75% of cap, break at 100%, escalate vs iterate based on profile severity" detector should reuse this shape. **Recommend** for v8.x: extract `BudgetDecision` / `BudgetAction` / `BudgetRecommendation` into a shared `gate/_breaker_base.py` (or keep as the de-facto template) so P-09's complexity detector + any future detectors (rate / fan-out / depth) can reuse.
- **100% line coverage on a new gate module is achievable AND mandatory.** P-03 hit 100% line coverage on `gate/budget.py` (well above CP-2's 80% floor). With 84 tests across 17 classes (target was ≥20 tests), the cost was high upfront but eliminates all future dead-code or untested-branch surprises. **Adopt** as v8.x standard: every new `gate/*.py` module ships at 100% line coverage at first merge — gate behavior is too critical to leave coverage gaps.
- **STRICT profile = ESCALATE at hard ceiling is the correct default for production safety.** Verbatim from AC #6: STRICT (max_tokens=80_000) at cumulative=80_001 returns `BREAK + ESCALATE`. This converts a "silent runaway round" into a "human-escalation event" the moment the hard cap is breached — exactly the S-5 (No Silent Failures) intent. STANDARD's BREAK→ITERATE is a softer fallback for the iterate-and-recover use case, but STRICT's hard ESCALATE is what makes the breaker production-safe. **Reinforce**: any future profile classified as "production / high-stakes" MUST ship with BREAK→ESCALATE; only "iterative / experimental" profiles may use BREAK→ITERATE.
- **Schema `version` stay-at-2 is a stronger contract than `canonical_order` length stay-at-13.** P-03's schema edit added `gate.token_budget` as NESTED — `canonical_order` length stays 13 AND `version` stays 2. Both byte-baseline tests (v7.0.0 + v7.3.0) PASS unchanged. The `version` invariant is actually the *stronger* contract because it implies "no consumer needs to migrate"; the `canonical_order` length is just the cache-prefix proxy. **Update the P6 / A-2 documentation** to make this two-invariant contract explicit: a NESTED-field schema edit should not bump `version`, only TOP-LEVEL additions (which P-08 + P-10 are pre-authorized to do per plan §S03 / §S05) should bump `version` to 3.
- **Critical-path patches must default to risk-isolation defaults.** P-03 sits on the longest critical chain (P-03 → P-05 → P-07 → P-10, length 4). The risk-isolation discipline applied: (a) `max_tokens=0` is the v7.8.0-byte-identical default, (b) `breaker=None` is the v7.8.0-byte-identical `evaluate_gate` default, (c) v7.0.0 + v7.3.0 byte-baselines tested unchanged, (d) 100% line coverage. **Reinforce**: every patch on a critical path of length ≥3 in the wave-DAG MUST adopt the same defaults — additive-only, default-disabled, byte-identicality regression-tested.
- **Insert-only diff (`+1219 / -0`) is the safest possible new-module pattern.** P-03 added 1219 lines and removed 0 — no existing content modified, deleted, or reordered. Same insert-only discipline P-13's retro called out for doc-debt patches, applied here to a new gate module. The diff was trivially reviewable AND eliminated any merge-conflict risk against the in-flight P-04 (which touches `gate/scorer.py` `_evaluate_checks` — a different function from P-03's `evaluate_gate` integration). **Recommend**: new-module patches should default to insert-only and explicitly justify any modify/delete in the PR description; in-place gate edits (P-04, P-05, P-06, P-07, P-09) need to be sequenced via wave ordering rather than relying on insert-only.
- **`detect_dead_apis` allowlist as a forward-provisioning marker.** P-03 (and P-02 + P-11) all allowlisted their new public symbols even though no in-repo call site existed yet. This converts "potential dead code at the v8.0.0 cut" into "deliberate forward provisioning for external consumers" with an auditable record. **Adopt** as the canonical v8.x pattern: every patch that exposes a new public symbol consumed by external dispatchers should add the allowlist entry in the same patch, with a comment explaining the consumer (e.g., `# consumed by external dispatchers via TokenBudgetBreaker.from_profile_name`).
