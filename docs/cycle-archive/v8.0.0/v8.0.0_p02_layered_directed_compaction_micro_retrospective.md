## 4. Key Learnings

- **Pre-declare ALL coupling files in the dispatch — the "≤6 owned" budget should include OOB propagation slots.** P-02 touched 12 files because adding `directed_compact` to the public surface forced README scenario-count tick + demo HTML + dead-API allowlist + benchmark baseline regen as mathematical consequences. P-11 (next patch) handled this more cleanly by splitting into 2 commits (`feat(entropy)` for owned files + `coupling(P-11)` for the 7 invariant pins); P-02's single-commit collapse is harder to bisect. **Recommendation for next-iteration dispatcher**: for every patch that touches (a) public symbol surface, (b) an EvoBench scenario count, or (c) a `template_count` / `profile_count` numeric, automatically widen the owned-files budget to include `README.md + workflow-system/human/demo/*.html + scripts/detect_dead_apis.py + benchmarks/devolaflow_context/baselines/<v>_baseline.json` slots (call them "coupling slots" in the lean dispatch, distinct from "core slots").
- **Splitting feat-vs-coupling commits aids bisect.** P-11 (next patch) demonstrated this best practice: `02d4ff8 feat(entropy)` + `f68710e coupling(P-11)`. P-02 collapsed both into `03b9fb0` — works fine for green path but harder to bisect if a later regression is traced to (e.g.) the `v7.8.0_baseline.json` regen vs. the actual algorithm change. **Adopt** the 2-commit-per-patch convention (`feat(...)` + `coupling(<patch-id>)`) as the default for any patch with ≥2 OOB files.
- **`directive=None` byte-identicality is a powerful regression-defense pattern.** P-02 added `directive: dict | None = None` to **two** functions (`_select_sections_by_priority` in compressor + same name in task_adaptive_selector), with the explicit contract that `directive=None` is byte-identical to v7.x. Two test classes (`TestSummarisePredecessorRefactor::test_directive_none_byte_identical` + `TestSelectorDirectiveBackwardCompat`) lock this in as forward-acting regression guards. **Reinforce** in v8.x: every "extend with optional dict overlay" pattern should ship with a `default=None` byte-identicality regression test in the same patch — converts a future-merge-hazard into a tested invariant.
- **`max_drop_pct` as a hard ceiling beats "best-effort" wording.** `directed_compact(focus_keywords, max_drop_pct=0.20)` makes the worst-case behavior numerically auditable: the function MUST drop ≤20% of total characters, and focus paragraphs MUST never be dropped (the test class `TestDirectedCompact` has 17 tests spanning pass-through / focus retention ≥80% / drop ≤max_drop_pct / edge cases). This shape is preferable to an opaque "tries to keep focus content" heuristic. **Adopt** as the canonical pattern for v8.x compaction work: every text-level compaction API should expose a hard `max_drop_pct` ceiling rather than a "try to keep" heuristic — this also lets P-12's abstractive engine inherit a clean numeric SLA.
- **EvoBench baseline regen at the same patch boundary as a scenario-count change is the cleanest pattern.** P-02 regenerated `v7.8.0_baseline.json` simultaneously with adding 2 new scenarios — this resolved a pre-existing tiktoken/no-tiktoken drift on `compression_retention_medium` and `design_workflow` *at the same time* as expanding the suite from 39 → 41 scenarios. Doing the regen in a separate patch would have either (a) left the existing 39 with stale baselines longer, or (b) doubled the SI-4 verification surface for the 2-new-scenarios PR. **Recommend** the joint pattern (`new scenarios + baseline regen + dead-API allowlist`) as the default for EvoBench-touching patches in v8.x.
- **`recency_decay_factor: 0.9` default is conservative — observe the 3 sensitive scenarios.** P-02's plan §3 line 157 predicted `compression_retention_easy/medium/hard` would drift `+2-3pp` from recency decay. Actual measured drift was 0pp (PR #61 §EvoBench Verification: *"39 existing scenarios: 0 regression >5pp"*); with the conservative 0.9 default, the recency overlay barely activates on existing scenarios because they're single-round. **Action item for v8.x convergence-loop work** (P-07 / P-09): when round_count ≥ 3, the 0.9 default compounds to ~0.73 weight at round 5 — measure whether this is too aggressive for multi-round predecessor stacking and consider `recency_decay_factor: 0.95` as a tunable for `complex_feature` profile.
- **P6 invariant safety via NESTED-only fields lets schema grow without cache-prefix invalidation.** P-02 added `pred[*].compact_directive` as a NESTED field under an existing top-level key (`pred`); `canonical_order` length stays 13 and `version` stays 2. This is exactly the pattern A-2 / ADR-001 §2 mandates. Two byte-baseline tests (v7.0.0 + v7.3.0) PASS unchanged post-patch — proof the cached-prefix contract is intact. **Reinforce**: every v8.x patch that adds dispatch-payload fields should default to NESTED-under-existing-key; only P-08 + P-10 are pre-authorized to extend `canonical_order` (per plan §S03 / §S05 schedule).
