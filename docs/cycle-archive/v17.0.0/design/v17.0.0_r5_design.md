## 2. 设计决策

### D-R5-1 容量/阈值配置化 + guard 语义（B6）

新暗配置 NEST：`context_profiles.yaml#meta.capacity`（键缺省 → 现字面值字节等价）：

```yaml
meta:
  capacity:
    round_capacity: 5        # 1..5（stage schema 硬顶不变）
    max_concurrency: 4       # 1..8
    stop_guard:
      stagnation_rounds: 2   # 1..5
      unsuccessful_item_rounds: 3  # 1..6
```

1. **单一 reader**：新 `src/devolaflow/harness/capacity.py::capacity_profile(profiles_path=None) -> CapacityProfile`（frozen dataclass，含 `source: "config"|"default"` 逐字段溯源）。round_engine / dispatch_executor / preflight_runtime / telemetry 的四处字面值改为经此 reader 取默认（模块常量保留为 fallback，测试 pin 不动）。A-5：capacity.py 是唯一 owner，消费方 import，不得本地重定义。
2. **提案闭环接通**：`meta.capacity.*` 四条路径加入 `_AUTO_CONFIG_TARGETS`（范围校验同 layer_token_budgets 先例）；提案生成按 `model_hint` 允许建议覆写（frontier 档可提并发/容量上调建议，需人审 apply——apply 路径本身已存在）。`stage.capacity_per_round` 保持 `CHANGE_REQUIRED` 不动（per-change 人审语义不变）。
3. **guard 语义落点（本轮克制）**：容量约束的"guard 化"定义为——数值进入可机器校验、可提案调优的配置面（guard = machine-verifiable + tunable）。**不**改 `summarize_constraints` 的 quantifiable_ratio 计数（避免重 pin 30+ fixture 期望值）；账本记录（非 dispatch payload）追加 `capacity_profile: {round_capacity, max_concurrency, source}`（附加于 `slice_savings_pct` 之后，键序 pin 保持）。tier 计数整合列入 v18 SI-1 候选。
4. **并发 4 vs 文档 5 的不一致裁决**：两者是不同轴——wave 任务上限 5（容量）vs 执行器同时并发默认 4（吞吐）。不改值；在 `references/agent-hierarchy.md` §5 补一句区分措辞。

### D-R5-2 probe 模型表配置驱动

1. 新暗配置 `context_profiles.yaml#meta.probe_models`：`[{provider, model}, ...]` 列表；键缺省 → CLI 现单模型行为字节等价。
2. `harness/__main__.py` probe 子命令：`--model` 省略且配置表存在 → 逐模型 sweep `run_probe`，每模型独立 profile JSON（`PROFILE_KEYS` schema 不变，一模型一份）；`--model` 显式给出 → 现行为原样。
3. `llm_client._DEFAULT_MODELS` **不动**（字节兼容 fallback；模型 ID 刷新属操作者配置行为，写进 references 说明，不硬编码猜新 ID）。
4. 新 reader `harness/probe.py::load_probe_model_table(profiles_path=None)`（或置于 capacity.py 同级——实现者定，owner 唯一即可）。
