# v17.0.0 R4 设计 — focus/loop（B4 goal/loop 适配层 + 自动 checkpoint/resume）

* 日期：2026-08-25
* 输入：G17-B4（`.local/research/v17.0.0_gap_analysis.md:29`）+ R4 focus/loop 面调研
* 分支（待建）：`feat/v17-r4-focus-loop`（R3 合并后自 main）

## 1. 事实基线（调研锚点）

* 轮次引擎（`agent_workspace/round_engine.py`）：`evaluate_round_pass` 纯函数无 IO，PASS 后**没有任何自动 checkpoint 生产者**；`write_checkpoint`/`load_checkpoint`（`checkpoint.py:202`）今天无自动触发方。
* `plan_checklist_resume`（`resume.py:293`）零写、零生产调用方；slash 命令侧 `_M3_OPERATOR_API_PINS`（`slash_commands.py:142-152`）**有意**保持手动。
* `goal.md`（C-9 200/400 token）无哈希/陈旧校验；`goal_loop` 是 BG-004 提示位（canonical pos 14），与 goal.md 无绑定。
* R2 hostbridge 只有 `preToolUse`/`beforeShellExecution` 事件位；`sessionStart`（Cursor）/`SessionStart`（Claude，stdout 注入上下文）均未接。
* CreateGoal/UpdateGoal 在仓内零引用 — host Goal 工具作为可选后续，不入 R4。

## 2. 设计决策

### D-R4-1 session-start resume 适配（冒烟面）

新 `src/devolaflow/hostbridge/session.py` + `__main__` 子命令 `python -m devolaflow.hostbridge resume [--host cursor|claude]`：

1. 激活闸：**复用 `DEVOLAFLOW_AGENT_WORKSPACE=1`**（W-20 复用优先测试通过：session-start resume 正是 A-6.2/SKILL §Workspace Engagement 的同一激活面——workspace 会话接洽；非 `"1"` → 空输出 exit 0 零 IO）。
2. `scan_workspace(repo_root).active_changes`：0 → 静默；1 → `plan_checklist_resume(repo_root, change_id)` → stdout 输出紧凑恢复摘要（change-id、disposition、resume_round、已勾 ID 数、下一轮选择、goal 漂移警示），供 host 注入上下文；>1 → 只列清单让操作者选（不自动挑）。
3. 全程只读（resume 本身零写）；任何异常 → 空输出 exit 0 + hostbridge 审计账本记 `error_allow`（S-5）。
4. `install.py` 为 cursor/claude 配置增 sessionStart/SessionStart 钩子项（dogfood 配置同步再生）；Codex/Kimi/DSH 本轮不接 session 位（Codex trust 摩擦、Kimi 用户级 Beta、DSH 走插件后续），降级说明写入 `references/host-bridges.md`。

### D-R4-2 round PASS → 自动 checkpoint（组合 API）

新 `agent_workspace/checkpoint.py::checkpoint_round_pass(repo_root, change_id, pass_result, checked_ids, *, stage_view, ...)`（名字实现者可调）：组装合法 `convergence_round_complete` checkpoint payload（有序 `checked_ids`、stage.md 交叉引用、`project_state.config_hash`、**新增 `goal_hash`**）并 `write_checkpoint`。调用面：

* 库级组合 API（供 L0 在 round PASS 后一步调用，替代手拼 payload）；
* slash 侧把 `_M3_OPERATOR_API_PINS` 中 checkpoint 项从 "deliberately not invoked" 升级为 `DEVOLAFLOW_AGENT_WORKSPACE=1` 时经组合 API 可用（pin 测试相应改写——语义从"永不自动"改为"闸内可用"，属 v17 行为演进，测试同 PR 更新）。

### D-R4-3 goal_loop ↔ goal.md 哈希绑定

* 新 `goal_content_hash(repo_root, change_id) -> str`（sha256, 归一化换行后哈希 goal.md 字节；文件缺失 → `""`）。
* `checkpoint_round_pass` 写入 `goal_hash`；`plan_checklist_resume` 增**加性**漂移检查：checkpoint 带 `goal_hash` 且与当前不符 → 新 disposition `GOAL_DRIFT`（旧 checkpoint 无该字段 → 跳过检查，完全向后兼容）。
* resume 摘要输出中 GOAL_DRIFT 显式警示（goal 变了必须人审后再续跑——BG-004 的"回述目标"从提示位变成可校验事实）。

## 3. 边界

* 不动 R2 boundary 判定路径（file_write/shell 语义原样）；session 是新入口不是新 kind 复用 deny 语义。
* 不新增 env flag（W-20 复用 `DEVOLAFLOW_AGENT_WORKSPACE`）。
* `ResumeDisposition` 枚举加成员属加性变更；旧值语义不动。
* A-2 无涉（checkpoint/resume 均非 dispatch payload）。
* W-17：R4 ≤ 12 个新测试函数（周期累计 6+27+12+12 = 57 ≤ 150）。

## 3.5 实施结果（2026-08-25 收口）

* T4：三决策全落地，11 个新测试（3 checkpoint / 1 resume / 7 session）；覆盖 session 97% / checkpoint 91% / resume 85%。关键实现选择：`goal_content_hash` 落在 checkpoint.py（`sha256:<hex>` 镜像 config_hash 格式，NEST 于 `project_state.goal_hash`）；GOAL_DRIFT 判定序在 CONFIG_DRIFT 之后、ACTIVE_ESCALATIONS 之前；单 change 无 checkpoint（新鲜 change）按异常路径静默 + `error_allow` 账本；Claude matcher `startup|resume`。
* `_M3_OPERATOR_API_PINS` 措辞升级无需改测试（v16 ghost 只 pin 符号存在性）。
* L0：ghost pin 1 个（`test_v17_0_0_r4_focus_loop_wired`）。W-17 本轮 11+1=12 ≤ 12;周期累计 6+27+10+12=55。

## 3.6 CHANGELOG 备存文本（周期收口 rollup 时采用）

- **R4 — focus/loop (G17-B4)**: session-start resume adapter
  `python -m devolaflow.hostbridge resume [--host cursor|claude]` prints a compact
  checklist-resume summary for host context injection (Cursor `sessionStart` /
  Claude `SessionStart` hooks wired by the installer; Codex/Kimi/DSH deliberately
  deferred per `references/host-bridges.md` §8). Operator-visible behaviour change:
  activation REUSES `DEVOLAFLOW_AGENT_WORKSPACE=1` per W-20 — no new env flag; flag
  off → empty stdout, exit 0, zero filesystem IO. New composition API
  `checkpoint_round_pass` assembles and persists the `convergence_round_complete`
  checkpoint in one step after a round PASS (ordered `checked_ids`, `config_hash`,
  new `project_state.goal_hash` via `goal_content_hash`), returning the stage.md
  cross-reference. `plan_checklist_resume` gains the additive `GOAL_DRIFT`
  disposition when the recorded goal hash mismatches the current goal.md (legacy
  checkpoints without the field are unaffected); the session summary prints an
  explicit human-review warning. `_M3_OPERATOR_API_PINS` semantics evolved from
  "deliberately not invoked" to "available via the composition API when the
  workspace flag is on".
