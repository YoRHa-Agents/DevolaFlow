## 4. What we learned

**A feature can pass every test and still have no reachable path.** `scan`
correctly flagged three over-threshold folders; `plan` then proposed zero moves
for all three, because automatic classification only relocates closed risks and
historical output, and the actual weight was in hand-written design documents
classified `LIVE` and `RETAINED`. `--include` existed and would have worked, but
nothing in the output named it, and the retained files that were the whole
problem were not printed at all. Both ends were individually correct and the
funnel between them was a dead end. Every unit test passed throughout, because
each tested its own end. The lesson is not "write integration tests" — it is
that a tool has to be run against material nobody prepared for it.

**A cost you decline to measure gets paid anyway.** v24's own retrospective
telegraphed this: relocating two risks saved 432 tokens for a digest that cost
nearly as much. Pricing it turned out to be simple, but only after rejecting
the obvious shortcut. A constant, or a per-row estimate, would have drifted the
moment the digest layout changed. Rendering the digest the plan *would* write
and measuring that is exact by construction, and it cost one refactor —
splitting `render_digest` into a row-taking function — to obtain.

**Vocabulary that nothing writes is a lie the ledger tells quietly.**
`OUTCOME_BYPASSED` was defined in v24 and emitted by nothing, so a reader
querying the telemetry could not distinguish "no plan was made" from "a plan
declined itself". The absence looked identical to the healthy case. Declaring
an enum value is a promise that the state is observable; the promise is only
kept when a production path writes it.

**The extractor was grading its own inputs.** Retro-digest matched only the
literal phrase "key learnings" and read only bullets and table rows. v23.1.0
wrote `## Learning`; v24.0.0 wrote `## 4. What we learned` with bold-lead
paragraphs. Both contributed nothing, and the digest reported `OK` — the two
newest and most relevant cycles were absorbed into a healthy-looking aggregate.
The fix was in two parts, and only the second one matters long term: broaden
the vocabulary, and make a source that yields nothing say so. Status `OK` over
silently empty sources is worse than a failure, because it does not prompt
anyone to look.

**Fixing the instance is not fixing the class.** v24 closed F-00 by teaching
the reader one retired gate name. The reader still had roughly forty other
paths that abort an entire ledger on one bad row, so the next malformed write
would reproduce the incident under a different name. Opt-in row quarantine
addresses the shape of the failure rather than its instance, and strict stays
the default so nothing silently loosens.

Both deep-analysis passes surfaced more than this cycle fixed. The remainder is
parked in `.local/tasks/v24.1-self-digest/parking/`, one file per risk, rather
than summarised here:

| Risk | Severity | Why it did not land |
|---|---|---|
| `RISK-001` compact apply moves a file before its ledger row is durable | blocker | Needs a two-phase or journalled apply; structural |
| `RISK-002` a failed digest marks a successful apply as refused | critical | Splitting the two outcomes changes the `CompactResult` contract |
| `RISK-003` a compacted closed risk keeps `state: closed` in its relocated file | major | Known divergence from ADR §4.1; carries a design question, not just a fix |
| `RISK-004` the F-00 reader fix has no test that reads a retired gate from a ledger | major | Small and arguably in scope; landed after close |
| `RISK-005` `summarize()` cannot answer whether compaction paid for itself | minor | Plan-time net accounting shipped, but ledger rows carry no digest cost |
| `RISK-006` argparse failures break the one-JSON-object contract | minor | The `--folder` fix removed the likeliest trigger |
| `RISK-007` the digest spends a column on a hash too short to verify with | minor | Layout change; would move `digest_tokens` |

`RISK-001` is the uncomfortable one. It is a blocker by severity and it shipped
in v24.0.0, which means the legacy sweep this cycle ran on top of it. The sweep
verified 3/3 mappings clean afterwards, so it did not fire — but that is
evidence the window is narrow, not that it is closed.

- The composite did not move: 9.83 in, 9.83 out, across a cycle whose entire
  subject was defects in shipped behaviour. The six W-3 dimensions cannot see a

  first cycle with concrete evidence for one.

  is a retrospective whose lessons the repository cannot currently read.

  probably exists; a ghost-style check that every enum member has a production
  writer would find it mechanically.
- `RISK-001` and `RISK-002` are both in `apply_plan` and both concern what the
  result says versus what the filesystem did. They should be taken together as
  one durability pass rather than as two separate patches.
