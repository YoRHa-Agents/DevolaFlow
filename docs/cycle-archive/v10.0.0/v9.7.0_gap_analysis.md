  The new `predecessor_dedup_ledger` is OPTIONAL — absence is canonical so the

* The 9 baselines required by the user's PV-02 spec:
  v7.0.0, v7.3.0, v8.0.0-P08, v8.0.0-P10, v8.3.0-PV05, v8.4.0, v9.2.0, v9.3.0
  (currently fixture-only — PV-02 wires it into the test), v9.7.0 (new in PV-02).

### §4.2 P1 / S-1 dispatcher-not-implementer

* PV-03 auto-wire MUST preserve P1 — `AsyncDispatchExecutor` only schedules
  callables; the wave dispatcher passes the L3 task callables in. The
  executor never inspects, mutates, or executes work itself.

### §4.3 W-20 env-flag reuse vs new-flag policy

* PV-04 introduces `DEVOLAFLOW_WARMUP`. W-20 §3 orthogonality test:
  - `DEVOLAFLOW_AGENT_WORKSPACE` — activates workspace scaffolding (different surface)
  - `DEVOLAFLOW_RTK_PROXY` — activates command mapping (different surface)
  - `DEVOLAFLOW_SI_CHIP_DEEP` — activates Si-Chip deep mode (different surface)
  - **None of these activate selector cache warmup** → new flag justified per W-20 §3.

### §4.4 W-17 per-PV test cap

PV-02 adds 6-8 NEW test functions; PV-03 adds 5-7; PV-04 adds 3-5. Cumulative
v9.7.0 = 14-20 new functions. Well below the +30/PV ceiling and the +150 cycle
cap (cycle starts at v9.6.0 baseline).

### §4.5 STRICT gate (composite ≥ 9.0)

This is the FINAL minor before the v10.0.0 rollup; STRICT gate applies. Plus a
cumulative-latency guard: cumulative `select_context.p95` MUST stay ≥ 35%
better than v9.2.4 baseline (v9.2.4 baseline ~80 ms select_context.p95 →
v9.7.0 target ~1600 µs = ~98% improvement, easily achieved).
