## §1 Deficiencies (from cProfile + code inspection)

The PV-01 cProfile harness (200 selector iterations + 1000 cheap-function
iterations + 200 full-flow iterations, total 131 s wall clock and
385.6 M function calls) surfaced the deficiencies below. Numbers are
verbatim from `.local/research/v9.3.0_cprofile_summary.txt`.

| # | Deficiency | Evidence | Layer |
|---|---|---|---|

| D-S-2 | `load_profiles` re-parses 84 KB `context_profiles.yaml` on EVERY call (no cache) | 600 calls × 121.266 s cumulative = 96.6 % of select_context cost | hot-path |

## §2 Priority ranking

### §2.1 BLOCKER — must fix in v9.3.0 (cycle-defining)

* **D-S-1, D-S-2, D-S-3, D-S-4** — the `select_context` 209 ms / call
 cost IS the user-visible perf complaint. PV-03 closes all four with
 a single LRU-cache landing.

### §2.2 CRITICAL — must fix in v9.3.0 (high-leverage)

* **D-E-3** — multi-task wave fan-out is structurally serial. PV-05
 (re-targeted per perf_research §4.3) closes this.
* **D-E-4** — SHORTCUT_SIMPLE auto-enforcement closes the long-tail.
 PV-06 closes this.
* **D-E-1** — no latency harness. PV-02 closes this; without PV-02 we
 cannot empirically verify any of PV-03..PV-06.

### §2.3 MAJOR — should fix in v9.3.0 (maintainability + correctness)

* **D-C-1, D-C-2, D-C-3** — compressor split + 2 NineS-flagged
 complexity hotspots. PV-04 closes (3-module split per perf_research
 §6 Q3 recommendation).
* **D-S-5** — `estimate_tokens` LRU cache. Cheap sub-task within
 PV-03's scope (~10 LOC).
* **D-T-2** — wholesale baseline regen at PV-02 (W-16 mandate).

### §2.4 MINOR — defer to v9.7.0 or v9.4.0

* **D-S-6** — selector LOC count. Splitting `task_adaptive_selector.py`
 into a package mirrors PV-04's compressor split work but at higher
 baseline-drift risk because the file's surface is more API-public.
 Defer to v9.7.0.
* **D-S-7** — deprecated line-based lookup warnings. Cleanup pass;
 defer to v9.4.0 or v9.5.0 (the Si-Chip integration cycle which
 already touches the section-anchor surface).
* **D-C-4, D-C-5** — compressor regex loop micro-optimisation
 (precompile + collapse to single regex). NOT cycle-critical (compressor
 is 2.3 % of dispatch); defer to v9.7.0.
* **D-H-3** — hook registry as ContextVar. Required by full async
 dispatch (v9.7.0 PV-03); freeze-at-first-dispatch is sufficient for
 v9.3.0 PV-05's wave-level fan-out.
* **D-T-4** — NineS self-eval. Per W-7, runs at cycle close (PV-07).

### §2.5 SPEC-CORRECTION — must address in PV-02..PV-07 dispatch

* **D-H-1, D-H-2** — cycle plan PF-6 / PV-05 specification was based
 on architectural reasoning (sequential = wrong) NOT measured cost.
 The L0 must affirm the §6 Q1 binary choice in `perf_research.md`
 BEFORE PV-05 dispatches; if (B) wins, PV-05 ships an inversion
 (slower than today) and PV-07 retrospective documents.

## §6 Risks summary (full register in perf_research §5)

* **R-A2-DRIFT (CRITICAL).** PV-04's compressor split can shift
 whitespace in pickled bytes → `tests/test_layout_invariant_multi_baseline.py`
 fails on any of the 6 pinned baselines. Mitigation: run full
 multi-baseline test on every commit during PV-04; bisect on first
 failure.
* **R-spike-1 (HIGH).** L0 may reject the PV-05 re-target (perf_research
 §6 Q1) and prefer the original ThreadPoolExecutor target. The
 measured data is unambiguous BUT the L0's prerogative dominates;
 PV-07 retrospective will document either outcome.
* **R-LRU-1..R-LRU-3 (LOW-MED).** PV-03 LRU edge cases (mtime
 invalidation, thrash, unhashable args). All have one-line
 mitigations documented in perf_research §5.
* **R-SIMPLE-1 (MED).** PV-06's auto-shortcut may misroute a complex
 task. Escape hatch: L3 emits `COMPLEXITY_PROMOTION_REQUIRED`
 escalation. Track misclassification rate as a v9.3 metric.
