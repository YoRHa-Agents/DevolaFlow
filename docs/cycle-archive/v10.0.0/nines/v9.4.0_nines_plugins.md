## Cycle interpretation

The 2 cyclomatic-complexity warnings on `resolve_plugin` / `ensure_plugin` are **non-blocking** for v9.4.0. The cycle plan §3 v9.4.0 deliberately layers NEW behaviours **above** `ensure_plugin()` (a `pre_plugin_invocation` lifecycle hook + a `devolaflow plugins refresh` CLI) rather than splitting the existing function. Decomposing `ensure_plugin` would invalidate the v8.3.1 R5 strict byte-stable contract that v8.4.0 PV-01 pinned for the RTK distinguish-cmd path. Defer the complexity-reduction work to a future maintenance PV (telegraphed candidate for v9.7.0 PV-N or v10.1.x).

The "0 Agent-facing artifacts" finding for `src/devolaflow/plugins/` is **expected** — agent-facing artifacts live under `workflow-system/agent/`. The plugins package is a runtime-only library; its agent-facing surface is `workflow-system/agent/knowledge/runtime-plugins.yaml` (the registry) which sits OUTSIDE the analyzed path.
