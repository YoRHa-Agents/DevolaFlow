## §4 Key learnings

* **L-1 (stacked-PR mechanics):** GitHub auto-retargets and sometimes
  auto-closes stacked PRs when a mid-stack base branch is deleted on merge
  (#174 auto-closed, content landed via #175; #170 needed reopen). Playbook:
  merge bottom-up WITHOUT `--delete-branch`, retarget children explicitly,
  delete branches in a final sweep.
* **L-2 (review threads block merges silently):** unresolved Bugbot threads
  held #169/#173 in BLOCKED despite green CI. Playbook: enumerate threads via
  GraphQL, fix-or-reply, resolve explicitly before attempting merge.
* **L-3 (release runbook gap — root cause of DR-2/3/4):** the operator-driven
  release path skipped SI-3 evaluation, W-7 retrospective, and W-16 cycle-close
  regen because none of them live in the release-preflight gate list —
  `release-preflight` covers code gates only. Fix direction: add a
  human-checklist stanza to the release runbook (not a Make gate — SI-3/W-7
  are judgment artifacts, W-9 stays 7 gates).
* **L-4 (tag hygiene):** v15.0.0 shipped without a git tag (repo tag sequence
  jumped v14.1.0 → v15.1.0). Cured alongside the v15.2.0 release: `v15.0.0`
  backfilled onto bump commit `cba2b83`.
* **L-5 (dedup precedent):** compiled-surface duplication (mdc + AGENTS.md)
  went unnoticed for a full MAJOR cycle because both surfaces individually
  passed their own lints — cross-surface injection accounting only surfaced it
  during the workflow-wide benefit analysis. Worth repeating that analysis at
  each MAJOR close.
