## §1. Two-view methodology

Per the v8.3.0 PV-09 + v8.4.0 rollup precedent, EvoBench results in this
cycle are reported in two views:

* **View A — vs archived v8.4.0 baseline (48 scenarios)**: shows the
  cumulative cycle delta across the 48 scenarios that EXISTED at v8.4.0.
  Useful for detecting hidden regressions in pre-cycle scenarios.
* **View B — vs current v9.0.0 baseline (53 scenarios)**: shows the
  per-PV-07 regression status against the regenerated cycle baseline
  (the W-16 wholesale regen). Used by `tests/test_benchmarks.py` for
  CI enforcement.

The **W-4 / SI-4 invariant** (composite must not drop > 5 pp per scenario
vs the regenerated baseline) is enforced against View B. View A is a
diagnostic — drift > 5 pp here is a flag to investigate but NOT a CI blocker
because the PV-06 introduced 5 NEW scenarios that change the cycle's score
distribution.

## §5. PV-07 EvoBench attribution

**Net change from PV-07:** **0 scenarios added/removed; 0 scenarios drift
> 5 pp.** PV-07's rule rebalancing operates on AGENTS.md (the compiled
output of `.rules/*.mdc`) which is NOT exercised by EvoBench scenarios.
The per-task-type slicing function is OPT-IN via YAML knob; the default
`enabled: false` produces byte-identical AGENTS.md, so no scenario sees
any change. The W-21 Soul-set freeze governance rule is added to
`.rules/workflow.mdc` (which IS in AGENTS.md), but again — not in
SKILL.md, so EvoBench's SKILL-section-driven scoring is unchanged.

**The AGENTS.md token-budget bump (8000 → 12000 per ADR-007 D5)** is also
EvoBench-neutral: AGENTS.md compilation is a development-time step
(operators run `RuleCompiler.compile_all()` after editing `.rules/*.mdc`);
the runtime `select_context` path consumes SKILL.md, not AGENTS.md.

## §7. Action items carried to v9.1.0+

* **Per-task-type slicing telemetry** — once operators flip
  `meta.agents_md_slice.enabled: true`, capture telemetry on:
  (a) opt-in adoption rate, (b) per-profile slice savings (compare to
  the predicted 15-70% range in `v9.0.0_pv07_rule_audit.md` §2.2),
  (c) any unexpected EvoBench drift attributable to L0/L1/L2/L3
  dispatchers consuming the sliced AGENTS.md.
* **AGENTS.md as future EvoBench surface** — currently AGENTS.md is
  excluded from EvoBench scenarios (which exercise SKILL.md sections).
  As more operators consume AGENTS.md as a primary rule corpus, a
  parallel suite of AGENTS.md-section scenarios may be warranted in
  v9.x sustaining.
* **The 90 composite floor for `_disabled.yaml` scenarios** — pinned at
  PV-06 ADR-006 D3 + R-4 rollback condition. Continue enforcing in
  v9.1.0+; consider tightening to 92-95 if all 5 sustain at 96.05+
  for several minor releases.
