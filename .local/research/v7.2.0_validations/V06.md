## SF-1 Rule Update

Proposed wording for `.cursor/rules/skill-format-rules.mdc` (replaces lines 6-8 of current file). The current rule:

```
## Rule SF-1 — Line Budget

SKILL.md must stay under 500 lines. Verify with `wc -l` or the `test_skill_md_under_500_lines` integration test before committing changes.
```

becomes:

```
## Rule SF-1 — Tiered Line Budget

Agent-facing skill files are subject to tiered line-count ceilings, adopted from gsd
v1.37.0 (issue #2361) and applied to the canonical 12-file set listed in
`scripts/sync_cursor_skill.py::MIRRORED_FILES`:

| Tier    | Ceiling | Files                                                | Enforced by |
|---------|---------|-------------------------------------------------------|---|
| Default | < 500   | `workflow-system/agent/SKILL.md`                      | `tests/test_integration.py::test_skill_md_under_500_lines` |
| Large   | ≤ 1000  | `workflow-system/agent/references/*.md` (8 files)     | `tests/test_reference_size_budgets.py::test_reference_within_large_tier` |
| XL      | ≤ 1600  | `workflow-system/agent/examples/*.md` (3 files)       | `tests/test_reference_size_budgets.py::test_example_within_xl_tier` |

Rationale: SKILL.md is loaded into every dispatcher prompt and must stay tight;
references are loaded on-demand by L1/L2/L3 agents and may carry richer context;
examples are only consulted when an agent needs a worked trace, so they get the
widest budget.

Verify before committing changes with either:

```bash
wc -l workflow-system/agent/SKILL.md \
      workflow-system/agent/references/*.md \
      workflow-system/agent/examples/*.md
python -m pytest tests/test_integration.py::test_skill_md_under_500_lines \
                 tests/test_reference_size_budgets.py -v
```
```

Note the asymmetry between Default (`< 500`, strict) and Large/XL (`≤ ceiling`, inclusive) is **deliberate**: the `< 500` form preserves the long-standing
existing `test_skill_md_under_500_lines` semantics (zero behaviour change for that test); the new tests use the natural reading of "limit" from the gsd source.
Concretely: SKILL.md may have 499 lines but not 500; references may have 1000 lines but not 1001.

## Risks / Caveats

1. **SKILL.md headroom (NOT introduced by C-006, but visible)**: SKILL.md is at 498/500. The next minor edit will trip the existing `test_skill_md_under_500_lines`. C-006 keeps the Default ceiling at 500 to preserve the cached prefix invariant (P6) and avoid scope creep, but a follow-up candidate should consider either (a) extracting a SKILL.md section into a new `references/*.md` file, or (b) explicitly raising the Default tier to 600. Surface this in the v7.2.0 retrospective.
2. **Large-tier headroom on references**: the largest reference (`context-isolation.md`) is at 53% of its new ceiling (533/1000) — comfortable. None of the 8 references is within 25% of the limit. No near-term churn risk.
3. **XL-tier headroom on examples**: the largest example (`full-pipeline-trace.md`) is at 26% of its new ceiling (408/1600) — generous. Examples have ~4× headroom.
4. **List drift risk**: the new test imports `MIRRORED_FILES` from `scripts/sync_cursor_skill.py`. If a future change to that list (e.g. adding a 9th reference) breaks the import-time list comprehension, the `test_canonical_lists_match_sf3_contract` sanity test will fail loudly with the actual count vs the expected `8 / 3` — easy to fix in one place.
5. **Inclusive vs strict asymmetry**: SKILL.md uses `< 500` (existing convention) while new tests use `<= 1000` / `<= 1600`. This is intentional and documented in the SF-1 update, but a contributor unfamiliar with the legacy might find it surprising. Mitigation: the table in SF-1 makes the operator explicit per row.
