## 决策点

### 决策点 1：目录命名 / 布局（关联 ADR-1 · 缺陷 D-3）
- **选项**：A) 新建一级同级目录 `.local/human/`（与 `.agent/`/`memory/`/`research/` 平级）；B) 嵌套进 `.local/feedbacks/`；C) 复用 `.local/memory/`
- **权衡**：
  - A) 人↔agent 边界最清晰、不与现有树冲突；代价：需新建目录并纳入 scan
  - B) 零新目录；但 `feedbacks/` 为被动/事后语义，与「前向持久」诉求冲突
  - C) 零新增；但 `memory/` 承载 agent 行为（W-23.4），混淆人类意图
- **设计推荐**：A —— 人类输入需前向、持久，独立同级目录才划得清人↔agent 边界。

### 决策点 2：Git 跟踪范围（关联 ADR-2 · 缺陷 D-4）
- **选项**：A) 跟踪整棵树 `!.local/human/**`（INPUT+OUTPUT+archive）；B) 仅跟踪 INPUT；C) 全部私有（不跟踪）
- **权衡**：
  - A) 权威输入与有界报告均可 PR 评审；代价：`.gitignore` + `tests/test_gitignore_policy.py` 增量
  - B) 仅锁权威输入；但有界收敛报告失去 PR 可见性
  - C) 零改动；但违背 D-4（权威区须可评审、持久）
- **设计推荐**：A —— 受 C-9 预算约束的报告也值得 PR 可见，且足迹很小。

### 决策点 3：不可变性机制（关联 ADR-3 · 缺陷 D-1）
- **选项**：A) 修订协议 + 追加式（批准后不可改，改动只追加 `input/amendments/<日期>-<slug>.md` + 版本戳，复用 S-9）；B) 文件只读 `chmod -w`；C) 冻结整份 spec
- **权衡**：
  - A) 保留逐条 WHY 回测脉络、不新增 Soul 规则；代价：依赖约定 + lint 钩子
  - B) 机械强制；但脆弱、无 WHY 轨迹、协作不便
  - C) 强一致；但 spec 必然演进，过度僵化
- **设计推荐**：A ——「不可改」指批准后追加而非原地编辑；修订账本本身即 引导回测 锚点（参考 spec-kit `https://github.com/github/spec-kit`）。
- **你的选择**：☑ A ▢ B ▢ C ▢ 其他：________

### 决策点 4：回归 / 可追溯模型（关联 ADR-4 · 缺陷 D-1）
- **选项**：A) 稳定 `REQ-<域>-NN` + 可追溯矩阵（`Unmapped: 0 ✓`）+ 修订账本 + 日期归档；B) 纯散文需求；C) 沿用 TRACKER 状态行
- **权衡**：
  - A) 每条需求可校验、可检出范围缩水、可审计漂移；代价：需维护 ID 与矩阵
  - B) 写起来快；但不可追溯、易被静默丢弃
  - C) 复用现状；但状态行 ≠ 覆盖矩阵，且 TRACKER 已失修
- **设计推荐**：A —— 覆盖须可证明、漂移须可审计；矩阵取代 TRACKER 的覆盖职责（见决策点 7；参考 OpenSpec `https://github.com/Fission-AI/OpenSpec` + 内部 A-4）。
- **你的选择**：☑ A ▢ B ▢ C ▢ 其他：________

### 决策点 5：输出格式与预算（关联 ADR-5 · 缺陷 D-2）
- **选项**：A) 结论先行 + 状态枚举（`passed|gaps_found|human_needed`）+ 显式 C-9 预算（报告 ≤500 词、DIGEST ≤100 行）；B) 复用 agent `REPORT.md` 既有风格；C) 不设预算上限
- **权衡**：
  - A) 一分钟可决策、防淹没、证据先于断言；代价：新增第 5 个 reporter 风格 + lint 行
  - B) 零新增；但现有风格均非「人类优先 / 可略读上限」
  - C) 最灵活；但「无上限」正是淹没 bug 本身
- **设计推荐**：A —— 反淹没诉求要求硬上限 + 结论先行；引用而非复述 CHANGELOG / 回顾。

### 决策点 6：scan_workspace 集成方式（关联 ADR-6 · 缺陷 D-1·D-2）
- **选项**：A) 在 `scan_workspace`/`WorkspaceContext` 追加字段（`has_human_dir`/`human_constitution`/`human_requirements`/`human_digest`）；B) 另写独立扫描器；C) 复用 / 重载 `recent_feedbacks`
- **权衡**：
  - A) 纯追加、现有键字节稳定、S-5 安全默认；代价：4 个新字段 + helper
  - B) 隔离清晰；但重复既有发现契约
  - C) 零新字段；但把「被动建议」与「绑定权威」混为一谈
- **设计推荐**：A —— 仅追加、不破坏现有键；新增「何时启用」行指向权威输入。

### 决策点 7：TRACKER 去向（关联 ADR-7 · 缺陷 D-3）
- **选项**：A) 覆盖职责交给 `requirements.md` 矩阵，`.local/feedbacks/TRACKER.md` 退为被动解决账本并把横幅 `Auto-` 改为 `Human-maintained`；B) 删除 TRACKER.md；C) 现在就做完整自动更新器
- **权衡**：

- **设计推荐**：A —— 矩阵做覆盖 SSOT，TRACKER 退回被动角色并修正失实横幅。
