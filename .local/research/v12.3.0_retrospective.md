## 4 — Key learnings (process improvements for the next cycle)

### 4.1 The "extract-to-Tier-3-reference" pattern is high-leverage but Tier-2 nav is mandatory

PV-03 extracted Task Quality Score to `references/task-quality-score.md` (semantically Tier-3 on-demand) but had to register it in the Tier-2 nav table for the `tests/test_no_ghost_features.py::test_reference_skill_md_tier2_parity` test (SF-4 parity contract). **Recommendation for v13.0.0+**: clarify the SF-4 contract — should Tier-2 nav be a SUPERSET of all references regardless of load semantic, or should Tier-3-only references be excluded? Current behavior is the former; if changed, the test needs an explicit Tier-2-exempt list.

### 4.2 The `tiktoken` autouse fixture must be honoured during baseline regen

PV-04's baseline regen initially produced different composite scores than pytest because the conftest autouse fixture `_force_fallback_token_estimator` forces `tiktoken=None` for deterministic benchmark scoring. My initial regen used the system's installed `tiktoken`, producing 99.51 composite, but pytest sees 93.88 because it forces fallback. **Recommendation for v12.4.0+**: update `benchmarks/devolaflow_context/generate_baseline.py` to set `sys.modules["tiktoken"] = None` at module import (Option B from conftest docstring) so standalone regens automatically match pytest behavior. Avoids the 3-attempt trial-and-error I hit at PV-04 close.

### 4.3 Section line anchors drift on every SKILL.md restructure — batch-realign as a single PV step

PV-02 + PV-03 + PV-04 each shifted SKILL.md content boundaries. The `context_profiles.yaml` section_anchors block has 25+ line-anchored sections; each restructure requires batch realignment. **Recommendation for v12.4.0+**: build a `scripts/realign_section_anchors.py` tool that auto-computes `lines: "X-Y"` from current SKILL.md headers and updates `context_profiles.yaml` in place. Would have saved ~15 minutes of manual anchor edits this cycle.

### 4.4 The W-16 "MAY at cycle start OR close" wording cleanup landed cleanly

PV-04's W-16 paragraph clarification (per v12.2.0 retro §4.2 learning) propagated through `make compile-rules` to `AGENTS.md` + `.cursor/rules/repo-governance.mdc` without surprises. The compile pipeline + the existing CI lint `test_rule_surfaces_compile_only` worked as designed. **Confirms** that rules-doc edits are a safe + cheap surface for absorbing retrospective learnings.

### 4.5 The 3-PV cycle shape (PV-02 banner + PV-03 extraction + PV-04 telegraph) is the right scope for a "polish" MINOR

Compared to v12.2.0's 5-PV cycle (which involved fresh BG primitives + new tests + runtime hooks + benchmark regen), v12.3.0's 3-PV cycle (3 focused surfaces + 1 cleanup) hit higher SI-3 composite (9.225 vs 9.075) with less cumulative test delta (+4 vs +36). **Recommendation**: alternate between "expansion" MINORs (v12.0.0, v12.2.0) and "polish" MINORs (v12.1.0, v12.3.0) — the rhythm keeps cumulative test budget under W-17 +150 cap.
