## §4 Key Learnings (feed-forward to v8.3.0 SI-1)

1. **Markdown heading discovery requires fenced-code-block awareness**. Without `_FENCE_RE` guard, code samples in SKILL.md (e.g. plan-mode-template's nested `## Overview` examples) prematurely terminate parent sections. The fence-aware discovery added in `_heading_indices` should be promoted as a reusable utility for any future markdown analyzer in the codebase.
2. **The legacy line-based registry was extracting WRONG content for many sections** (e.g. `hierarchy_table: lines "185-195"` actually extracts mid-table content from Repo-Init Pre-Dispatch Contract; `wave_task_constraints: lines "194-198"` extracts selection heuristics). EvoBench scores stayed stable across cycles only because the wrong content stayed CONSISTENTLY wrong. v8.2.x migration must re-baseline scenario-by-scenario.
3. **Anchor-based discovery + line-based fallback is the correct migration pattern** — the deprecation warning surfaces every legacy lookup at runtime, giving a measurable migration backlog without forcing a big-bang rewrite. R5 backward-compat discipline (proven in v8.0.0 P-10 and v8.0.0 P-08) scales cleanly to runtime config.
4. **The `section_anchors:` extended YAML form (`{file: ..., heading: ...}`) is essential** for sections where the snake_case anchor name doesn't match the rendered markdown heading text. The anchor-name → heading mapping varies enough across SKILL.md that auto-derivation alone is insufficient.
5. **Opt-in primitive flips on STRICT only** is the right granularity for B3 partial closures — preserves byte-stability for the other 3 profiles while letting strict-mode users immediately benefit. The pattern (boolean field on `GateProfile`, default `False`, STRICT explicit `True`) extends cleanly to the remaining 5 primitives in v8.2.x.
