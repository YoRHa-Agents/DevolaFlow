## §2 Patterns by fork

### 2.1 dir-layout

- **Truth / changes / archive triad** — OpenSpec splits `openspec/specs/<capability>/spec.md` (current truth) from `openspec/changes/<id>/` (proposal.md + tasks.md + delta `specs/<name>/spec.md`) and freezes completed work via `mv openspec/changes/<name> openspec/changes/archive/YYYY-MM-DD-<name>`. Source: `https://github.com/Fission-AI/OpenSpec` (`src/core/templates/workflows/archive-change.ts`). **DF takeaway:** clone this 3-bucket shape for `.local/human/` — a stable requirements truth dir, an in-flight proposal dir, and a date-prefixed archive.
- **Dedicated human-doc tree, distinct from the agent spec tree** — Kiro writes human PRDs to a separate `documents/PRD_[Product]_[Date].html` while the agent spec lives under `.kiro/specs/[product-slug]/` and durable human steering under `.kiro/steering/*.md`. Source: `https://github.com/aws-samples/sample-kiro-cli-prompts-for-product-teams` (`.kiro/steering/prd-guide.md`, `product-workflow.md`). **DF takeaway:** human reports get their own top-level dir, never co-mingled with agent specs.
- **Single small human-owned planning dir with named canonical files** — get-shit-done puts everything human-facing under `.planning/` (`PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md`, `todos/pending/`, `.continue-here*.md`). Source: `https://github.com/gsd-build/get-shit-done` (`get-shit-done/templates/state.md`, `requirements.md`). **DF takeaway:** prefer a small fixed file set under `.local/human/` over a sprawling tree.
- **DevolaFlow already shards `.local/`** into `feedbacks/`, `memory/`, `research/`, `.agent/`, `index.md` (see `workflow-system/agent/references/agent-workspace.md` §2). **DF takeaway:** `.local/human/` is a natural new sibling — no new top-level concept needed.

### 2.2 immutability

- **Amendable "constitution" with an explicit amendment protocol** — spec-kit's `templates/constitution-template.md` ships a `## Governance` section ("Constitution supersedes all other practices; Amendments require documentation, approval, migration plan") and a footer `**Version**: [CONSTITUTION_VERSION] | **Ratified**: [RATIFICATION_DATE] | **Last Amended**: [LAST_AMENDED_DATE]`. Source: `https://github.com/github/spec-kit`. **DF takeaway:** model durable human INPUT as an amendable constitution (version + ratified + last-amended stamp) — regression/guidance value WITHOUT literal write-locking.
- **Immutable-INPUT ≠ frozen-spec boundary** — the SDD-2026 (BCMS) article warns "do NOT treat specs as frozen — specs evolve, edit spec→code". Source: `https://thebcms.com/blog/spec-driven-development`. **DF takeaway:** constitution-level principles/constraints stay durable; per-requirement specs may evolve through the amendment trail rather than being locked.
- **Approval freezes scope before work** — superpowers `<HARD-GATE>`: "Do NOT invoke any implementation skill, write any code, scaffold any project, or take any implementation action until you have presented a design and the user has approved it." Source: `https://github.com/obra/superpowers` (`skills/brainstorming/SKILL.md`). **DF takeaway:** human INPUT becomes a binding contract only after an explicit approval gate; pre-approval it is mutable, post-approval it is immutable.
- **Revise-by-append, never edit-in-place** — DevolaFlow Soul rule S-9: "To convey new information, the agent MUST author a new envelope with `seq+1`." Source: `workflow-system/agent/references/agent-workspace.md` §6. **DF takeaway:** human-requirement revisions append a new dated amendment, preserving the prior text verbatim.

### 2.3 regression-traceability

- **Stable REQ-IDs + traceability matrix + Out-of-Scope** — gsd `REQUIREMENTS.md` uses `- [ ] **AUTH-01**: …` IDs, a `## Traceability` table (`| Requirement | Phase | Status |`), an `## Out of Scope` table (`| Feature | Reason |`), and coverage counts ("Unmapped: 0 ✓"); the README touts "scope reduction detection prevents the planner from silently dropping your requirements." Source: `https://github.com/gsd-build/get-shit-done` (`get-shit-done/templates/requirements.md`, `README.md`). **DF takeaway:** every human requirement gets a stable ID + a traceability row so coverage is provable and dropped scope is detectable.
- **Archive preserves WHY, merged only at archive** — OpenSpec keys requirements by `### Requirement:` headings and merges deltas into living truth only at archive; the bitbytebit comparison notes OpenSpec uniquely keeps "not just what changed but **why** … the original acceptance criteria". DevolaFlow's A-4 mirrors this: "every change archive preserves the proposed delta, so the archive log answers 'what did we add to spec X across all of v8.3.0?'" Sources: `https://github.com/Fission-AI/OpenSpec`; `workflow-system/agent/references/agent-workspace.md` §7. **DF takeaway:** a dated archive of every requirement change is the regression/audit ledger.
- **Evidence-before-claims gate** — superpowers `verification-before-completion`: "NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE" with a Common-Failures table (`Claim | Requires | Not Sufficient`) whose row "Requirements met | Line-by-line checklist | Tests passing" forbids extrapolation. Source: `https://github.com/obra/superpowers` (`skills/verification-before-completion/SKILL.md`). **DF takeaway:** a human OUTPUT must tie each claimed-met requirement to fresh evidence (REQ-ID → evidence row) — the traceability check is the anti-overclaim mechanism.
- **Checkable acceptance criteria** — Kiro stores requirements in EARS form (`WHEN [event] THE SYSTEM SHALL [response]`), making each requirement testable and thus traceable. Source: kiro `.kiro/steering/prd-guide.md`. **DF takeaway:** keep human acceptance criteria in checkable form so a status (Pending/Complete/Blocked) is unambiguous.

### 2.4 output-format

- **Bounded, conclusion-first, quantified report contract** — agency-agents' exec-summary specifies "Total length: 325–475 words (≤ 500 max)", "decide … in under three minutes", "Every key finding must include ≥ 1 quantified or comparative data point", and recommendations carrying "owner + timeline + expected result" in a fixed 5-section layout. Source: `https://github.com/msitarzewski/agency-agents` (`support/support-executive-summary-generator.md`). **DF takeaway:** human OUTPUT = word/token-budget + ask-first + quantified + owner/next-step.
- **Small living digest read first** — gsd `STATE.md`: "Keep STATE.md under 100 lines. It's a DIGEST, not an archive", read first in every workflow, updated after every significant action. Source: `https://github.com/gsd-build/get-shit-done` (`get-shit-done/templates/state.md`). **DF takeaway:** a ≤100-line human digest as the "read-once, know where we are" surface.
- **Explicit per-component token budgets (anti-flooding)** — mem0/Anthropic context-engineering articles prescribe allocating a token budget per component and compressing when it overflows ("smallest set of high-signal tokens"). Sources: `https://mem0.ai/blog/context-engineering-in-multi-turn-ai-agents`, `https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents`. **DF takeaway:** cap each human OUTPUT artifact with an explicit budget — directly mirrors DevolaFlow's C-9.
- **Templated, deterministic REPORT.md** — DevolaFlow `reporter.py` renders `What changed / Why / How / Verification / Files touched / Learnings / Handoff chain` with byte-identical output under a pinned clock (AC-5 idempotency), opt-in CLI. Source: `src/devolaflow/agent_workspace/reporter.py`. **DF takeaway:** reuse this template + idempotency for the human convergence report (a 5th, human flavour).

### 2.5 separation

- **Dual output channel (human report vs agent spec)** — Kiro's "Dual Output Strategy": "Generate TWO outputs: 1. **Traditional PRD** → `documents/PRD_[Product]_[Date].html` 2. **Kiro Spec** → `.kiro/specs/[product-slug]/requirements.md`", with steering files gated by `inclusion: always|manual`. Source: kiro `.kiro/steering/prd-guide.md`. **DF takeaway:** physically separate the human report channel from the agent spec/state channel.
- **Durable human intent ≠ ephemeral agent memory** — the harness/layering articles split durable+versioned+shared (human) from ephemeral session and accumulated auto-memory (agent): "The scratchpad dies when the task ends. The true durable context already lives in your repository — AGENTS.md + ADRs". Sources: `https://softwareguru.substack.com/p/demystifying-agent-harness`, `https://hivetrail.com/blog/agents-md-vs-claude-md-cross-tool-standard/`, `https://www.philschmid.de/agent-harness-2026`. **DF takeaway:** place `.local/human/` as the durable, human-authored tier, sibling to (not nested in) the agent tiers.
- **Who-writes-what column model** — the .MD-paradigm / CLAUDE-vs-AGENTS-vs-MEMORY taxonomies classify each file by load-timing AND write-owner: human-authored instruction files vs agent-appended `MEMORY.md`, with "human operational intent … in portable, reviewable artifacts that travel with the work." Sources: `https://amitray.com/claude-md-vs-agents-md-memory-md-skills-md-context-md-guide-2026/`, `https://www.linkedin.com/pulse/md-paradigm-agentic-ai-from-sprawl-structure-rohit-sharma-udmhc`. **DF takeaway:** tag every `.local/human/` artifact with an explicit write-owner = human (INPUT) or write-owner = agent (OUTPUT drafts), so the immutable-INPUT vs append-by-agent contracts are unambiguous.
- **Vocabulary vs behaviour already separated in DF** — Rule W-23.4: "`CONTEXT.md` is VOCABULARY … `.local/memory/specs/<domain>/spec.md` … is BEHAVIOUR. They DO NOT overlap." And `scan_workspace` already enumerates `recent_feedbacks` (human) separately from `source_of_truth_specs`/`active_changes` (agent). Sources: `.cursor/rules/repo-governance.mdc` W-23.4; `src/devolaflow/workspace_context.py`. **DF takeaway:** the human/agent boundary is an established DF pattern; `.local/human/` extends it with a new discovery surface.

## §3 Internal precedents to reuse

| Precedent | What it already gives us | Where it falls short for a HUMAN surface |
|---|---|---|
| **C-9 per-artifact budgets** (`agent-workspace.md` §9) | Soft/hard token ceilings (goal 200/400, acceptance 400/800, spec 1500/3000, STATUS 100/200, `REPORT.md` 1500/3000) + `lint <change-id>` | No row for human INPUT (requirements/constraints) or a decide-in-3-min human OUTPUT — need new budget rows |
| **S-9 append-only handoff** (Soul P0) | Append-only ledger (`seq+1`, `O_EXCL`, `EnvelopeImmutableError`) | Scoped to agent↔agent envelopes; the discipline transfers but no human-INPUT amendment channel exists |
| **A-4 truth+delta+archive** (`agent-workspace.md` §7) | `.local/memory/specs/<domain>/spec.md` truth; delta merged only at archive after gate PASS (≥8.5/≥9.0); `propose_merge` never auto-applies | It is the AGENT behaviour contract, not human intent; not human-readable, no requirements doc |
| **REPORT.md** (`reporter.py`) | 4 templated, idempotent, opt-in flavours (per-change / workspace / memory / rules) | All 4 are agent/rules/memory dashboards; none is a human convergence report; not capped to a skim budget |
| **feedbacks/ + TRACKER.md** | Per-version human feedback (`feedback_for_vX.Y.Z.md`); TRACKER's Open/Resolved/Deferred ledger; "do not edit source files" | Feedback is reactive/post-hoc, not forward immutable INPUT (requirements+constraints); TRACKER is status, not a coverage matrix |
| **scan_workspace** (`workspace_context.py`) | Pure-function frozen `WorkspaceContext`; surfaces `recent_feedbacks` (cap 3), `source_of_truth_specs`, `active_changes`; S-5 safe defaults | No `.local/human/` field yet — needs a new surface (e.g. `has_human_dir` / `human_requirements`) for L0 to route on |

## §4 Synthesis → recommendation

Cross-repo comparison (★ = the repo's standout contribution to that fork):

| Repo | dir-layout | immutability | regression-traceability | output-format | separation |
|---|---|---|---|---|---|
| **OpenSpec** | ★ truth/changes/archive triad | merge-only-at-archive | ★ `### Requirement:` IDs + archive WHY | proposal+tasks delta | specs(truth) vs changes(flight) |
| **spec-kit** | single constitution file | ★ amendment protocol + Version/Ratified/Last-Amended stamp | "supersedes" precedence | — | constitution vs runtime guidance |
| **kiro** | documents/ vs `.kiro/specs/` | `inclusion: always/manual` steering | EARS testable AC | PRD HTML + dashboard | ★ dual output channel |
| **gsd** | `.planning/` named-file set | v1/v2 + frozen Out-of-Scope | ★ REQ-IDs + traceability matrix + coverage | ★ STATE.md ≤100-line digest | PROJECT/REQUIREMENTS/STATE split |
| **superpowers** | docs/specs + docs/plans | ★ HARD-GATE approval | ★ evidence-before-claims table | status enums (`DONE/…/BLOCKED`) | blocking vs advisory verdicts |

**Recommended direction for `.local/human/`:**

- **INPUT = amendable constitution + REQ-ID requirements.** Adopt spec-kit's Governance + `Version | Ratified | Last Amended` stamp for durable constraints/principles, plus gsd-style `REQ-IDs + traceability matrix + Out-of-Scope` for requirements; revise via S-9 append (never edit-in-place). This is "immutable for regression value" without literal write-locking.
- **LINEAGE = truth + delta + dated archive.** Reuse OpenSpec/A-4 so each human requirement change leaves a dated "what changed and **why**" archive; couple it to the existing `feedbacks/TRACKER.md` resolution ledger rather than inventing a parallel tracker.
- **OUTPUT = budget-capped, conclusion-first convergence report.** Build on the `reporter.py` template + a NEW C-9 budget row, enforcing agency-agents' contract (≤500 words / decide-in-3-min / quantified / owner+next-step) and a gsd ≤100-line STATE digest as the read-first surface — the anti-flooding mechanism.
- **SEPARATION = `.local/human/` as a first-class sibling.** Place it beside `.local/.agent/`, `.local/memory/`, `.local/research/` (Kiro dual-channel + harness layering); register it as a new `scan_workspace` surface so L0 routes human INPUT/OUTPUT distinctly, preserving the existing CONTEXT.md-vs-spec.md (W-23.4) human/agent boundary.
- **GATE = evidence + blocking-vs-advisory.** Gate human OUTPUT claims on superpowers' evidence-before-claims (REQ-ID → fresh evidence) and split findings into blocking vs "advisory, do not block approval" so convergence reports cannot silently over-claim.
