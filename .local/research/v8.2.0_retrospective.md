## §4. Key Learnings (Process / Tooling / Architecture)

### §4.1 Wave-internal-parallel + sequential-on-shared-FS dispatch is a valid compromise

The plan §S00-S04 specified "wave-internal parallel" but the dispatcher (L0) had to serialize within waves due to shared filesystem (single git worktree). All 18 patches landed sequentially despite the dispatch model being "parallel". **Verdict:** Plan authors should annotate the actual filesystem-isolation requirement; v8.3.0 should document this as an explicit dispatch constraint (or use git worktrees for true parallel patch dev).

### §4.2 Stalled subagents are recoverable via finalization L3 dispatch

P-01, P-09, P-08 (and SI-3+SI-8 retros in S09) all stalled mid-task before commit, but the working tree always preserved their progress. **L0's recovery pattern: dispatch a finalization subagent with verify-then-commit-then-PR contract.** This worked 3 of 4 times; the 4th (S09 SI-3+SI-8) was finalized by L0 directly via Write tool (orchestration aggregation, not implementation). Codify this pattern in the plan template.

### §4.3 Two-commit coupling discipline (feat + coupling) reliably absorbs scope-creep

P-08 + P-11 + PV-05 all used the `feat()` + `coupling()` two-commit pattern when SF-4 / template_count / human-doc registries needed regenerating in the same PR. **Codified as v8.x convention** per v8.0.0 retrospective §4.5 and confirmed by v8.2.0 cycle. v8.3.0 should make this explicit in `.cursor/rules/` (next-cycle plan input).

### §4.4 R5 backward-compat alias preservation scales to runtime objects

P-10 introduced R5 for `acceptance_criteria_v2`; PV-03 generalized the discipline to a full SessionState refactor across 3 domains (learnings + lifecycle + legibility). **All 71+ existing learnings tests passed unchanged.** Pattern is reliable: ship NEW shape alongside OLD as deprecated alias, adapter layer, opt-in default-off. v8.3.0 `.local/.agent/` workspace can adopt the same discipline.

### §4.5 Per-patch micro-retros aggregate cheaply into 3-cycle SI-8 retrospectives

Writing per-patch SI-8 4-section retros (~120 lines each) cost ~25 min per patch but enabled this 3-cycle aggregate retro to be authored in <30 min by L0 directly (vs the typical ~2-3h subagent dispatch for SI-8). **Codify as v8.x convention** and propagate to v8.3.0 plan template.

### §4.6 NineS post-cycle composite as G3 hard gate is reliable

`nines self-eval` composite ≥ 0.90 (G3 strict) reliably validates major release quality; the 25-sub-score breakdown surfaces measurement artifacts (e.g., `code_coverage: 0.0` timeout) without breaking the gate. **Pattern works**: keep G3 strict ≥ 9.0 for v9.x major; use G2 ≥ 8.5 for minor pre-releases.

### §4.7 EvoBench ceiling effect (>97% mean) limits delta-driven validation

v7.8.0 baseline mean was 97.24/100; v8.0.0 added +0.067pp; v8.2.0 added +0.0072pp. **Net delta as a primary G3 gate is unreliable at this ceiling** — switch to "0 regression" + "scenario count growth" + "5/5 PV ACCEPT" as the actual hard gates (which is what plan §1.3 codified). For v9.x, consider adding harder scenarios to lower the baseline mean and re-enable delta-driven validation.

### §4.8 Plan-stipulated G1/G2/G3 pause-for-signoff was bypassed twice in v8.x

User instruction "Don't stop until all to-dos done" overrode plan's "主动暂停等我签收" at G1 and G2; G3 sign-off arrived via the natural conversation flow (this retrospective). **Going forward**: codify the override hierarchy in the plan template — explicit user "continue" message overrides the plan pause; explicit user "stop" message enforces it.

### §4.9 v8.3.0 feedback captured mid-cycle is acceptable

User added `.local/feedbacks/feedback_for_v8.2.0.md` mid-v8.2.0 proposing v8.3.0 architecture (`.local/.agent/{active,handoff,archive}/`). **L0 captured it without disrupting v8.2.0 cycle**, deferred analysis to post-v8.2.0 SI-1 planning gate. Pattern: feedback files are append-only; L0 reads them at planning gates only, not during execution. Codify in v8.3.0 plan template.

### §4.10 100% accept rate across 18 patches (13 v8.0.0 + 5 v8.2.0) sets a high bar

Cycle accept rate has been 100% for v7.2.0 (4/4) → v7.3.0 (6/6) → v7.5.0 (8/8) → v8.0.0 (13/13) → v8.2.0 (5/5). **The plan-driven decomposition (SI-1 patch plan with 8 mandatory fields per patch) is the structural reason.** v8.3.0 should preserve this discipline; the proposed `.local/.agent/active/` artifact may be a natural successor to the per-patch micro-retro convention.
