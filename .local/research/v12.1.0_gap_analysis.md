## 2 — Deficiency Enumeration

### D-1 — Task Quality Score scope is implicit, not explicit (BLOCKER)

**Symptom**: subagents (L1 / L2 / L3) interpret SKILL.md §"Task Quality Score" as something they
should produce in their reports, leading to score-noise in TaskReport / WaveReport / StageReport
artifacts.

**Root cause** (verbatim from `workflow-system/agent/SKILL.md`):

* **Line 104** — `7. **REPORT** final results + Task Quality Score` is listed under
  §"AGENT MODE — Full Orchestration" Execution Protocol; this section IS scoped to L0 by the
  surrounding heading (§"You are the L0 Project Agent"). However…
* **Lines 451–475** — §"Task Quality Score" stands as a top-level `##` section with no L0-only
  scoping marker. The opening sentence reads
  `**After every Standard+ complexity workflow**, evaluate the user's original request:` —
  ambiguous: a subagent receiving this section in context may interpret "every Standard+ workflow"
  as "every dispatch I receive".
* **`workflow-system/agent/context_profiles.yaml`** — `task_quality_score:` priority is set at
  values OTHER than `skip` for 19 of the 30+ profiles enumerated (e.g. `feature: supplementary`
  line 720; `feature_implementation: critical` line 1338; `feedback: critical` line 1803). A
  subagent dispatched against any of these profiles receives the §451–475 block in its context
  window WITHOUT the surrounding L0 framing from §"AGENT MODE".

**Impact**: violates the §"Reporting completion" contract at SKILL.md line 337
(StatusReport carries `task_id, state, progress_pct, artifacts, metrics` — NO `quality_score`
field). Adds noise to subagent outputs that L0 must filter when collating the final report.

**Proposed fix**:

1. SKILL.md §"Task Quality Score" — add explicit L0-ONLY scoping marker (one line);
   add explicit "Subagents MUST NOT score" rule.
2. SKILL.md §"Dispatch & Report Protocol" → "Reporting completion" — append the
   "subagent reports DO NOT include Task Quality Score" exclusion.
3. Add `tests/test_subagent_output_restrictions.py` pinning the SKILL.md guarantee at
   compile time (assertion: SKILL.md §451–475 contains both "L0 ONLY" and
   "Subagents MUST NOT" substrings).

**File-level scope** (4 files):
* `workflow-system/agent/SKILL.md` (~10 added lines, 0 deleted)
* `tests/test_subagent_output_restrictions.py` (NEW; ~50 lines)
* `CHANGELOG.md` (new ## [12.1.0] entry)

### D-2 — Subagent hang/freeze guidance absent (BLOCKER)

**Symptom**: dispatched L3 Task Agents occasionally hang indefinitely. SKILL.md mentions
`timeout_seconds: 7200` as a default at line 331 — a 2-hour ceiling — but no actionable
prevention guidance is given to either L0 (the dispatcher) or L3 (the dispatched).

**Root cause analysis** — common hang vectors observable in the field:

| Vector | Why it hangs | Where it should be blocked |
|---|---|---|
| L3 invokes `AskQuestion` waiting for human input | Subagent has no human-facing channel; the question never resolves | L3 prompt MUST forbid `AskQuestion`; escalate up via StatusReport instead |
| L3 recursively spawns `Task` tool (nested subagents) | DevolaFlow's 4-layer hierarchy stops at L3 (leaf); recursive Task creates an unmodelled layer that exceeds context budgets and amplifies hang risk | L3 prompt MUST forbid `Task` tool re-entry; only L0/L1/L2 dispatch |
| Shell commands without `block_until_ms` | Default Shell call may block forever waiting for I/O | L3 MUST set explicit `block_until_ms` on every Shell invocation that could be long-running |
| `WebFetch` / `WebSearch` without timeout | Network calls can stall indefinitely when upstream is slow | Existing tools have implicit timeouts; verify and document |
| Internal infinite loop in subagent reasoning (no `max_iterations`) | Agent keeps "thinking" without converging | L0 dispatch MUST specify `timeout_seconds` per task; L3 self-monitors progress |
| Subagent waits on a missing dependency (file, lock, port) | No timeout on the wait | L3 MUST treat missing-dep as escalation, not retry-forever |

**Existing primitives already in repo** (not currently surfaced in SKILL.md):
* `src/devolaflow/agent_workspace/dispatch_executor.py::AsyncDispatchExecutor` — offers
  `dispatch_parallel` with `asyncio.Semaphore`-bounded concurrency BUT does NOT enforce
  per-task timeouts. The S-5 contract captures exceptions per `TaskOutcome` but does not
  fire on hang.
* SKILL.md §"Dispatch & Report Protocol" — names `timeout_seconds` field but does not
  document how L3 should self-monitor against it.
* SKILL.md §"Escalation severity" — `AUTO_RECOVER` / `PAUSE` / `HUMAN_INTERVENE` /
  `FULL_ROLLBACK` exist but the table doesn't say "use HUMAN_INTERVENE on suspected hang".

**Impact**: workflow stages effectively halt when a subagent hangs; no automated recovery
because the hang is not detected. Operator must manually kill the subagent and restart.

**Proposed fix**:

1. SKILL.md — NEW subsection §"Subagent Hang Prevention" (~25 lines) under existing
   §"Context Isolation" or §"Dispatch & Report Protocol". Content:
   * **L0 contract**: ALWAYS set `timeout_seconds` in TaskDispatch; budget per task type
     (research=2700s / impl=1800s / test=900s / review=1200s / hotfix=600s).
   * **L3 forbidden patterns**: `AskQuestion` (no human channel), recursive `Task` tool
     (P5 invariant — leaf), unbounded `Shell` (every call has `block_until_ms`),
     unbounded `WebFetch`/`WebSearch`, internal loops without max_iterations.
   * **L3 progress contract**: emit a heartbeat (`progress_pct` update) at least every 5
     minutes for long-running tasks; if no progress observed → self-escalate via
     StatusReport(`escalation: HUMAN_INTERVENE`, reason='suspected_hang').
   * **L0 hang detection**: if a dispatched task exceeds `timeout_seconds` OR shows no
     `progress_pct` change for 10 minutes → cancel + escalate per P4.
2. `tests/test_subagent_output_restrictions.py` — extend with assertions that SKILL.md
   contains the new section and the L3 forbidden-patterns list.

**File-level scope** (additive overlap with D-1):
* `workflow-system/agent/SKILL.md` (~25 additional lines)
* `tests/test_subagent_output_restrictions.py` (extended; +30 lines)
