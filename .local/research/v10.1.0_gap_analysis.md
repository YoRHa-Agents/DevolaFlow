> 其实太浓烈了。我希望它更接近于人的语气，所以我希望你可以再进行一些
> 调研和分析，包括如何去评价 AI 味这件事情，然后以及如何降低这种状态或
> 者行文的风格。如果有需要克隆一些仓库的话，还是克隆到
> /home/agent/reference/目录下。
>
> 然后思考如何去优化这些产出，调整文风，包括输出的形式。但是同时呢，对
> 于本身的性能又减少干扰和污染。我希望你做一些调研，然后去做一些迭代的
> 尝试，确保它有明显有效了之后，再去上线一个新的 minor 版本。

English (working translation, used in agent-facing artefacts only —
the source of truth is the Mandarin text above):

> The writing in DevolaFlow's docs and writing-task outputs feels too
> "AI-flavored." Make it closer to a human voice. Research how to
> EVALUATE AI-flavor and how to REDUCE it, cloning reference repos to
> `/home/agent/reference/` if needed. Optimize the output and writing
> style, including output FORM, while NOT polluting performance or the
> dispatch path. Iterate experimentally; only ship a minor version once
> the improvement is clearly measurable.

The user mandate maps to **four hard constraints** that bound the
v10.1.0 design space:

| # | Constraint | Source phrase | Cycle-design implication |
|---|---|---|---|
| C-1 | Define a measurable AI-voice metric | "如何去评价 AI 味这件事情" | PV-01 must produce a scorer that runs cheaply enough to gate CI; PV-02 will refine. |
| C-2 | Demonstrate measurable improvement before release | "确保它有明显有效了之后，再去上线一个新的 minor 版本" | The release gate is W-3 SI-3 PLUS a NEW v10.1.0 naturalness-delta gate (≥ 5-point lift on the worst 10 docs). |
| C-3 | Do NOT pollute the performance-critical path | "对于本身的性能又减少干扰和污染" | Module placement under `src/devolaflow/writing_style/` (or equivalent isolated namespace); zero touches to `compressor/`, `task_adaptive_selector.py`, `lifecycle/`, `feedback.py`. |
| C-4 | Iterate experimentally before shipping | "做一些迭代的尝试" | Multi-PV cycle (PV-01 research → PV-02 design → PV-03 transformer + scorer → PV-04 wire-in + experiments → PV-05 close). |

The Mandarin "**AI 味**" is the load-bearing term. There is no clean
single-word English translation; "AI flavor", "AI-ness", "AI smell",
and "AI signature" all approximate it. The PV-01 research identifies
~12 measurable stylometric features that compose into the vernacular
sense of AI 味 (see §3 below + research synthesis §1).

### §2.2 — Measured baseline (from `v10.1.0_aivoice_baseline.md`)

The probe ran on 23 DevolaFlow documents + 4 "human-clean"
references + 5 "meta-editorial" references (anti-AI editorial guides
from `humanize-writing` and `skill-deslop`). Aggregate result:

| Aggregate | docs | total prose words | naturalness 0-100 |
|---|---:|---:|---:|
| `AGG:human-clean` | 4 | 2,508 | **71.02** (target) |
| `AGG:meta-editorial` | 5 | 5,701 | 72.73 (calibration anchor) |
| `AGG:devolaflow` | 23 | 80,368 | **69.96** (current) |

The aggregate gap is only 1.06 points — DevolaFlow is **not** as bad
as the user feedback suggests on average. But the aggregate is
hiding a heavy-tailed distribution. Worst offenders:

| Document | Naturalness | Top-3 driving features |
|---|---:|---|
| `df:en/integration-guide` | **50.37** | bullet 0.388, header 0.259, em-dash 25.75 |
| `df:CHANGELOG` | **52.70** | bullet 0.628, em-dash 31.42, bold 34.38 |
| `df:en/faq` | **54.29** | bullet 0.377, header 0.279, tier2 vocab 5.94 |
| `df:zh/integration-guide` | 60.86 | bullet 0.382, em-dash 17.32, header 0.250 |
| `df:zh/workflow-types` | 62.63 | bold 50.78, sentence-len uniformity |
| `df:README` | **63.91** | bold 35.62, em-dash 38.36 |
| `df:en/quickstart` | 64.01 | bullet 0.379, bold 58.61 |

Top-3 most-AI-flavored features in DevolaFlow vs human-clean:

| Feature | DF mean | Human-clean mean | Delta | Interpretation |
|---|---:|---:|---:|---|
| `emdash_per_1k` | **15.39** | 7.79 | +7.60 (+98%) | em-dash density nearly 2× the human baseline |
| `bold_per_1k` | **44.68** | 37.27 | +7.41 (+20%) | bold inline overuse; CHANGELOG runs 34 |
| `bullet_ratio` | 0.262 | 0.259 | +0.003 (~0%) | aggregate looks fine but the worst docs hit 0.628 |

Conversely, where DevolaFlow is **already cleaner** than the human
baseline:

| Feature | DF mean | Human-clean mean | Delta |
|---|---:|---:|---:|
| `tier1_per_1k` | 0.11 | 1.31 | -1.20 (DF cleaner) |
| `tier2_per_1k` | 0.80 | 1.10 | -0.30 (DF cleaner) |
| `signposts_per_1k` | 0.10 | 0.00 | +0.10 (essentially equal) |
| `neg_parallel_per_1k` | 0.00 | 0.00 | even |

This is a **load-bearing finding**: DevolaFlow does NOT have a
lexical AI-vocab problem. We don't say "delve", "tapestry",
"leverage", "embark on a journey". We don't write "It's not just X,
it's Y" reframes. The user complaint maps to **structural** density
(em-dash + bold + bullet cluster + header cluster) in the longest /
most-templated docs, NOT to AI-vocab leakage. This dramatically
narrows PV-02 scope (see §3).

### §2.4 — Why this hasn't been addressed before

Three reasons; documenting them up-front so v10.1.0 doesn't repeat
the mistakes:

1. **The lexical narrative dominates.** Public discourse about AI-
   writing focuses on "delve" and "tapestry" — but DevolaFlow's docs
   already score very low on those tokens (Tier 1 density 0.11 vs
   human 1.31). Without a STRUCTURAL probe (em-dash + bold + bullet)
   the problem looks invisible. The user's "AI 味" complaint is
   structural, not lexical, and we'd missed that.
2. **The CHANGELOG is path-locked.** `CHANGELOG.md` is hand-edited
   per release using the precedent set in v8.x. The
   `bold-inline + em-dash + bullet-table` pattern is so embedded in
   the existing 4945 lines that any rewrite proposal feels like a
   massive inconsistency burden. PV-02 must decide whether to
   transform NEW entries only (additive, low risk) vs back-fix the
   historical entries (high churn, high inconsistency cost).
3. **Demo + EN + ZH are auto-generated.** Because the EN/ZH pages
   come from `generate_human_docs.py` which reads SKILL.md, the
   "AI flavor" is inherited from SKILL.md's own structural choices.
   But SKILL.md is performance-critical (it's loaded into every
   dispatcher prompt; A-2 frozen prefix). So we CANNOT touch SKILL.md
   to fix the human docs — the transformer must run AFTER generation
   and ONLY against the human-facing artefacts.

## §5 — Risk Register

| # | Risk | Likelihood | Mitigation |
|---|---|---|---|
| R-1 | The transformer rewrites code-block context and breaks copy-paste-able snippets in EN/ZH guides. | MEDIUM | PV-02 explicit rule: transformer NEVER edits inside fenced ` ``` ` blocks or inline `code` spans. PV-03 must include a byte-stable test on a fixture with embedded code. |

| R-4 | "Performance non-pollution" violated because the new module accidentally imports something hot. | LOW | Static lint in PV-04: `tests/test_writing_style_isolation.py` walks `writing_style/` AST and asserts NO import from the 6 hot-path modules. |
