## §1 — Gaps Identified (from SI-1 planning gate)

The SI-1 gap analysis (`.local/research/v11.3.0_gap_analysis.md`)
identified that the [grill-with-docs upstream skill](https://github.com/mattpocock/skills/tree/main/skills/engineering/grill-with-docs)
packages a discrete behavioural pattern that DevolaFlow did **not**
own: a one-question-at-a-time **adversarial interview** that
stress-tests an in-flight plan against the codebase, a project-local
**domain glossary** (`CONTEXT.md`), and a project-local **ADR ledger**
(`docs/adr/`) — and which **mutates those documentation surfaces
inline** as decisions crystallize.

The gap analysis §3.1 7-primitive coverage matrix found **6 of 7
primitives have a non-trivial gap**:

| # | Primitive | Coverage at v11.1.3 | Gap |
|---|---|---|---|
| 1 | One-question-at-a-time interview | partial | repo-init bootstrap only; not design-time stress-test |
| 2 | Codebase-first exploration | covered | strong (L0 read permissions per AGENT MODE) |
| 3 | CONTEXT.md domain-glossary maintenance | missing | no glossary convention exists |
| 4 | ADR sparingly with 3-condition gate | partial | Design Team produces ADRs by default; no 3-condition gate |
| 5 | Inline doc updates as decisions crystallize | partial | per-change spec.md exists but is batch-oriented |
| 6 | Fuzzy-term sharpening | missing | no surface |
| 7 | Concrete scenario probing | missing | no surface |

Format-rule primitives F-1..F-7 (CONTEXT.md required structure +
opinionated-term + only-project-specific + single-vs-multi-context
inference + ADR sequential numbering + ADR minimum-body + ADR
qualifying-decision matrix) were **fully missing** at v11.1.3.

## §4 — Key Learnings

1. **Wholesale baseline regen requires section-anchor migration
   discipline.** Wave 1+2 added content to SKILL.md without
   migrating the affected sections off line-based lookup. The W-16
   wholesale regen captures the new equilibrium correctly, but the
   per-scenario `quality_thresholds.min_composite` floors are
   cycle-start-set hard floors that the regen does NOT update —
   they fail when relevance drops below the floor's implicit
   relevance assumption. **Recommendation for v11.4.0+ cycles
   that touch SKILL.md**: when adding ≥ 5 lines to SKILL.md, the
   Wave-N L3 owner MUST also (a) verify the section_anchors
   registry covers the affected sections (no `lines='X-Y'`
   deprecation warnings under the modified scenarios), and
   (b) either reaffirm or update the scenario `min_composite`
   floors that touch the modified profiles. Codify as a
   pre-commit hook lint or as a new W-rule in v11.4.0+ planning.

2. **The 3-stage L1/L2/L3 dispatch pattern (research →
   3-parallel-implementation → 2-parallel-integration →
   1-sequential-cycle-close) worked well for a single-PV MINOR
   cycle.** The research wave produced the gap analysis + nines
   analyses + verbatim sources, the implementation wave produced
   grill_mode.py + 2 references + tests in parallel, the
   integration wave landed SKILL.md edits + W-22/W-23 + ghost
   audit refresh, and Stage 3 (this task) handles cycle-close
   uniformly. Recommend the same shape for v11.4.0.

3. **W-18 ghost-audit BEFORE CHANGELOG sequencing produced an
   intentional intermediate-state failure that worked as
   designed.** Wave 2's W-18 ghost-audit refresh shipped the
   `test_v11_3_0_new_surfaces_have_coverage` lint with the
   CHANGELOG portion expected to FAIL until Stage 3 lands the
   `## [11.3.0]` entry. Stage 3's first action (CHANGELOG entry
   authoring) closes that intentional failure. The W-18 docstring
   explicitly documents this — the intermediate failure IS the
   sequencing gate working. This pattern is worth replicating
   in future cycles where the W-18 refresh + CHANGELOG must
   ship across separate Waves (v11.4.0+ candidate documentation
   improvement: codify the "expected-failure intermediate state"
   as a normative SKILL.md §"W-18 Sequencing" sub-section).

4. **The v11.1.3 D-3 tiktoken determinism documentation paid off
   this cycle.** The W-16 wholesale baseline regen was the first
   cycle where D-3 Option B (pre-pinning `sys.modules["tiktoken"]
   = None` before any devolaflow import) was empirically tested
   in the field. The gap-analysis-anticipated `pytest
   tests/test_benchmarks.py --regenerate-baselines` flag does not
   exist on this branch (the regen mechanism is `python -m
   benchmarks.devolaflow_context.generate_baseline`); falling
   back to D-3 Option B avoided the ~7pp divergence trap. The
   v11.1.3 D-3 reference doc (`troubleshooting.md` §2.16) was
   load-bearing for Stage 3 — preserve as Tier-2 reference
   discipline going forward.

5. **R-12 ADR scheme conflict is empirically benign.** The gap
   analysis §3.3 and §5 R-12 telegraphed a low-severity conflict
   between the new ADR format (`0001-slug.md` sequential
   numbering, lazy `docs/adr/` creation per `domain-awareness.md`
   §8) and the historical `.local/research/adr/vN-ADR-NNN-slug.md`
   directory (10+ historical ADRs). The retro-distinction is
   carried in `domain-awareness.md` §9 — historical ADRs are NOT
   retrofitted; v11.3.0+ new ADRs adopt the format. No ADRs were
   added in v11.3.0 (the cycle would have failed the W-22.3
   3-condition gate even if proposed: grill-mode integration is
   "Architectural shape" per F-7 but lacks "Surprising without
   context" since it parallels the documented external skill
   1:1 — qualifies_as_adr would return `(False, ["surprising_without_context"])`).
   The 3-condition gate's first real test will be the next
   genuine cross-context ADR proposal in v11.4.0+.

6. **Single-PV MINOR cycle absent baseline-regen pytest flag is
   acceptable but should be remediated.** The gap analysis
   anticipated `pytest tests/test_benchmarks.py
   --regenerate-baselines` as the canonical invocation; the
   actual regen surface is `python -m
   benchmarks.devolaflow_context.generate_baseline`. The two
   surfaces produce equivalent baselines under v11.1.3 D-3
   Option B but the asymmetry is operator-confusing. **v11.4.0+
   candidate**: add a `--regenerate-baselines` (or
   `--regen-baselines`) pytest flag that thinly wraps the
   existing module + pins `tiktoken=None` automatically; deprecate
   the standalone module invocation in favour of the unified
   pytest entry-point. Keeps W-16 + v11.1.3 D-3 contracts
   together at one operator-facing surface.
