## §4. Key Learnings (process improvements for next cycle)

### §4.1 What worked well (continue doing)

1. **The 7-PV cycle structure honored the v8.4.0 retro §4.1 #2 pattern** — every PV shipped as a real semver patch (NOT lightweight pvNN tags as v8.3.0 used). The per-PV git history (`v8.4.1` → `v8.4.2` → ... → `v8.5.1` → `v9.0.0`) is more discoverable than v8.3.0's lightweight-tag approach. **Recommendation:** continue this pattern in v9.1.0+ when there are ≥ 3 PVs.

2. **W-17 per-PV test cap discipline (codified in PV-05) directly controlled cycle test growth.** Predicted +150 cycle cap; delivered +97 NEW test functions = 0.65× the cap (vs v8.0.0's 4.7× over-delivery). The mid-cycle audit at PV-05 caught the trajectory early and re-calibrated PV-06/PV-07 budgets. **Recommendation:** make this the default discipline for v9.1.0+.

3. **R5 strict triple-codification stayed disciplined for all 7 PVs.** Every new feature in this cycle has the R5 contract codified at THREE layers (unit test + lifecycle integration + EvoBench scenario). When env-flag/YAML-knob is off, all 3 layers prove byte-identical behavior to the predecessor version. PV-07's `test_slice_disabled_returns_full_byte_identical` is a direct continuation of the pattern. **Recommendation:** continue this for v9.1.0+ opt-in features.

4. **A-5 SSOT registry pattern (PV-03 ADR-003) was the cycle's most reusable architectural primitive.** The pattern was applied 5×: `WHITELIST` (v8.3.2) + `MemoryCase` (v8.3.3) + `CommandMapping` (v8.3.4) + `plugins.yaml` + `runtime-plugins.yaml`. The CI lint (`test_registry_single_owner`) prevents future shadowing. **Recommendation:** any new cross-cutting registry surface in v9.1.0+ should default to following A-5.

### §4.2 What didn't work well (process improvements for v9.1.0+)

1. **AGENTS.md token-budget overflow caught at PV-07 instead of pre-flight.** When PV-07 added W-21 (~+30 LOC source), the existing 8000-token AGENTS.md budget overflowed silently — the workflow layer was dropped from the compiled output without an error or warning. The compiler's `_truncate_to_budget` logic dropped `workflow.mdc` (priority 3) as the lowest-priority non-`always_include` layer. The drop was caught by manual inspection, not by an automated check. **Recommendation:** v9.1.0+ should add a `compile-time`assertion that every layer in `include_layers` survives compilation OR raises `LayerTruncatedError` (instead of silent drop). The 12000 budget bump in PV-07 was a band-aid; the real fix is loud compile-time failure on truncation.

The split would let PR (a) focus on R5 strict triple codification reviews while PR (b) focuses on documentation completeness.

The lag means future cycle-N+1 SI-1 planning gates can't reference the archive until cycle-N's PV-07 has shipped — slightly less useful for mid-cycle reviews. **Recommendation:** v9.1.0+ could populate the archive at every CYCLE-MINOR boundary (e.g., at PV-06 close in this cycle) so the archive is always within 1 PV of the latest committed research artifact.
