## 1. Goal & non-goals

### 1.1 Primary goal

Ship a **staged, prompt-side** context-compression toolkit in DevolaFlow
that realises the top-5 ranked recommendations from the S01 research
report (`.local/research/v7.0.0_context_compression_research.md`) across
the v7.0.0 → v7.1.0 cycle. Each primitive must:

1. Be **deterministic** (no LLM calls by default — only extractive
   paths and regex / schema-driven logic).
2. Be **benchmark-measurable** (every primitive ships a scenario +
   threshold so its benefit is observable in EvoBench or NineS).
3. Be **backwards-compatible** (additive API, additive schema,
   feature-flagged opt-in).
4. Compose with the existing L0→L3 hierarchy and the lean dispatch /
   report schemas without requiring a schema bump.

### 1.2 Success criteria

- Round-over-round dispatch prefix stability (H.2) ≥ 80 % round 1→2
  and ≥ 70 % round 1→3 on every task_id.
- Compression retention (H.1) ≥ 95 % on preserve-list entities at the
  easy / medium tiers; ≥ 90 % on hard.
- Persistence carry-through (H.4) ≥ 90 % on all three synthetic
  scenarios.
- SI-3 weighted composite ≥ 8.8 / 10 at v7.1.0 cut (above the 8.5 rule
  minimum in `.cursor/rules/self-improve-iteration-rules.mdc`).
- NineS `code_quality`, `analysis`, `evaluation` dimensions each non-
  regressing vs. v6.2.1 baseline; `analysis` and `evaluation` ≥ +0.02
  at v7.1.0.

### 1.3 Non-goals — what staged compression is NOT

- **Not a Cursor product change.** We do not negotiate KV-cache
  behaviour with the Cursor platform team for v7.x. Research §D.5
  shows Cursor does not publish cache-hit telemetry, and open question
  K.7 is resolved as "stay prompt-side for v7.x" (see §7.7). All our
  levers are at the prompt-construction boundary.
- **Not a Claude / OpenAI server-side compaction replacement.** When a
  downstream deployment uses Anthropic's `compact_20260112` or OpenAI's
  `/responses/compact`, our primitives **complement** those features
  by ensuring the client-side payload is already minimal before the
  server-side compactor fires.
- **Not a model-swap or tool-swap mechanism.** Per research §B.6, we
  never swap model or toolset mid-session; any primitive added in v7
  must be compatible with a single-session cached prefix.
- **Not a memory-tool surface change.** K.5 is resolved as "keep JSONL"
  (see §7.5). v7 does not expose a Claude-style file-system memory
  tool.
- **Not a change to the 4-layer agent hierarchy.** L0 / L1 / L2 / L3
  budgets and responsibilities are unchanged.
- **Not a version count commitment beyond v7.1.0.** Any item deferred
  here lands in a later iteration with its own SI-1 gate.

### 1.4 Scope boundary enforcement

`.local/research/v7.0.0_version_roadmap.md` lists every file each
version is allowed to touch. Any v7.0.x implementation PR that touches
a file outside its roadmap's file list fails the `check_file_ownership`
hook and is blocked at dispatch time.

## 2. Glossary

A single normative glossary so that every downstream stage agent uses
the same vocabulary.

| Term | Definition | First used in |
|---|---|---|
| **Cache layout** | The rendered key order of a lean-dispatch YAML payload, starting from `hdr` and ending at `gate` in the v7.0.0 baseline. Defined in `schemas/lean-dispatch.yaml` under `layout_invariant:`. | v7-ADR-001 §2 |
| **Cache-layout invariant** | The rule that every renderer must emit top-level keys in the declared canonical order. Enforced by `devolaflow.compressor.assert_dispatch_layout()`. | v7-ADR-001 §2 |
| **LCP (longest common prefix)** | A byte-wise proxy for cache-hit rate. H.2 asserts LCP between rounds ≥ 80 % (1→2) and ≥ 70 % (1→3). | §5.2 |
| **Predecessor artifact** | A file produced by an upstream stage and referenced by a downstream stage's lean dispatch under `pred[*].ref`. May be summarised deterministically via `summarise_predecessor()` or pass-through if below the trigger threshold. | §4.3 |
| **Predecessor summary** | A bounded-token deterministic extract of a predecessor artifact that preserves named entities verbatim (CO-2) and selects sections by `schema_hint` priority. Default mode: extractive. Abstractive mode is opt-in only. | §4.3 |
| **Schema hint** | One of `design`, `research`, `adr`, `gate_report`, or `null`, telling the summariser which section-priority ordering to apply. Inferred from path prefix or filename pattern. | §4.3 |
| **Tool-output truncation** | The primitive that replaces the middle portion of a large tool-result payload with a placeholder (`…[truncated N chars]…`), preserving configurable head + tail byte ranges. | §4.2 |
| **Tool-use clearing** | The primitive that keeps `tool_use` records (name + args) but replaces older `tool_result` payloads with `[cleared — call #N]`. Default `keep=3`. | §4.2 |
| **Persistence probe** | A pytest-based end-to-end harness that asserts named entities introduced in Stage A survive into Stage B's dispatch verbatim. Carry-through ≥ 90 %. | §4.4 |
| **Entity carry-through rate** | The fraction of preserve-list entities in Stage A's artifact that appear verbatim in Stage B's dispatched payload. | §5.4 |
| **Named entity** | An item matched by one of the preserve-list regex patterns in `src/devolaflow/compressor.py` (`file_paths`, `task_ids`, `version_strings`, `commit_hashes`, `metric_values`, `error_messages`, `acceptance_criterion_bullets`, `interface_signatures`). | v7-ADR-003 §2.1 |
| **Learnings v1** | The pre-v7 schema of `operational.jsonl` — 9 fields. | §4.5 |
| **Learnings v2** | The v7.0.3 schema that adds 4 optional fields (`confidence_half_life_days`, `last_accessed`, `pinned_for_session`, `promotion_count`) and three helpers (`consolidate_session`, `decay_confidence`, `pin_learning_for_session`). | §4.5 |
| **Session pinning** | Attaching a specific `session_id` to a learning so that `load_relevant_learnings(session_id=X)` surfaces it regardless of `min_confidence`. | §4.5 |
| **Confidence decay** | Linear downward adjustment of a learning's confidence proportional to days since `last_accessed`, floored at 0.1. See `decay_confidence()`. | §4.5 |
| **Session consolidation** | End-of-session bump (+0.05) applied to every learning actually surfaced during the session via `consolidate_session(session_id, used_learnings)`. | §4.5 |
| **Trigger threshold (relative)** | Summarisation fires when the predecessor artifact exceeds `summary_trigger_pct` % (default 25) of the consuming layer's token budget. | §4.3, §7.1 |
| **Summary mode** | One of `extractive` (default, deterministic) or `abstractive` (opt-in, LLM-driven). | §4.3 |
| **Reinforcement block** | The `reinforce:` top-level block in lean dispatch, appended at round 2+ with `{round, prior, target, rules}` containing prior-round gate findings. Canonical position: 10. | v7-ADR-001 §2 |
| **Plan mode** | A task-adaptive selection state that prefers design-altitude sections. Activated via env var `DEVOLAFLOW_PLAN_MODE=1`, marker file `.devolaflow_plan_mode`, or explicit `select_context(plan_mode=True)`. Propagation scope resolved in §7.2. | §7.2 |
| **Layout-invariant baseline file** | `benchmarks/devolaflow_context/baselines/layout_invariant_v7.0.0.yaml` — the golden rendered bytes of a canonical dispatch, used by `test_layout_invariant_baseline` to fail on accidental renderer-library changes. | §5.2 |
| **Compression scenario** | A JSON file under `benchmarks/devolaflow_context/scenarios/compression_*.json` containing `{artifact_body, probe_facts, probe_decoys}` used by H.1 to score retention. | §5.1 |

### 3.2 Data flow for a convergence round

```
Round N dispatch:
  1. task_adaptive_selector.select_context(task_type, round_num=N)
        - detects plan_mode
        - applies round N overrides
        - injects learnings (v2, with session_id)
  2. renderer builds dispatch dict in canonical order
  3. compressor.assert_dispatch_layout(dict, DEFAULT_DISPATCH_LAYOUT)
        - fail-fast on reorder (v7-ADR-001)
  4. pred[*].body vs. pred[*].summary_mode decision per artifact:
        if tokens(artifact) >= summary_trigger_pct * L3_budget:
            summary = compressor.summarise_predecessor(path, max_tokens=500, mode="extractive", schema_hint=hint)
            pred[i] = {ref: path, key_facts: summary.extracted_entities, summary_text: summary.summary_text}
        else:
            pred[i] = {ref: path, body: read(path)}
  5. if round_num >= 2 and profile.tool_output_truncation.enabled:
        prior_tool_uses = collect prior-round tool_use records
        cleared = compressor.clear_old_tool_uses(prior_tool_uses, keep=3, exclude_tool_names=["Read"])
        embed cleared into dispatch.pred[*].tool_results block
  6. render(dispatch) → yaml bytes → send to L3
  7. L3 produces StatusReport with its own tool_results block
  8. H.2 / H.4 benchmarks run against (round N, round N-1) pair at CI time.
```

### 4.1 Cache-layout invariant (J.1)

#### Public API

```python
# src/devolaflow/compressor.py

DEFAULT_DISPATCH_LAYOUT: list[str] = [
    "hdr", "task", "goal", "assumptions",
    "pred", "files", "rules", "shared",
    "accept", "reinforce", "verify_cfg", "gate",
]

class DispatchLayoutError(ValueError):
    """Raised by assert_dispatch_layout when top-level key order is wrong."""


def assert_dispatch_layout(
    payload: dict,
    layout_spec: list[str] = DEFAULT_DISPATCH_LAYOUT,
) -> None:
    """Fail-fast when payload's top-level key order does not match layout_spec.

    Raises DispatchLayoutError with a message naming the first out-of-order key.
    Unknown keys (not in layout_spec) are allowed ONLY if they appear after
    all known keys — i.e., appended at the tail. In-middle unknown keys fail.
    """
```

**Non-breaking change guarantee:** existing public signatures
(`compress_message`, `validate_lean_format`, `validate_preserve_list`,
`detect_drop_violations`) remain unchanged. New symbols only.

#### Schema diff — `schemas/lean-dispatch.yaml`

```diff
+# --- LAYOUT INVARIANT (v7.0.0+) ---
+# Canonical top-level key order for every rendered lean dispatch.
+# Renderers MUST emit keys in this order. Enforced by
+# devolaflow.compressor.assert_dispatch_layout().
+layout_invariant:
+  canonical_order:
+    - hdr
+    - task
+    - goal
+    - assumptions
+    - pred
+    - files
+    - rules
+    - shared
+    - accept
+    - reinforce
+    - verify_cfg
+    - gate
+  rules:
+    - "New fields introduced after v7.0.0 MUST be appended after 'gate'."
+    - "Existing fields MUST NOT be reordered without a major version bump + successor ADR."
+    - "Unknown fields between existing canonical keys are a hard error."
```

**No existing field is removed or renamed.** All pre-v7 dispatches
continue to parse because the invariant is an *order* assertion, not a
shape assertion.

### 4.2 Tool-output truncation (J.2)

#### Public API

```python
# src/devolaflow/compressor.py

def truncate_tool_output(
    payload: str,
    keep_head_chars: int = 500,
    keep_tail_chars: int = 500,
    replace_middle: str = "…[truncated {dropped} chars / {dropped_tokens} tokens]…",
) -> dict:
    """Character-bounded head/tail truncation for a single tool-result payload.

    Returns {
        "truncated_text": str,
        "original_chars": int,
        "original_tokens": int,
        "kept_chars": int,
        "kept_tokens": int,
        "dropped_chars": int,
        "dropped_tokens": int,
        "was_truncated": bool,

def clear_old_tool_uses(
    tool_uses: list[dict],
    keep: int = 3,
    exclude_tool_names: list[str] | None = None,
) -> list[dict]:
    """Replace tool_result payloads for all but the most recent `keep` tool uses.

    Each element in tool_uses is {id, name, args, result}. The returned

    entries unchanged, and replaces the `result` field on older entries

    names tools whose results are never cleared.
    """
```

### 4.3 Hierarchical predecessor summary (J.3)

#### Public API

```python
# src/devolaflow/compressor.py

def summarise_predecessor(
    artifact_path: str,
    max_tokens: int = 500,
    mode: str = "extractive",
    schema_hint: str | None = None,
) -> dict:
    """Produce a bounded-token summary of a predecessor artifact.

    Returns {
        "summary_text": str,              # ≤ max_tokens tokens
        "mode": str,
        "token_count": int,
        "extracted_entities": list[dict], # {type, value, source_line}
        "covered_sections": list[str],
        "dropped_sections": list[str],
        "was_bounded": bool,
    }

    Raises FileNotFoundError if artifact_path is missing.
    Accepts .md, .yaml, .json. Other extensions fall back to
    token-stream H2-equivalent extraction.
    """


def extract_named_entities(text: str) -> list[dict]:
    """Deterministic NER over DevolaFlow's structured entity classes.

    Returns list of {type, value, source_line} dicts. Uses the preserve-list
    regex patterns in compressor.PRESERVE_PATTERNS plus two new patterns
    for acceptance_criterion_bullets and interface_signatures.
    """
```

## 7. Open questions resolved

All 8 open questions from research §K are resolved below with rationale.
Any question marked "DEFERRED" names the earliest cycle it re-enters
the planning pipeline.

### 7.1 Forced-summarisation threshold — RESOLVED

**Decision:** Relative threshold **25 % of consuming layer's token
budget** triggers `summarise_predecessor()`.

For default budgets: L0 (3 K) → 750, L1 (5 K) → 1250, L2 (4 K) → 1000,
L3 (8 K) → 2000. Configurable as `summary_trigger_pct` in
`workflow-system/agent/context_profiles.yaml` meta block.

**Rationale:** A relative threshold (not absolute) tracks the
consuming layer's budget and scales with future budget tuning. 25 %
aligns with the context-isolation reference's guidance that
predecessor summaries should be 3-5 sentences max (~80-150 tokens
each) — with a 2000-token budget at L3, we can include multiple such
summaries before exhausting budget.

**Ships in:** v7.0.2 (ADR-003).

### 7.2 Plan-mode escalation propagation — RESOLVED

**Decision:** Propagate plan-mode overrides to **L1 only**. L2 does
**not** inherit plan-mode section priorities.

**Rationale:**
- Pro (propagate to L1): L1 Stage agents actively decompose research
  into waves and benefit from design-altitude primitives
  (`agent_hierarchy`, `decomposition_gate`, `rationalization_prevention`).
  L0 → L1 is the layer where *plans become wave lists*.
- Con (don't propagate to L2): L2 Wave agents have the smallest
  budget (4 K tokens). Plan-mode's critical-priority promotions cost
  ~1-1.5 K tokens; adding them to L2 would crowd out the dispatcher-
  not-implementer contract (P1).
- The `task_adaptive_selector.apply_plan_mode_overrides()` helper
  composes cleanly with the existing round-escalation pipeline.

**Implementation:** v7.1.0 adds a `plan_mode_propagate_layers: [L1]`
meta knob in `context_profiles.yaml` and a 20-LOC call-site in
`task_adaptive_selector.select_context()`. v7.0.x keeps the existing
L0-only propagation (status quo).

### 7.3 Cache-layout SLO — RESOLVED

**Decision:** LCP ≥ **80 %** (round 1→2) and LCP ≥ **70 %** (round
1→3) as a proxy for the 90 % cache-hit-rate target cited in research
§B.6.

**Rationale:** Direct cache-hit-rate measurement is blocked by open
question K.7 (Cursor platform). LCP is a **necessary but not
sufficient** condition for cache stability — we adopt it as the
strictest measurable proxy. Thresholds match research §H.2 draft
values.

**Ships in:** v7.0.0 (ADR-001).

### 7.4 Tool-result clearing default — RESOLVED

**Decision:** `keep=3`, matching Anthropic's published default in
`[ref-6]`. `exclude_tool_names=["Read"]` by default.

**Rationale:** Empirical evidence from Anthropic's cookbook shows
`keep=3` suffices on real workloads. H.1 retention benchmarks (H.1 at
§5.1) guard against surprises at the DevolaFlow scale. Operators can
raise to `keep=5` per profile if their workflow warrants it.

**Ships in:** v7.0.1 (ADR-002).

### 7.5 Memory-tool surface area — RESOLVED

**Decision:** **Keep JSONL**. Do **not** expose a Claude-style
file-system memory tool (`view`/`create`/`str_replace`/`insert`/
`delete`/`rename`) in v7.x.

**Rationale:**
- Hook-based validation already covers JSONL shape trivially
  (`test_on_complete` runs `test_learnings.py` on every dispatch).
- A file-system memory tool duplicates the functionality that the
  existing `Read` / `Write` / `StrReplace` tools provide against the
  JSONL file.
- v7 scope is tight; adding a new tool surface would force a SKILL.md
  re-budgeting pass and likely a rule re-write in
  `.cursor/rules/skill-format-rules.mdc`.
- **DEFERRED to v8.x+** if learnings-consumption metrics show a
  workflow benefit. Re-entry into planning via SI-1 gate in v8.0.0.

**Ships in:** v7.0.3 (additive schema only).

### 7.6 NineS V1 evaluator authoring — RESOLVED

**Decision:** Author **3** compression-specific golden TOMLs in
v7.0.2 (`compression_retention_easy/medium/hard`) and **2** more in
v7.1.0 (`compression_tool_output`, `compression_persistence`) — total
**5** by the cycle's end.

**Rationale:** The research report asked whether 3-5 was feasible.
The answer is yes: three of them map 1:1 to the three H.1 probe
scenarios we already design for v7.0.2; the final two plug in at
v7.1.0 as part of the adoption / retrospective release. Spreading the
authoring across two versions keeps the v7.0.2 scope manageable.

### 7.7 Cursor product roadmap dependency — RESOLVED

**Decision:** **Stay strictly prompt-side for v7.x**. No proactive
outreach to Cursor in this iteration.

**Rationale:** The prompt-side stack (cache-layout invariant +
truncation + summariser) is sufficient to realise the 5-10x cost
improvement per research §A. Cursor cooperation would add value but
isn't on any v7 critical path. **DEFERRED to v8.x** with a specific
outreach plan authored in v7.1.0's retrospective — once we have our
own LCP telemetry from v7.0.0+ to present.

### 7.8 Sub-agent context budget — RESOLVED

**Decision:** **Raise `sub_agent_context_budget` from 3000 to 5000
tokens** for all decomposition-enabled profiles (`feature`,
`refactor`, `skill-optimization`, `perf-optimization`, `migration`,
`security-audit`). Non-decomposition profiles are unaffected.

**Rationale:** Research §B.4 + §C.5 cite sub-agents using "tens of
thousands of tokens" internally. 3000 is too tight for JIT
retrieval. 5000 stays well under the 8000 L3 ceiling and leaves
headroom for the coordinator's returned summary (≤ 2000 tokens per
research §B.4).

**Ships in:** v7.0.1 (bundled with the truncation release because
both touch `context_profiles.yaml`).

## 9. Backwards compatibility + migration plan

### 9.1 Breaking-change enumeration

The v7 cycle has **one** user-visible breaking expectation and **zero**
breaking Python API changes.

| Version | Breaking? | What breaks | Opt-out |
|---|---|---|---|
| v7.0.0 | **Yes (governance)** | Downstream dispatch renderers that reordered top-level keys silently now raise `DispatchLayoutError`. | Any renderer that needs a different order MUST author a successor ADR revising `layout_invariant.canonical_order`. No runtime opt-out — this is the governance contract. |
| v7.0.1 | No | Optional `tool_results` block is additive. | N/A (not required). |
| v7.0.2 | No | Optional `summary_mode`, `summary_max_tokens` fields are additive with defaults. | `summary_mode: extractive` is the default (identical behaviour to pre-v7 ad-hoc extraction). |
| v7.0.3 | No | Learnings v2 fields are additive with defaults. | Pre-v7 entries parse unchanged. |
| v7.1.0 | No (adoption only) | Default profiles flip `tool_output_truncation.enabled: true` and `summary_mode: extractive`. Operators who relied on the disabled behaviour must explicitly opt out. | Set `tool_output_truncation.enabled: false` / `summary_mode: null` in the operator's profile override. |

### 9.2 Rationale for the v7.0.0 MAJOR bump

Per SemVer, a MAJOR bump is required when "you make incompatible API
changes". The cache-layout invariant is not an API change at the
Python level — it's an **expectation contract** at the rendered-YAML
level. We bump MAJOR because:

1. Any downstream tooling that silently reordered dispatch sections
   now fails a runtime assertion.
2. `.cursor/rules/devola-flow-rules.mdc` gains a new permanent rule
   (P6 — Preserve Cached Prefix) which is a governance-level
   constraint indistinguishable from a breaking change to workflow
   consumers.
3. Future v7+ primitives will assume the invariant holds; downgrades
   back to v6.x are one-way.

This MAJOR rationale is documented in the v7.0.0 CHANGELOG entry.

### 9.3 Migration path (version-by-version)

**v6.2.1 → v7.0.0:**
- Run `scripts/bump_version.py 7.0.0` (updates 8 sync locations per
  §4.1 of the roadmap).
- Verify `tests/test_benchmarks.py::test_layout_invariant_baseline`
  passes against the new golden file.
- Existing profile behaviour unchanged; no operator action needed
  unless a custom dispatch renderer is in use.

**v7.0.0 → v7.0.1:**
- Run `scripts/bump_version.py 7.0.1`.
- Sub-agent budget raised to 5000 for 6 profiles; this is **additive
  room** — no operator action required. Operators who manually
  pinned sub-agent budget to 3000 see their override honoured.

**v7.0.1 → v7.0.2:**
- Run `scripts/bump_version.py 7.0.2`.
- `summary_mode: extractive` is the default; any operator who wants
  the pre-v7.0.2 ad-hoc behaviour must set `summary_mode: null` in
  their profile (not recommended).

**v7.0.2 → v7.0.3:**
- Run `scripts/bump_version.py 7.0.3`.
- First load of `operational.jsonl` shims `last_accessed` for legacy
  entries lazily (no file rewrite).
- Persistence probe runs in the default pytest suite; CI is expected
  to succeed on a freshly-migrated repo.

**v7.0.3 → v7.1.0:**
- Run `scripts/bump_version.py 7.1.0`.
- Run `make sync-human-docs` to propagate version into generated docs.
- 6 profiles flip `tool_output_truncation.enabled: true`; operators
  see a ~20 % dispatch-size reduction in round 2+ convergence.
- Default `summary_mode` on all predecessor-consuming profiles set to
  extractive; operators already on v7.0.2 see no change.
- SI-8 retrospective and SI-3 scorecard live under
  `.local/research/retrospective_v7.0_to_v7.1.md` and
  `.local/research/v7.1.0_evaluation_report.md`.

### 9.4 Feature-flag map

Every v7 primitive is behind a flag that defaults to "disabled" at
patch cut and "enabled" at v7.1.0 adoption:

| Primitive | Flag | Default v7.0.x | Default v7.1.0 |

| Plan-mode L1 propagation | `plan_mode_propagate_layers: [L1]` | L0 only (pre-v7 behaviour) | L0 + L1 |

|---|---|---|
