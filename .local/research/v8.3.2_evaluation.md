### 2.2 Architecture rationality (weight 0.20) — score **9.3/10**

**Evidence:**
- **Additive 5th lifecycle event** (`pre_shell_call`) added to `DEFAULT_EVENTS` tuple alongside existing 4. The `lifecycle/__init__.py` change is pure additive: `_set_default_hook(_PRE_SHELL_CALL_EVENT, pre_shell_call)` line + 1 export each in `PRE_SHELL_CALL_EVENT` constant + `pre_shell_call` function name + `__all__` entry. R5 strict — all 4 pre-existing event tests pass byte-identical (the only test change is `tests/test_lifecycle_hooks.py::test_default_events_match_skill_md_table` expanded set assertion 4 → 5).
- **Single-source-of-truth pattern** mirrored from RTK's `src/discover/registry.rs` (per SI-2 NineS analysis §4.1) — `shell_proxy/registry.py::WHITELIST` is the ONLY file that knows about which commands to rewrite; the proxy + the hook + the tests all read from it. Adding a new entry is a 1-line dict change.
- **Tier model** lifted from RTK's filter design + SI-2 §6.1 whitelist table: Tier 1 ships default-on (5 commands the W-9 / SI-10 gate exercises every PV: `pytest`, `ruff check`, `git diff`, `git log`, `git status`); Tier 2 opt-in via secondary env-flag `DEVOLAFLOW_RTK_PROXY_TIER2=1` (6 commands with lower per-call frequency or smaller savings: `git add`, `git commit`, `git show`, `cargo test`, `npm test`, `make`).
- **Frozen activation snapshot** — `ShellProxyConfig` is captured once per `ShellProxy` instantiation; the per-call hot path is dict + regex match (no env re-read, no PATH lookup). When the env-flag is off, the snapshot is the trivial defaults path (no `shutil.which`, no subprocess) per R5 strict.
- **Thin delegator hook** — `lifecycle/pre_shell_call.py` contains NO rewrite logic. It validates the payload schema (`PSC001..PSC004` violation codes), calls `ShellProxy().wrap_command(cmd)`, and stuffs the result + config snapshot into `HookResult.metadata`. Rewriting concerns are isolated in `shell_proxy/`; lifecycle integration is isolated in `lifecycle/pre_shell_call.py`.
- **Default-off discipline** — the env-flag is the single activation point. Even when the user accidentally has `rtk` on PATH but does NOT set the env-flag, the proxy is OFF (per `is_proxy_enabled()` returning False). No surprise activation.
- **R5 strict** verified by:
  - All 3107 pre-existing tests pass byte-identical when env-flag off
  - `tests/test_shell_proxy_disabled_is_noop.py` codifies the contract at the unit-test layer (103 lines, 4 collected tests with intentionally-named test functions to flag intent)
  - `benchmarks/devolaflow_context/scenarios/shell_proxy_disabled.yaml` codifies it at the EvoBench layer (composite 91.21 above floor 90)
- **Graceful degradation** — when env-flag IS set but rtk is missing or distinguish fails, the proxy logs a WARNING and gracefully passthroughs (does NOT raise). Matches RTK's own Claude hook behavior in `hooks/claude/rtk-rewrite.sh` lines 21-24 per SI-2 NineS analysis §6.2.
- Slight bump from v8.3.1's 9.0 — more architectural surface; clean module boundaries; RTK-faithful design pattern (single-source-of-truth registry + thin-delegator hook).

**Score 9.3** — clean module boundaries, single-source-of-truth registry, proper hot-path discipline, RTK-faithful design pattern.

- 0 regressions > 5pp across all 46 EvoBench scenarios vs `v8.3.0_baseline.json`
- Equal to v8.3.1's 9.0 — passes the W-4 / SI-4 hard gate (0 regression > 5pp); the new event adds a sub-microsecond cost per Shell-tool dispatch
