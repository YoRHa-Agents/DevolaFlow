## §2 — Per-dimension detail

### §2.1 Code quality (9.0)

* **Linting**: `ruff check src/ tests/ benchmarks/` clean across 227 files. Zero violations introduced; the SIM108 noqa in `dispatch_executor.py::_run_one_sync` is justified by an inline comment-bearing branch (the comment-bearing if/else is more readable than a ternary).
* **Formatting**: `ruff format --check` clean across 227 files.
* **Complexity hotspots**: PV-04 closed `extract_named_entities` CC=11 + `_assemble_abstractive_summary` CC=11 by isolating them in `transforms.py` (still CC=11 per radon — the LOGICAL refactor of those 2 functions is deferred to a future PV per gap analysis §2.4 — but the structural impact is reduced because they're no longer interleaved with the layout / patterns surfaces).
* **Documentation**: Every new public symbol carries a docstring; every cache layer + dead-api workaround carries a comment block citing the rule it satisfies.

**Score deduction (-1.0)**: NineS CC=11 hotspots not yet decomposed (deferred to v9.4.0+).

### §2.2 Architecture rationality (9.5)

* **A-2 frozen prefix preserved**: All 25 multi-baseline byte-stability tests pass byte-identically; the new `layout_invariant_v9.3.0.yaml` is a verbatim copy of `layout_invariant_v9.2.0.yaml` (no schema bump). The frozen prefix invariant (positions 1-12) is unchanged.
* **PV-04 3-module split honours cache-layout governance**: The split chose the granularity that minimises cache-prefix-drift risk per the user's Q3 = C affirmation. `__init__.py` re-exports preserve the public API at the same path.
* **PV-05 P1 invariant verified**: `test_executor_calls_only_provided_callables` is the architectural witness — it asserts the exact invocation count after a parallel dispatch, proving the executor never invokes any internal helpers. This is the canonical P1 (Soul Rule S-1) test pattern.
* **PV-06 W-20 §3 orthogonality**: The new `DEVOLAFLOW_SIMPLE_SHORTCUT` env flag passes the W-20 reuse-first checklist with a documented orthogonality justification (different activation surface than every existing flag). The justification is committed inline in `references/env-flags.md` §2.12.
* **Empirical research drove cycle ordering**: The PV-01 cProfile harness's discovery that `run_hooks` is microseconds-scale (vs the cycle plan's hypothesis that it was a hot path) caused the PV-05 re-target. This is the canonical "research-before-implementation" pattern that W-1 / SI-1 mandates.

**Score deduction (-0.5)**: PV-05 ships the executor as a library only (no auto-wire); the architectural completion (dispatcher integration) is deferred to v9.7.0 PV-03. The library-only landing is correct for v9.3.0's risk profile but the architectural arc is incomplete.

### §2.3 Test adequacy (9.0)

* **Cycle test count**: +36 NEW test functions across PV-02 through PV-07 (24% W-17 utilisation; +114 headroom for v9.4..v9.7 cycles to consume).
* **Coverage floor**: ≥ 80% maintained on every new module per the W-9 / S-3 contract.
* **Regression guards wired**: PV-02's latency harness ships the regression guards for the next 5 minor cycles. The per-primitive p95 sanity ceilings (`P95_SANITY_CEILING_US` in `tests/test_dispatch_latency.py`) are intentionally generous (10× post-PV-03 expected) to catch a 100× regression without false-positiving on slow CI.
* **P1 invariant test**: `tests/test_async_dispatch_executor.py::test_executor_calls_only_provided_callables` is the canonical architectural witness for Soul Rule S-1.
* **Multi-baseline byte stability**: all 7 historical baselines pass byte-identically (PV-04's risk-tier-1 surface).

**Score deduction (-1.0)**: The PV-05 perf-sensitive test (`test_select_context_lru_warm_path_is_materially_faster`) is opt-in via `DEVOLAFLOW_RUN_PERF_TESTS=1` to avoid CI false-positives on slow workers. The choice is correct, but the live regression guard is then the per-primitive p95 sanity ceiling, not a per-PV delta against the wholesale baseline. A future PV may want to wire a delta-based regression guard.

### §2.4 Maintainability (9.5)

* **Compressor split**: 2541 LOC single-file → 4 thematically-tight files (321 + 301 + 221 + 1983). Future maintainers can navigate by concern (`patterns` for regex tables, `layout` for cache governance, `transforms` for compression pipeline, `__init__` for public re-exports).
* **LRU cache layer documentation**: The `task_adaptive_selector.py` cache layer block carries a verbatim mutability contract + an explanation of the split-by-branch design + the rationale for `lru_cache(maxsize=2048)` ceiling. A future maintainer reading this block can predict the cache behaviour without digging into the implementation.
* **Dead-API pin pattern**: PV-04, PV-05, and PV-06 all use the same private-tuple pattern. The pattern is consistent and self-explanatory; the inline comments cite the precedent module.
* **Env-flag inventory**: `references/env-flags.md` §2.12 entry mirrors the 11 sibling entries' table format — a future operator scanning the file finds the new flag without re-learning the schema.

**Score deduction (-0.5)**: The PV-04 `__file__` redirect (so radon CC tests find the helpers) is non-obvious. While the inline comment explains it, a future structural refactor (e.g. moving the CC tests to `tests/test_compressor_complexity.py`) would be cleaner.

### §2.5 Compatibility (10.0)

* **All 7 layout-invariant baselines byte-identical**: v7.0.0 + v7.3.0 + v8.0.0-P08 + v8.0.0-P10 (via prefix-check) + v8.3.0-PV05 + v8.4.0 + v9.2.0 + v9.3.0 (the new witness). Any future schema bump would have to add an 8th baseline AND keep all 7 prior baselines passing.
* **`compressor` public API preserved**: Every symbol in the original `compressor.py::__all__` is still importable from `devolaflow.compressor` at the same path. Test verification: `from devolaflow.compressor import [30+ symbols]` works unchanged.
* **`DEVOLAFLOW_SIMPLE_SHORTCUT` opt-out path is byte-identical**: When the flag is unset (default), `shortcut_verdict(...)` returns `"NO_SHORTCUT"` for every input — preserving v9.2.4 behaviour byte-identically.
* **No breaking version semantics**: v9.3.0 is a MINOR (additive features only); no Python module renames, no signature changes on existing public functions, no removed env flags.
* **Test count is purely additive**: 3635 → 3676 (no deletions, no skips added beyond the opt-in perf test).

**No score deduction.** Compatibility is the v9.3.0 cycle's strongest dimension — every PV was designed to preserve the v9.2.4 surface verbatim where possible.

### §2.6 Performance impact (9.5)

* **Headline gain**: select_context p95 80ms → 2ms = **40× speedup, 97.5% improvement**. Exceeds the ≥90% improvement target set in `.local/research/v9.3.0_gap_analysis.md` §6 by 7.5pp.
* **Full-dispatch gain**: full_dispatch p95 79ms → 4ms = **94.7% improvement**. The L0→L1 dispatch shape is the user-visible bottleneck.
* **Pytest wall clock**: 55s → 17s = 3.3× speedup. Side effect of PV-03's LRU cache reducing the 600+ select_context calls fanned across 3635 tests.
* **EvoBench composite unchanged**: All 53 scenarios stay within ±2% of baseline (the W-4 regression-threshold floor). No benchmark regressions.
* **No regressions on any measured primitive**: Even `run_hooks` (already microseconds-scale pre-PV-03) saw a 22% p95 improvement — purely from the LRU cache reducing the dominant cost upstream.

**Score deduction (-0.5)**: The PV-05 AsyncDispatchExecutor's perf gain is purely architectural (the cycle didn't measure its end-to-end impact because there's no dispatcher seam yet). The library is faster-when-applicable but the applicable surface is empty in v9.3.0. Future PVs will surface the gain.
