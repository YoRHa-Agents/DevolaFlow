## 1. Gaps identified (SI-1 planning gate)

The v10.5.0 cycle was scoped via the v11.0.0 admission rollout as the
second MINOR cycle after v10.4.0. Source-of-truth direction:
`.local/research/v10_internal_optimization_directions.md` §3.1 (D-A
architecture health) + §3.7 (D-D documentation health). The per-PDS
gap analyses live at `.local/research/v11.0.0_patches/D-A-1.md` /
`D-A-2.md` / `D-A-3.md` / `D-A-4.md` / `D-D-3.md` / `D-D-4.md`.

The 6 gaps admitted for v10.5.0:

1. **D-A-1** — SKILL.md §"4-Layer Agent Hierarchy" implies L1 Stage +
   L2 Wave are dispatched per cycle; empirical evidence across 13
   v9.x-v10.x cycle docs shows most cycles collapse L0 → L3 in
   practice. The documentation / practice mismatch costs operator
   time-to-action on Simple tasks (~50% overhead reading 4-layer
   table before deciding to skip). **Fix:** audit script + advisory
   annotation + new XL-tier example covering the multi-team analyze
   counter-case.
2. **D-A-2 Phase A** — 22 workflow templates registered in
   `workflow-system/agent/templates/builtin/`, but audit reveals
   only 6 are USED in cycle execution (27% utilization rate). 16
   templates are REGISTERED-but-unused in v9.0.0..v10.3.0 cycles.
   **Fix:** audit script + per-yaml deprecation comment header + SKILL.md /
   meta-framework.md / team-roles.md `(legacy)` annotations. Phase B
   compose-not-define collapse deferred to v12.0+.
3. **D-A-3** — No reference answers "what does L0 do when returning
   to an active change folder ≥ 24 h later, in a new session?" The
   machinery exists (STATUS.yaml, append-only handoff envelopes,
   change_context dispatch field) but the RESUME protocol is
   undocumented. **Fix:** new §3.6 "Resume After Pause" subsection in
   `references/agent-workspace.md` documenting 5-step pre-resume
   checklist + resume dispatch contract + concurrency-safe resume +
   stale-change pruning.
4. **D-A-4** — `activation_verdict()` has no per-dispatch operator
   override; `--no-change` is slash-command-level only. Operators
   wanting ad-hoc exploratory dispatch must unset the env flag
   globally. **Fix:** add `force_no_change: bool = False` fourth
   parameter; default preserves byte-identical v10.4.x behaviour.
5. **D-D-3** — C-4 tiered line budgets may cause compression pressure
   that pushes paragraphs from "dense but clear" to "compressed and
   ambiguous". No audit measures this. **Fix:** measurement script
   with deterministic heuristic (>= 100 words AND >= 5 abbreviations
   AND zero embedded examples) emitting per-doc density table + 3
   worst-paragraph candidates.
6. **D-D-4** — `tests/test_no_ghost_features.py` now holds 24+ cycle-
   specific W-18 lints (~150 LOC each × N = ~3600+ LOC of
   per-cycle lint). Linear extrapolation projects ~24K LOC by v15.0.0.
   **Fix:** audit script emitting cycle-by-cycle trajectory +
   stale-pin detection. Consolidation DEFERRED (would lose
   per-cycle traceability).

## 3. What was deferred and why

- **D-A-2 Phase B** (compose-not-define collapse — replace TIER-2
  yaml files with parametrized invocations of TIER-1 templates
  via 5 composition operators). Deferred to **v12.0+** per PDS
  §2 Phase B note. Rationale: Phase B requires the registry schema
  to support `alias-of` / `macro` fields → schema bump v1.0 → v2.0
  requires independent SI-1 gap analysis. Phase A (audit + tagging)
  is the evidence bundle that justifies the schema bump; shipping
  both in v10.5.0 would exceed the cycle budget and conflate two
  independent decisions.
- **D-D-3 3-paragraph reference extensions** — the PDS §5 cites 3
  specific paragraphs (SKILL.md L38-40 install, SKILL.md L460
  Operational Learnings, compression-pipeline.md L192-199 transform
  table) with before/after expansion proposals. The PATCH ships the
  audit + proposals; APPLYING the expansions is deferred to v11.X.0+
  per PDS §6 CONDITIONAL_PASS rationale. Rationale: applying
  expansions concurrent with the audit would conflate the
  observability deliverable with the refactor decision.
- **D-D-4 consolidation of historical lints** — the 4 proposed
  consolidation patterns stay as PROPOSALS only. Rationale: per
  v10.0.0 retrospective §4.2 "demo/index.html 'automated' lint
  trip" precedent, the per-cycle traceability is load-bearing for
  bug-finding. The trajectory projection identifies the v13.0.0+
  crossover point where consolidation savings exceed traceability
  cost; until then, preserving the per-cycle ledger is correct.
- **W-9 SI-10 fast-path enforcement on D-A-4** — the
  `force_no_change` parameter is a natural complement to a
  `precommit-fast` path (skip the workspace scaffold for in-PR
  iteration). The parameter ships in v10.5.0; the precommit-fast
  plumbing (D-X-3 from v10.4.0) already supports it via the
  function-parameter path. No new env flag needed (W-20 reuse-first).
- **NineS self-eval** — skipped for v10.5.0 per the normative note
  in Rule W-2 ("When NineS is unavailable, manual analysis following
  the same dimensions is acceptable but must be noted as manual").
  Manual analysis is embedded in the PDS §5 benefit_metrics tables
  for each of the 6 patches; W-3 §3 weighted composite is the
  operator-facing gate.

## 4. Key learnings

1. **Cycle plan §6 R-11 file-touch serialization worked.** The
   5 PVs touched overlapping surfaces (SKILL.md, meta-framework.md,
   team-roles.md) but sequential execution (PV-01 → PV-02 → PV-03 →
   PV-04 → PV-05) avoided merge conflicts entirely. For future
   cycles with multiple-PDS SKILL.md edits, the serialization
   discipline should be preserved.
2. **W-20 reuse-first env-flag policy preserved.** D-A-4 could have
   been authored as a new `DEVOLAFLOW_FORCE_NO_CHANGE` env flag; the
   reuse-first test (same activation surface as `DEVOLAFLOW_AGENT_WORKSPACE`)
   correctly routed the feature through a function parameter instead.
   The parameter path is strictly better: scoped per-dispatch, zero
   env-pollution, no new lifecycle hook.
3. **PDS evidence-bundle-first pattern paid off.** All 4 audit
   scripts (D-A-1, D-A-2, D-D-3, D-D-4) ship OBSERVABILITY only; zero
   refactor decisions baked in. This separates the evidence
   production from the decision-making and matches the v10.0.0
   retrospective §4.5 "high-information vs scaffolding distinction".
   Future cycles should prefer evidence-first patches over combined
   evidence + refactor patches.
4. **Rule A-6.3.1 sub-rule would be cleaner than an A-6.3 inline
   citation.** The D-A-4 patch adds `force_no_change` but does NOT
   materialize a dedicated A-6.3.1 sub-rule in `.rules/architecture.mdc`.
   Instead the feature is cross-referenced inline. Next cycle should
   consider whether materializing A-6.3.1 as a formal sub-rule
   improves discoverability (answer is probably yes — defer to
   v10.6.0 SI-1 to decide).
5. **W-18 ghost-audit authoring should be templatized.** The v10.5.0
   W-18 stanza (~120 LOC) follows the same pattern as every prior
   cycle: define ~15 constants, then 15 assertions, then 1
   explanation docstring. D-D-4's consolidation proposals propose
   exactly this templatization. The v12.0+ consolidation decision
   should be informed by the audit's trajectory table + v11.X.0
   operator feedback.
6. **The 4th example file (multi-stage-trace.md) benefits from the
   D-A-1 pattern.** The synthesis "here's the collapse rule AND
   here's the counter-case" is more operator-friendly than either
   alone. Future SKILL.md advisory wordings should include the
   counter-case reference inline.
