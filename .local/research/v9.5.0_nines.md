## §3 — Limitations of manual fallback

1. **No JSON output** — manual analysis cannot produce the structured `nines.json` artifact. Future cycles with NineS available will produce both `.json` + `.md`.
2. **No automated AST walk** — cyclomatic complexity numbers are manual estimates. NineS-driven analysis would compute them via radon for precision.
3. **No symbolic execution / dead-code detection** — beyond what `tests/test_dead_apis.py` already provides.
4. **No diff-vs-baseline metric** — the v9.4.0 baseline composite of 0.911 is sourced from the v9.4.0 retrospective; without NineS we cannot recompute the baseline against the current src/ tree.

## §4 — Recommendation for future cycles

The v9.6.0 cycle MAY consider:

* Installing NineS in the dev/CI environment via the v9.4.0 `pip` backend in `runtime-plugins.yaml` (already wired — just requires `nines>=3.0.0` in the env)
* Setting `DEVOLAFLOW_AUTO_INSTALL_PLUGINS=1` to auto-install NineS on the first dispatch that needs it
* Running `nines -f json -c nines.toml self-eval ...` at PV-N close to produce both the `.json` + `.md` artifacts

Until then, manual fallback per W-2 is the canonical alternative — explicitly noted here per the W-2 contract.
