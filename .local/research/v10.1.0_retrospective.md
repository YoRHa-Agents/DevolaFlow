# v10.1.0 — Cycle Retrospective (W-7 SI-8)

## 1. Gaps identified (from SI-1 planning gate)

The v10.1.0 SI-1 gap analysis (`.local/research/v10.1.0_gap_analysis.md`)
enumerated 14 gaps: 4 BLOCKER, 5 MAJOR, 5 MINOR.

The BLOCKER set was the minimum for the cycle to deliver on the user's
feedback mandate:

* **G-A1** — No measurement infrastructure for "AI 味". No scorer, no CI
  gate, no per-doc threshold anywhere in the repo.
* **G-A2** — No transformation engine. The worst documents needed
  mechanical fixes but there was no module that could apply them.
* **G-A3** — No release-gate integration. Without a gate, every future
  CHANGELOG entry would inherit the same AI-flavored pattern.
* **G-A4** — No legacy-vs-new content policy. Historical CHANGELOG
  entries and user guides needed different treatment.

The MAJOR set included scorer sophistication (burstiness + MTLD
refinements), a human-facing style guide, the hot-path non-pollution
architecture rule, golden baselines committed to the repo, and
quote-aware lexical tokenisation.

The MINOR set covered future-iteration work: Mandarin tokenisation
improvements, LLM-as-judge calibration, html-aware demo scoring, and
Si-Chip wiring.

## 2. What was implemented

All four BLOCKERs closed.

**G-A1 closed in PV-02.** `src/devolaflow/writing_style/scorer.py` is
the production port of the PV-01 probe. It extracts 16 features per
document — chars, words, sentences, CJK chars, avg sentence length,
sentence-length standard deviation, burstiness, TTR, header ratio,
bullet ratio, bold density, em-dash density, Tier-1 vocab density,
Tier-2 vocab density, signpost density, negative-parallelism density,
and copula-dodge density — and collapses them into a naturalness
composite on the 0-to-100 scale. The aggregate on the DevolaFlow
corpus matches the PV-01 baseline of 69.958 byte-for-byte, so the
benchmark harness is the source of truth for all subsequent gates.

**G-A2 closed in PV-03.** Five SAFE transforms ship as the PV-03
batch: `emdash`, `bullets`, `signposts`, `headers`, `cliches`. Each is
a pure function that edits prose regions only; protected regions
(fenced code, inline code, markdown links, version strings, html tags,
bare URLs) come through every transform byte-identical. The tests
include a region-split round-trip assertion plus region-awareness
assertions for each protected span type.

**G-A3 closed across PV-04 + PV-05.** PV-04 wires the scorer + transforms
into `scripts/generate_human_docs.py` (in-pipeline humanization at EN
/ ZH guide generation time) and adds a `make humanize-docs` target
plus a `scripts/humanize_doc.py` CLI (`score` / `check` / `apply`).
PV-05 runs the humanizer against the real corpus, measures POST vs
PRE, evaluates the three ship conditions, and ships a regression
test (`tests/test_writing_style_benchmark_regression.py`) that pins
the post-transform baseline as the floor for every future PV.

**G-A4 closed via tone profiles.** The three profiles —
`technical_concise` (CHANGELOG, research artefacts), `documentation_natural`
(README, EN / ZH guides), `marketing_warm` (demo landing) — are the
policy surface. CHANGELOG entries get T-S1 + T-S5 only per Q-D;
structural transforms (bullets, signposts, headers) are disabled on
that profile so the release-notes register stays intact.

The MAJOR set was partially addressed. G-B4 (hot-path non-pollution)
landed as `tests/test_writing_style_isolated.py` — the static import
graph lint that blocks any module under `writing_style/` from being
imported by the dispatch hot path. G-B5 (golden baselines) landed as
`benchmarks/writing_style/baselines/v10.1.0_pre.json` and
`v10.1.0_post.json`. The remaining MAJOR items (G-B1 scorer
sophistication, G-B2 quote-aware tokenisation, G-B3 contributor style
guide) are deferred to v10.2.0; the BLOCKER closures were sufficient
to ship the feedback fix.

## 3. What was deferred and why

**MTLD lexical diversity (G-B1).** TTR with a 200-token sliding window
is the PV-01 approximation. MTLD is better on technical docs but
adds complexity without a matching user-visible win. Deferred to
v10.2.0 when we have a measurement surface to tune against.

**Quote / example aware tokenisation (G-B2).** The blockquote + table
strip in `_strip_quoted_examples` is good enough for the PV-01 corpus
(it kept the editorial meta corpus above the human-clean aggregate).
A fuller `code:` / `quote:` / `example:` tag-aware tokenizer is a
v10.2.0 candidate.

**Contributor writing guide (G-B3).** A `workflow-system/human/CONTRIBUTING-WRITING.md`
doc would teach new authors the same rubric the scorer enforces.
Deferred because the gate itself (the regression test) surfaces the
same lessons mechanically; a human-facing doc is a v10.2.0 quality-of-
life improvement.

**Mandarin tokenisation via jieba (G-C2).** The PV-01 probe's CJK = 1
word per character mapping was sufficient to score all 8 ZH guides
consistently. A real tokenizer is a v10.2.0+ refinement.

**LLM-judge calibration (G-C3).** Optional and offline. The weights
we shipped in `compute_composite` are first-pass intuition calibrated
against the human-clean corpus. Fitting them against a Claude /
GPT-4 judge would tighten the composite, but it never runs in CI
(per the user mandate C-3) and is not blocking.

**HTML-aware demo scoring (G-C4).** The demo landing page scores 90.57
because the html strip removes most visible prose. This is an
artefact; the demo is excluded from the gate in practice. Fixing it
requires a `<p>` / `<li>` / `<h*>` tag-aware pre-pass. Deferred.

**Si-Chip integration (G-C5, G-B5 partially).** Cost-vs-naturalness
Pareto analysis via Si-Chip's `count_tokens` is interesting but
orthogonal to the v10.1.0 feedback mandate.

**T-R1 through T-R4 "risky" transforms.** Tier-1 vocab substitution,
copula-dodge unwinding, negative-parallelism rewrites, and "from X
to Y" range collapses all require context-aware judgment that
mechanical regex cannot provide safely. The PV-01 research explicitly
categorised these as risky. None ship in v10.1.0; the SAFE-only
policy was the deliberate scope cap.

**T-OL series (header restructuring, section reordering, code
rewriting, signature paraphrasing, CLI rewriting, version normalisation,
tone shift, first-person addition, humour addition).** Permanently
off-limits per the PV-01 research §5.3. None are candidates for any
future v10.x cycle.

## 4. Key learnings

**The AI-flavor problem is structural density, not lexical leakage.**
The PV-01 measurement found that DevolaFlow's docs are already clean
on Tier-1 vocabulary ("delve", "tapestry", etc. — 0.11 per 1000 vs
the human-clean baseline of 1.31). The real tells were structural:
bold density at 44.68 vs 37.27, em-dash density at 15.39 vs 7.79,
bullet ratios in the worst docs hitting 0.628. That meant the
transform scope could be much narrower than the 30-plus tokens the
"humanize-writing" reference corpus teaches — we only needed five
transforms covering the four structural dimensions and a vocabulary
guard-rail.

**Region-walking is not the right scope for every transform.** The
first four transforms (emdash, bullets, signposts, cliches) operate
per prose region and that is correct — each transform edits within a
region boundary and never crosses one. The fifth (headers) counted
body word counts per region at first, which misfired on the README
because inline-code and markdown-link fragmentation produces small
prose regions that lose the context of a trailing table or bullet
block. Moving the headers transform to document-scope counting with
a line-level fence tracker solved it. The lesson is that region-
safety applies to the EDIT boundary, not necessarily to the
MEASUREMENT boundary — a transform can read the whole document and
only write within region boundaries.

**Per-paragraph caps are not enough when entries are short.** The
PV-03 em-dash cap triggered at 3+ em-dashes per paragraph, which is
the natural interpretation of the PV-01 spec. But CHANGELOG entries
are one em-dash each, per bullet; the per-paragraph cap never fires.
We needed a document-scope density cap at 8 per 1000 words to move
CHANGELOG. The lesson generalises: cycle-level targets (density
floors / ceilings) need a cycle-level enforcement pass, not only
per-paragraph ones.

**The algorithmic ship gate is the right discipline.** The task
spec said: "Do not rationalize a marginal miss into a ship. The
decision is algorithmic." We came close to rationalizing a 72.943
aggregate as good-enough (below the 73 floor) before we tightened
the em-dash target from 12 to 8 per 1000 words. Having the three
hard conditions in the spec kept the decision honest: we kept
iterating on the transform parameters until all three passed with
comfortable margin, instead of declaring victory early.

**CHANGELOG prose in this entry should embody what it describes.**
This cycle's CHANGELOG entry itself goes through the `technical_concise`
humanizer profile on every future generation. We wrote it in prose,
without signposting openers, without em-dash showers, without "in
conclusion" or "it's important to note". That is what v10.1.0 is for.
If the entry reads as natural technical prose, we did the job.
