## Fallback semantics

The estimator fallback is `max(1, len(text) // 4)`, where `len` counts Python
Unicode characters, not UTF-8 bytes and not provider tokens. It is a
deterministic sizing heuristic, not a tokenizer. It floors the result and
returns at least one token for non-empty short text.

For reference, the fallback values for these exact inputs would be:

- `AGENTS.md`: `7986` versus tiktoken `8315` (absolute `329`, relative
  `3.96%`).
- `workflow-system/agent/SKILL.md`: `4490` versus tiktoken `4396` (absolute
  `94`, relative `2.14%`).
- `tests/fixtures/example_dispatch.yaml`: `303` versus tiktoken `340`
  (absolute `37`, relative `10.88%`).

The fallback is not the measured DevolaFlow result here because tiktoken was
available in the isolated probe environment. It remains the result expected
from the initially observed stock environment.

## Interpretation and limitations

1. DevolaFlow and the explicitly selected `gpt-4o` tiktoken encoding are
   byte-for-byte consistent on all three samples. This is expected because the
   current estimator delegates to that same encoding when importable.
2. The CLI fallback produced a positive difference above offline counts for
   all three samples (`44`, `3205`, and `181`), but the magnitude is not
   stable: approximately `0.53%`, `72.91%`, and `53.24%`. Therefore the run
   shows an observed positive deviation, but does **not** establish a
   systematic tokenizer bias.
3. The CLI value includes the provider's own request accounting and may differ
   in tokenizer, prompt serialization, hidden/system context, or accounting
   boundaries. A usage difference is only an indirect estimate of the
   inserted artifact, not an official count-tokens operation.
4. A preliminary pair run without unique probe IDs showed cache contamination
   (including a cache-read value of `1635` for the fixture baseline and a
   `14524` AGENTS difference). Those values were excluded from the primary
   result; the unique-ID run above had zero cache fields and is the reportable
   CLI observation.
5. The CLI provider/model identity was `firstParty/ark-code-latest`, not an
   Anthropic model identity. This further limits any comparison to Anthropic
   API tokenization.
6. The three samples are representative repository artifacts, but three
   observations cannot prove provider-wide behavior. No official API result
   exists in this run, so official-provider parity remains `INSUFFICIENT`.

## Reproduction commands

Run from the repository root. These commands intentionally expose only
availability and aggregate counts; they do not print credentials or file
contents.

```bash
git rev-parse HEAD
git status --short --untracked-files=all
python3.13 -m pip install --disable-pip-version-check --no-input \
  --target .local/research/.tmp/site-packages pyyaml tiktoken
PYTHONPATH="src:.local/research/.tmp/site-packages" python3.13 - <<'PY'
from pathlib import Path
import hashlib
import tiktoken
from devolaflow.task_adaptive_selector import estimate_tokens

enc = tiktoken.encoding_for_model("gpt-4o")
for rel in (
    "AGENTS.md",
    "workflow-system/agent/SKILL.md",
    "tests/fixtures/example_dispatch.yaml",
):
    raw = Path(rel).read_bytes()
    text = raw.decode("utf-8")
    print(
        rel,
        len(raw),
        hashlib.sha256(raw).hexdigest(),
        estimate_tokens(text),
        len(enc.encode(text)),
    )
PY
claude auth status
claude --version
```

The CLI pair procedure is: invoke `claude -p` twice per sample with identical
flags and wrapper text, insert the exact UTF-8-decoded sample only in the
second prompt, parse JSON `usage.input_tokens`, and subtract
`with_target - without_target`. Each pair must use a fresh unique probe ID,
`--no-session-persistence`, and record cache-read/cache-creation fields.

After reproducing, remove only the temporary dependency directory:

```bash
rm -rf .local/research/.tmp/site-packages
```
