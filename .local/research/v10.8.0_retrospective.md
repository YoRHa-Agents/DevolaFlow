## 1. Gaps identified (from v11.0.0 SI-1 planning gate)

The v11.0.0-cycle PDS pile at `.local/research/v11.0.0_patches/D-C-*.md`
documented 3 PDSs under Wave 5 "External Tool Coupling". The coupling
theme surfaces three related external-tool pain points that accumulated
across v9.x → v10.7.0:

* **D-C-1 (Upstream-Unreachable Degraded-Mode Contract)** — DevolaFlow
  registers 4 external plugins (NineS / Si-Chip / RTK / ui-pro) with
  per-plugin fallback code shipped at or before v10.3.0, but the
  contract is INVISIBLE to the agent reading the skill corpus. 2 of 4
  plugins (Si-Chip PSE001, ui-pro PPI001) had no `references/*.md`
  documentation; an operator asking "what happens when GitHub is down?"
  had to read 4 separate source files to assemble the answer. Metric
  impact: degraded-mode test coverage at 25% (1/4 plugins).
* **D-C-2 (Bridge Shape Contract Tests)** — the v10.2.3 PV-04 bridge
  defect (`src/devolaflow/si_chip_bridge/models.py::MetricsReport.from_yaml_dict`
  silently zeroing every score because it only read top-level keys while
  Si-Chip v0.1.6+ emitted nested paths) was invisible to the unit-test
  suite for 2 full PVs. `tests/integration/` did not exist at v10.3.0
  baseline; no cached-fixture regression protected the shape contract.
* **D-C-3 (`pre_plugin_invocation` Responsibility Split)** — the single
  lifecycle hook at `DEFAULT_EVENTS` position 9 served two stacked
  purposes (install via `ensure_plugin` + upgrade via `is_plugin_stale`
  + `upgrade_plugin`). The v10.2.1 PV-02 D-P-2 daily-upgrade integration
  was correctly REUSED with `DEVOLAFLOW_AUTO_INSTALL_PLUGINS` per W-20
  at the time; 2 years on, the responsibility-stacking now creates an
  operator "all-or-nothing" trap — users who want install without
  daily-upgrade cannot configure that.

The 3 PDSs satisfy the v11.0.0 admission gates G-1 (internal value;
zero EvoBench dependency), G-2 (both-tier benefit — synthetic small
repo benefits from degraded paths + integration test infrastructure;
large repo benefits from the v10.2.3 defect-class preemption), G-3 (zero
external-tool deps — the contract + tests are DF-side), G-4
(cycle-budget; ~28 NEW test functions within W-17 +30/PV cap when summed
across the 3 PDSs with the v10.8.0 consolidation applied per R-17
below), G-5 (Soul-freeze preserved at 10), G-6 (cache-prefix gate
preserved; zero `canonical_order` mutations), G-7 (compatibility;
pure-additive with 1-cycle alias for the split), G-8 (test coverage ≥
80%), G-9 (CHANGELOG + retrospective + W-18 lint refresh).

## 3. What was deferred and why

### 3.1 Deferred to v11.0.0+

* **DEVOLAFLOW_AUTO_UPGRADE_PLUGINS** (orthogonal upgrade env flag) —
  TELEGRAPHED in `env-flags.md` §2.13 and D-C-3 §2 step 4. The 1-cycle
  alias window at v10.8.0 REUSES `DEVOLAFLOW_AUTO_INSTALL_PLUGINS` per
  W-20 reuse-first. v12.0.0+ SI-1 will re-evaluate the orthogonality
  argument (the activation surfaces for install vs upgrade are now
  distinct after the split, so the W-20 §3 orthogonality test may
  admit the new flag; the decision is deferred 2+ cycles to match the
  W-21 Soul-set governance telegraph cadence).
* **Alias removal at `DEFAULT_EVENTS` position 9** — TELEGRAPHED for
  v12.0.0+. The `pre_plugin_invocation` event remains as a
  byte-identical alias through v11.x; operators registering extra
  handlers on this event should migrate to
  `pre_plugin_invocation_install` / `pre_plugin_invocation_upgrade`
  during the v11.x cycle.
* **D-C-2 5th plugin** (if v11.0.0+ adds another plugin to
  `runtime-plugins.yaml`) — the contract test scaffold is in place;
  adding a 5th plugin would spawn one more `tests/integration/test_<plugin>_shape_contract.py`
  file with a matching fixture subdirectory. Deferred until a real new
  plugin motivates the addition.
* **Fixture drift detection lint** — the weekly CI cron currently opens
  a draft PR on drift; a sharper "fixture captured_from_plugin_version
  lags runtime-plugins.yaml min_version by >2 minor" lint is deferred
  to v11.0.0+ once the weekly cron has ≥4 data points.
* **DeprecationWarning emission in the alias handler when extras are
  registered on `PRE_PLUGIN_INVOCATION_EVENT`** (D-C-3 §9 R1 mitigation
  item) — deferred to v11.0.0 to keep v10.8.0 PR scope pure-additive
  + zero operator-facing log noise. v11.0.0 SI-1 will evaluate whether
  the warning's cache-byte cost justifies the migration surface.

## 4. Key learnings

### 4.1 Docs-as-contract is cheap insurance (D-C-1)

The degraded-mode reference is a 347-LOC markdown file + 8 regression
tests; no new Python module, no new env flag. Total effort is well
under the M estimate per the PDS. The ~600 LOC target from D-C-1 §2
was trimmed to 347 by structuring each per-plugin section as a table
row + 4 taxonomy bullets rather than a prose walkthrough — readers
reach the per-plugin action in ~1 scroll. The "Degraded ≠ Full"
leading warning is the single highest-leverage paragraph in the
reference; without it, the doc would risk giving operators a false
confidence that DF runs fully offline. R1 mitigation is the essential
design element.

### 4.2 Captured fixtures catch what mocks miss (D-C-2)

The v10.2.3 bridge defect was invisible to unit tests for 2 PVs because
hand-crafted mocks mirrored the LEGACY top-level shape. A single real
fixture captured from `aggregate_eval.py` v0.1.6 output would have
caught the defect at PR-time. D-C-2 operationalizes this lesson
(verbatim from the v10.3.0 retrospective §4 KL2): every bridge surface
now has a fixture captured from real upstream output + a shape contract
test. The weekly CI cron closes the drift-detection loop.

### 4.3 Responsibility split without flag split is the right v10.8.0 shape (D-C-3)

The architectural split of `pre_plugin_invocation` into install +
upgrade handlers unlocks the operator-independence OPTION for v12.0.0+
WITHOUT taking it. REUSING `DEVOLAFLOW_AUTO_INSTALL_PLUGINS` for 1
cycle preserves v10.3.0 byte-identical behaviour AND lets the v11.x
operator-feedback signal inform whether the `DEVOLAFLOW_AUTO_UPGRADE_PLUGINS`
flag is actually worth introducing. The W-20 orthogonality test
result will depend on whether operators REQUEST independent control
over the 1-cycle window; forcing the flag split NOW would commit the
cycle before the evidence is in.

### 4.4 Multi-PDS cycles compound forecast risk (W-17)

The v10.8.0 cycle collapsed 3 PDSs in 1 PR per the cycle plan's rollup
discipline. The per-PDS test forecasts (12-16 / 16-22 / 5) summed to
33-43; the dispatch task's aggregate cap was 30. The inconsistency
surfaced only when all 3 PDS test files were drafted end-to-end. Future
multi-PDS cycles should state both the PDS-range sum AND the PR-cap
explicitly in the cycle plan; the W-17 mid-cycle audit at PV-05 is
designed to catch this class of drift, but for a 1-PR MINOR cycle
(no PV-05 checkpoint), the forecast discipline must happen at the
SI-1 planning gate.

### 4.5 W-18 ghost-audit refresh pre-commit discipline

The v10.8.0 CHANGELOG entry was NOT authored until
`tests/test_no_ghost_features.py::test_v10_8_0_new_symbols_have_coverage`
was wired AND confirmed passing against every NEW symbol pinned above.
The pin sequencing (W-18 lint refresh → CHANGELOG entry) prevents the
v8.4.x-era pattern where CHANGELOG cited "feature X ships in PV-N" but
the ghost audit had no coverage assertion for X. Enforced by the
existing `test_ghost_audit_refresh_present` lint; this cycle's
retrospective §5 verification step confirmed the sequence held.

### 4.6 Cache-prefix invariant held across 10 → 12 event bump (G-6)

DEFAULT_EVENTS grew 10 → 12 per A-2.2 append-only. Positions 1-10
remain BYTE-STABLE. The multi-baseline byte test
(`tests/test_layout_invariant_multi_baseline.py`) stayed green
because the layout applies to the dispatch payload's `canonical_order`
(A-2.1 frozen prefix positions 1-12; A-2.2 append-only positions 13+),
NOT to `DEFAULT_EVENTS`. D-C-3's lifecycle events are an analogous
invariant pinned by `tests/test_lifecycle_hooks.py` + the new D-C-3
test suite; positions 11 + 12 appended at the tail preserve
backward-compat for every existing handler registration.
