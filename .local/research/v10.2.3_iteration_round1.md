## §1 — Track A: Bridge defect fix

**File:** `src/devolaflow/si_chip_bridge/models.py::MetricsReport.from_yaml_dict`

The pre-PV-04 implementation read top-level keys ONLY:

```python
composite=float(data.get("composite") or 0.0),
metadata_tokens=int(data.get("C1_metadata_tokens") or data.get("metadata_tokens") or 0),
body_tokens=int(data.get("C2_body_tokens") or data.get("body_tokens") or 0),
task_delta=float(data.get("task_delta") or 0.0),
value_vector=float(data.get("value_vector") or 0.0),
```

Si-Chip's `aggregate_eval.py` v0.1.6 emits ALL its MVP-8 metrics under
nested paths (`metrics.task_quality.*`, `metrics.context_economy.*`,
`summary.*`) — the top-level keys are absent. The pre-PV-04 bridge
silently zeroed every score → DEFER on every file.

The PV-04 fix introduces nested-path lookup for ALL 5 fields with the
legacy top-level shape preserved as backward-compat fallback:

* `composite` → `metrics.task_quality.T1_pass_rate` (canonical
  composite proxy per Si-Chip spec §23) → legacy top-level `composite`
* `task_delta` → `summary.baseline_delta` →
  `metrics.task_quality.T3_baseline_delta` → legacy `task_delta`
* `value_vector` → legacy `value_vector` → `summary.baseline_delta`
* `metadata_tokens` → `metrics.context_economy.C1_metadata_tokens` →
  legacy `C1_metadata_tokens`/`metadata_tokens`
* `body_tokens` → `metrics.context_economy.C2_body_tokens` → legacy
  `C2_body_tokens`/`body_tokens`

The MVP-8 nested paths are checked FIRST so that a hybrid-shape
document (e.g. a future Si-Chip emit carrying both surfaces) is
scored against the canonical surface. Backward-compat preserved:
existing legacy-fixture tests (`test_metrics_report_from_yaml_dict_accepts_legacy_field_aliases`)
still pass byte-identically.

5 NEW tests under `TestMetricsReportFromYamlDictMvp8` pin the
contract:

1. `test_from_yaml_dict_reads_mvp8_keys` — fixture mirroring
   `.local/dogfood/10.2.1/skill-optimization_after_metrics.yaml`;
   asserts composite=0.9, task_delta=0.9, value_vector=0.9,
   metadata_tokens=310, body_tokens=4646.
2. `test_from_yaml_dict_reads_legacy_top_level_keys` — flat-shape
   fixture; asserts the v10.2.1 contract still works.
3. `test_from_yaml_dict_handles_missing_metrics_block` — empty dict
   AND non-dict `metrics`/`summary`; asserts no KeyError, all-zero
   defaults.
4. `test_from_yaml_dict_handles_partial_metrics_block` — populated
   T1 + null T3/baseline_delta + null C2; asserts populated keys
   parse + missing fields zero out.
5. `test_from_yaml_dict_mvp8_nested_takes_precedence_over_legacy` —
   hybrid fixture; asserts MVP-8 nested values WIN when both shapes
   coexist.

## §2 — Track B: CC reductions

### B-1: `pre_plugin_invocation` (CC=18 → ≤10)

**File:** `src/devolaflow/lifecycle/pre_plugin_invocation.py`

NineS PV-03 deep-analysis flagged the parent `pre_plugin_invocation`
function at CC=18 (row #2 in `.local/research/v10.2.2_nines.md` §2),
introduced by the PV-02 D-P-2 daily-upgrade integration. Two helpers
extracted:

* **`_resolve_upgrade_threshold_hours(default: int) -> int`** —
  registry-read body (4 exception sinks: FileNotFoundError, OSError,
  generic Exception, defaults-section type check). Returns the
  threshold or the default; never raises. Per S-5: errors log at
  WARNING.
* **`_run_install_then_upgrade_for_plugin(plugin_id: str, *, threshold_hours: int) -> list[HookViolation]`** —
  per-plugin install + optional upgrade body. Owns the 4 PPI* code
  paths (PPI001 ensure failure, PPI003 upgrade failure) + the
  staleness-probe + the 3 try/except branches. Returns at most 1
  violation (PPI001 OR PPI003); empty list on the happy path. Per
  S-5: non-domain exceptions are logged at WARNING and re-raised.

The parent function's loop body is now a one-liner that extends
`install_violations` with the helper's return. Estimated post-fix CC
≤ 7 (3 early-return gates + the for-loop iteration). 3 NEW tests in
`TestRunInstallThenUpgradeHelper` pin the helper's signature, happy
path, and PPI001-on-install-failure path.

### B-2: `post_skill_edit` (CC=13 → ≤7)

**File:** `src/devolaflow/lifecycle/post_skill_edit.py`

NineS PV-03 deep-analysis flagged the parent `post_skill_edit`
function at CC=13 (row #7), introduced by the PV-02 D-S-5 dedup-
fingerprint logic. Three changes:

* **NEW `_compute_fingerprint(skill_files, verdict, notes) -> str`** —
  the idiomatic-name helper matching the user-spec signature; argument
  order (skill_files, verdict, notes) follows natural English reading.
  The legacy `_compute_defer_fingerprint(skill_files, notes, verdict)`
  is preserved as a thin backward-compat wrapper for v10.2.1 callers
  (`tests/test_sichip_dedup_feedback_doc.py` imports the legacy name).
* **NEW `_load_existing_fingerprints(feedback_dir) -> set[str]`** —
  the idiomatic-name sidecar reader; identical body to
  `_read_fingerprint_sidecar`. The legacy name is preserved as a thin
  alias.
* **NEW `_run_si_chip_evaluation(primary_skill, skill_files, ability_name, threshold) -> tuple[result|None, list[HookViolation], str|None]`** —
  the orchestration extraction that drives the actual CC reduction.
  Owns the 3 try/except branches (SiChipUnavailable / SiChipError /
  unexpected) and the typed PSE001 / PSE002 violation construction.
  The third tuple element is a "terminal verdict string" the parent
  uses to short-circuit when an exception fired; `None` on the
  happy path.

The parent `post_skill_edit` is now ≈70 LOC (down from ≈170) with 4
early-return gates + 1 helper call + 1 verdict branch. Estimated
post-fix CC ≤ 7. 5 NEW tests across 3 test classes pin the helpers'
signatures + happy-path + error-path contracts.
