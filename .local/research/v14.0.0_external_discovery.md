## Top picks (most transferable patterns)

- **Immutable "constitution" with an explicit amendment protocol** (spec-kit `constitution-template.md`): a human-owned principles file that supersedes other practices and is changed only via documented amendment + `Version/Ratified/Last-Amended` stamp. Best fit for the *immutable long-term INPUT* direction — gives regression/guidance value without literal write-locking.
- **Source-of-truth + delta + archive triad** (OpenSpec; DevolaFlow already does this via A-4 + `.local/.agent/active/<id>/`): current truth lives in one place; each change is a delta whose archive answers *why*. Reuse this shape for human INPUT so requirements have traceable lineage (couples cleanly with the existing `.local/feedbacks/` tracker).
- **Dual output channel** (Kiro `prd-guide.md` Dual Output Strategy): human report (concise, skimmable, e.g. HTML/Markdown digest) is a *separate artifact* from the agent spec (EARS/structured). Map directly to `.local/human/` (human report) vs `.local/.agent/`+`.local/memory/` (agent spec/state) — the core separation goal.
- **Bounded, conclusion-first report contract** (agency-agents exec-summary template + Anthropic/mem0 budgets + Exec-Summary prompts): cap human OUTPUT (≤~250-500 words, ask/verdict first, quantified, owner+next-step), enforced by an explicit token/word budget. This is the anti-"context flooding" mechanism for convergence/status reports.
- **Durable human intent ≠ ephemeral agent memory** (Schmid harness, Softwareguru, Hivetrail/Amit Ray layering): treat the human surface as the durable, versioned, human-authored tier; keep agent scratch/memory in its own tier. Validates placing `.local/human/` as a first-class sibling to `.local/.agent/` / `.local/memory/` / `.local/research/`.
