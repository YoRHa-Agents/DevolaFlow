### 3.2 — Target STRICT state (v12.0.0 PV-02)

Two-step promotion in PV-02:

#### 3.2.1 — `validate_cascade_gate_fields` raises instead of returning warnings

Two design options (PV-02 L1 picks; L0 does not pre-pick — mirrors v11.1.0 DEC-002
precedent):

* **Option A**: Add a `strict: bool = True` keyword argument that defaults to True
  at v12.0.0; when `True`, raise `CascadeViolationError` instead of returning the
  warning list. Backward-compat shim: callers passing `strict=False` get v11.x
  byte-identical behaviour. Pro: single function; one BREAKING-change axis.
  Con: callers must opt in to BREAKING via parameter change; unobvious.

* **Option B**: Add a NEW function `validate_cascade_gate_fields_strict` that always
  raises; deprecate the SOFT version with a `DeprecationWarning` for one cycle
  (v12.0.0..v12.x) and remove at v13.0.0. Pro: explicit migration path. Con: two
  functions for one concern.

PV-02 L1 evaluates both and picks per the v11.1.0 PV-02 Candidate-A/B/C precedent.

#### 3.2.2 — `audit_layer_usage.py --strict` default-OFF → default-ON

Flip `run(...)`'s `strict` parameter default from `False` to `True`. Update CLI's
argparse `--strict` to be implied-True with an explicit `--no-strict` opt-out (mirror
the v9.0.0 PV-06 Theme-T5 default-on flip pattern that promoted the 5 gate primitives
in v9.1.5 PV-05). Backward-compat: operators who were running the audit
observability-only must add `--no-strict` to their invocation; the
`tests/test_audit_layer_usage.py::test_strict_flag_default_off_preserves_byte_identical_v11_0x`
test from v11.1.0 PV-05 (per v11.1.0 retrospective §"audit_layer_usage.py:317
test_strict_flag_default_off_preserves_byte_identical_v11_0x") MUST be RENAMED to
`test_no_strict_flag_preserves_byte_identical_v11_0x` and assert the inverse.

The cascade regex in `audit_layer_usage.py:114-118` (broadened by v11.1.2 PV-W2 D-2
