## Methodology notes

Per `feedback`, the script:

1. Extracts AC items from numbered lists + severity-tagged table rows.
2. Pulls every concrete file path that anchors to one of the repo's known top-level dirs (`src/`, `tests/`, `workflow-system/`, `scripts/`, `benchmarks/`, `schemas/`, `.cursor/`, `.rules/`, etc.).
3. Pulls backtick-wrapped identifier-shaped symbols (≥5 chars, snake/Camel).
4. Pulls every `DEVOLAFLOW_*` env flag mention.
5. Cross-checks each artifact against the live repo state.
6. Looks up `CHANGELOG.md` for any version entry ≥ feedback's version (proxy for "the cycle that closed this feedback").
7. Verdict matrix:
   - **PASS:** modern feedback (v8+), CHANGELOG closure present, ≥50% paths and ≥50% symbols still resolve.
   - **SUPERSEDED:** older feedback (≤v7.x) with later CHANGELOG closure OR no concrete artifacts to chase.
   - **DEGRADED:** partial coverage, no blockers — typically a renamed module / re-organised path.
   - **DEFERRED:** in-flight cycle plan (the current MAJOR cycle's kickoff).
   - **FAIL:** no later CHANGELOG closure AND > 50% paths missing.

This is a CONSERVATIVE heuristic — designed to surface the kind of
regression-by-rename / regression-by-deletion that a rollup PR could
introduce, NOT to mechanically scrape natural-language AC bullet text.
