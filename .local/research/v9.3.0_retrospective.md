## §3 — What was deferred and why

### §3.1 Explicitly deferred to v9.4.0+ (gap-analysis MINOR tier)

* **D-S-6** (selector LOC count = 1680). Splitting `task_adaptive_selector.py` mirrors PV-04's compressor split work but at higher baseline-drift risk because the file's surface is more API-public. Telegraphed for **v9.7.0** (alongside the second perf overhaul).
* **D-S-7** (deprecated line-based lookup warnings). Cleanup pass; telegraphed for **v9.4.0 or v9.5.0** (the Si-Chip integration cycle which already touches the section-anchor surface).
* **D-C-4 + D-C-5** (compressor regex loop micro-optimisation). NOT cycle-critical (compressor is 2.3% of dispatch wall clock); telegraphed for **v9.7.0**.
* **D-H-3** (hook registry as ContextVar). Required by full async dispatch (v9.7.0 PV-03); freeze-at-first-dispatch is sufficient for v9.3.0 PV-05's wave-level fan-out.

### §3.2 Spec-deviation rationales (PV-05 + PV-06)

* **PV-05 RE-TARGET (run_hooks → L2-wave)**: The PV-01 cProfile harness measured `run_hooks(pre_dispatch)` at 9.2 µs / call — *microseconds*. ThreadPoolExecutor.submit overhead is 5-10× larger. The original cycle-plan target was empirically anti-improvement. The user affirmed the re-target via Q1 = A; PV-05 ships the AsyncDispatchExecutor at the L2-wave level instead. Run_hooks parallelism is now permanently deferred (the cycle plan PF-6 entry is closed as SPEC-CORRECTION).
* **PV-05 NO env flag**: The user spec mentioned `DEVOLAFLOW_ASYNC_DISPATCH=1`; the implementation chose to ship the executor as a pure library (callers opt in via explicit method choice) per W-20 §3 (no new flag is justified at this PV's scope when the activation is the act of calling). A future PV that auto-wires the executor into the dispatcher MAY introduce a flag at that point.
* **PV-06 OPT-IN (not auto-on)**: Per Q4 = B, the env flag is opt-in for v9.3.0 with telegraphed default-flip in v9.7.0 (matches the v9.0.0 PV-06 → v9.1.5 PV-05 default-flip pattern that promoted the 5 Theme T5 gate primitives — one cycle of operator-adoption observation before flipping default).

## §4 — Key learnings

### §4.1 What worked well

1. **Empirical PV-01 research saved a misranked PV.** The cProfile harness immediately surfaced that `run_hooks` was microseconds-scale — the cycle-plan PV-05 spec was based on architectural intuition ("sequential = wrong") rather than measured cost. Catching this before any implementation work prevented a slower-than-baseline ship.
2. **mtime-probed LRU cache pattern is reusable.** The `(path_str, mtime_ns)` cache key auto-invalidates without explicit `cache_clear()` calls. The pattern is idiomatic Python and honours the existing test infrastructure when paired with a split-by-branch design (see learning #3).
3. **Split-by-branch caches respect monkey-patch test fixtures.** The `_estimate_tokens_tiktoken_cached` / `_estimate_tokens_fallback_cached` split was THE fix for the `conftest.py::_force_fallback_token_estimator` interaction. Without the split, PV-03 would have introduced silent test pollution. Telegraphed for similar patterns in v9.7.0.
4. **L3 subagent dispatch (PV-04) was the right risk-management choice.** The 2541 → 4-file split has high cache-prefix-drift potential; dispatching a focused subagent with explicit A-2 frozen-prefix safety constraints AND verifying the result before commit (rather than auto-trusting the subagent) is the canonical pattern for high-risk refactors.
5. **`_dead_api_pins` precedent compounds.** PV-04, PV-05, and PV-06 all used the same private-tuple pattern to satisfy the dead-API detector. The pattern is now established and future PVs can apply it without inventing new mechanisms. A v9.4.0+ PV may want to consolidate into a shared helper or formalise as an A-rule.

### §4.2 What didn't work well

1. **PV-03 cache pollution surfaced LATE in the dev loop.** The split-by-branch design was discovered only when the full pytest suite ran and a benchmark test failed in pollution. A pre-PV-03 audit of the test suite for "cache-mutating fixtures" would have surfaced the conftest interaction earlier. Process improvement: add a "test-fixture isolation audit" pass to future LRU-cache PVs.
2. **PV-04 subagent's CC-test workaround was non-obvious.** The `__file__` redirect to `transforms.py` (so radon `cc_visit` finds the helpers) is correct but counter-intuitive for a future maintainer reading `__init__.py`. The inline comment explains it, but a structural refactor (e.g. moving the CC tests to `transforms.py` directly) would be cleaner. Defer to v9.7.0 selector-split work to consolidate the pattern.
3. **`scripts/detect_dead_apis.py::DEFAULT_ALLOWLIST` drift after PV-04.** The 6 historically-allowlisted symbols' qualified names changed from `compressor:fn` to `compressor.transforms:fn` post-split. The `_dead_api_pins` workaround keeps the detector green but the allowlist itself is now stale (entries match nothing). A follow-up PV should migrate the allowlist entries to the new qualified names.

### §4.3 Process-invariant strengthenings

1. **Mid-cycle audit at PV-05 (W-17)**: cumulative NEW test functions through PV-05 was +27 / +150 cap (18% utilisation, +123 headroom). Forecasted PV-06 + PV-07 contribution at +10 + +1 = +11 → cycle total +38 (well within cap). Audit confirmed no W-17 violation risk.
2. **Latency-harness ROI proven**: PV-02's harness was the precondition for proving PV-03's 97.5% improvement. Without the harness, the gain claim would be unverified. Future perf-cycle PVs MUST author a harness as the FIRST PV (not just a research artifact) to enable W-4 / SI-4 regression guards.
3. **W-16 wholesale baseline regen scales to MAJOR cycles**: the v8.4.0 retro §"R-7" lesson held — the v9.2.0 baseline was the most-recent committed reference; the v9.3.0 wholesale regen at PV-02 is the canonical anchor for the rest of the v10.0.0 cycle. v9.4..v9.7 PVs will compare against `v9.3.0_baseline.json`.
4. **R5 strict env-flag parsing pattern is robust**: the `== "1"` literal-only matching matches every other DevolaFlow opt-in flag and is verified by `tests/test_simple_shortcut.py::test_shortcut_from_env_strict_one` cross-product over `"true"`/`"yes"`/`"on"`/`"01"`/`" 1"`/`"1\n"`/`""`/absent.
5. **3-PV PATCH cycle precedent (v9.2.2 → v9.2.4) was right-sized**: the v9.3.0 cycle is 6 PVs (research + 5 implementation) which is the canonical MINOR cadence. PATCH cycles stay 3-PV; MINOR cycles fit 5-7 PVs.
