## §2 — Regex Design + Source Edit

### Current vs Proposed vs Landed

| State | Pattern | Notes |
|---|---|---|
| Pre-D-2 (v10.5.0 legacy) | `Dispatch\s+type\s*[:=]\s*(Wave\|Stage\|Task)\b` (re.IGNORECASE) | Plain-text only; missed v11.x bold |
| Dispatcher's proposed | `\*{0,2}Dispatch\s+type\*{0,2}\s*[:=]\s*\*{0,2}\s*(Wave\|Stage\|Task)\*{0,2}` | **Has gap** on full-bold case |
| **Landed (v11.1.2)** | `\*{0,2}Dispatch\s+type\*{0,2}\s*[:=]\s*\*{0,2}\s*\*{0,2}\s*(Wave\|Stage\|Task)\b\*{0,2}` (re.IGNORECASE) | All 4 styles + `\b` + IGNORECASE preserved |

### Deviations from dispatcher's proposal (with justification)

1. **DUAL `\*{0,2}\s*\*{0,2}` slot between `[:=]` and the value group.** The
   dispatcher's single-slot proposal (`\s*\*{0,2}\s*(Wave|Stage|Task)`) does
   NOT match the full-bold case `**Dispatch type:** **Wave**` because the
   closing-label `**` and the opening-value `**` are separated by whitespace
   and require TWO asterisk slots. Single slot greedily binds to the closing-
   label `**`, leaving nothing for the opening-value `**`. The dual slot
   `\*{0,2}\s*\*{0,2}\s*` admits 0/1/2 asterisk runs uniformly across the
   gap. Verified by `test_dispatch_type_regex_matches_full_bold`.

2. **Preserved `\b` word boundary after the value capture group.** The
   dispatcher's proposal dropped `\b`; the original v10.5.0 contract uses
   `\b` to prevent matching `Wave1` / `Wave_2` etc. as `Wave`. I retained
   `\b\*{0,2}` in the landed regex — `\b` between `e` (word) and `*`
   (non-word) is satisfied for both `Wave` (end-of-string or whitespace
   next) AND `Wave**` (asterisk next; word-boundary OK).

3. **Preserved `re.IGNORECASE` flag.** The dispatcher's proposal didn't
   re-state the flag; the landed version preserves it for byte-identical
   case-insensitive matching of `dispatch type:` / `DISPATCH TYPE:`
   variants (the v10.5.0 contract).

### Other regex/string in `audit_layer_usage.py` reviewed (no widening needed)

* **`_LAYER_MENTION_RE`** (`\bL{0,1,2,3}\b`): plain-text; bold `**L0**` already
  matches because `\b` between `*` and `L` is a word boundary (asterisk is
  non-word, L is word). No bold-format issue.
* **`_COLLAPSE_RE`** (`L0\s*[\u2192>\-]+\s*L3 | Single-Task\s+shortcut |
  SHORTCUT_SIMPLE`): no bold-format issue (markers are unique enough that
  bolding them doesn't break the regex; the `\s*` quantifier permissively
  handles whitespace).

Decision: only `_DISPATCH_TYPE_RE` needed widening. Documented in stage
report; ghost-audit pins the regex broadening via `\*{0,2}` substring +
`v11.1.2 D-2` source comment + `docs/cycle-archive/v11.1.0/retrospective.md`
citation.
