### 2.2 Architecture rationality (weight 0.20) — score **9.3/10**

**Evidence:**
- **Single-module design** — unlike PV-03 (which split into `cache.py` + `router.py`), PV-04's commands layer is a single ~600-line module because the value type (`CommandMapping`), the validation predicates, the loader, and the apply entry point are all tightly coupled around the YAML recipe shape. Splitting would be artificial — the `FilterRule` dataclass is intimate with the `CommandMapping`, and the apply path's `_strip_ansi` / `_apply_filter_rules` / `_truncate_to_lines` helpers are intimate with `apply_local_recipe`. The cohesion benefit outweighs the separate-file benefit at this scope.
- **Schema-first design** — `schemas/command-mapping.yaml` (282 lines) is the canonical source-of-truth; the `CommandMapping` dataclass mirrors `recipe_fields` verbatim; `build_mapping_from_dict` is the single funnel through which YAML payloads become `CommandMapping` instances. Adding a new field is a 3-step change (schema YAML + dataclass field + build helper extraction); test suite covers all three.
- **RTK schema reuse** — the recipe format mirrors RTK's `[filters.<name>]` TOML schema verbatim where they overlap (`description`, `strip_lines_matching` / `pre_filters`, `truncate_lines_at` / `truncate_lines`, `max_lines`, `strip_ansi`, `on_empty`). Operators familiar with RTK can pattern-match the new YAML format. Two DevolaFlow-only fields: `version_stamp` (cache invalidation per cycle plan §6 R3) and `repo_signal` (namespace disambiguation when multiple repos share a command).
- **Lazy load + cache reuse** — `load_command_mappings()` reads from disk and returns an immutable dict; `apply_local_recipe(mappings=...)` accepts a pre-loaded dict to skip IO entirely. Tests can inject a custom `mappings` to bypass the filesystem (e.g. `test_pre_loaded_mappings_skip_filesystem`).
- **Apply-failure is the safe path** (per cycle plan §6 R3 analog) — every error path degrades to `(output, False)` so the caller falls back to RTK's already-applied rewrite (or passthrough). This is the canonical R5 strict pattern: the new feature can NEVER break Shell-tool output; it can only optionally compress it further.
- **Two predicates run for every recipe BEFORE it joins the loader's return dict** — `_is_recipe_version_stale` (exact string equality with `devolaflow.__version__`) AND `_is_recipe_ttl_expired` (anchor `last_updated` only). Recipes invalidate automatically when `__version__` bumps; recipes invalidate after their TTL window; both predicates are cheap dict reads with no clock skew beyond the local UTC midnight boundary. The `_today_iso()` helper wraps the wall-clock read so tests can `monkeypatch` it without touching `datetime` globally.
- **Activation snapshot REUSED from PV-02** — `is_command_mapping_active(env)` is the same env-flag check as `is_proxy_enabled(env)`. NO new env-flag was introduced. The hot path (`apply_local_recipe`) does ONE env read at the start then early-returns when the proxy is disabled.
- **Default-off discipline** — the env-flag is the single activation point. Even when `.local/memory/commands/<repo>/<cmd>.yaml` files exist, the recipe layer is OFF when the env-flag is unset. No surprise activation. AND when the env-flag IS set but the directory is absent (fresh checkout / CI), the loader returns an empty dict and `apply_local_recipe` is a no-op — byte-identical to v8.3.3 behavior.
- **Precedence chain explicit** — local recipe wins → falls back to RTK's `rtk rewrite` → falls back to passthrough. The chain is documented in 4 places: (1) the gap analysis §2.1 M-002 row (verbatim user ask), (2) the `schemas/command-mapping.yaml` design comments, (3) the `apply_local_recipe` docstring, (4) the `ShellProxy.apply_recipe_to_output` docstring. Operators see the precedence at every layer.
- **ShellProxy integration is additive** — `wrap_command(cmd)` is byte-identical pre/post v8.3.4 (R5 strict — verified by `test_wrap_command_byte_identical_post_pv04`). The new `apply_recipe_to_output(cmd, output)` method is OPTIONAL — callers that don't invoke it see no behavior change. The recipe layer operates on captured output, not on the dispatch command, which is the correct separation of concerns.
- **R5 strict** verified by:
  - All 3179 pre-existing tests pass byte-identical when env-flag off
  - `tests/test_shell_proxy_commands.py::TestLoadR5StrictOff::test_env_off_does_not_touch_path_read_text` codifies the R5 contract at the unit-test layer with a `monkeypatch.setattr(Path, "read_text", watcher)` watcher that asserts the watcher was never called
  - `benchmarks/devolaflow_context/scenarios/command_mapping_density.yaml` codifies the dispatch-surface invariant at the EvoBench layer (composite 99.73 above floor 90)
- **Operator-friendly seed kit** — the `.local/memory/commands/README.md` operator doc explains how to add a recipe (5-step workflow), the schema link, and the default-off env-flag in 80 lines; the seed recipes carry the 3 most common DevolaFlow Shell-tool calls (pytest, ruff check, git diff) with realistic regex patterns. Future operators can extend by authoring matching `<cmd>.yaml` files (no index file required — basename glob, mirroring RTK's `src/filters/*.toml` discovery pattern per SI-2 §4.3).
- Equal to v8.3.3's 9.3 — clean module boundaries (single-module justified), single-source-of-truth schema, RTK schema reuse pattern, proper lazy-load + frozen-snapshot discipline, additive ShellProxy integration, NO new env-flag (REUSE PV-02 surface).

**Score 9.3** — clean module design, schema-first + RTK-reuse, lazy-load + immutable-snapshot, additive integration via `apply_recipe_to_output`, R5 strict default-off + NO new env-flag, operator-friendly seed kit.
