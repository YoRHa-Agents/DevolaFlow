# DevolaFlow v23.1.0 Phase A：Credibility Audit

## 1. 审计结论

本审计区分“实现存在”“配置存在”“历史计算结果”和“本轮可复核运行证据”。当前仓库能证明 harness 的数据契约与保护性测试，但不能证明 v23.1.0 已完成 120-run，也不能证明 token savings、质量收益或 ROI。

最终结论：**Phase A = INSUFFICIENT**。本轮范围是 **不做账单、只计量 token**；由于没有 provider usage、价格输入和匹配的真实任务结果，**ROI = INSUFFICIENT**，不得换算金额或宣称投资回报。

## 4. 外部对标

外部资料用于验证方法边界和可比性要求；它们不是本仓库 v23.1.0 的运行证明。公开资料没有为本项目产生 provider-reported measurement，因此本节只给出“对标结论”和“内部缺口”。

### 4.1 Tokenizer

- [OpenAI tiktoken](https://github.com/openai/tiktoken)：提供面向 OpenAI 模型的 BPE tokenizer 实现。对标结论：token 数必须绑定 tokenizer、模型/encoding 和版本；DevolaFlow 当前 `estimate_tokens` 的结果应标为 estimated，不能跨 provider 直接比较。
- [Hugging Face tokenizers](https://github.com/huggingface/tokenizers)：提供可复用 tokenizer 实现与多语言 tokenization 工具。对标结论：同一文本在 tokenizer/encoding 改变时 token 数可变，内部报告必须保存 tokenizer provenance，而不是只保存一个整数。

### 4.2 Observability

- [OpenTelemetry specification](https://github.com/open-telemetry/opentelemetry-specification)：定义跨系统的 telemetry 语义、上下文和可移植性原则。对标结论：DevolaFlow 的 `run_id`、salt、repo ref/sha、source、provenance 和 event schema 方向正确；但没有 v23.1.0 event stream，就不能完成 trace-level attribution。
- [OpenTelemetry semantic conventions](https://github.com/open-telemetry/semantic-conventions)：提供稳定的观测属性命名约定。对标结论：token component、model、channel、task class、status 和 uncertainty 应保持结构化字段，避免将关键归因埋入自由文本。

### 4.3 Agent evaluation

- [OpenAI Evals](https://github.com/openai/evals)：提供模型/系统评测框架和 eval registry 组织方式。对标结论：内部 probe fixture 与确定性评分可作为离线 contract，但仍需真实运行 artifact 和清晰的 eval spec，不能用 fixture 通过替代生产任务效果。
- [SWE-bench](https://github.com/SWE-bench/SWE-bench)：以真实 GitHub issue、仓库和测试结果评估软件工程 agent。对标结论：要宣称 agent/skill ROI，必须使用真实任务 outcome 与可复现环境；单纯 token reduction 不是任务成功率。

### 4.4 Statistics

- [NIST/SEMATECH e-Handbook of Statistical Methods](https://www.itl.nist.gov/div898/handbook/)：覆盖抽样、描述统计、置信区间和实验分析。对标结论：120 次计划数不自动等于 120 个有效 observations；必须报告排除、缺失、方差和区间。
- [SciPy statistics reference](https://docs.scipy.org/doc/scipy/reference/stats.html)：提供可复核的统计分布与检验接口文档。对标结论：p50/p95、均值和差异应携带样本定义；没有原始样本时不能重新计算不确定性。

外部对标的共同结论是：tokenizer provenance、结构化 telemetry、真实任务评测和不确定性报告缺一不可。当前仓库代码为这些要求提供了接口方向，但 v23.1.0 运行证据尚未落地。

## 5. Credibility findings register

以下 finding 与 gap report 的 F-01 至 F-14 一一对应；每项均给出代码/产物证据和影响，严重度按 blocker/critical/major/minor 分级。

1. **F-01 / blocker — 120-run 原件缺失。** 证据：已有 `v23.1.0_token_cross_validation.md` 与 `v23.1.0_kimi_diagnosis.md` 仅是局部探针，预写入扫描无 v23.1.0 120-run artifact；`src/devolaflow/harness/calibration.py:44-48` 仍显示 v21.1.0 默认命名。影响：运行数、成功数、token 分布和 ROI 不可复核。
2. **F-02 / blocker — 版本身份不匹配。** 证据：`src/devolaflow/__init__.py:6` 和 `pyproject.toml:7-10` 都是 `23.0.0`。影响：不能将当前代码快照当作 v23.1.0 发布对象。
3. **F-03 / critical — ledger/baseline 缺失。** 证据：`src/devolaflow/harness/gap.py:47-60` 定义六个 coverage axes，`:241-252` 对缺 baseline 返回 GAP，`src/devolaflow/harness/aggregator.py:110-150` 要求主 ledger 和连续 segment。影响：无法做 W-16 或跨轮次回归。
4. **F-04 / critical — component observations 缺失。** 证据：`src/devolaflow/harness/context_tokens.py:64-79` 保留 None/0 语义，历史 evaluation 的三个 context component observed records 均为 0。影响：无法分摊 skill/rule/report token。
5. **F-05 / critical — estimator/provider 边界仍不完整。** 证据：`src/devolaflow/harness/telemetry.py:330-350` 调用 `estimate_tokens`，schema 的来源字段见 `schemas/token-injection-measurement.yaml:74-100`；三样本 cross-validation 的 offline/tiktoken 差为 `0`，但 CLI difference 为 `44/3205/181`，官方 Anthropic count_tokens 仍 INSUFFICIENT。影响：局部 parity 不足以推导 provider-wide usage、billing 或财务 ROI。
6. **F-06 / major — slice 不是实际 host saving。** 证据：`src/devolaflow/harness/telemetry.py:230-248` 明示 full corpus injection 与 configured saving 的差异。影响：历史 `49.61538461538461%` 不能称线上节省比例。
7. **F-07 / major — 默认 calibration 不是 120-run。** 证据：`src/devolaflow/harness/calibration.py:44-48` 为 10 replicates，`:200-228` 把不可用/认证/超时记录为 INSUFFICIENT。影响：planned 与 valid observations 必须分开报告。
8. **F-08 / major — 外部结果不可直接横比。** 证据：`src/devolaflow/harness/calibration.py:220-260` 将 matrix、preflight、summary 分开输出，`schemas/token-injection-measurement.yaml:108-130` 要求 uncertainty。影响：缺少同任务/同模型/同版本/同环境的配对数据。
9. **F-09 / major — 历史 READY 被低维度否定。** 证据：历史 evaluation composite `8.67`，但 test adequacy `6.67`、compatibility `5.00`。影响：不可只引用 overall verdict。
10. **F-10 / major — ratio 无 v23 raw input。** 证据：`src/devolaflow/_compressor_transforms/validation.py:188-266` 仅计算 estimator counts，`tests/test_compressor.py:138-188` 是契约测试。影响：不能报告 v23 平均压缩收益或质量保持率。
11. **F-11 / major — bypass 必须分层。** 证据：`src/devolaflow/_compressor_transforms/validation.py:214-238` 命中 bypass 时 ratio 为 `0.0` 且原文返回，测试见 `tests/test_compressor.py:990-1060`。影响：混合统计会误读安全保护为压缩失败或收益。
12. **F-12 / major — layout witness 不等于 savings。** 证据：`src/devolaflow/compressor/layout.py:127-168` 保护 12-key prefix 和 17-position layout。影响：layout 通过只能证明兼容性，不能证明 token/latency/ROI。
13. **F-13 / minor — compression 数字是边界。** 证据：`src/devolaflow/_compressor_transforms/common.py:31-37`、`:108-132` 规定 500、0.30、2、5、20%、320。影响：没有任务级 before/after 时，不能称平均效果。
14. **F-14 / minor — loop closure 无本轮证明。** 证据：`src/devolaflow/harness/gap.py:270-300` 在无 `proposal_applied` 时判 GAP，calibration preflight 见 `src/devolaflow/harness/calibration.py:180-228`。影响：proposal、capacity、fixture hash 和真实执行仍需产物确认。

## 6. Gate 建议

### Phase B：人类 gate

人类审批前应核对：v23.1.0 commit/version；120-run matrix；每个 raw artifact 的相对路径、sha256 和 metadata；实际 provider/estimator 区分；planned/executed/PASS/FAIL/INSUFFICIENT；四类 context token；bypass 分层；variance/interval；W-16 baseline；以及 SI-10/W-3 结果。任何缺失均保持 INSUFFICIENT，不以默认值补齐。

审批范围必须写明：**只批准 token metering，不批准 billing、费用估算或未经配对质量结果支持的 ROI 声明**。

### Phase C：修复顺序

1. 先锁版本和 commit，按显式 v23.1.0 命名生成 120-run raw/summary。
2. 再写入四类 token component、source/provenance、tokenizer/model、run metadata 和 uncertainty。
3. 将 provider usage 与本地 estimated count 分字段，禁止同名覆盖。
4. 建立 matched skill-off/skill-on real-task pairs，分开报告成功率、质量、token delta、bypass 和 p50/p95。
5. 校验 host 实际是否使用 slice；未接线前维持 configured/estimated 标签。
6. 生成 baseline，执行 aggregate/evaluate/gap/cross-validate 和六门 SI-10。
7. 只有 evidence complete 且人类批准后，才可讨论 efficiency claim；ROI 仍需额外业务输入，不能由 token metering 自动推出。

**审计签名：Phase A = INSUFFICIENT；v23.1.0 120-run = INSUFFICIENT；compression ROI = INSUFFICIENT；financial ROI = 不在范围内。**
