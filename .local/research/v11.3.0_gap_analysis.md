## §1 — Executive Summary

The `grill-with-docs` skill (`https://github.com/mattpocock/skills/tree/main/skills/engineering/grill-with-docs`) packages a discrete behavioural pattern that DevolaFlow does **not** currently own: a one-question-at-a-time **adversarial interview** that stress-tests an in-flight plan against (a) the codebase, (b) a project-local **domain glossary** (`CONTEXT.md`), and (c) a project-local **ADR ledger** (`docs/adr/`) — and which **mutates those documentation surfaces inline** as decisions crystallize. The upstream skill is intentionally minimal (3 files, 204 lines total per `wc -l`), but its rule density is high: 7 named primitives across 80 lines of SKILL.md plus 2 supporting format specifications. The pattern occupies the design-time layer between DevolaFlow's existing **PLAN MODE** (which produces a delegation contract for L1/L2/L3) and the **`change-driven`** workflow (which scaffolds `.local/.agent/active/<id>/spec.md` per change) — neither of which interview the operator one question at a time, neither of which maintains a domain-language glossary, and neither of which carries a 3-condition ADR-creation gate.

DevolaFlow needs this pattern because the **PLAN MODE** contract (per `references/plan-mode-enforcement.md`, 826 lines) currently assumes the operator already has a clear-enough mental model to author a plan template that L0 can dispatch — there is no upstream **clarification stage** that catches fuzzy terminology, undocumented conflicts between the operator's verbal model and the codebase, or surprise architectural choices that warrant an ADR. The `karpathy_skills_analysis.md` precedent (DevolaFlow's earliest external-skill absorption — produced for v4.5.0 cycle) explicitly identified "Think Before Coding" as a partial gap: "L3 task prompts do not uniformly require an explicit 'assumptions + open questions' block before first tool use." Grill-with-docs is the operator-facing complement to that L3-side gap — it asks the questions to the **human**, not just to the dispatcher payload.

The v11.3.0 cycle proposes a **single-PV MINOR release** that lands grill-mode as a parallel orthogonal axis to plan-mode (one MAY enter grill-mode FROM plan-mode, but neither is a prerequisite for the other), backed by 2 new Tier-2 references (`grill-mode.md`, `domain-awareness.md`), 1 new pure-function Python module (`src/devolaflow/skills/grill_mode.py`), 2 new workflow rules (W-22 Grill Mode Activation Contract, W-23 Domain Glossary Maintenance — Soul-set freeze at 10 per W-21 is preserved), and 1 new natural-language workflow trigger (`grill-driven`). NineS deep analysis of the upstream skill flags it as having **0 mechanism diversity** with **break-even at 21 interactions** (a marker that the upstream skill is rule-dense but distribution-thin); landing the pattern inside DevolaFlow's mechanism set (lifecycle hooks, dispatch envelope, behavioral_guidelines block, schemas) is the integration's primary value-add.
