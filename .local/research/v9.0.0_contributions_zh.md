本清单从 v2.1.0 (2026-04-07) → v8.4.0 (2026-04-23) 的 17 个日历日、82 个版本/PV 中提取了 **106 条** 重要变更项，按**影响力 / 留存度 / 技术债** 三维度 1-5 分评分并按综合得分降序排列。Top-5 英雄级贡献（综合 5.0/5.0）依次是：**v7.0.0 cache-layout invariant + P6 governance rule**（+ 5 schema generation 全部字节稳定）、**v6.0.3 dead-wire closure**（v6.0 单点最高 ROI 干预）、**v6.1.1 NineS tool-config breakthrough**（+18.9% 零 src/ 改动）、**v8.3.0 `.local/.agent/{active,handoff,archive}/` 工作区 + S-8/S-9/A-4/C-9 四条新硬规则**、以及 **v6.0.4 AdapterRegistry + DataDrivenAdapter**（4 → 11 平台）。贡献密度最高的时代是 **v8.x**（31 PV / ~70 小时；平均综合得分 4.4，高密度 PV cadence + 100% accept rate 49/49 lifetime），其次是 **v7.x**（22 release / 4 phases；平均综合得分 4.2），v6.x 紧随其后（13 release + 1 web milestone；平均 4.1）。早期时代 v2.x-v5.x 单条变更影响力极高（~25 项 ≥4.5），但因后续版本的层叠 / 重构使技术债项也聚集在此（10 条长尾中 3 条根源在 v3.x）。

## 评分方法学

每条变更按以下三个维度 1-5 分评分（5 分最高）：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| **影响力 (Impact)** | 仅局部优化 / 单文件 < 20 行 | 影响一个模块或一条流水线 | 架构级 / 跨整个生命周期 / 成为 Soul Rule 或 Architecture Rule 直接依据 |
| **留存度 (Retention)** | 已被废弃 / 后续版本替换 | 部分留存（opt-in default-off / 仅 STRICT 默认开启） | 截至 v8.4.0 仍为承重契约（default-on 或 Soul Rule / Architecture Rule） |
| **技术债 (Debt)** | 5 分 = 引入大量未清技术债 / dead-wire / 多入口冗余 | 3 分 = 部分债务已清 | 1 分 = 完全干净 / 已被清理 / 字节稳定 |

**综合得分公式**：
```
综合 = Impact × 0.4 + Retention × 0.4 + (6 − Debt) × 0.2
```

**示例**：
- v7.0.0 cache-layout invariant — 影响力 5 / 留存度 5 / 技术债 1 → 综合 = 5×0.4 + 5×0.4 + (6−1)×0.2 = **5.0**
- v8.0.0 P-07 monotonic ratchet — 影响力 5 / 留存度 4（仍 default-OFF）/ 技术债 3（B3 carry-forward）→ 5×0.4 + 4×0.4 + (6−3)×0.2 = **4.2**
- v3.6.0 P1 enforcement 27-line block — 影响力 5 / 留存度 5（S-1 直系祖先）/ 技术债 4（5+ 个周期重复漂移）→ 5×0.4 + 5×0.4 + (6−4)×0.2 = **4.4**

**评分锚点**（避免主观漂移）：
- **影响力 5 必要条件**：跨 ≥3 个 src/ 模块或 ≥1 个 schema/yaml 契约或 ≥1 条规则的引入。
- **留存度 5 必要条件**：在 v8.4.0 cycle 仍被 production code 调用，或在 50 条规则中保留。
- **技术债 5 必要条件**：v9.0.0 SI-1 已明确列入 BLOCKER / CRITICAL（cf. `v9.0.0_conflict_register.md` C-01..C-14）或 v8.4.0 retro §4 deferral 名单。

数据缺口（per S-5）：v6.x → v8.x 部分版本的 NineS / SI-3 composite 缺测，标记为 `-`，不参与"留存度"反推。
