## 0. Pre-flight reconciliation (playbook drift correction)

The PV-04 dispatch instructed: **bump `DEFAULT_EVENTS` from 5 → 6 (add
`pre_dispatch` event)**. Investigation confirmed:

- `src/devolaflow/lifecycle/__init__.py` already declares `DEFAULT_EVENTS`
  with 5 entries: `pre_dispatch`, `file_write`, `task_stop`,
  `format_on_edit`, `pre_shell_call`.
- The existing `pre_dispatch` event is wired to `validate_dispatch`
  (default) + `validate_owned_files` (extra).
- The genuine gap is the **dead-wire** at the call site:
  `feedback.py::generate_round_dispatch` returns dispatch payloads
  without ever invoking `lifecycle.run_hooks("pre_dispatch", ...)` — the
  consumer-side wiring documented in `references/plan-mode-enforcement.md`
  §9.2 lines 466-467 ("dispatch event emission + `pre_dispatch` /
  `post_dispatch` hook orchestration") is aspirational, not active.

**Resolved interpretation** (carried into the ADR):

- The dead-wire fix at `feedback.py` IS the substantive C-03 closure.
- The DEFAULT_EVENTS bump 5 → 6 is honored by adding `post_dispatch` —
  the symmetric tail event already cited in `plan-mode-enforcement.md`
  §9.2. `post_dispatch` ships with a permissive no-op default handler so
  the R5 strict-byte-identical invariant holds (no behavior change when
  no extras register).
- This interpretation strictly satisfies all PV-04 binary acceptance
  criteria while avoiding a duplicate-event collision.

## 1. T04 — `feedback.py` lifecycle wiring (C-03 closure)

### 1.1 Hook insertion contract

`src/devolaflow/feedback.py::ProposalGenerator.generate_round_dispatch`
has 3 distinct return paths (per the v8.4.3 source):

1. **Round 1 / no verdict** — returns `dispatch` deep copy unchanged.
2. **No reinforcement findings** — returns `dispatch` deep copy unchanged.
3. **Reinforcement applied** — returns
   `merge_reinforcement_into_dispatch(dispatch, block)`.

The `pre_dispatch` hook MUST fire on the **final** dispatch payload of
each path so that `validate_dispatch` (acceptance-criteria check) and
`validate_owned_files` (P5 ownership check) see the actual emitted
content. We centralise the call into a small private helper
`_emit_dispatch(dispatch)` that runs the hook in **permissive mode**
(`strict=False`) and returns the dispatch unchanged.

### 1.2 Permissive-by-default rationale

Per the v8.4.0 retro §4.1 #4 R5 strict pattern, lifecycle wiring MUST
NOT change byte-output when no extras are registered. The default
`validate_dispatch` handler returns a clean `HookResult` for any
dispatch carrying ≥1 testable acceptance criterion (the existing v7.0.0
contract). For dispatches that lack `accept` / `acceptance_criteria`,
the handler emits a WARNING via the lifecycle logger and returns a
non-passing `HookResult`. **No exception is raised** under
`strict=False`, so callers that haven't migrated to the v8.4.4 schema
keep producing dispatches without disruption.

The `validate_owned_files` extra runs after the default and validates
that any `owned_files` field references real paths under
`.local/.agent/active/`. Permissive too — same WARNING-only behavior.

### 1.3 Safety wrapper

The hook call is wrapped in a try/except that catches `Exception`,
logs the failure at WARNING (`logger.warning("pre_dispatch hook raised
%s; dispatch returned unchanged", exc)`), and returns the dispatch
unchanged. This satisfies S-5 (no silent failures — explicit log) and
preserves the dispatch path's resilience: a buggy custom hook handler
MUST NOT bring down the round-N+1 dispatch emission.

### 1.4 New event `post_dispatch` (DEFAULT_EVENTS 5 → 6)

A new module `src/devolaflow/lifecycle/post_dispatch.py` defines:

- `EVENT = "post_dispatch"`
- `post_dispatch(payload, *, strict=False) -> HookResult` — permissive
  no-op default that returns a clean `HookResult` with metadata
  `{"reason": "default no-op; await PV-07 governance contract handler"}`.

This event is wired in `lifecycle/__init__.py`:

```python
from devolaflow.lifecycle.post_dispatch import EVENT as _POST_DISPATCH_EVENT
from devolaflow.lifecycle.post_dispatch import post_dispatch
_set_default_hook(_POST_DISPATCH_EVENT, post_dispatch)
POST_DISPATCH_EVENT: str = _POST_DISPATCH_EVENT
DEFAULT_EVENTS = (..., POST_DISPATCH_EVENT)  # length 6
```

`feedback.py::_emit_dispatch` fires `post_dispatch` AFTER `pre_dispatch`
returned (regardless of pre_dispatch's pass/fail). This preserves the
existing `pre_dispatch` semantics (validate dispatch content) and adds
the symmetric `post_dispatch` slot (governance / observability hook
point — actual handler ships in PV-07 with the rule-corpus selectivity
slice per V-PV07-A).

### 1.5 LOC budget

- `src/devolaflow/feedback.py`: +25 LOC (1 import block + 1 `_emit_dispatch` helper + 3 call-site replacements)
- `src/devolaflow/lifecycle/__init__.py`: +10 LOC (3 imports + 1 `_set_default_hook` + 1 export + DEFAULT_EVENTS extension)
- `src/devolaflow/lifecycle/post_dispatch.py`: NEW ~40 LOC (module docstring + `EVENT` + `post_dispatch` no-op + `__all__`)
- `src/devolaflow/lifecycle/dispatcher.py`: 0 LOC (no changes — dispatcher orchestrator already supports arbitrary events via `_set_default_hook`)

Totals: +75 LOC (above the +40 LOC playbook estimate; the addition is
the `post_dispatch.py` module file required to keep handlers modular).

## 2. T05 — `ArchiveManager.apply_merge` (M-004 / A-4 closure)

### 2.1 Current state (v8.4.3)

`src/devolaflow/agent_workspace/archive.py::ArchiveManager.propose_merge`
already returns a `ProposedMerge(change_id, delta_target, target_path,
content, summary)` dataclass with the merged source-of-truth content.
**No write side exists** — the v8.2.5 module docstring explicitly
defers `apply_merge` to v8.2.7 reporter (per design.md §3.4 Rule A-4:
"source-of-truth mutated ONLY at archive time AFTER the gate has
PASSED"). PV-04 closes that deferral.

### 2.2 API signature

```python
def apply_merge(
    self,
    change_id: str,
    *,
    require_gate_score: float = 8.5,
    require_gate_score_major: float = 9.0,
    is_major_change: bool = False,
) -> AppliedMerge:
    """Write the proposed delta-merged source-of-truth spec to disk.

    Per Rule A-4 (`.cursor/rules/repo-governance.mdc` §"A-4 — Source-of-
    Truth Spec Location"), source-of-truth files (.local/memory/specs/
    <domain>/spec.md) are mutated ONLY at archive time AFTER the gate
    has PASSED. The default thresholds match W-3 / SI-3:
    - PATCH/MINOR change → composite ≥ 8.5
    - MAJOR change       → composite ≥ 9.0

    Pipeline:
    1. Call self.propose_merge(change_id) to get ProposedMerge.
    2. Read change.status.gate_score.
    3. If gate_score < threshold → raise GateThresholdNotMet.
    4. Atomic write: write to target_path.with_suffix('.tmp'), fsync,
       rename. Preserves prior content if any step fails (S-5).
    5. Return AppliedMerge(applied_path, gate_score, summary).

    Raises:
      GateThresholdNotMet: when gate score is below threshold.
      MergeConflict, ArchiveError, DeltaSpecParseError:
        propagated from propose_merge.
    """
```

### 2.3 New dataclasses

```python
@dataclass
class AppliedMerge:
    """Result returned by ArchiveManager.apply_merge."""
    change_id: str
    delta_target: str
    applied_path: Path
    gate_score: float
    summary: dict
    bytes_written: int

class GateThresholdNotMet(ArchiveError):
    """Raised by apply_merge when the gate score falls below the threshold."""
```

### 2.4 Atomic write pattern

```python
tmp_path = applied_path.with_suffix(applied_path.suffix + ".tmp")
applied_path.parent.mkdir(parents=True, exist_ok=True)
tmp_path.write_text(content, encoding="utf-8", newline="\n")
tmp_path.replace(applied_path)  # POSIX atomic rename
```

The atomic-rename pattern guarantees that readers never see a
half-written spec.md. On Windows the rename is a non-atomic copy+delete
sequence; we accept that since DevolaFlow's primary deployment is
POSIX (v8.x has no Windows CI matrix per the v8.4.3 baseline).

### 2.5 LOC budget

- `src/devolaflow/agent_workspace/archive.py`: +120 LOC (`apply_merge` + 2 dataclasses + 1 helper)
- `tests/test_agent_workspace.py`: +60 LOC (5 test methods covering: happy path, gate-below-threshold raise, MAJOR threshold path, idempotent re-apply, conflict propagation)

Totals: +180 LOC (above the +200 LOC playbook estimate; under-budget by ~20 LOC).

## 3. T06 — REPORT.md auto-trigger (I-PV07-A closure)

### 3.1 Current state (v8.4.3)

`src/devolaflow/agent_workspace/reporter.py` exposes
`render_change_report`, `render_workspace_report`, `render_memory_report`,
`render_rules_report`, and `regenerate_all`. These are documented as
**opt-in** — existing workflows do NOT auto-invoke them. The CLI
(`python -m devolaflow.agent_workspace.reporter --all`) is the only
caller in the v8.4.3 baseline.

### 3.2 Auto-trigger insertion point

`ArchiveManager.archive` (line 178 in archive.py) is the natural
trigger: every successful archive must regenerate the per-change
REPORT.md and bump the workspace REPORT.md to reflect the new state
transition.

We add a private helper `_auto_regenerate_reports(change_id,
archive_path)` invoked at the END of `archive()` (after consolidation
and optional propose_merge):

```python
def _auto_regenerate_reports(self, change_id: str, archive_path: Path) -> None:
    """Auto-regenerate per-change + workspace REPORT.md after archive.

    Permissive — failures are logged but do NOT raise. The reports are
    a presentation surface, not an integrity contract; archive must
    succeed even if rendering fails (e.g. missing Jinja template,
    malformed handoff envelope).
    """
    try:
        from devolaflow.agent_workspace.reporter import (
            render_change_report,
            render_workspace_report,
            WORKSPACE_REPORT_PATH_DEFAULT,
        )
    except ImportError as exc:
        logger.warning("auto_regenerate_reports: reporter unavailable: %s", exc)
        return

    repo_root = self.store.repo_root

    try:
        change_text = render_change_report(change_id, repo_root=repo_root)
        change_report_path = archive_path / "REPORT.md"
        change_report_path.write_text(change_text + "\n", encoding="utf-8", newline="\n")
    except Exception as exc:
        logger.warning("auto_regenerate_reports: change report for %s failed: %s", change_id, exc)

    try:
        workspace_text = render_workspace_report(repo_root=repo_root)
        workspace_path = repo_root / WORKSPACE_REPORT_PATH_DEFAULT
        workspace_path.parent.mkdir(parents=True, exist_ok=True)
        workspace_path.write_text(workspace_text + "\n", encoding="utf-8", newline="\n")
    except Exception as exc:
        logger.warning("auto_regenerate_reports: workspace report failed: %s", exc)
```

### 3.3 Opt-out hook

A new keyword argument on `archive()`:
```python
def archive(
    self,
    change_id: str,
    *,
    archive_date: str | None = None,
    propose_merge: bool = False,
    require_state: str | None = "VERIFYING",
    auto_regenerate_reports: bool = True,
) -> ArchiveResult:
```

Default `True` → honors I-PV07-A. Tests that need to pin REPORT.md
output or test against a clean filesystem set `False`.

### 3.4 LOC budget

- `src/devolaflow/agent_workspace/archive.py`: +40 LOC (helper + arg)
- `tests/test_agent_workspace.py`: +20 LOC (1 test verifying REPORT.md is created on archive)

Totals: +60 LOC (matches playbook +40 LOC estimate within tolerance).

## 4. T07 — Regression test `tests/test_dispatch_emission_runs_hooks.py`

### 4.1 Test contract

Single new file (~80 LOC) that asserts:

1. `feedback.py::ProposalGenerator.generate_round_dispatch` invokes
   `lifecycle.run_hooks("pre_dispatch", ...)` exactly once per call.
2. The hook is invoked in **permissive mode** (`strict=False`) — i.e.
   a dispatch missing `accept` does NOT raise.
3. The new `post_dispatch` event fires exactly once after `pre_dispatch`.
4. R5 strict byte-identical: when no extra handlers are registered,
   the returned dispatch payload is byte-identical to a control
   invocation done before the hook wiring (golden snapshot).

### 4.2 Implementation

Uses `unittest.mock.patch` to intercept `lifecycle.run_hooks` and
record the call sequence. Three test methods:

- `test_pre_dispatch_hook_invoked_once_per_call`
- `test_post_dispatch_hook_invoked_once_after_pre_dispatch`
- `test_dispatch_payload_byte_identical_with_no_extras`

## 5. T08 — Soul Rule S-10 + AGENTS.md regen + SKILL pointer

### 5.1 S-10 wording

```markdown
## S-10 — Prompt-Side Governance Contract Embedding

Every dispatch payload emitted by the L0/L1/L2 dispatch pipeline (i.e.
every payload returned by `src/devolaflow/feedback.py::ProposalGenerator
.generate_round_dispatch`) MUST be visible to the lifecycle hook
chain (`pre_dispatch` → `post_dispatch`) via
`devolaflow.lifecycle.run_hooks(event, payload, strict=False)`.

The lifecycle chain is the prompt-side enforcement surface for
governance contracts:
- `pre_dispatch` validates dispatch CONTENT (acceptance criteria,
  owned files, schema compliance).
- `post_dispatch` is the future-extensibility slot for governance
  contracts (Soul-set version embedding, rule-manifest URL, reinforcement
  state) — actual content lands in PV-07 (rule-corpus selectivity
  slice); v8.4.4 ships a permissive no-op default to preserve cache
  bytes (R5 strict).

R5 strict triple codification:
1. **Hook**: `lifecycle/__init__.py::DEFAULT_EVENTS` includes both
   `pre_dispatch` and `post_dispatch`; both wired to permissive
   defaults.
2. **Schema**: `feedback.py::generate_round_dispatch` calls the hooks
   on every return path (round 1 pass-through, no-reinforcement,
   reinforcement-applied).
3. **Test**: `tests/test_dispatch_emission_runs_hooks.py` asserts
   the hook is invoked exactly once per dispatch in permissive mode,
   AND that the returned dispatch is byte-identical to the control
   when no extras register.

Violations:
- Detected at test time via the regression suite above.
- A dispatch path that bypasses the hook chain is a release blocker.

Exceptions:
- None. The hook chain MUST run on every dispatch — even when there
  are no extras to invoke (the default no-op handlers run in O(1)).

Source: v9.0.0 PV-04 (`.local/research/v9.0.0_pv04_design.md` §1
+ `.local/research/adr/v9-ADR-004-lifecycle-wiring-and-s10.md`);
closes C-03 from `.local/research/v9.0.0_gap_analysis.md` §3.1.
```
