## §2. T02 — Per-Task-Type Slice Design

### §2.1 Goal

Per gap analysis §5.7 + decomposition §"Theme T6" line 192 verbatim: the per-task-type AGENTS.md slice changes the rule corpus visible to cached-prefix L0 dispatchers. A hotfix Task Agent does not need the full 21-row Workflow layer (W-1..W-21 carry research-cycle process knowledge irrelevant to a 1-bug fix); a research Task Agent does not need the gate-mechanism Architecture rules (A-3..A-5 are about runtime registry / cache invariants).

### §2.2 Layer-prefix slice mapping per task profile

Each task profile maps to an ordered list of **layer prefixes** that select which `## <prefix>-<N>` headings under AGENTS.md (and the compiled cursor target) survive the slice. The slice is post-hoc filter applied to the already-compiled AGENTS.md content; it never reorders or rewrites canonical rules — it only HIDES rules irrelevant to the task type.

| Task profile | Soul (S-*) | Architecture (A-*) | Conventions (C-*) | Workflow (W-*) | Style (ST-*) | Token saving (est.) |
|---|---|---|---|---|---|---|
| **hotfix** | ALL (S-1..S-10) | A-1, A-2 | C-1, C-2, C-3, C-8 | W-9 (SI-10), W-11 (gate) | — | ~40% (skip W-1..W-8, W-10, W-12..W-21, A-3..A-5, ST-*, C-4..C-7, C-9) |
| **feature** | ALL | ALL (A-1..A-5) | ALL (C-1..C-9) | W-1..W-15 | ST-1, ST-3, ST-4, ST-7 | ~15% (skip W-16..W-21 cycle process, ST-2, ST-5, ST-6, ST-8..ST-13) |
| **research** | ALL | A-1 (hierarchy only) | C-1, C-2, C-3 | W-1, W-2 (planning only) | — | ~70% (skip A-2..A-5 cache/registry, C-4..C-9, W-3..W-21, all Style) |
| **refactor** | ALL | ALL | ALL | W-1..W-15, W-18 (ghost audit) | ST-1, ST-3, ST-4 | ~20% |
| **review** | ALL | A-1, A-2 (cache invariants) | C-1, C-2, C-3, C-8 | W-3 (eval), W-9, W-11 | — | ~50% |
| **design** | ALL | ALL | C-1, C-2, C-3, C-4, C-5, C-7 | W-1, W-2, W-7 (retro) | ST-1, ST-3, ST-7 | ~30% (skip runtime-only C-6, C-8, C-9; runtime-cycle W-rules) |
| **convergence** / **rdrr** | ALL | ALL | ALL | ALL (W-1..W-21) | ALL | 0% (full set — round-aware multi-pass needs everything) |
| **documentation** | S-1, S-2, S-4, S-5, S-7 | A-1, A-3 (token budgets) | C-1, C-2, C-3, C-4, C-5, C-6, C-7 | W-7 (retro) | ALL (ST-1..ST-13 — doc rules central) | ~40% |
| **default** (unmatched) | ALL | ALL | ALL | ALL | ALL | 0% (full set — safe fallback) |

### §2.3 Configuration shape

Add a new `agents_md_slice` block under `meta:` in `workflow-system/agent/context_profiles.yaml`. Schema:

```yaml
meta:
  # ... existing keys ...
  agents_md_slice:
    enabled: false  # opt-in; default OFF preserves v8.5.1 byte-identical full AGENTS.md
    profiles:
      hotfix:
        soul: all
        architecture: ["A-1", "A-2"]
        conventions: ["C-1", "C-2", "C-3", "C-8"]
        workflow: ["W-9", "W-11"]
        style: []
      research:
        soul: all
        architecture: ["A-1"]
        conventions: ["C-1", "C-2", "C-3"]
        workflow: ["W-1", "W-2"]
        style: []
      # ... etc.
    fallback: full  # when no profile matches → return full AGENTS.md
```

**Default `enabled: false`** preserves v8.5.1 byte-identical behaviour for every L0/L1/L2/L3 dispatcher that has not opted in. Operators wanting per-task-type slicing flip `enabled: true` per `references/env-flags.md` §7 W-20 reuse-first orthogonality test (the slicing's activation surface IS orthogonal to every existing flag — it's a NEW post-compile filter, not a runtime hook reuse — so a NEW `enabled` knob is justified per W-20).

### §2.4 Selector algorithm (T03 design)

```python
def select_agents_md_slice(task_type: str, profiles_path: Path | None = None) -> dict:
    """Filter AGENTS.md to the rule slice for ``task_type``.

    Returns dict with:
      - sliced_text: filtered AGENTS.md text (Soul + selected sections only)
      - included_rules: list of rule IDs preserved (e.g. ["S-1", "S-2", ..., "A-1", "W-9"])
      - skipped_rules: list of rule IDs hidden
      - profile_name: which agents_md_slice profile matched
      - total_tokens: estimated token count of sliced text
      - full_tokens: estimated token count of unsliced AGENTS.md
      - slice_savings_pct: percentage reduction
    """
    config = load_profiles(profiles_path)
    slice_cfg = config.get("meta", {}).get("agents_md_slice", {})
    if not slice_cfg.get("enabled", False):
        # Opt-out fast path: return full AGENTS.md
        return {"sliced_text": _read_agents_md(), "included_rules": "all", ...}

    profile_name = _match_slice_profile(task_type, slice_cfg)
    profile = slice_cfg.get("profiles", {}).get(profile_name, {})
    sliced = _filter_agents_md_by_layer_prefix(_read_agents_md(), profile)
    return {
        "sliced_text": sliced.text,
        "included_rules": sliced.included,
        "skipped_rules": sliced.skipped,
        "profile_name": profile_name,
        "total_tokens": estimate_tokens(sliced.text),
        "full_tokens": estimate_tokens(_read_agents_md()),
        "slice_savings_pct": ...,
    }
```

The filter walks AGENTS.md by `^## ([SACW]|ST)-\d+` heading regex. For each heading match, it consults the per-profile layer mapping (`"all"` keeps every rule in that layer; a list keeps only the listed rule IDs; missing key skips the entire layer). Rule body extends to the next `^## ` or `^# ` (top-level layer header). Top-level layer headings (`^# Soul Rules`) are preserved if any rule in that layer survives.

### §2.5 R5 strict invariant

The selector preserves byte-identical v8.5.1 output WHEN `agents_md_slice.enabled: false` (the default). Tests pin the invariant:

* `tests/test_no_ghost_features.py::test_rule_count_under_cap` — counts `^## ([SACW]|ST)-\d+` in compiled AGENTS.md, asserts ≤ **60** (HARD).
* `tests/test_no_ghost_features.py::test_rule_surfaces_compile_only` — verifies `.cursor/rules/repo-governance.mdc` SHA-256 matches the compiler output stored in `.rules/.compile-hashes.json` (drift detection); also verifies the deprecated `.cursor/rules/{devola-flow,workflow}-rules.mdc` stubs match expected stub-template content (cross-reference to `.rules/`).

### §2.6 Per-task-type slice 0 EvoBench drift verification

Per playbook §6.7.4 acceptance: the slice must produce **0 EvoBench drift** because the AGENTS.md slice does NOT participate in EvoBench scenarios (which exercise SKILL.md sections, not AGENTS.md rules).
