## 1. Gaps Identified

Three minor releases (`v7.6.0` / `v7.7.0` / `v7.8.0`) shipped without `CHANGELOG.md` entries — a **user-visible release-notes regression vs. v7.5.0's exemplary entry** and an explicit **S-4 (No Ghost Features) violation in the CHANGELOG ↔ code direction** (releases that exist in the version source-of-truth `src/devolaflow/__init__.py` and as git tags but not in CHANGELOG). Per `.local/research/v8.0.0_patch_plan.md` §3 P-13 (lines 489-516):

- Gap **C1** (Task A handoff #3 from v7.8.0 cycle close-out): *"`CHANGELOG.md` 当前止于 `[7.5.0]` (line 8); v7.6/v7.7/v7.8 三段缺失。落地: P-13 (v8.0.0 周期内, 文本-only patch)"*. The v7.5.0 retrospective had set the precedent for full per-release entries, but the v7.6.0/v7.7.0/v7.8.0 cycles all bumped `__version__` without authoring a CHANGELOG block, leaving `bump_version.py`'s pattern-replacement mechanism to silently update version *strings* while leaving release-notes *content* unauthored.
- Structural gap (PR #60 §Notes for Reviewer + this patch's §4 Learnings): `scripts/bump_version.py` pattern-replaces version strings across the canonical 7 sync locations but **does NOT auto-add a CHANGELOG entry skeleton**. This is structural debt — every minor/major release has historically required out-of-band manual CHANGELOG authorship that has now slipped 3 cycles in a row. The risk is that without a forcing-function inside `bump_version.py`, the same gap re-opens at every future minor bump.
- Demo-page gap (DS-4 / ST-4 coupling): the canonical `<!-- What's New in v7.8.0 -->` placeholder at `workflow-system/human/demo/index.html:237` referenced `data-i18n="landing.whatsNew.v730.desc"` (i.e., **v7.3.0 cycle content under a v7.8.0 header**). This is pre-existing tech debt from prior version-bump scripts that bumped `<h2>` headers without refreshing the body — surfaced during P-13's verification work but explicitly not in P-13's "Append" scope.

The three source commits providing the verbatim CO-2 lift material were identified as `1a4f1ee` (v7.6.0 — `repo-init v2 redesign + lifecycle hooks + format conventions`), `828b9ff` (v7.7.0 — `interview implementation + memory wiring + progressive merge`), `17d2a14` (v7.8.0 — `canonical manifest prompt-side enforcement + doctor command`). ## 4. Key Learnings

- **CO-2 verbatim extraction from `git show --format='%H%n%aI%n%s%n%n%b'` is reliable and fast.** The 3 commits were lifted in <30 minutes total (vs. the 1h estimate in patch plan §3 P-13 for "git log 提取"). The format string yields commit SHA + ISO date + subject + body in one shot, which maps cleanly into a `## [X.Y.Z]` entry without any paraphrase risk. **Adopt** this command pattern as the canonical CHANGELOG-backfill helper; consider codifying as a `make changelog-extract VERSION=X.Y.Z` Makefile target in a future v8.x grooming patch.
- **Demo HTML "What's New" entries should be authored alongside CHANGELOG entries (DS-4 coupling is real, not a follow-up).** P-13 was efficient *because* the dispatch instructed both files in one patch; if the HTML had been separated into a follow-up, the canonical-entry blocks and the doc-consistency tests would have shipped without their visual counterpart, risking another 3-cycle drift. **Reinforce** in the v8.0.0 retrospective: "any patch that adds a CHANGELOG entry MUST include the matching demo HTML 'What's New' block in the same patch" — this should become a Cursor rule under `.cursor/rules/documentation-sync-rules.mdc` (or noted in W-7/SI-8 as a process invariant).
- **`bump_version.py` should be enhanced post-cycle to template a CHANGELOG entry skeleton.** The structural debt that produced this 3-cycle slip is that `bump_version.py` performs 7 pattern replacements but does NOT add a `## [<new-version>] — TBD` skeleton block to `CHANGELOG.md`. **Action item for v8.2.0** (or possibly a v8.1.0 self-analysis emergent patch): enhance `scripts/bump_version.py` to insert a `## [<new-version>] — <ISO date>\n\n### Added\n- TBD\n\n### Changed\n- TBD\n` skeleton above the previous version's entry, forcing the bumper to either fill it in or explicitly delete it. This converts a passive-omission failure mode into an active-decision failure mode.
- **Doc-consistency tests work as a forward-acting regression guard.** The 3 new `test_changelog_has_v7_*_entry` assertions guarantee that any future commit that *deletes* one of these entries (e.g., during a misguided `git rebase --interactive` or a CHANGELOG cleanup) will fail SI-10 step 1. **Adopt** the pattern of adding one `test_changelog_has_v<NEW_VERSION>_entry` per future minor/major bump as part of the bump-version protocol — pairs naturally with the auto-skeleton enhancement above.
- **Append-only-with-explicit-scope-bleed-flag is a sustainable PR-discipline pattern.** P-13's PR description explicitly named the `<!-- What's New in v7.8.0 -->` placeholder as out-of-scope tech debt with the verbatim phrase *"Refreshing the placeholder is OUT OF SCOPE for P-13 and is left for a follow-up patch"*. This made the deferral auditable AND prevented the reviewer from interpreting silence as "not noticed". **Reinforce**: every patch that intentionally leaves adjacent tech debt untouched should explicitly call it out in the PR §Notes-for-Reviewer block, with the prescribed verbatim language template "OUT OF SCOPE for <patch-id>; deferred to <follow-up-patch-or-cycle>".
- **Disjoint owned-file design enables 9-second sibling-merge windows.** PR #60 (P-13) merged at `15:16:44Z`, PR #59 (P-01) merged at `15:16:35Z` — a 9-second gap with zero conflicts because P-01 owned `src/devolaflow/*.py + tests/test_complexity_cleanup.py` while P-13 owned `CHANGELOG.md + demo/index.html + tests/test_doc_consistency.py` (zero file overlap, verified at plan §5 Wave 1 row: *"P-01 owned: data_driven, runtime, format_on_edit, researcher, task_adaptive_selector:main, tests/test_complexity_cleanup. P-13 owned: CHANGELOG, demo HTML, en/zh changelog, tests/test_doc_consistency. **零交叉**"*). **Validate** the `Wave-internal parallel + wave-between stack` PR topology design decision (plan §Overview line 43) — Wave 1 is the proof point that disjoint ownership genuinely enables parallel merge.
- **Insert-only patches are the safest possible doc-debt closure pattern.** P-13 added 180 lines and removed 0 — no existing content was modified, deleted, or reordered. This made the diff trivially reviewable AND eliminated any merge-conflict risk against in-flight patches (notably P-01, which merged 9 seconds earlier). **Recommend**: future doc-debt-closure patches should default to insert-only and explicitly justify any modify/delete in the PR description.
