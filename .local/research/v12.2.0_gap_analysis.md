### D-1 — `.local/` gitignore over-corrects: team-collab subdirs leak into private state (BLOCKER, closes v12.1.0 feedback)

**Symptom** (verbatim from `.local/feedbacks/feedback_for_v12.1.0.md`):

```
devola init 时，对 gitignore 的操作表现有问题
.local下除了必要的面向 git 仓库和团队协作的内容以外，都需要正确 ignore
```

**Root cause**: v9.2.3 PV-02 (`src/devolaflow/local/workspace.py:294 _LOCAL_GITIGNORE_RULE = ".local/"`) replaced the legacy whitelist semantics (`.local/*` + `!.local/.agent/` + `!.local/memory/specs/`) with a single broad `.local/` ignore. The motivation was "private by default for shell history / memory state". Net effect: team-collab artifacts that SHOULD be reviewable (A-4 source-of-truth specs at `.local/memory/specs/<domain>/spec.md`; in-flight research artifacts at `.local/research/v*` that W-19 retros cite) became invisible to teammates without an opt-in `git add -f`.

**Impact**:
* A-4 source-of-truth `.local/memory/specs/<domain>/spec.md` contracts cannot be reviewed by PR without `git add -f` workarounds — violates the intent of M-004 ADR (A-4) that specs are team contracts
* In-flight research artifacts under `.local/research/v12.2.0_*` (this very gap analysis!) are invisible to PR reviewers until the W-19 cycle-end archive step graduates them to `docs/cycle-archive/v12.2.0/` — slows mid-cycle feedback
* Operator confusion: the `feedback_for_v12.1.0.md` author explicitly observed the regression

**Proposed fix** (PV-02):

Replace the broad `.local/` rule with a selective whitelist block per the user's explicit team-collab set:

```bash
# DevolaFlow local workspace (private — whitelist team-collab subdirs)
# Per .local/feedbacks/feedback_for_v12.1.0.md — narrow whitelist replaces broad ignore.
.local/*
!.local/.gitignore
!.local/memory/
.local/memory/*
!.local/memory/specs/
!.local/memory/specs/**
!.local/research/
!.local/research/**
```

Operator's selected team-collab set (from plan-mode questions):
* `.local/memory/specs/` (A-4 source-of-truth contracts; canonical merged baselines)
* `.local/research/` (gap analysis + ADRs + design docs; cited by W-7/W-19 retros)

Operator's NON-selected (intentionally personal/transient):
* `.local/feedbacks/` (per-version personal observations — graduate to CHANGELOG)
* `.local/tasks/` (per-cycle personal task definitions — graduate to commits)
* `.local/.agent/active/`, `.local/.agent/archive/`, `.local/.agent/handoff/` (per-developer change folders + machine handoff state)
* `.local/memory/{operational.jsonl,session_state.json,prefs.md,plugin_install.log,commands/,cases/}` (machine state)
* `.local/dogfood/`, `.local/sandbox/`, `.local/benchmarks/`, `.local/scratch/`, `.local/logs/`, `.local/prototypes/` (scratch/dev)

**File-level scope** (4 files):
* `src/devolaflow/local/workspace.py` — replace `_LOCAL_GITIGNORE_RULE` + `_is_broad_local_ignore_rule` semantics + `ensure_local_gitignore` write logic
* `.gitignore` — repo-root self-fix (line 49 area)
* `tests/test_local_workspace.py` + `tests/test_scaffold_gitignore_audit.py` + `tests/test_init_doctor.py` — update fixtures to expect the new block

### D-2 — Mnimiy 12-rule article: 3 candidate behavioral gaps (Rules 5/7/11) — MAJOR

**Symptom**: the article's empirical claim (mistake rate **41% → 11% → 3%** with no-rules / 4-rules / 12-rules templates) suggests 8 extension rules close gaps beyond Karpathy's original 4. DevolaFlow already implements Karpathy 1-4 as BG-001..BG-004 (per `workflow-system/agent/references/behavioral-guidelines.md`). Question: which of the 8 extensions close gaps NOT covered by S-1..S-10, A-1..A-7, W-1..W-24, BG-001..BG-004?

**Manual NineS-style decomposition** (NineS Python-AST tool returned 0 findings for the markdown article; W-2 fallback applies — manual analysis following the same dimensions):

|---|---|---|---|---|

| 6 | Hard token budgets, no exceptions | A-3 + W-6 (context budget enforcement) + `gate.token_budget` (v8.0.0 P-03) | **Already covered** — reinforce at L3 self-check level | "A 90-minute debugging session iterating on the same 8KB error message. By the end, Claude was suggesting fixes the user had rejected 40 messages earlier." |

**Verdict**: **3 NEW behavioral primitive candidates** (BG-005, BG-006, BG-007) closing Article Rules 5, 7, 11. Each candidate must clear the [W-22.3 ADR 3-condition gate](.cursor/rules/repo-governance.mdc) when surfaced — but **none of the 3 qualify as ADR-worthy** because each is:
* NOT hard to reverse (text edit + one field in `behavioral_guidelines`)
* NOT surprising without context (each maps to a well-known failure mode from the article)
* NOT a real trade-off (additive coverage of a previously-uncovered gap)

Per W-22.3, ADRs are skipped; BG additions are routine behavioral-primitive extensions.

**Article validity assessment**: the article's empirical data (30 codebases × 50 tasks × 6 weeks; **compliance stayed flat 78% → 76% between 4-rules and 12-rules**) supports the additive hypothesis — adding rules 5-12 closes failure modes the original 4 didn't touch without competing for the same attention budget. **DevolaFlow inherits this benefit at lower cost** because our base coverage already includes Rules 8, 9, 10, 12 via Soul/Workflow surfaces (article reduces compliance by ~10pp; we add only 3 rules so the compliance cost is minimal — estimated ~1-2pp).

**Article DECLINE assessment**: Rules 6 + 8 are already covered via different surfaces (A-3 + execution-protocol.md). Rules 9, 10, 12 are at HIGHER rigor in DevolaFlow than the article suggests (CP-2 80% coverage > article's "tests must check behavior"; S-9 append-only ledger > article's "checkpoints"; S-5 Soul invariant > article's "fail visibly").
