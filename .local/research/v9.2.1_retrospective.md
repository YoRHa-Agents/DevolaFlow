## 4. Key learnings (process improvements for next cycle)

### 4.1 What worked well (continue doing)

1. **The self-update workflow as cycle-close validation is proven.** The 7 stages (`check-refs → research-updates → decompose → integrate → test → evaluate → release`) are a repeatable cycle-close pattern. PV-07 discharged in < 3 hours wall-clock (within the 6-hour stage budget sum). The staged pipeline also produced 7 named artefacts that map 1:1 to the cycle-level ACs — making the verification audit trail trivially inspectable.

2. **Zero-code-path PATCH discipline held cleanly.** The cycle plan §PV-07 explicitly pinned "zero new code paths"; the final diff honours this verbatim (no new src/ modules, no new env flags, no new rules, no new schema extensions). The NineS composite byte-identical outcome (0.907348 → 0.907348 delta 0.000000) is the mathematical proof that the discipline held — any code-path introduction would have shifted at least one axis by ≥ 0.001.

3. **Recursive engagement exercises the capability end-to-end.** PV-07 opened its own change folder via `/devola:propose`, wrote its own handoff envelope, and archived itself at Stage 7. This is the single strongest evidence that the cycle's deliverable works on its own author — a claim the cycle plan §"self-update workflow as cycle-close validation" predicted and this PV proved.

4. **Multi-fixture parametrization kept the W-17 budget lean.** 4 NEW test functions + 12 parametrize expansions gave 12 new test cases for the cost of 4 cap-counted tests (3 cases/test). If I'd written these as 12 separate test functions I would have overrun the PV-07 +4 NEW cap by 200%.

5. **W-18 ghost-audit refresh BEFORE CHANGELOG held discipline again.** The `test_v9_2_1_new_symbols_have_coverage` lint ran GREEN before I wrote the `[9.2.1]` CHANGELOG entry. This surfaced the archive-script's `other/` subdir routing immediately (my initial path pinning assumed everything went under `nines/`; the ghost-audit test failed fast, I fixed the paths, re-ran green, then wrote the CHANGELOG).

6. **W-20 reuse-first held across the entire 7-PV cycle.** Zero new env flags in 7 PVs. The `DEVOLAFLOW_AGENT_WORKSPACE` / `DEVOLAFLOW_MEMORY_ROUTER` / `DEVOLAFLOW_AGENTS_MD_SLICE` reuses are now the canonical pattern — any v9.3.0+ flag proposal should look at these three surfaces for the reuse target before authoring a new flag.

### 4.2 What didn't work well (process improvements for v9.3.0+)

1. **Archive-script subdirectory routing was opaque until runtime.** `scripts/archive_research_artifacts.py` routes files to `nines/` / `evaluation/` / `other/` subdirs based on filename prefix — but the routing rules aren't documented in the script's docstring. I had to run the script and inspect the output directory to learn that `v9.2.1_check_refs.md` lands in `other/`. **Recommendation for v9.3.0+**: document the routing rules in the script's module docstring OR emit a dry-run mode that prints the target location for each source file.

2. **The slugify rules stripped dots from the preferred change-id.** My dispatch specified `v9.2.1-self-update-validation` but `/devola:propose "v9.2.1 self-update validation"` slugified it to `v9-2-1-self-update-validation` (dots collapsed into dashes, even though the change-id regex allows dots). I had to delete the auto-created folder and re-invoke `scaffold_change_folder(..., change_id="v9.2.1-self-update-validation")` via the Python API. **Recommendation for v9.3.0+**: teach `slugify` to preserve dots when the resulting slug still matches the change-id regex, OR add a `--change-id` flag to `/devola:propose` that bypasses slugify.

3. **The archive script's `--extra-prefix v9.2.` sweep includes ALL v9.2.* artefacts, not just v9.2.1.** On the first post-bump archive run the script would re-process `v9.2.0_*` artefacts too (idempotent per W-19, so this is a no-op write — but it's noisy in the terminal output). Not a correctness issue but a usability papercut. **Recommendation for v9.3.0+**: support a `--prefix-exclude v9.2.0.` kwarg so the operator can explicitly say "everything else under v9.2.* but not v9.2.0".
