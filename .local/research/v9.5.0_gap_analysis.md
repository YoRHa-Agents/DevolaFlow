## §2 — Si-Chip empirical baseline (pre-cycle probe)

The Si-Chip v0.4.0 install script (canonical: https://yorha-agents.github.io/Si-Chip/install.sh) was executed at PV-01 cycle-start to confirm the integration target:

```bash
$ curl -fsSL --max-time 30 https://yorha-agents.github.io/Si-Chip/install.sh | bash -s -- --target cursor --scope global --yes --force
=> Installing Si-Chip (cursor) to /root/.cursor/skills/si-chip
ERROR: post-install: SKILL.md missing at /root/.cursor/skills/si-chip
$ find ~/.cursor/skills/si-chip -type f | wc -l
21
$ ls ~/.cursor/skills/si-chip/si-chip/
DESIGN.md SKILL.md references scripts
```

**Finding:** Si-Chip v0.4.0 ships **21 files** (1 SKILL.md + 1 DESIGN.md + 14 references + 5 scripts) BUT the installer's POST-INSTALL CHECK looks at the wrong path — files land at `~/.cursor/skills/si-chip/si-chip/<name>` (double-nested) while the installer expects them at `~/.cursor/skills/si-chip/<name>` (single level). The installer exits 1; the payload is intact and usable but at a different path than documented.

**Concrete script verification (the 3 scripts the bridge wraps):**

```bash
$ python ~/.cursor/skills/si-chip/si-chip/scripts/count_tokens.py \
    --file ~/.cursor/skills/si-chip/si-chip/SKILL.md --both
metadata_tokens=94
body_tokens=4646
verdict=pass

$ python ~/.cursor/skills/si-chip/si-chip/scripts/profile_static.py --help
usage: profile_static.py [-h] --ability ABILITY [--out OUT]
                         [--templates-dir TEMPLATES_DIR] ...

$ python ~/.cursor/skills/si-chip/si-chip/scripts/aggregate_eval.py --help
usage: aggregate_eval.py [-h] --runs-dir RUNS_DIR --baseline-dir BASELINE_DIR
                         [--out OUT] [--skill-md SKILL_MD] ...
```

All 3 scripts work correctly. The installer post-install check failure is a **packaging defect upstream**; the runtime integration is unaffected because the bridge's `install_resolver.py` (PV-02) tries multiple candidate paths in order. The defect is captured in §5 as an upstream feedback item.

## §3 — Deficiencies enumerated (priority-ranked, ≥ 8 per W-1 contract)

### 3.1 Critical (blockers for v9.5.0 close)

#### D-S-1 — Si-Chip not in `runtime-plugins.yaml` *(CRITICAL)*

**Source:** v10.0.0 cycle plan §3 v9.5.0 row + user requirement verbatim §1.
**Surface:** `workflow-system/agent/knowledge/runtime-plugins.yaml`.
**Evidence:** Current schema_version 3 registry has 3 entries (`nines`, `ui-pro`, `rtk`). Si-Chip is not registered. Without registration, `plugins_for_workflow("skill-optimization")` returns only `["nines"]` even though the v9.5.0 templates wire `si-chip` into `skill-optimization` AND `self-update` AND `nines-assisted`.
**Fix:** Add a 4th entry `id: si-chip`, backend `curl_install_script` (reuses RTK plumbing from v8.3.1 PV-01), `install_cmd: "curl -fsSL https://yorha-agents.github.io/Si-Chip/install.sh | bash -s -- --target cursor --scope global --yes"`, `upgrade_cmd: <same as install_cmd>` (Si-Chip installer is idempotent per its v0.4.0 spec, mirroring the RTK contract), `version_check_cmd` that probes both single-level and nested install paths, `min_version: "0.4.0"`, `canonical_url: "https://github.com/YoRHa-Agents/Si-Chip"`, `invoked_by_workflows: [skill-optimization, self-update, nines-assisted]`.
**verify_distinguish_cmd decision:** SKIP. Si-Chip has no known name collision (RTK precedent only fires because of the rtk-type-kit collision documented in RTK INSTALL.md). The `verify_distinguish_cmd` field is optional in schema v3 per `installer.py::RuntimePluginSpec`; omitting it is byte-compat.
**Owned files in PV-01:** `runtime-plugins.yaml` (EDIT — append 4th plugin block), `plugins.yaml` (EDIT — add `si-chip` to the legacy catalog for backward-compat with pre-v8.2.1 callers), `tests/test_plugin_sichip_registration.py` (NEW).

#### D-S-2 — `si_chip_bridge` Python module missing *(CRITICAL)*

**Source:** Cycle plan §3 v9.5.0 row + user requirement "wrap or elevate" + Q2=B DEEP integration signoff.
**Surface:** `src/devolaflow/`.
**Evidence:** Si-Chip ships 5 standalone CLI scripts (`profile_static.py`, `count_tokens.py`, `aggregate_eval.py`, plus 2 quickstart `.md` cheat-sheets). DevolaFlow's lifecycle hooks (`pre_dispatch`, `post_dispatch`, `pre_handoff`, `pre_plugin_invocation`) are pure Python — they cannot directly invoke external CLI scripts without a typed wrapper. Without the bridge module, the `post_skill_edit` hook (PV-04) would have to embed subprocess + YAML-parsing logic inline, violating S-5 (loud failures) AND duplicating Si-Chip's own typed contract.
**Fix:** Author `src/devolaflow/si_chip_bridge/` package with 4 modules:
1. `__init__.py` — public API re-exports (`profile`, `evaluate`, `aggregate_delta`, `apply_or_defer`, `SiChipResult`, `SiChipError`, `SiChipUnavailable`).
2. `runner.py` — subprocess wrappers for `profile_static.py`, `aggregate_eval.py`. Subprocess invocation through `subprocess.run` with explicit `check=False` + stderr capture per S-5; timeout default 90s mirroring `runtime-plugins.yaml#defaults.network_timeout_seconds`.
3. `models.py` — `@dataclass(frozen=True)` types matching the Si-Chip YAML shape subset (`BasicAbilityProfile`, `MetricsReport`, `IterationDeltaReport`, `ApplyVerdict`).
4. `install_resolver.py` — searches for the Si-Chip install dir in priority order: (1) `$SI_CHIP_HOME` env var, (2) `~/.cursor/skills/si-chip/`, (3) `~/.cursor/skills/si-chip/si-chip/` (the v0.4.0 nested-installer-bug path), (4) `~/.claude/skills/si-chip/`, (5) `~/.claude/skills/si-chip/si-chip/`, (6) `/home/agent/reference/Si-Chip/` (local clone fallback). Returns `None` when no candidate is found — the bridge then surfaces `SiChipUnavailable` per S-5 loud failure.
**Owned files in PV-02:** 4 new module files + `tests/test_si_chip_bridge.py` (NEW).

#### D-S-3 — Templates do not wire `si_chip_dogfood` stage *(CRITICAL UX)*

**Source:** Cycle plan §3 v9.5.0 row + user requirement "comprehensive analysis and optimisation".
**Surface:** `workflow-system/agent/templates/builtin/skill-optimization.yaml` + `self-update.yaml`.
**Evidence:** Current `skill-optimization.yaml` runs `survey → profile → optimize → benchmark → document` (5 stages). Without a Si-Chip stage between `optimize` and `benchmark`, optimisation candidates land in code WITHOUT the iteration_delta gate — operators discover regressions only via EvoBench at `benchmark`. Inserting `si_chip_dogfood` between them gives Si-Chip's iteration_delta a chance to DEFER changes that fail the +0.10 threshold BEFORE they hit the slower EvoBench gate.
**Fix:** Insert `si_chip_dogfood` stage in `skill-optimization.yaml` (primitive: `validate`, team: `test`, alias: `si_chip_dogfood`, between `optimize` and `benchmark`) AND add `si_chip_gate` optional stage in `self-update.yaml` between `integrate` and `test`. Both stages reference `devolaflow.si_chip_bridge.evaluate` + `apply_or_defer` via the standard `nines_commands`-style mapping.
**Owned files in PV-03:** Both template YAML files (EDIT — additive stage + composition update), `tests/test_sichip_template_integration.py` (NEW).

#### D-S-4 — `post_skill_edit` lifecycle hook + DEEP env flag missing *(CRITICAL — Q2=B contract)*

**Source:** User Q2=B (DEEP integration always-on signoff).
**Surface:** `src/devolaflow/lifecycle/`.

Wire into `lifecycle/__init__.py::DEFAULT_EVENTS` at position 10 per A-2.2 append-only.
**Owned files in PV-04:** `lifecycle/post_skill_edit.py` (NEW), `lifecycle/__init__.py` (EDIT — append the new event), `references/env-flags.md` (EDIT — §2.14 entry), `tests/test_post_skill_edit_hook.py` (NEW).

### 3.2 Major (must ship for v9.5.0)

#### D-S-5 — `DEVOLAFLOW_SI_CHIP_DEEP` env-flag W-20 §3 orthogonality *(MAJOR design)*

**Source:** W-20 reuse-first vs new-flag policy.
**Surface:** `workflow-system/agent/references/env-flags.md`.
**W-20 §3 orthogonality analysis (3 candidates):**

* **Existing flag candidate 1: `DEVOLAFLOW_AUTO_INSTALL_PLUGINS`** (v9.4.0 PV-02, default-OFF, opt-IN, R5 strict). Activates the dispatcher's `pre_plugin_invocation` hook to auto-install plugins cited in the dispatch payload. **Different surface** — it controls PRE-dispatch plugin installation; DEEP integration controls POST-skill-edit dogfood evaluation. An operator may want one without the other (auto-install YES + dogfood NO is a valid configuration: "install plugins but don't run them on every commit").
* **Existing flag candidate 2: `DEVOLAFLOW_AUTO_INSTALL`** (default-ON, opt-OUT). Read by `installer.py::ensure_plugin` to control whether the install primitive performs the install vs raises `PluginVersionMismatch`. **Different surface** — primitive-level vs hook-level activation.
* **Existing flag candidate 3: `DEVOLAFLOW_AGENT_WORKSPACE`** (default-OFF, opt-IN). Activates the workspace lifecycle (active/handoff folder management). **Conceptually orthogonal** — workspace activation has nothing to do with skill self-evaluation cadence.
* **Verdict:** NEW flag justified per W-20 §3. The new `DEVOLAFLOW_SI_CHIP_DEEP` activates a **distinct runtime surface**: the `post_skill_edit` hook's Si-Chip evaluation execution. It composes meaningfully with `DEVOLAFLOW_AUTO_INSTALL_PLUGINS`: setting both ON + the `skill-optimization` workflow gives the full pipeline (auto-install Si-Chip → dogfood-evaluate skill changes → DEFER below threshold). Setting just `SI_CHIP_DEEP=1` without `AUTO_INSTALL_PLUGINS=1` is also valid for operators who pre-install Si-Chip manually.

**Activation rule:** `DEVOLAFLOW_SI_CHIP_DEEP=1` (R5 strict — `"1"` only; rejects `"true"`/`"yes"`/`"on"`/`"01"`/`"1\n"`/`""`). Default-OFF; opt-in for v9.5.0. Telegraphed default-flip candidate for v9.7.0 (per the v8.5.1 PV-06 → v9.1.5 PV-05 default-flip pattern).
**Fix:** Author the flag in `lifecycle/post_skill_edit.py`. Document in `references/env-flags.md` §2.14 (the canonical inventory). Author R5 strict zero-IO test in `tests/test_post_skill_edit_hook.py`.
**Owned files in PV-04:** Same as D-S-4.

#### D-S-7 — Si-Chip nested-install path bug needs upstream feedback *(MAJOR — discovered at PV-01 §2)*

**Source:** §2 above.
**Surface:** Upstream Si-Chip v0.4.0 installer.
**Evidence:** Installer exits 1 because post-install SKILL.md check looks at single-level path `~/.cursor/skills/si-chip/SKILL.md` while the actual extraction lands at nested path `~/.cursor/skills/si-chip/si-chip/SKILL.md`. All 21 files arrive correctly; only the post-install check is broken.
**Fix:** Two-layer mitigation:

2. **Upstream feedback** — capture the bug in `.local/feedbacks/v9.5.0_sichip_deferred.md` §"Upstream defects" with the exact installer output + the proposed one-line fix (move the `--strip-components=1` flag onto the `tar -xzf` invocation in the install script). Recommend filing as Si-Chip GitHub issue.
**Owned files in PV-02 + PV-05:** `install_resolver.py` (PV-02) + `.local/feedbacks/v9.5.0_sichip_deferred.md` §"Upstream defects" (PV-05).
