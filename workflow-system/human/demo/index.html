The checklist-round model

A signed goal and checklist stay stable while the system selects priority work, partitions it into waves, dispatches atomic tasks, and gates the evidence before another round begins.

L0

Project

Owns the goal, checklist, preflight, round selection, gates, reinforcement, and final report. It dispatches; it does not implement delegated work.

L1

Wave

Partitions independent items, dispatches up to five Task agents in parallel, detects conflicts, and aggregates evidence proposals.

L2

Task

Implements one atomic assignment, runs bounded implement-review-fix loops, verifies each acceptance criterion, and returns a lean StatusReport.

One round, end to end

  1. Select priority checklist items

    Reverted blockers first, then P0, P1, and P2 in stable order.

  2. Partition work into waves

    Keep writable ownership disjoint and dependencies explicit.

  3. Dispatch and verify Tasks

    Each Task works within a retry ceiling and reports commands, artifacts, findings, and criterion-level results.

  4. Gate evidence before continuing

    A round passes only when selected items have valid evidence, checks pass, reinforcement closes, and blockers reach zero.

Human boundaries remain explicit: preflight, revision, escalation, and abort.

npx @yorha-agents/devola-flow install all

Requires Node 18 or newer. The installer downloads the manifest-defined skill file set from the matching release tag.

25 seeds, one generated catalog

Seeds pre-populate decomposition knowledge for a checklist. Their source labels preserve provenance; they do not execute or prescribe order, teams, duration, loops, or gates.

    Seed and runtime are different contracts

    The change-driven seed is non-executable decomposition knowledge like the other 22 seed files. Separately, builtin/change-driven.yaml is the sole executable runtime: it proposes, signs preflight, runs checklist rounds, and archives the result.

    The nines-assisted filename remains an opaque compatibility ID. It does not activate or recommend an evaluator.

    Current release window

    Home now keeps a compact v17/v16 window. The former 73-entry release stack belongs in Timeline, where older history can retain its original context.

    New in v17.3.0

    • Every change folder now scaffolds an entrance.md onboarding router so fresh sessions, external agent tools, and human auditors know what to read first.
    • The router is static by contract: it maps each scenario to a minimal read order and always points at STATUS.yaml and stage.md instead of mirroring progress.
    • A parity lint locks the router's artifact inventory to the budget registry; folders from earlier releases lint as a warning until backfilled.

    v16.0.0 · Checklist rounds become the product model

    • Project → Wave → Task replaced the previous hierarchy, while priority-driven checklist rounds replaced ordered template execution.
    • Twenty-three templates became non-executable checklist seeds; one change-driven runtime and signed preflight govern execution.
    • The built-in harness added telemetry, deterministic six-dimension evaluation, bounded probes, and approval-only proposals.
