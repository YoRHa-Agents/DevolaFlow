How It Works

Every workflow executes through a strict 4-layer hierarchy. Upper layers dispatch; only the bottom layer works.

L0
Project
picks workflow type, dispatches stages
~3K ctx
▼ dispatches
L1
Stage
decomposes into waves, runs quality gates
~5K ctx
▼ dispatches
L2
Wave
dispatches tasks in parallel, collects results
~4K ctx
▼ dispatches
L3
Task
writes code, runs tests, reviews — the ONLY layer that works
~8K ctx

What's New in v7.0.0

v7.0.0 opens the staged-context-compression cycle (J.1 of v7.0→v7.1) by shipping the cache-layout invariant: a runtime-validated 12-key canonical order for every lean dispatch, a round-stability SLO (LCP ≥ 80% round 1→2, ≥ 70% round 1→3) backed by a golden baseline test, and Rule P6 (Preserve Cached Prefix) in the workspace ruleset. Additive at the Python level; backwards-incompatible governance contract for downstream tooling that reordered dispatch sections.

INVARIANT

Cache-Layout Invariant

Canonical 12-key order: hdr → task → goal → assumptions → pred → files → rules → shared → accept → reinforce → verify_cfg → gate. New keys MUST be appended after gate. Source of truth: schemas/lean-dispatch.yaml#layout_invariant.

View Schema →
VALIDATOR

assert_dispatch_layout()

Runtime validator in devolaflow.compressor raises DispatchLayoutError on any out-of-order key. Companion compute_dispatch_lcp_pct() returns the rendered-prefix stability fraction used by the H.2 stability test.

View Code →
SLO

Round-Stable Dispatch Render

LCP ≥ 80% round 1→2, ≥ 70% round 1→3 — measured 0.8487 / 0.8487 on the synthetic 3-round task_id. Enforced via tests/test_compressor.py::test_dispatch_prefix_is_stable_across_rounds and a golden baseline byte-comparison.

View ADR →
METRICS

1015 Tests, +6 New

5 new layout-invariant unit tests + 1 golden baseline test. Rule P6 (Preserve Cached Prefix) added to .cursor/rules/devola-flow-rules.mdc. Roadmap: v7.0.1 tool-output truncation → v7.0.2 hierarchical summary → v7.0.3 persistence probe → v7.1.0 adoption + retrospective.
